# What do I do when a store does not have data of the timestamp requested by the downstream?

This topic describes how to perform troubleshooting when a store does not have data of the timestamp requested by the downstream.

## Symptom

When JDBCWriter pulls data from a store, any of the following errors is reported in `error.log`:

* `Store XXX without server id`

* `Refused connect attempt for requesting checkpoint`

* `Invalid start time, shall within store's data keep time which normally is 24 hours`

## Possible causes

According to the data cleanup mechanism of Store, data in a store is cleaned up upon expiration against the current time. For a data synchronization task, the default data retention period is 24 hours. For a data migration task, the default data retention period is 120 hours. Once the retention period of the data expires, the data will be cleaned up and cannot be pulled by the downstream.

## Troubleshooting procedure

Start a new store to pull back data.

1. Log on to the OceanBase Migration Service (OMS) console.

2. In the left-side navigation pane, click **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.DataMigration">Data Migration</UI-TERM>**.

3. In the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>**  list, click the name of the target task to go to its details page.

4. Click **<UI-TERM key="oms-community.Migration.Detail.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** in the upper-right corner.

5. In the **<UI-TERM key="oms-community.Sync.constants.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** dialog box, find the corresponding store and copy the topic of the store.

   ![Copy a topic](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/%E5%A4%8D%E5%88%B6%20topic.png)

6. Start a new store for the topic.

   1. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.OMMonitoring">OPS & Monitoring</UI-TERM>** > **<UI-TERM key="oms-community.Operation.OperationComponent.Component">Component</UI-TERM>**. The **<UI-TERM key="oms-community.components.MonitorDrawer.LogPullComponent">Store</UI-TERM>** tab automatically appears.

   2. Click **<UI-TERM key="oms-community.Operation.Store.Add">Add</UI-TERM>** in the upper-right corner of the page.

   3. In the **<UI-TERM key="oms-community.EndpointPublic.components.KafkaForm.Add">Add</UI-TERM>** dialog box, configure the parameters.

      | Parameter | Description |
      |----------------------|-----------------|
      | Subtopic | Enter the copied topic.  |
      | Node | Select the server to start the store.  |
      | Timestamp | Select the start time for data pullback. This start time needs to cover the timestamp requested by the downstream.  |

   4. Click **<UI-TERM key="oms-community.Store.New.Add">Add</UI-TERM>**.

7. Return to the **<UI-TERM key="oms-community.OCP.components.ErrorInfo.MigrationProject">Data Migration Task</UI-TERM>** page and modify the parameters.

   1. Log on to the OMS console. In the left-side navigation pane, click **<UI-TERM key="oms-community.Migration.Detail.DataMigration">Data Migration</UI-TERM>**.

   2. In the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>**  list, click the name of the target task to go to its details page.

   3. Click **<UI-TERM key="oms-community.Detail.components.SyncMonitorDrawer.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** in the upper-right corner.

   4. On the **<UI-TERM key="oms-community.Migration.constants.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** page, click **<UI-TERM key="oms-community.Operation.components.machineCom.Update">Update</UI-TERM>** for the new store.

   5. In the **<UI-TERM key="oms-community.Operator.Checker.useCheckerAction.UpdateConfigurations">Update Configuration</UI-TERM>** dialog box, hover the pointer over the incremental data retention period parameter `store.clearer.outdated` and click the Edit icon to modify the parameter.

      The Unit of this parameter is seconds. The data retention period must be able to cover the timestamp requested by the downstream. After you modify the parameters, check whether the task is restored after a period of time. If the downstream JDBCWriter is still abnormal, restart the JDBCWriter.

   6. After you modify the YAML configuration as required, click **<UI-TERM key="oms-community.Connector.New.Update">Update</UI-TERM>**.
