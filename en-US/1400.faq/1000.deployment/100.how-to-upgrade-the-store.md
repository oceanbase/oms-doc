# Upgrade Store

This topic describes how to upgrade the Store version on a server.

## Upgrade Store

After you upload the new `oboms-xlog-store` RPM package to the OMS Community Edition container, you can run the `rpm -Uvh` command to install and upgrade the package. Here is an example:

```shell
# Query the installed version.
[root ~]# rpm -qa oboms-xlog-store
oboms-xlog-store-5.1.1-20220328193528.alios7.x86_64

# Upgrade to the new version.
[root ~]# rpm -Uvh oboms-xlog-store-5.1.2-20220518152726.alios7.x86_64.rpm
```

## Create a Store in the New Version

Each store\[XXXX\] working directory is a sandbox environment. After you upgrade the Store RPM package, the new version is only available for newly created stores. To create a new store, perform the following steps:

1. Log in to the OMS Community Edition console.

2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.OMMonitoring">OPS & Monitoring</UI-TERM>** **\>** **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.Components">Component</UI-TERM>**. The **Store** page automatically appears.

3. On the **<UI-TERM>Store</UI-TERM>** page, click **<UI-TERM key="oms-community.Operation.Store.Add">Add</UI-TERM>** in the upper-right corner.

   * If you have deployed the store in a single region, the region information is displayed on the right of **<UI-TERM>Store</UI-TERM>**.

   * If you have deployed the store in multiple regions, the **Region** column is displayed on the **<UI-TERM>Store</UI-TERM>** page after you create a store.

4. In the **<UI-TERM key="oms-community.Operation.Store.Add">Add</UI-TERM>** dialog box, configure the parameters.

   | Parameter | Required | Description |
   |-----------|------|------------------------------------------------------------------------------------------------|
   | Subtopic  | Yes   | The data source at the cluster or tenant level. Select the corresponding subtopic based on your task. <br> The subtopic corresponds to the part between the two colons in the Store component ID on the **<UI-TERM key="oms-community.Migration.constants.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** dialog box on the task details page.                                                                |
   | Node      | No    | Specifies the machine where the store is started. In a single-node deployment, only one machine is available, and the store is created on this machine by default. In a high-availability scenario, if you do not specify the Node, the system automatically schedules the store to a machine that has not reached its performance bottleneck. <br> **Note:**<br> If only some machines are upgraded, make sure to select the corresponding **Node** when you create a new store. |
   | Timestamp | Yes   | The timestamp that specifies the starting point of the store. Make sure that database logs exist to avoid store startup failure.                           |

5. Click **<UI-TERM key="oms-community.Detail.components.MigrationInfos.Submitted">Submit</UI-TERM>**.
