# How do I upgrade Store?

This topic describes how to upgrade Store on a server.

## Upgrade Store

On the [RPM query page](http://rpm.corp.taobao.com/), query the version of the RPM package `oboms-xlog-store` required for the Store component. Download the package of the required version to the OceanBase Migration Service (OMS) server, and then run the `rpm -Uvh` command to install the package to upgrade the component. Procedure:

```shell
# Query the current version.
[root ~]# rpm -qa oboms-xlog-store
oboms-xlog-store-5.1.1-20220328193528.alios7.x86_64

# Upgrade the component after you obtain the RPM package of the new version.
[root ~]# rpm -Uvh oboms-xlog-store-5.1.2-20220518152726.alios7.x86_64.rpm
```

## Create a store based on the new version

Each `store\[XXXX\]` working directory is a sandbox environment. That is, the new version is valid only for a new store after the Store RPM package is installed. To create a store, perform the following operations:

1. Log in to the OMS console.

2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.OMMonitoring">OPS & Monitoring</UI-TERM>** **>** **<UI-TERM key="oms-community.Operation.OperationComponent.Component">Component</UI-TERM>**. The **<UI-TERM key="oms-community.components.MonitorDrawer.LogPullComponent">Store</UI-TERM>** tab automatically appears.

3. On the **<UI-TERM key="oms-community.components.MonitorDrawer.LogPullComponent">Store</UI-TERM>** tab, click **<UI-TERM key="oms-community.EndpointPublic.components.KafkaForm.Add">Add</UI-TERM>** in the upper-right corner.

   * For single-region deployment, the region information is displayed on the right of **<UI-TERM key="oms-community.components.MonitorDrawer.LogPullComponent">Store</UI-TERM>**.

   * For multi-region deployment, the **<UI-TERM key="oms-community.Operation.Checker.Geographical">Region</UI-TERM>** column is displayed on the **<UI-TERM key="oms-community.components.MonitorDrawer.LogPullComponent">Store</UI-TERM>** tab after you add a store.

4. In the **<UI-TERM key="oms-community.EndpointPublic.components.KafkaForm.Add">Add</UI-TERM>** dialog box, configure the parameters.

   | Parameter | Required | Description |
   |-----------|------|------------------------------------------------------------------------------------------------|
   | Subtopic | Yes | A cluster- or tenant-level data source. Select a subtopic based on the specific task.<br>The subtopic is displayed between the two colons in the store component ID on the **<UI-TERM key="oms-v2.Detail.components.SyncMonitorDrawer.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** dialog box of the task details page.  |
   | Node | No | The server on which the store is started. In standalone mode, only one server is deployed, and the store is created on that server by default. When no node is specified in high availability scenarios, the system automatically schedules the store to a server that has not experienced any performance bottleneck. <br>**Notice:**<br>If the component is upgraded on only some servers, select the corresponding node when you create the store.  |
   | Timestamp | Yes | The point in time from which the store is started.  Make sure that the database logs exist. Otherwise, the store may fail to start.  |

5. Click **<UI-TERM key="oms-community.Detail.components.MigrationInfos.Submitted">Submit</UI-TERM>**.
