# User privileges

Before you migrate a database by using OceanBase Migration Service (OMS) Community Edition, make sure that a database user is created for each data source as a migration user or synchronization user. The user must have the required privileges for the source and destination data sources.

## Permissions for a MySQL database as the source

* The user of the source MySQL database must have the SELECT privilege on the database to be migrated. If the source database is MySQL V8.0, you must also grant the SHOW VIEW privilege to the user.

  ```sql
  GRANT SELECT ON <database_name>.* TO '<user_name>';
  ```

* When you perform incremental synchronization from a MySQL database, the user must have the REPLICATION CLIENT, REPLICATION SLAVE, and SELECT *.* privileges.

  ```sql
  GRANT REPLICATION CLIENT, REPLICATION SLAVE ON *.* TO '<user_name>' [WITH GRANT OPTION];
  GRANT SELECT ON *.* TO '<user_name>';
  ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <ul>
   <li>
   <p>If the user does not have the SELECT privilege on all tables of the source database, the task may fail. </p>
   </li>
   <li>
   <p><code>WITH GRANT OPTION</code> is an optional parameter. </p>
   </li>
   </ul>
   </main>

* When you migrate data from a MySQL database to the MySQL-compatible mode of OceanBase Database, if there is reverse incremental data, the user must have the CREATE, SELECT, INSERT, UPDATE, and DELETE privileges on the source test database.

  ```SQL
  GRANT CREATE,SELECT,INSERT,UPDATE,DELETE ON test.* TO '<user_name>';
  ```

## Permissions for a MySQL database as the destination

When a MySQL database is used as the destination, the user must have the CREATE, CREATE VIEW, INSERT, UPDATE, and DELETE privileges on the destination database.

```sql
GRANT <privilege_type> ON <database_name>.<table_name> TO '<user_name>'@'<host_name>' [WITH GRANT OPTION];
```

|        Parameter         |                               Description                                |
|-------------------|--------------------------------|
| privilege_type    | The privilege to grant the account the CREATE, INSERT, and UPDATE privileges. To grant all privileges to the account, specify ALL. |
| database_name     | The name of the database. To grant the account the privileges on all databases, specify an asterisk (\*).                          |
| table_name        | The name of the table. To grant the account the privileges on all tables, specify an asterisk (\*).                              |
| user_name         | The account to be granted the privileges.                                                         |
| host_name         | The host from which the account can log in. If the account can log in from any host, specify a percent sign (%).                            |
| WITH GRANT OPTION | The privilege to grant the account the GRANT command. This parameter is optional.                                   |

## Permissions for OceanBase Database Community Edition as the source

When OceanBase Database Community Edition is used as the source, the user must have the following privileges:

* If the destination is a message queue such as Kafka or RocketMQ, the user must have the SELECT privilege on the database to be synchronized.

   If the destination is a database such as MySQL Database or OceanBase Database Community Edition, the user must have the SELECT privilege on the database to be migrated and the oceanbase database.

   ```sql
   GRANT SELECT ON <database_name>.* TO '<user_name>';
   GRANT SELECT ON oceanbase.* TO '<user_name>';
   ```

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>Only OceanBase Database Community Edition V4.0.0 and later versions require the <code>SELECT</code> privilege on the <code>oceanbase</code> database. </p>
   </main>

* If you perform incremental data synchronization, you must read incremental log data and database object structure information. Therefore, you must create a user in the sys tenant of the source database and grant the SELECT ON *.* privilege to the user.

   ```sql
   GRANT SELECT ON <database_name>.* TO <drc_user>;
   ```

* When you migrate data between MySQL-compatible modes of OceanBase Database, if there is reverse incremental data, the user must have the CREATE, SELECT, INSERT, UPDATE, and DELETE privileges on the source test database.

   ```SQL
   GRANT CREATE,SELECT,INSERT,UPDATE,DELETE ON test.* TO '<user_name>';
   ```

## Permissions for OceanBase Database Community Edition as the destination

When OceanBase Database Community Edition is used as the destination, the user must have the following privileges:

* The CREATE, CREATE VIEW, SELECT, INSERT, UPDATE, ALTER, INDEX, and DELETE privileges on the destination database.

   ```sql
   GRANT CREATE,CREATE VIEW,SELECT,INSERT,UPDATE,ALTER,INDEX,DELETE ON <database_name>.* TO '<user_name>';
   ```

* The SELECT privilege on the entire tenant.

   ```sql
   GRANT SELECT ON *.* TO '<user_name>';
   ```

## Permissions for a TiDB database as the source

* The user of the source TiDB database must have the SELECT and PROCESS privileges on the database to be migrated.

  ```sql
  GRANT SELECT ON <database_name>.* TO '<user_name>';
  GRANT PROCESS ON *.* TO '<user_name>'@'%';
  ```

* When you perform incremental synchronization from a TiDB database, the user must have the REPLICATION CLIENT, REPLICATION SLAVE, and SELECT *.* privileges.

  ```sql
  GRANT REPLICATION CLIENT, REPLICATION SLAVE ON *.* TO '<user_name>' [WITH GRANT OPTION];
  GRANT SELECT ON *.* TO '<user_name>';
  ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><code>WITH GRANT OPTION</code> is an optional parameter. </p>
   </main>

## Permissions required when a PostgreSQL database is the source

When you migrate data from a PostgreSQL database to a MySQL-compatible mode of OceanBase Database, you must grant the migration user the `SELECT` privilege on tables and views.

When you incrementally synchronize data from a PostgreSQL database to a MySQL-compatible mode of OceanBase Database, you must grant the migration user the following privileges:

* If the migration user is not a superuser, the migration user must be granted the `CREATE PUBLICATION` privilege. Otherwise, an error will be returned when you create a publication.

* The migration user must have the `REPLICATION` and `LOGIN` roles and the `CREATE PUBLICATION` privilege.

  * `CREATE USER <user_name> REPLICATION LOGIN ENCRYPTED PASSWORD '<password>';`

  * `GRANT CREATE ON DATABASE <database_name> TO <user_name>;`

* The migration user must be the owner of the tables to be migrated.

   ```sql
   // Create a replication_group.
   CREATE ROLE <replication_group>;
   // Add the original owner of the tables to be migrated to the replication_group.
   GRANT <replication_group> TO <original_owner>;
   // Add the migration user to the replication_group.
   GRANT <replication_group> TO <replication_user>;
   // Change the owner of the tables to be migrated to the new replication_group.
   ALTER TABLE <table_name> OWNER TO <replication_group>;
  ```

## Permissions required when an ElasticSearch database is the source

When an ElasticSearch database is the source, the database user must have the `view_index_metadata` privilege on the indexes to be migrated.

```JSON
POST /_security/role/{roleName}
{
  "cluster": ["all"],
  "indices": [
    {
      "names": [ "index_name" ],
      "privileges": ["view_index_metadata"]
    }
  ],
  "run_as": [ "*" ],
  "metadata": {},
  "transient_metadata": {
    "enabled": true
  }
}
```

## Permissions required when an ElasticSearch database is the destination

When an ElasticSearch database is the destination, the database user must have the `create_index`, `write`, and `view_index_metadata` privileges.

```JSON
POST /_security/role/{roleName}
{
  "cluster": ["all"],
  "indices": [
    {
      "names": [ "*" ],
      "privileges": ["create_index","write","view_index_metadata"]
    }
  ],
  "metadata": {},
  "transient_metadata": {
    "enabled": true
  }
}
```

## Permissions required when MongoDB is the source

When MongoDB is the source, the database user must have the `listDatabases`, `listCollections`, `find`, `collStats`, and `splitVector` privileges.

```JavaScript
db.createRole({
  role: "username",
  privileges: [
     { resource: { db: "database", collection: "" }, actions: ["listDatabases","listCollections","find","splitVector","collStats"] }
  ],
 roles:[]
});
```

## Permissions required when StarRocks is the source

* When the version of the StarRocks database is V2.3.18, the database user must have the `SELECT_PRIV` and `CREATE_PRIV` privileges on the databases to be migrated.

  ```sql
  GRANT SELECT_PRIV,CREATE_PRIV ON *.* TO '<user_name>'@'<host_name>';
  ```

* When the version of the StarRocks database is V3.3.15, the database user must have the `SELECT`, `CREATE TABLE`, and `CREATE FUNCTION` privileges on the databases to be migrated.

  ```sql
  GRANT SELECT ON ALL TABLES IN ALL DATABASES TO USER '<user_name>'@'<host_name>' WITH GRANT OPTION;
  GRANT CREATE TABLE ON ALL DATABASES TO USER '<user_name>'@'<host_name>' WITH GRANT OPTION;
  GRANT CREATE FUNCTION ON ALL DATABASES TO USER '<user_name>'@'<host_name>' WITH GRANT OPTION;
  ```

## Permissions required when ClickHouse is the source

* The database user must have the `SHOW USERS` and `SHOW ROLES` privileges to query the privileges of users.

  ```SQL
  GRANT SHOW USERS, SHOW ROLES ON *.* TO <user_name>;
  ```

* The database user must have the `SELECT` privilege on the databases to be migrated.

  ```SQL
  GRANT SELECT ON *.* TO <user_name>;
  ```

* The database user must have the global `CREATE` privilege to create an external database of OceanBase Database Community Edition.

  ```SQL
  GRANT CREATE ON *.* TO <user_name>;
  ```

## Permissions required when Kafka is the destination

If Kafka authentication is enabled, see [Create a Kafka data source](100.create-a-data-source/500.create-a-kafka-data-source.md).

When Kafka is the destination, the synchronization user must have the following privileges:

* Create and view Topics

* View Topic Partition information

* Write Records

* Read Records

## Permissions required when RocketMQ is the destination

When RocketMQ is the destination, the synchronization user must have the following privileges:

* Create and view Topics

* View Topic MessageQueue information

* Write Records

* Read Records
