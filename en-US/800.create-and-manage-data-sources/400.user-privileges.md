# User privileges

Before you use OceanBase Migration Service (OMS) Community Edition to migrate a database, make sure that a database user is created for migration or synchronization in each data source. The user must have the required privileges in the source and destination data sources.

## Permissions required when a MySQL database is the source

* The database user must have read permissions on the database to be migrated. If the source database is MySQL V8.0, the user must also have the `SHOW VIEW` privilege.

  ```sql
  GRANT SELECT ON <database_name>.* TO '<user_name>';
  ```

* During incremental synchronization from a MySQL database, the database user must have the `REPLICATION CLIENT`, `REPLICATION SLAVE`, and `SELECT *.*` privileges.

  ```sql
  GRANT REPLICATION CLIENT, REPLICATION SLAVE ON *.* TO '<user_name>' [WITH GRANT OPTION];
  GRANT SELECT ON *.* TO '<user_name>';
  ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <ul>
   <li>
   <p>If the database user does not have read permissions on all tables in the source database, the task may fail. </p>
   </li>
   <li>
   <p><code>WITH GRANT OPTION</code> is an optional parameter. </p>
   </li>
   </ul>
   </main>

* When you migrate data from a MySQL database to a MySQL compatible mode of OceanBase Database, if there is reverse incremental data, the migration user must have the `CREATE`, `SELECT`, `INSERT`, `UPDATE`, and `DELETE` privileges on the `test` database in the source database.

  ```SQL
  GRANT CREATE,SELECT,INSERT,UPDATE,DELETE ON test.* TO '<user_name>';
  ```

## Permissions required when a MySQL database is the destination

When a MySQL database is the destination, the migration user must have the `CREATE`, `CREATE VIEW`, `INSERT`, `UPDATE`, and `DELETE` privileges on the destination database.

```sql
GRANT <privilege_type> ON <database_name>.<table_name> TO '<user_name>'@'<host_name>' [WITH GRANT OPTION];
```

|        Parameter         |                               Description                                |
|-------------------|--------------------------------|
| privilege_type    | The privileges to be granted to the account, such as `CREATE`, `INSERT`, and `UPDATE`. If you want to grant all privileges to the account, specify ALL. |
| database_name     | The name of the database. If you want to grant all privileges on all databases to the account, specify a star (\*).                          |
| table_name        | The name of the table. If you want to grant all privileges on all tables to the account, specify a star (\*).                              |
| user_name         | The account to be granted privileges.                                                         |
| host_name         | The host from which the account can log in. If the account can log in from any host, specify a percent sign (%).                            |
| WITH GRANT OPTION | The privilege to use the `GRANT` command. This parameter is optional.                                   |

## User privileges when OceanBase Database Community Edition is the source

When OceanBase Database Community Edition is the source, the migration or synchronization user must have the following privileges:

* If the destination is a message queue such as Kafka or RocketMQ, the user must have the `SELECT` privilege on the database to be synchronized from the source.

   If the destination is a database such as MySQL or OceanBase Database Community Edition, the user must have the `SELECT` privilege on the database to be migrated from the source and on the `oceanbase` database.

   ```sql
   GRANT SELECT ON <database_name>.* TO '<user_name>';
   GRANT SELECT ON oceanbase.* TO '<user_name>';
   ```

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>Only OceanBase Database Community Edition V4.0.0 and later require the <code>SELECT</code> privilege on the <code>oceanbase</code> database. </p>
   </main>

* If the scenario involves incremental data synchronization, you must read incremental log data and database object structure information. Therefore, you must create a user in the sys tenant of the source and grant the `SELECT ON *.*` privilege to the user.

   ```sql
   GRANT SELECT ON <database_name>.* TO <drc_user>;
   ```

* When you migrate data between MySQL compatible modes of OceanBase Database, if there is reverse incremental data, the migration user must also have the `CREATE`, `SELECT`, `INSERT`, `UPDATE`, and `DELETE` privileges on the `test` database of the source.

   ```SQL
   GRANT CREATE,SELECT,INSERT,UPDATE,DELETE ON test.* TO '<user_name>';
   ```

## User privileges when OceanBase Database Community Edition is the destination

When OceanBase Database Community Edition is the destination, the migration user must have the following privileges:

* The user must have the `CREATE`, `CREATE VIEW`, `SELECT`, `INSERT`, `UPDATE`, `ALTER`, `INDEX`, and `DELETE` privileges on the destination database.

   ```sql
   GRANT CREATE,CREATE VIEW,SELECT,INSERT,UPDATE,ALTER,INDEX,DELETE ON <database_name>.* TO '<user_name>';
   ```

* The user must have the `SELECT` privilege on the entire tenant.

   ```sql
   GRANT SELECT ON *.* TO '<user_name>';
   ```

## User privileges when TiDB is the source

* The database user must have the read privilege on the database to be migrated and the `PROCESS` privilege.

  ```sql
  GRANT SELECT ON <database_name>.* TO '<user_name>';
  GRANT PROCESS ON *.* TO '<user_name>'@'%';
  ```

* When TiDB is used for incremental synchronization, the database user must have the `REPLICATION CLIENT`, `REPLICATION SLAVE`, and `SELECT *.*` privileges.

  ```sql
  GRANT REPLICATION CLIENT, REPLICATION SLAVE ON *.* TO '<user_name>' [WITH GRANT OPTION];
  GRANT SELECT ON *.* TO '<user_name>';
  ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><code>WITH GRANT OPTION</code> is an optional parameter. </p>
   </main>

## Permissions required when a PostgreSQL database serves as the source

In the schema migration phase from a PostgreSQL database to a MySQL-compatible OceanBase database, the migration user must be granted the `SELECT` privilege on tables and views.

In the incremental synchronization phase from a PostgreSQL database to a MySQL-compatible OceanBase database, the migration user must be granted the following privileges:

* If the wildcard is included in the whitelist of the tables to be migrated, the superuser must be used. Otherwise, an error will occur when creating a publication due to lack of privileges. If the wildcard is not included, the superuser is not required.

* The role must have the REPLICATION and LOGIN privileges and the CREATE PUBLICATION privilege.

  * `CREATE USER <user_name> REPLICATION LOGIN ENCRYPTED PASSWORD '<password>';`

  * `GRANT CREATE ON DATABASE <database_name> TO <user_name>;`

* The user must be the owner of the tables to be migrated.

   ```sql
   // Create a replication_group.
   CREATE ROLE <replication_group>;
   // Add the original owner of the tables to be migrated to the replication_group.
   GRANT <replication_group> TO <original_owner>;
   // Add the migration user to the replication_group.
   GRANT <replication_group> TO <replication_user>;
   // Change the owner of the tables to be migrated to the new replication_group.
   ALTER TABLE <table_name> OWNER TO <replication_group>;
  ```

## Permissions required when an ElasticSearch database serves as the source

When an ElasticSearch database serves as the source, the database user must have the `view_index_metadata` privilege on the indexes to be migrated.

```JSON
POST /_security/role/{roleName}
{
  "cluster": ["all"],
  "indices": [
    {
      "names": [ "index_name" ],
      "privileges": ["view_index_metadata"]
    }
  ],
  "run_as": [ "*" ],
  "metadata": {},
  "transient_metadata": {
    "enabled": true
  }
}
```

## Permissions required when an ElasticSearch database serves as the destination

When an ElasticSearch database serves as the destination, the database user must have the `create_index`, `write`, and `view_index_metadata` privileges.

```JSON
POST /_security/role/{roleName}
{
  "cluster": ["all"],
  "indices": [
    {
      "names": [ "*" ],
      "privileges": ["create_index","write","view_index_metadata"]
    }
  ],
  "metadata": {},
  "transient_metadata": {
    "enabled": true
  }
}
```

## Permissions required when a MongoDB database serves as the source

When a MongoDB database serves as the source, the database user must have the `listDatabases`, `listCollections`, `find`, `collStats`, and `splitVector` privileges.

```JavaScript
db.createRole({
  role: "username",
  privileges: [
     { resource: { db: "database", collection: "" }, actions: ["listDatabases","listCollections","find","splitVector","collStats"] }
  ],
 roles:[]
});
```

## Permissions required when a StarRocks database serves as the source

* When the StarRocks database version is V2.3.18, the database user must have the `SELECT_PRIV` and `CREATE_PRIV` privileges on the databases to be migrated.

  ```sql
  GRANT SELECT_PRIV,CREATE_PRIV ON *.* TO '<user_name>'@'<host_name>';
  ```

* When the StarRocks database version is V3.3.15, the database user must have the `SELECT`, `CREATE TABLE`, and `CREATE FUNCTION` privileges on the databases to be migrated.

  ```sql
  GRANT SELECT ON ALL TABLES IN ALL DATABASES TO USER '<user_name>'@'<host_name>' WITH GRANT OPTION;
  GRANT CREATE TABLE ON ALL DATABASES TO USER '<user_name>'@'<host_name>' WITH GRANT OPTION;
  GRANT CREATE FUNCTION ON ALL DATABASES TO USER '<user_name>'@'<host_name>' WITH GRANT OPTION;
  ```

## Permissions required when Kafka serves as the destination

If Kafka authentication is enabled, see [Create a Kafka data source](100.create-a-data-source/500.create-a-kafka-data-source.md).

When Kafka serves as the destination, the synchronization user must have the following privileges:

* Create and view Topics

* View Topic Partition information

* Write Records

* Read Records

## Permissions required when RocketMQ is the destination

When RocketMQ is the destination, the synchronization user must have the following permissions:

* Create and view Topics

* View Topic MessageQueue information

* Write Records

* Read Records
