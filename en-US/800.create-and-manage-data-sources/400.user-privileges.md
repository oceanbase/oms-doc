# User privileges

Before you migrate a database of OceanBase Migration Service (OMS) Community Edition, make sure that you have created a database user for each data source as the migration user or synchronization user. The user must have the privileges on the source and destination data sources.

## User privileges required when a MySQL database serves as the source data source

* The database user must have the read privilege on the database from which data is to be migrated. If the MySQL database version is 8.0, you also need to grant the `SHOW VIEW` privilege.

  ```sql
  GRANT SELECT ON <database_name>.* TO '<user_name>';
  ```

* When you synchronize incremental data from a MySQL database, the database user must have the `REPLICATION CLIENT`, `REPLICATION SLAVE`, and `SELECT *.*` privileges.

  ```sql
  GRANT REPLICATION CLIENT, REPLICATION SLAVE ON *.* TO '<user_name>' [WITH GRANT OPTION];
  GRANT SELECT ON *.* TO '<user_name>';
  ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <ul>
   <li>
   <p>If the database user does not have the read privilege on all tables at the source, the migration task may be interrupted during incremental synchronization. </p>
   </li>
   <li>
   <p>The <code>WITH GRANT OPTION</code> parameter is optional. </p>
   </li>
   </ul>
   </main>

## User privileges required when a MySQL database serves as the destination data source

When a MySQL database serves as the destination data source, the migration user must have the `CREATE`, `CREATE VIEW`, `INSERT`, `UPDATE`, and `DELETE` privileges on the destination database.

```sql
GRANT <privilege_type> ON <database_name>.<table_name> TO '<user_name>'@'<host_name>' [WITH GRANT OPTION];
```

|        Parameter         |                               Description                                |
|-------------------|--------------------------------|
| privilege_type    | The privilege to grant. You can grant the `CREATE`, `INSERT`, and `UPDATE` privileges to the account. If you want to grant all privileges to the account, set this parameter to ALL. |
| database_name     | The name of the database. If you want to grant all privileges on all databases to the account, set this parameter to an asterisk (\*).                          |
| table_name        | The name of the table. If you want to grant all privileges on all tables to the account, set this parameter to an asterisk (\*).                              |
| user_name         | The account to which the privilege is to be granted.                                                         |
| host_name         | The host from which the account is allowed to log in to the database. If the account is allowed to log in to the database from any host, set this parameter to a percent sign (%).                            |
| WITH GRANT OPTION | The privilege to grant. You can grant the `GRANT` command privilege to the account. This parameter is optional.                                   |

## User privileges required when OceanBase Database Community Edition serves as the source data source

When OceanBase Database Community Edition serves as the source data source, the migration or synchronization user must have the following privileges:

* If the destination is a Kafka or RocketMQ instance, the user must have the `SELECT` privilege on the source database from which data is to be synchronized.

   If the destination is a MySQL database or OceanBase Database Community Edition instance, the user must have the `SELECT` privilege on the source database from which data is to be migrated and the `oceanbase` database.

   <main id="notice" type='notice'>
   <h4>Note</h4>
   <p>You need to grant the <code>SELECT</code> privilege on the <code>oceanbase</code> database only to OceanBase Database Community Edition V4.0.0 and later. </p>
   </main>

* If you are performing incremental data synchronization, you need to create a user under the `sys` tenant of OceanBase Database Community Edition and grant the `SELECT ON *.*` privilege to the user.

## User privileges required when OceanBase Database Community Edition serves as the destination data source

When OceanBase Database Community Edition serves as the destination data source, the user privileges required for migration are as follows:

* The user must have the `CREATE`, `CREATE VIEW`, `SELECT`, `INSERT`, `UPDATE`, `ALTER`, `INDEX`, and `DELETE` privileges on the destination database.

   ```sql
   GRANT CREATE,CREATE VIEW,SELECT,INSERT,UPDATE,ALTER,INDEX,DELETE ON <database_name>.* TO '<user_name>';
   ```

* The user must have the `SELECT` privilege on the entire tenant.

   ```sql
   GRANT SELECT ON *.* TO '<user_name>';
   ```

## User privileges required when TiDB serves as the source data source

* The user must have the read privilege on the database from which data is to be migrated.

  ```sql
  GRANT SELECT ON <database_name>.* TO '<user_name>';
  ```

* When incremental data is to be synchronized from TiDB, the user must have the `REPLICATION CLIENT`, `REPLICATION SLAVE`, and `SELECT *.*` privileges.

  ```sql
  GRANT REPLICATION CLIENT, REPLICATION SLAVE ON *.* TO '<user_name>' [WITH GRANT OPTION];
  GRANT SELECT ON *.* TO '<user_name>';
  ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p>The <code>WITH GRANT OPTION</code> parameter is optional. </p>
   </main>

## User privileges required when PostgreSQL serves as the source data source

During schema migration from PostgreSQL to MySQL compatible mode of OceanBase Database, the migration user must have the `SELECT` privilege on tables and views.

During incremental synchronization from PostgreSQL to MySQL compatible mode of OceanBase Database, the migration user must have the following privileges:

* If the specified allowlist of tables to migrate contains wildcard characters, the user must be a superuser. Otherwise, publication creation will fail and an error indicating no privilege will be returned. If no wildcard character is contained, the user does not need to be a superuser.

* The user must have the REPLICATION and LOGIN roles, and the CREATE PUBLICATION privilege.

  * `CREATE USER <user_name> REPLICATION LOGIN ENCRYPTED PASSWORD '<password>';`

  * `GRANT CREATE ON DATABASE <database_name> TO <user_name>;`

* The user must be the owner of the tables to migrate.

   ```sql
   // Create a role named replication_group.
   CREATE ROLE <replication_group>;
   // Add the original owner of the tables to migrate to the replication_group role.
   GRANT <replication_group> TO <original_owner>;
   // Add the migration account to the replication_group role.
   GRANT <replication_group> TO <replication_user>;
   // Change the owner of the tables to migrate to the replication_group role.
   ALTER TABLE <table_name> OWNER TO <replication_group>;
  ```

## User privileges required when an ElasticSearch database serves as the source data source

When an ElasticSearch database serves as the source data source, the user must have the `view_index_metadata` privilege on the indexes to migrate.

```JSON
POST /_security/role/{roleName}
{
  "cluster": ["all"],
  "indices": [
    {
      "names": [ "index_name" ],
      "privileges": ["view_index_metadata"]
    }
  ],
  "run_as": [ "*" ],
  "metadata": {},
  "transient_metadata": {
    "enabled": true
  }
}
```

## User privileges required when an ElasticSearch database serves as the destination data source

When an ElasticSearch database serves as the destination data source, the user must have the `create_index`, `write`, and `view_index_metadata` privileges.

```JSON
POST /_security/role/{roleName}
{
  "cluster": ["all"],
  "indices": [
    {
      "names": [ "*" ],
      "privileges": ["create_index","write","view_index_metadata"]
    }
  ],
  "metadata": {},
  "transient_metadata": {
    "enabled": true
  }
}
```

## User privileges required when Kafka is the destination

If Kafka authentication is enabled, see [Create a Kafka data source](100.create-a-data-source/500.create-a-kafka-data-source.md).

When Kafka is the destination, the user must have the following privileges:

* Create and view topics

* View topic partition information

* Write records

* Read records

## User privileges required when RocketMQ is the destination

When RocketMQ is the destination, the user must have the following privileges:

* Create and view topics

* View topic message queue information

* Write records

* Read records
