# Create a database user

Before you use the data migration or synchronization feature of OceanBase Migration Service (OMS) Community Edition, you must create dedicated database users in the source and target databases for the data migration or synchronization task and grant corresponding privileges to these users.

## OceanBase-CE data source

### Create an OceanBase Community Edition user

In this example, an OceanBase Community Edition user is created. Specify this user for the **<UI-TERM key="oms-community.endpoints.MySqlForm.FormItem.DatabaseUsername">Database username</UI-TERM>** field when you create an OceanBase-CE data source. For example, the username of the database can be `OMSTEST`.

<!--![create-obce-user-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-ce/create-obce-user-zh.png)-->

1. Log in to the OceanBase Community Edition console as the system administrator.

2. In the source business tenant, create a data migration or synchronization user.

   ```sql
   CREATE USER '<user_name>' IDENTIFIED BY '<password>';
   ```

3. Use the `GRANT` statement to grant privileges to the database user. For more information, see [User privileges](../800.create-and-manage-data-sources/400.user-privileges.md).

### Create a DRC user

If you need to read incremental log data and database object schemas from OceanBase Community Edition, create a DRC user in the **sys** tenant of the source.

In this example, a DRC user is created. Specify this user for the **<UI-TERM key="oms-community.EndpointPublic.components.OracleForm.UserName">Username</UI-TERM>** field in **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsDetail.AdvancedConfiguration">Advanced Options</UI-TERM>** when you create an OceanBase-CE data source. For example, the username of the DRC user can be `user01`.

<!--![create-user1-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/create-user1-zh.png)-->

* Create a user

   ```sql
   CREATE USER <drc_user> IDENTIFIED BY <drc_password>;
   ```

* Grant privileges

   ```sql
   GRANT SELECT ON <db_name>.* TO <drc_user>;
   ```

### Create the __oceanbase_inner_drc_user user

If you need to migrate a table without a primary key, create the `__oceanbase_inner_drc_user` user in the **Source Business Tenant** before you execute the data migration task.

Here, the `__oceanbase_inner_drc_user` user is created. Specify this user for the **__oceanbase_inner_drc_user Password** field when you create an OceanBase-CE data source.

<!--![create-user2-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/create-user2-zh.png)-->

* Create a user

   ```sql
   CREATE USER __oceanbase_inner_drc_user IDENTIFIED BY '<password>';
   ```

* Grant privileges

   ```sql
   GRANT SELECT ON *.* TO __oceanbase_inner_drc_user;
   ```

## MySQL data source

The MySQL database user created in this section is used to fill in **<UI-TERM key="oms-community.endpoints.MySqlForm.FormItem.DatabaseUsername">Database username</UI-TERM>** when you create a MySQL data source.

<!--![create-user4-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/create-user4-zh.png)-->

1. Log in to the MySQL database.

2. Create a user in the MySQL database for data migration or synchronization.

   ```sql
   CREATE USER '<user_name>'@'<host_name>' IDENTIFIED BY '<password>';
   ```

   |    Parameter    |                   Description                    |
   |----------|-----------------------------------------|
   | user_name | The name of the user to be created.                                 |
   | host_name   | The host from which the account is allowed to log in to the database. If the account is allowed to log in to the database from any host, use percent sign (%). |
   | password | The password of the user to be created.   |

3. Execute the `GRANT` statement to grant privileges to the created database user. For more information, see [User privileges](../800.create-and-manage-data-sources/400.user-privileges.md).

## ElasticSearch data source

The ElasticSearch database user created in this section is used to fill in **<UI-TERM key="oms-community.pages.Endpoint.DatabaseUsername">Database username</UI-TERM>** when you create an ElasticSearch data source.

1. Create a role.

   ```JSON
   POST /_security/role/{roleName}
   {
   "cluster": ["all"],
   "indices": [
      {
         "names": [ "*" ],
         "privileges": ["all"]
      }
   ],
   "metadata": {},
   "transient_metadata": {
      "enabled": true
   }
   }

2. Create a database user and assign the role to the user.

   ```JSON
   POST /_security/user/{username}
   {
   "password" : "123456",
   "roles" : ["role"],
   "full_name" : "username",
   "email" : "",
   "metadata" : {
   }
   }
   ```

## MongoDB data source

The MongoDB database user created here is used to fill in the **<UI-TERM key="oms-community.pages.Endpoint.DatabaseUsername">Database username</UI-TERM>** field when creating a MongoDB data source.

1. Connect to the MongoDB database instance using the mongo command.

2. Switch to the authentication database that stores user information.

   ```JavaScript
   use <database_name>
   ```

3. Create a database user and assign roles to the user.

   ```JavaScript
   db.createUser({
   user: "username",
   pwd: "password",
   roles: [
      { role: "read", db: "databaseName" }
   ]
   });   
   ```
