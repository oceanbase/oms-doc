# Create a database user

Before you use the data migration and synchronization features of OceanBase Migration Service (OMS) Community Edition, you must create a dedicated database user in the source and destination databases for the data migration or synchronization task and grant the corresponding permissions to the user.

## OceanBase-CE data source

### Create an OceanBase Community Edition user

You need to create an OceanBase Community Edition user for the **<UI-TERM key="oms-community.endpoints.MySqlForm.FormItem.DatabaseUsername">Database username</UI-TERM>** field when you create an OceanBase-CE data source. For example, you can set the database username to `OMSTEST`.

![create-obce-user-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-ce/create-obce-user-zh.png)

1. Log in to OceanBase Community Edition as the system administrator.

2. Create a user in the source business tenant for data migration or synchronization.

   ```sql
   CREATE USER '<user_name>' IDENTIFIED BY '<password>';
   ```

3. Use the `GRANT` statement to grant privileges to the database user. For more information, see [User privileges](../800.create-and-manage-data-sources/400.user-privileges.md).

### Create a DRC user

If you want to read incremental log data and database object structure information from OceanBase Community Edition, create a DRC user in the **sys** tenant at the source.

You need to create a DRC user for the **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsDetail.AdvancedConfiguration">Advanced Options</UI-TERM>** field when you create an OceanBase-CE data source. For example, you can set the username to `user01`.

![create-user1-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/create-user1-zh.png)

* Create a user

   ```sql
   CREATE USER <drc_user> IDENTIFIED BY <drc_password>;
   ```

* Grant privileges

   ```sql
   GRANT SELECT ON <db_name>.* TO <drc_user>;
   ```

### Create the __oceanbase_inner_drc_user user

If you want to migrate a table without a primary key, create the `__oceanbase_inner_drc_user` user in the **source business tenant** before you execute a data migration task.

You need to create the `__oceanbase_inner_drc_user` user for the **__oceanbase_inner_drc_user password** field when you create an OceanBase-CE data source.

![create-user2-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/create-user2-zh.png)

* Create a user

   ```sql
   CREATE USER __oceanbase_inner_drc_user IDENTIFIED BY '<password>';
   ```

* Grant privileges

   ```sql
   GRANT SELECT ON *.* TO __oceanbase_inner_drc_user;
   ```

## MySQL data source

You need to create a MySQL database user for the **<UI-TERM key="oms-community.endpoints.MySqlForm.FormItem.DatabaseUsername">Database username</UI-TERM>** field when you create a MySQL data source.

![create-user4-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/create-user4-zh.png)

1. Log in to the MySQL database.

2. Create a user in the MySQL database for data migration or synchronization.

   ```sql
   CREATE USER '<user_name>'@'<host_name>' IDENTIFIED BY '<password>';
   ```

   |    Parameter    |                   Description                    |
   |----------|-----------------------------------------|
   | user_name | The name of the user to be created.                                 |
   | host_name   | The host that allows the account to log in. If the account can log in from any host, use the percent sign (%). |
   | password | The password of the user to be created.   |

3. Use the `GRANT` statement to grant privileges to the database user. For more information, see [User privileges](../800.create-and-manage-data-sources/400.user-privileges.md).

## PostgreSQL data source

## ElasticSearch data source

The ElasticSearch database user created here is used to fill in the **<UI-TERM key="oms-community.pages.Endpoint.DatabaseUsername">Database username</UI-TERM>** field when creating an ElasticSearch data source.

1. Create a role.

   ```JSON
   POST /_security/role/{roleName}
   {
   "cluster": ["all"],
   "indices": [
      {
         "names": [ "*" ],
         "privileges": ["all"]
      }
   ],
   "metadata": {},
   "transient_metadata": {
      "enabled": true
   }
   }

2. Create a database user and assign the role to it.

   ```JSON
   POST /_security/user/{username}
   {
   "password" : "123456",
   "roles" : ["role"],
   "full_name" : "username",
   "email" : "",
   "metadata" : {
   }
   }
   ```

## MongoDB data source

The MongoDB database user created here is used to fill in the **<UI-TERM key="oms-community.pages.Endpoint.DatabaseUsername">Database username</UI-TERM>** field when creating a MongoDB data source.

1. Connect to the MongoDB database instance by using the mongo command.

2. Switch to the authentication database used to store user information.

   ```JavaScript
   use <database_name>
   ```

3. Create a database user.

   ```JavaScript
   db.createUser({
   user: "username",
   pwd: "password",
   roles: [
      { role: "roleName", db: "<database_name>" }
   ]
   });
   ```

4. Create a role and grant permissions. For more information, see [User privileges](../800.create-and-manage-data-sources/400.user-privileges.md).
