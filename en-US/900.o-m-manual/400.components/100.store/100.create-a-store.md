# Add a store

OceanBase Migration Service (OMS) Community Edition allows you to add a store on the Store page in the O&M Monitoring module.

## Background information

A store component pulls incremental data from the source instance, parses and filters the data, and persists the data locally in a specified format. In scenarios such as load balancing or when a store needs to pull data back, we recommend that you add a store. In scenarios such as load balancing or when a store needs to pull data back, we recommend that you add a store.

* If database logs still exist, you need to pull data from several days ago.

  At this time, the data points of the current store have expired. If you restart the current store, all downstream components will experience delays. In this case, you need to create a store that starts pulling data from a specified timestamp.

* You can perform load balancing on a subtopic, which can be a cluster, tenant, or database.

  The purpose is to prevent too many downstream components from consuming store resources, which can affect stability and lead to large-scale delays.

## Procedure

1. Log in to the OMS Community Edition console.

2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.SystemParam.contants.OMMonitoring">OPS & Monitoring</UI-TERM>** **>** **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.Components">Component</UI-TERM>**. The **Store** page automatically appears.

3. On the **<UI-TERM>Store</UI-TERM>** page, click **<UI-TERM key="oms-community.EndpointPublic.components.KafkaForm.Add">Add</UI-TERM>** in the upper-right corner.

4. In the **<UI-TERM key="oms-community.Store.New.Add">Add</UI-TERM>** dialog box, configure the parameters.

   | Parameter | Required | Description |
   |-----------|------|-------|
   | Subtopic  | Yes   | The data source at the cluster or tenant level. Select the corresponding subtopic based on the specific task. <br>The subtopic corresponds to the part between the two colons in the Store component ID of the **<UI-TERM key="oms-community.Sync.constants.ViewComponentMonitoring">View Component Monitoring</UI-TERM>** dialog box on the task details page.                                                                |
   | Node      | No    | Specifies the server on which to start the store. In a single-node deployment, the store is created on the only server by default. In a high-availability scenario, if you do not specify the node, the system automatically schedules the store to a server that has not reached its performance bottleneck. |
   | Timestamp | Yes   | The timestamp. After the store is started, specify the timestamp from which to pull database logs. Make sure that database logs exist, otherwise the store will fail to start.                        |

   Here is an example of how to check whether database logs exist:

   * For a MySQL database, you can use the `mysqlbinlog` tool to view the `binlog` files on the source server.

   * For a PostgreSQL database, OMS Community Edition saves logs from the current time for 48 hours by default after the store is started for the first time. If the store fails to start for the first time, you cannot specify a timestamp earlier than the current time for log pulling.

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <ul>
      <li>
      <p>If the store was started for the first time within 48 hours, you can specify any time after the first start time for log pulling. </p>
      </li>
      <li>
      <p>If the store was started for the first time more than 48 hours ago, you can specify any time within the last 48 hours for log pulling. </p>
      </li>
      </ul>
      </main>

5. Click **<UI-TERM key="oms-community.Operation.Store.Add">Add</UI-TERM>**.
