# View system alerts

This topic describes the monitoring range supported by the system alert feature. This topic also describes how to view system alerts.

## Background information

OceanBase Migration Service (OMS) monitors system events, such as the OMS host failure, resource usage over thresholds, and downtime migration, and sends alerts to corresponding channels.

## Procedure

1. Log on to the OMS console.

2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** \> **<UI-TERM>Alert Management</UI-TERM>**.

3. On the **<UI-TERM>Alert Management</UI-TERM>** page, click the **<UI-TERM key="oms-community.pages.Notification.SystemAlertInformation">System Alert Information</UI-TERM>** tab.

   By default, the **<UI-TERM key="oms-community.pages.Notification.SystemAlertInformation">System Alert Information</UI-TERM>** page displays alerts of the last 7 days. In the upper-right corner of the page, you can select **<UI-TERM key="oms-community.Notification.System.LastWeek">Last 7 Days</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Group.LastThreeWeeks">Last 3 Weeks</UI-TERM>**, **<UI-TERM key="oms-community.Notification.utils.LastMonth">Last Month</UI-TERM>**, or **<UI-TERM key="oms-community.Notification.utils.LastThreeMonths">Last 3 Months</UI-TERM>** from the drop-down list to view alerts within different ranges of time. You can also enter the alert ID or message content in the search box in the upper-right corner to search for an alert.

   You can filter alerts by using the **<UI-TERM key="oms-community.Notification.System.AlertEvents">Alert Events</UI-TERM>** and **<UI-TERM key="oms-community.Notification.System.SendingStatus">Sending Status</UI-TERM>** columns on the **<UI-TERM key="oms-community.pages.Notification.SystemAlertInformation">System Alert Information</UI-TERM>** page.
   * The following types of alert events are supported:

     * OMS host failure. For more information about how to handle this alert, see [oms_host_down](../../1200.reference-guide/300.alarm-reference/100.oms-host-down.md).

     * Usage of resources on the OMS host over thresholds. For more information about how to handle this alert, see [oms_host_threshold](../../1200.reference-guide/300.alarm-reference/300.oms-host-threshold.md).

     * OMS downtime migration. For more information about how to handle this alert, see [oms_host_down_migrate_resource](../../1200.reference-guide/300.alarm-reference/200.oms-host-down-migrate-resource.md).

   * An alert can be in one of the following sending status:

     * Pending: The alert is waiting for its sending to be scheduled.

     * Failed: The alert failed to be sent to the destination channel due to network issues or other unknown reasons.

     * Successful: The alert is sent to the destination channel, such as OceanBase Cloud Platform (OCP).

     * Completed: If the alert is not triggered within 3 hours, the alert status becomes Completed.

     * Sent again: The alert is sent again because the last sending failed.

   You can also click the host node of the alert to view details on the **<UI-TERM key="oms-community.Operation.Machine.Machine">Server</UI-TERM>** page. For more information, see [View server information](../../900.o-m-manual/300.server/100.view-server-information.md).
