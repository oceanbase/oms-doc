# Overview

OceanBase Migration Service (OMS) supports users with different roles and allows you to control permissions of different roles and avoid risks such as data breach.

The left-side navigation pane of the console of OMS provides the following modules: **<UI-TERM key="oms-community.Operation.Overview.SummaryInvestingComZa">Overview</UI-TERM>**, **<UI-TERM key="oms-community.Migration.Detail.DataMigration">Data Migration</UI-TERM>**, **<UI-TERM key="oms-community.Sync.Detail.DataSynchronization">Data Synchronization</UI-TERM>**, **<UI-TERM key="oms-community.pages.Endpoint.DataSourceManagement">Data Source Management</UI-TERM>**, **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.OMMonitoring">OPS & Monitoring</UI-TERM>**, and **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>**. Supported user roles include ROOT, ROOT-VIEWER, ADMIN, ADMIN-VIEWER, and USER.

## ROOT

The root user generated by the system has the ROOT role and cannot be deleted. This user is equivalent to a system administrator and has read and write permissions on the entire system.

* The root user can create users with the ROOT-VIEWER, ADMIN, ADMIN-VIEWER, or USER role.

* The root user can access and operate all modules of the console of OMS, such as **<UI-TERM key="oms-community.layout.constants.SummaryInvestingComZa">Overview</UI-TERM>**, **<UI-TERM key="oms-community.Migration.New.DataMigration">Data Migration</UI-TERM>**, **<UI-TERM key="oms-community.layout.constants.DataSynchronization">Data Synchronization</UI-TERM>**, **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.DataSourceManagement">Data Source Management</UI-TERM>**, **<UI-TERM key="oms-community.Welcome.constants.OMMonitoring">OPS & Monitoring</UI-TERM>**, and **<UI-TERM key="transmit.terminal.notification">System Management</UI-TERM>**.

## ROOT-VIEWER

Users with the ROOT-VIEWER role are created by the root user and have read-only permissions of a system administrator.

## ADMIN

An admin user generated by the system has the ADMIN role and cannot be deleted.

* This user is equivalent to a department administrator and has the permissions to create users with the ADMIN-VIEWER, or USER role under the department.

* An admin user can access and operate all modules of the console of OMS, such as **<UI-TERM key="oms-community.Operation.Overview.SummaryInvestingComZa">Overview</UI-TERM>**, **<UI-TERM key="oms-community.New.components.EndpointForm.DataMigration">Data Migration</UI-TERM>**, **<UI-TERM key="oms-community.src.constants.DataSynchronization">Data Synchronization</UI-TERM>**, **<UI-TERM key="oms-community.pages.Endpoint.DataSourceManagement">Data Source Management</UI-TERM>**, **<UI-TERM key="oms-community.layout.constants.OMMonitoring">OPS & Monitoring</UI-TERM>**, and **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>**.

   > **Notice:**
   >
   > In the left-side navigation pane of the **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** page, the first module is **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.UserManagement">User Management</UI-TERM>**.

* An admin user manages all tasks in the department, including tasks created by other users with the ADMIN role in the department. However, the admin user of a department cannot manage tasks of other departments.

## ADMIN-VIEWER

Users with the ADMIN-VIEWER role have read-only permissions of a department administrator, including:

* Read-only permission on all modules of the console of OMS, such as **<UI-TERM key="oms-community.layout.constants.SummaryInvestingComZa">Overview</UI-TERM>**, **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**, **<UI-TERM key="oms-community.Sync.Detail.DataSynchronization">Data Synchronization</UI-TERM>**, **<UI-TERM key="oms-community.pages.Endpoint.DataSourceManagement">Data Source Management</UI-TERM>**, **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.OMMonitoring">OPS & Monitoring</UI-TERM>**, and **<UI-TERM key="transmit.terminal.notification">System Management</UI-TERM>**.

   > **Notice:**
   >
   > In the left-side navigation pane of the **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** page, the first module is **<UI-TERM key="oms-community.Audit.constants.UserManagement">User Management</UI-TERM>**.

* Read-only permission on tasks created by all users in the department

## USER

Users with the USER role are created by the root user or users with the ADMIN role. A user with the USER role is equivalent to an employee of a department of an organization and can handle only transactions owned by the user.

* A user with the USER role has the permissions to view only the tasks, data sources, and O&M tickets created by the user.

* The tasks created by the USER role can be viewed by the ADMIN and ADMIN-VIEWER roles of the department.

* The left-side navigation pane of the **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** page does not display the **<UI-TERM key="oms-community.SystemParam.contants.UserManagement">User Management</UI-TERM>** option.
