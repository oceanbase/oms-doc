# Create an SSO integration

OceanBase Migration Service (OMS) Community Edition has an account system. You can configure an SSO integration in OMS Community Edition and log in to the OMS Community Edition console by using SSO. This topic describes how to create an SSO integration.

## Prerequisites

* You have logged in to the OMS Community Edition console as an ADMIN user.

* You have deployed an authorization server.

## Limitations

* OAuth2 or OIDC integration supports only the authorization code mode.

* When you log off from OMS Community Edition by using OAuth2 or OIDC, only the login status of OMS Community Edition is cleared, but the login status of the SSO system is not cleared.

## Procedure

1. Log in to the OMS Community Edition console.

2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** > **<UI-TERM key="oms-community.pages.ExternalSSO.SSOManagement">SSO Management</UI-TERM>**.

3. On the **<UI-TERM key="oms-community.pages.ExternalSSO.SSOManagement">SSO Management</UI-TERM>** page, click **<UI-TERM key="ocp-v2.page.External.CreateSsoIntegration">Create SSO Integration</UI-TERM>** in the upper-right corner.

4. In the **<UI-TERM>Create SSO Integration</UI-TERM>** dialog box, configure the parameters.

    * Basic Information

      | Parameter | Description |
      |--------------|---------------|
      | Configuration Name  |  The login name, which must start with an English letter and end with an English letter or a number. It can contain English letters, digits, and underscores (_). The length must be 2 to 32 characters. |
      | Type  | The type of the SSO integration. Valid values: **OAuth2** and **OIDC**. |

    * OAuth Information

      | Parameter | Description |
      |--------------|---------------|
      | Client ID | The application identifier. Make sure that it is consistent with the configuration in the authorization server. |
      | Client Secret | The application key. Make sure that it is consistent with the configuration in the authorization server. |
      | Auth URL | The URL provided by the authorization server for obtaining the grant code. |
      | Token URL | The URL provided by the authorization server for obtaining the access token. |
      | User Info URL (Optional) | The URL provided by the authorization server for obtaining the user information. |
      | Redirect URL | The URL provided by the authorization server for redirecting to the OMS Community Edition service. <main id="notice" type='notice'><h4>Notice</h4><p>If the SSO system has a callback allowlist, you must add the URL to the allowlist. </p></main>  |
      | Scope | The authorization scope of the application. You can enter one or more scopes. We recommend that you set the scope to `profile`. <main id="notice" type='notice'><h4>Notice</h4><p>When you configure SSO by using a third-party application, the Scope parameter is required. </p></main>  |

    * Advanced Options

      You can choose whether to enable **<UI-TERM key="ocp-v2.page.External.SSOInfoDrawer.AdvancedOptions">Advanced Options</UI-TERM>**. If you enable this option, configure the following parameters.

      | Parameter | Description |
      |--------------|---------------|
      | jwkSet URL (Optional) | The URL provided by the authorization server for obtaining the public key. |
      | Issue URL (Optional) | The issue URL of the authentication service. <main id="notice" type='notice'><h4>Notice</h4><p>This parameter is displayed only when you select <b>OIDC</b> as the type. </p></main>  |
      | Client Authentication Method | The authentication method used to authenticate the client to the authorization server. |
      | Authorization Grant Type | The authorization method of OAuth2. |
      | User Info Authentication Method | The authentication method used to authenticate the access token in the resource request. |

    * User Field Mapping

      User field mapping is used to identify the identifier of the OMS Community Edition account associated with OAuth2 login. To map the user information of a third-party user to the user fields of an OMS Community Edition user, specify the following parameters.

      | Parameter | Description |
      |--------------|---------------|
      | User Information Data Structure Type | The type of the user information data structure. |
      | Username Field | The username field. |
      | Email Field (Optional) | The email field. |

5. After the parameters are configured, hover the pointer over the icon on the right of **<UI-TERM key="oms-community.pages.OCP.constant.TestConnection">Test Connection</UI-TERM>** and add the URL to the allowlist as prompted. Then, click **<UI-TERM key="oms-community.EndpointPublic.constants.TestConnection">Test Connection</UI-TERM>**.

6. After the test is passed, click **<UI-TERM key="oms-community.Sync.New.Save">Save</UI-TERM>**.

## What to do next

On the **<UI-TERM key="oms-community.pages.ExternalSSO.SSOManagement">SSO Management</UI-TERM>** page, enable the SSO integration that you created. For more information, see [Enable or disable an SSO integration](../500.sso-management/300.enable-and-disenable-sso.md).
