# Migrate data from an HBase database to an OBKV database

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from an HBase database to an OBKV database.

## Background information

You can create a data migration task in the OMS Community Edition console to migrate data from an HBase database to an OceanBase cluster. You can seamlessly migrate existing business data and incremental data from the source database to the OceanBase cluster by using schema migration, full migration, and incremental synchronization.

## Prerequisites

* You have created the corresponding schema in the destination OceanBase cluster. OMS Community Edition supports migrating tables and columns. Therefore, you must create the corresponding schema in the destination OceanBase cluster.

* If you plan to use the Flink mode for migration, you have created a Flink V1.14.0 cluster.

* Incremental synchronization requires that the HBase table has synchronous replication enabled. That is, the `REPLICATION_SCOPE` parameter is set to '1'.

## Limitations

* **Limitations on operations on the source database**

   **Do not perform DDL operations to change the schema of the source database during schema migration or full migration. Otherwise, the data migration task may be interrupted.**

* Only HBase databases of V1.2.0-cdh5.15.2 and V2.4.13 are supported.

* Data in the Latin1 character set cannot be written by using the direct load mode. An exception will be returned.

* Tag data cannot be migrated from an HBase database to an OceanBase cluster. Full verification is not supported.

* Incremental data in an HBase database cannot be imported to the destination OceanBase cluster by using the bulkload mode.

* OMS Community Edition supports migrating databases, tables, and columns whose names are ASCII characters and do not contain special characters (spaces, line breaks, or |"'`()=;/&).

## Considerations

* We recommend that you migrate no more than 1,000 tables at a time to avoid affecting the running of the data migration task.

* OMS Community Edition cannot obtain statistical information about tables in the HBase database. Therefore, the progress and estimated time displayed on all pages of OMS Community Edition are inaccurate. You can calculate the completion time based on the real-time RPS and the number of records in the table.

* Incremental data in the HBase database is replicated by using peers. A peer is created in the source HBase database. If you stop the incremental process of OMS Community Edition for a long time, the incremental data in the source HBase database cannot be sent to the incremental synchronization task of OMS Community Edition. This may result in the disk space being filled.

* The start point of incremental data in the HBase database cannot be specified. It is related only to the time when the peer is created. Therefore, if a peer is deleted, you must recreate the data migration task. You must also reinitialize the full migration task.

* If you use the Flink mode for migration and want to interrupt the migration process, you must stop the full migration and incremental synchronization tasks in OMS Community Edition and also stop the job in Flink.

  You can find the corresponding Flink job based on the data migration task ID in OMS Community Edition.

  * Full migration job: OMS_BATCH_{OMS Community Edition task ID}

  * Incremental synchronization job: OMS_STREAM_{OMS Community Edition task ID}

    You can also view the file `/home/ds/run/{component ID}/conf/flink_jobid` in the OMS Community Edition container to find the corresponding Flink job.

* No statistical information is available for incremental synchronization tasks from an HBase database to an OceanBase cluster.

* If you create a data migration task and configure only **<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>**, the data migration task requires that the local incremental logs of the source database are retained for more than 48 hours.

   ​​​If you create a data migration task and configure **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** + **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**, the data migration task requires that the local incremental logs of the source database are retained for at least 7 days. Otherwise, the data migration task may fail because the incremental logs cannot be obtained, or the data in the source and destination databases may be inconsistent.

* When you synchronize incremental data from an HBase database to an OceanBase cluster, the HBase server must be able to ping the OMS Community Edition server. You can configure this in the `/etc/hosts` file of the HBase server.

* If the HBase table is compressed by using the Snappy compression algorithm, you must copy the files in the `lib/native` directory of Hadoop to the `/home/ds/plugins/jdbc_connector` directory of the OMS Community Edition container.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>After you copy the files, run the <code>chown -R ds:ds <file name></code> command and replace <file name> with the name of the file owned by the ds user. </p>
   </main>

## Data type mapping

The following example shows how to map an HBase table to an OBKV table:

```sql
create table if not exists {TABLE_NAME} -- maps to HBase {namespace}.{table_name}${column_family}
(
    `K` varbinary(1024) not null, -- maps to HBase rowkey
    `Q` varbinary(256) not null,  -- maps to HBase column name in a column family
    `T` bigint not null,          -- maps to HBase version/timestamp
    `V` varbinary(1048576),       -- maps to HBase value
    primary key(`K`, `Q`, `T`))
partition by key(`K`) partitions 64
```

You can set the `struct.obkv.createtable` parameter to modify the default DDL statement for schema migration in OBKV.

| Parameter | Description | DDL statement |
|-----------|---------|-----------------------|
|struct.obkv.createtable| You can set this parameter on the **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>** page to specify the default DDL statement for schema migration in OBKV for all tasks. |`create table if not exists {TABLE_NAME} (`K` varbinary(1024) not null, `Q` varbinary(256) not null, `T` bigint not null, `V` varbinary(1048576), `TTL` bigint, primary key(`K`,`Q`,`T`)) partition by key(`K`) partitions 64;`|
|structObkvCreatetable| You can set this parameter in the **<UI-TERM key="oms-community.Migration.New.MigrationOptions">Migration Type</UI-TERM>** > **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** section. Click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** and modify the `sink.json` configuration to specify the default DDL statement for schema migration in OBKV for the current task. | `create table if not exists {TABLE_NAME} (`K` varbinary(1024) not null, `Q` varbinary(256) not null, `T` bigint not null, `V` varbinary(1048576), `TTL` bigint, primary key(`K`,`Q`,`T`)) partition by key(`K`) partitions 64;`|

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.src.constants.DataMigration">Data Migration</UI-TERM>**.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                                                            |
   | Source  | If you have created an HBase data source, select it from the drop-down list. 3. Click **<UI-TERM key="oms-community.Sync.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>**, and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.ReverseIncrement">Reverse Increment</UI-TERM>**.

   | Migration Type | Description |
   |------|--------------------------------------------------------------|
   | Schema Migration | After a schema migration task is started, OMS Community Edition migrates data object definitions (tables, indexes, constraints, comments, and views) from the source database to the destination database and automatically filters out temporary tables. |
   | Full Migration | After a full migration task is started, OMS Community Edition migrates existing data from tables in the source database to the corresponding tables in the destination database.            |
   | Incremental Synchronization | After an incremental synchronization task is started, OMS Community Edition synchronizes data changes (additions, modifications, or deletions) from the source database to the corresponding tables in the destination database.  |
   | Reverse Incremental | After a reverse incremental task is started, you can real-time synchronize data changes generated in the destination database after the business switch back to the source database.|

   * You can troubleshoot and fix the issue, and then perform the precheck again until it succeeds.

   * You can also click **<UI-TERM key="oms-community.components.SyncSwitch.PreCheckSubStep.Skip">Skip</UI-TERM>** in the Actions column of the error item.
