# Migrate data from a Milvus database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a Milvus database to OceanBase Database Community Edition.

## Background information

Milvus is a high-performance, highly scalable vector database that provides powerful data modeling capabilities. For more information, see [Milvus documentation](https://milvus.io/docs/zh/from-m2x.md).

The following table describes the key concepts of Milvus.

| Concept | Description |
|------------------|----------------|
| Database | Equivalent to a schema. A Milvus database can contain multiple databases, and a database can contain multiple collections. |
| Collection | Equivalent to a table. A collection stores specific data and contains multiple fields. You can also specify the dynamic field mode withEnableDynamicField when you create a collection. This means that each record can have different fields. |
| primary key | The primary key field. A collection can have only one primary key field. |
| Partition | A collection can be partitioned, similar to a partitioned table. |

OMS V4.2.9-CE and later support migrating dynamic fields from Milvus to OceanBase Database Community Edition.

* If the target table contains the `OMS_DYNAMIC_FIELD` field or the `sink.omsDynamicField` parameter is set to a value, the dynamic field data is written as a JSON string to the `OMS_DYNAMIC_FIELD` field or the field specified by the `sink.omsDynamicField` parameter.

* If the target table does not contain the `OMS_DYNAMIC_FIELD` field and the `sink.omsDynamicField` parameter is not set, the dynamic field data is discarded.

## Limitations

* **Limitations on operations on the source database**

   **Do not perform DDL operations to change the schema of a database or table during schema migration or full migration. Otherwise, the data migration task may fail.**

* At present, full verification and reverse incremental migration are not supported for data migration from Milvus databases to OceanBase Database Community Edition.

* At present, only Milvus databases of V2.4.5 and later are supported.

* OMS Community Edition supports migrating objects whose names are ASCII characters and do not contain special characters (including line breaks, spaces, and |"'`()=;/&).

* We recommend that you migrate no more than 1,000 tables at a time to avoid affecting the running of the data migration task.

## Data type mapping

|    Milvus database     | OceanBase Database Community Edition |
|------------------|------------------------|
|  BOOL         |    BOOL/TINYINT(1)  <br>Boolean type. Stores true or false values. Suitable for describing binary states. |
|  INT8         |   TINYINT  <br>8-bit integer. Suitable for storing small-range integer data.|
|  INT16        |   SMALLINT <br>16-bit integer. Suitable for storing medium-range integer data.|
|  INT32        |   INT/INTEGER <br>32-bit integer. Suitable for storing general integer data such as product quantities or user IDs.|
|  INT64        |   BIGINT  <br>64-bit integer. Suitable for storing large-range data such as timestamps or identifiers.|
|  FLOAT        |   FLOAT  <br>32-bit floating-point number. Suitable for data that requires general precision, such as grades or temperatures.|
|  DOUBLE       |   DOUBLE <br>64-bit double-precision floating-point number. Suitable for high-precision data such as financial information or scientific calculations.|
|  VARCHAR      |   VARCHAR <br>Specify `max_length` (range: 1 to 65,535). This parameter defines the maximum number of bytes that a VARCHAR field can store.|
|  FLOAT_VECTOR |   VECTOR <br>Vector data type. Stores 32-bit floating-point numbers. Typically used to represent real numbers in scientific calculations and machine learning. Suitable for scenarios that require high precision, such as distinguishing similar vectors.|
|  FLOAT16_VECTOR | VECTOR <br>Stores 16-bit half-precision floating-point numbers. Used in deep learning and GPU computing. In scenarios with low precision requirements, such as the low-precision recall phase of recommendation systems, it can save storage space.|
|  BFLOAT16_VECTOR | VECTOR <br>Stores 16-bit brain floating-point numbers (bfloat16). Suitable for scenarios that require fast processing of large amounts of vectors, such as large-scale image retrieval.|
|  BINARY_VECTOR  | VARBINARY <br>Stores binary vector types.|
|  SPARSE_FLOAT_VECTOR | JSON <br>Stores sparse vectors. The values are in a Map structure similar to a key-value (KV) structure: `{1: 0.6180500771665887, 0: 0.8255673677331509, 4: 0.4227293590979655, 2: 0.09220348558380687}`. |

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.New.components.EndpointForm.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.Migration.Detail.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

   | Parameter | Description |
   |--------|------------------------------------------------|
   | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and must be no longer than 64 characters.                                                                                                                                                 |
   | Tags (Optional)     | Click the text box to select a target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                                                            |
   | Source     | If you have created a Milvus data source, select one from the drop-down list. If not, click **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one on the right. For more information, see [Create a Milvus data source](../800.create-and-manage-data-sources/100.create-a-data-source/1200.create-a-milvus-data-source.md).                          |
   | Destination    | If you have created an OceanBase Database Community Edition data source, select one from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one on the right. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).   |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type | Description |
   |------|-------------------------------------------------------------------------|
   | Schema Migration | After a schema migration task starts, OMS Community Edition migrates the data object definitions (tables, indexes, constraints, comments, and views) from the source database to the destination database and automatically filters out temporary tables.<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">Manual Table Schema Adjustment Required</UI-TERM>**: OMS Community Edition allows you to customize the table structure. If you select this option, only the table structure SQL statements are obtained during the schema migration phase. After you modify the table structure, the migration task is executed.|
   | Full Migration | After a full migration task starts, OMS Community Edition migrates the existing data in the source database tables to the corresponding tables in the destination database. |
   | Incremental Synchronization | After an incremental synchronization task starts, OMS Community Edition synchronizes the data that has changed in the source database (newly added, modified, or deleted data) to the corresponding tables in the destination database.<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** currently supports only `Insert` and `Delete` in **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>`.  |

4. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select migration objects through the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** options. This topic describes how to select migration objects through the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For more information about how to configure match rules, see [Configure match rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The names of tables and columns to be migrated cannot contain Chinese characters. </p>
      </li>
      <li>
      <p>If the name of a database or table contains the $$ character, the data migration task cannot be created. </p>
      </li>
      </ul>
      </main>

     OMS Community Edition allows you to import objects, rename objects, and remove one or all migration objects.

     |   Action    |                                   Procedure                                                                          |
     |---------|---------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.Operator.Store.useStoreAction.Update">OK</UI-TERM>**.<br> **Notice:**<br> The imported objects will overwrite the previously selected objects. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can import a CSV file to rename databases and tables. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the validity check is passed, click **<UI-TERM key="oms-community.components.ProjectLabel.LabelManager.Determine">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                     |
     | Remove/Remove All | OMS Community Edition allows you to remove one or more objects temporarily selected to the target end during data mapping. <ul><li> Remove a single migration object <br> Hover the pointer over the target object in the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, and click **<UI-TERM key="oms-community.Migration.constants.Remove">Remove</UI-TERM>**.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.Endpoint.New.Add">OK</UI-TERM>**.  </ul>   |

5. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

   To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. To view or modify the parameters of the incremental synchronization component, click **<UI-TERM key="oms-community.CommunityParameterForm.components.IncrementalSync.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** section. For more information about the parameters, see the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) section.

   * Full migration

      On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** to display the following parameters.

      | Parameter | Description |
      |----|----------------------------------|
      | Concurrency | The options are **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of full migration varies, and the resources required for full migration tasks also vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual needs. |
      | Handling Strategy When Target Object Exists | The options are **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li> If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, OMS Community Edition will write data to the target table by recording conflicting data in logs and keeping the original data unchanged when the target table contains data that conflicts with the data to be written. <main id="notice" type='notice'><h4>Notice</h4><p> If you select <b>Ignore</b>, full validation will pull data in IN mode, and cannot validate scenarios where the target table contains data that the source table does not. The validation performance will also be degraded. </p></main></li><li> If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, an error will be returned when the target table contains data, and you need to process the target table data before continuing the migration. <main id="notice" type='notice'><h4>Notice</h4><p> If you click Restore after an error occurs, OMS Community Edition will ignore this configuration option and continue migrating the table data. Proceed with caution. </p></main></li> </ul>|
      | Write Mode | The options are **SQL** (data is written to the table by using the `INSERT` or `REPLACE` statement) and **Direct Load** (data is written to the table by using direct load). Currently, you cannot write vector data by using direct load. |

   * Incremental Synchronization

      On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** to display the following parameters.

      | Parameter | Description |
      |----|----------------------------------|
      | Concurrency | The options are **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of incremental synchronization varies, and the resources required for incremental synchronization tasks also vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual needs. |
      | Incremental Synchronization Start Timestamp | <ul><li> If you selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, this parameter is not displayed.   <li> If you did not select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, but selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**, you can specify the migration start timestamp. The default value is the current system time. For more information, see [Set the incremental synchronization start timestamp](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |

6. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>**. The system performs a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** phase, OMS Community Edition checks whether the read/write permissions of the database user and the network connection of the database meet the requirements. You can start a data migration task only after all the checks are passed. If an error occurs during the precheck:

   * You can troubleshoot and fix the error, and then run the precheck again until the precheck is successful.

   * You can also click **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">Skip</UI-TERM>** in the Actions column of the error item. A dialog box pops up to inform you of the specific impact of skipping this operation. After you confirm that you can skip this operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>** in the dialog box.

7. Click **<UI-TERM key="oms-community.components.MigrationPreTable.StartAProject">Start Task</UI-TERM>**. If you do not need to start the task at this time, click **<UI-TERM key="oms-community.biz.EndpointSupplement.Save">Save</UI-TERM>**. The system jumps to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects during the execution of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, it is executed based on the selected migration type. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
