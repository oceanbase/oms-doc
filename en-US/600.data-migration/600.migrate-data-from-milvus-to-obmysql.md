# Migrate data from a Milvus database to OceanBase Database

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a Milvus database to OceanBase Database.

## Background information

Milvus is a high-performance, highly scalable vector database that provides powerful data modeling capabilities. For more information, see [Milvus documentation](https://milvus.io/docs/zh/from-m2x.md).

The following table describes the key concepts in a Milvus database.

| Concept | Description |
|------------------|----------------|
| Database | A database is equivalent to a schema. A Milvus database can contain multiple databases, and a database can contain multiple collections. |
| Collection | A collection is equivalent to a table and is used to store specific data. A collection can contain multiple fields. You can also specify the `withEnableDynamicField` option when you create a collection to indicate that each record can have different fields. |
| Primary key | The primary key field. A collection can contain only one primary key field. |
| Partition | A collection can be partitioned, similar to partitioning a table. |

OMS V4.2.9-CE and later versions support migrating dynamic fields from Milvus to OceanBase Database Community Edition.

* If the destination table contains the `OMS_DYNAMIC_FIELD` field or the `sink.omsDynamicField=xxx` parameter is set, the dynamic field data is written as a JSON string to the `OMS_DYNAMIC_FIELD` field or the field specified by the `sink.omsDynamicField` parameter.

* If the destination table does not contain the `OMS_DYNAMIC_FIELD` field and the `sink.omsDynamicField=xxx` parameter is not set, the dynamic fields are discarded.

## Limitations

* **Limitations on operations on the source database**

   **Do not perform DDL operations to change the schema of the source database during schema migration or full migration. Otherwise, the data migration task may be interrupted.**

* Data migration from a Milvus database to OceanBase Database Community Edition does not support full verification or reverse incremental migration.

* Only Milvus databases of version V2.4.5 and later are supported.

* We recommend that you migrate no more than 1,000 tables at a time to avoid affecting the running of the data migration task.

## Data type mapping

|    Milvus data type     | OceanBase Database Community Edition data type |
|------------------|------------------------|
|  BOOL         |    BOOL/TINYINT(1)  <br>Boolean type for storing true or false values, suitable for representing binary states. |
|  INT8         |   TINYINT  <br>8-bit integer for storing small-range integer data.|
|  INT16        |   SMALLINT <br>16-bit integer for storing mid-range integer data.|
|  INT32        |   INT/INTEGER <br>32-bit integer for storing general integer data, such as product counts or user IDs.|
|  INT64        |   BIGINT  <br>64-bit integer for storing large-range data, such as timestamps or identifiers.|
|  FLOAT        |   FLOAT  <br>32-bit floating-point number for storing data that requires general precision, such as grades or temperatures.|
|  DOUBLE       |   DOUBLE <br>64-bit double-precision floating-point number for storing data that requires high precision, such as financial information or scientific calculations.|
|  VARCHAR      |   VARCHAR <br>Specifies the `max_length` (valid range: 1~65,535), which defines the maximum number of bytes that can be stored in a VARCHAR field.|
|  FLOAT_VECTOR |   VECTOR <br>Vector data type for storing 32-bit floating-point numbers, typically used to represent real numbers in scientific calculations and machine learning. Suitable for scenarios that require high precision, such as distinguishing similar vectors.|
|  FLOAT16_VECTOR | VECTOR <br>Stores 16-bit half-precision floating-point numbers, suitable for deep learning and GPU computing. In scenarios with low precision requirements, such as the low-precision recall phase of recommendation systems, it can save storage space.|
|  BFLOAT16_VECTOR | VECTOR <br>Stores 16-bit brain floating-point numbers (bfloat16), suitable for scenarios requiring rapid processing of large volumes of vectors, such as large-scale image retrieval.|
|  BINARY_VECTOR  | VARBINARY <br>Stores binary vector types.|
|  SPARSE_FLOAT_VECTOR | JSON <br>Stores sparse vector types, with values in a Map-like structure similar to KV: `{1: 0.6180500771665887, 0: 0.8255673677331509, 4: 0.4227293590979655, 2: 0.09220348558380687}`. |

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.New.components.EndpointForm.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.Migration.Detail.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

   | Parameter | Description |
   |--------|------------------------------------------------|
   | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and must be no longer than 64 characters.                                                                                                                                                 |
   | Tags (Optional)     | Click the text box and select the target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                                                            |
   | Source | If you have created a Milvus data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears. For more information, see [Create a Milvus data source](../800.create-and-manage-data-sources/100.create-a-data-source/1200.create-a-milvus-data-source.md).                          |
   | Destination | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).   |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type | Description |
   |------|-------------------------------------------------------------------------|
   | Schema Migration | After a schema migration task starts, OMS Community Edition migrates data object definitions (tables, indexes, constraints, comments, and views) from the source database to the destination database and automatically filters out temporary tables.<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">Manual Table Schema Adjustment Required</UI-TERM>**: OMS Community Edition allows you to customize the table structure. If you select this option, the schema migration phase only retrieves the table structure SQL statements. After you modify the table structure, the migration task will proceed. |
   | Full Migration | After a full migration task starts, OMS Community Edition migrates existing data from tables in the source database to tables in the destination database. |
   | Incremental Synchronization | After an incremental synchronization task starts, OMS Community Edition synchronizes data that has changed in the source database (newly added, modified, or deleted data) to tables in the destination database.<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** currently supports only `Insert` and `Delete` in **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>**.  |

4. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure match rules, see [Configure match rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The names of tables to be migrated and the names of columns in the tables cannot contain Chinese characters.</p>
      </li>
      <li>
      <p>If the database name or table name contains the $$ character, it will affect the creation of the data migration task.</p>
      </li>
      </ul>
      </main>

     OMS Community Edition allows you to import objects, rename objects, and remove individual or all migration objects.

     | Operation | Steps |
     |---------|---------------------------------------------------------------------------------------------------|
     | Import Objects | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.Operator.Store.useStoreAction.Update">OK</UI-TERM>**.<br> **Note:**<br> Importing will overwrite previous selections. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can rename databases and tables by importing CSV files. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the validity test is passed, click **<UI-TERM key="oms-community.components.ProjectLabel.LabelManager.Determine">OK</UI-TERM>**.</ol>    |
     | Rename | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                     |
     | Remove/Remove All | OMS Community Edition allows you to remove individual or all selected objects from the destination database during data mapping. <ul><li> Remove an individual migration object <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the mouse pointer over the destination object and click **<UI-TERM key="oms-community.Migration.constants.Remove">Remove</UI-TERM>** to remove the migration object.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.Endpoint.New.Add">OK</UI-TERM>** to remove all migration objects.  </ul>   |

5. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

   If you want to view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** section. If you want to view or modify the parameters of the incremental synchronization component, click **<UI-TERM key="oms-community.CommunityParameterForm.components.IncrementalSync.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** section. For more information, see the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) section.

   * Full Migration

      On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** to display the following parameters.

      | Parameter | Description |
      |----|----------------------------------|
      | Concurrency Level | The options are **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of full migration varies, and the resources required for full migration tasks also vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your needs.|
      | Handling Strategy When Target Objects Exist | The options are **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li> If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, when data exists in the destination table objects, OMS Community Edition will write the conflicting data to the destination and retain the original data. <main id="notice" type='notice'><h4>Notice</h4><p>When you select <b>Ignore</b>, full validation will use the IN mode to pull data, and it will not validate scenarios where data exists in the destination but not in the source. Additionally, the validation performance will be degraded. </p></main></li><li> If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, when data exists in the destination table objects, full migration will report an error and stop the migration. Please process the data in the destination database before continuing the migration. <main id="notice" type='notice'><h4>Notice</h4><p> If you click Restore after an error occurs, OMS Community Edition will ignore this configuration option and continue to migrate the table data. Proceed with caution. </p></main></li> </ul>|
      | Write Mode | The options are **SQL** (data is written to the table by using the `INSERT` or `REPLACE` statement) and **Direct Load** (data is written to the table by using direct load). Currently, data of the vector type cannot be written to the table by using direct load. |

   * Incremental Synchronization

      On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** to display the following parameters.

      | Parameter | Description |
      |----|----------------------------------|
      | Concurrency Level | The options are **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of incremental synchronization varies, and the resources required for incremental synchronization tasks also vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your needs.|
      | Incremental Synchronization Start Point| <ul><li> If you have selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, this parameter will not be displayed.   <li> If you have not selected **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, but you have selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**, please specify the data to be migrated after a specific time point. The default value is the current system time. For more information, see [Set the incremental synchronization timestamp](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |

6. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to precheck the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** section, OMS Community Edition checks whether the read and write permissions of the database user and the network connection of the database meet the requirements. Only after all precheck tasks are passed can the data migration task be started. If a precheck task fails:

   * You can troubleshoot and fix the issue, and then re-run the precheck task until the precheck task succeeds.

   * You can also click **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">Skip</UI-TERM>** in the Actions column of the failed precheck task. A dialog box will appear, prompting you of the specific impact of skipping this operation. If you confirm that you can skip this operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>** in the dialog box.

7. Click **<UI-TERM key="oms-community.components.MigrationPreTable.StartAProject">Start Task</UI-TERM>**. If you do not want to start the task, click **<UI-TERM key="oms-community.biz.EndpointSupplement.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects during the execution of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it will be executed based on the selected migration type. For more information, see [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) in the section titled "View Migration Details".
