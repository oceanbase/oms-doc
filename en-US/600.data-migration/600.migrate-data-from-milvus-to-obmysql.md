# Migrate data from a Milvus database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a Milvus database to OceanBase Database Community Edition.

## Background information

Milvus is a high-performance and highly scalable vector database service that provides powerful data modeling features. For more information, see [Milvus documentation](https://milvus.io/docs/from-m2x.md).

The following table describes the key concepts of Milvus.

| Concept | Description |
|------------------|----------------|
| Database | A database is equivalent to a schema. You can create multiple databases in Milvus. A database can contain multiple collections. |
| Collection| A collection is equivalent to a table. It stores detailed data and can contain multiple fields. When you create a collection, you can specify the `withEnableDynamicField` attribute to allow different records to have different fields. |
| Primary key | The primary key field. A collection contains only one primary key field. |
| Partition | A partition is a division of a collection. A partitioned collection is equivalent to a partitioned table. |

OMS V4.2.9-CE and later allow you to migrate dynamic fields from a Milvus database to OceanBase Database.

* If the target table has the `OMS_DYNAMIC_FIELD` field or the `sink.omsDynamicField` parameter is set to a value, the dynamic field data is written to the `OMS_DYNAMIC_FIELD` field or the field specified by the `sink.omsDynamicField` parameter as a whole JSON string.

* If the target table does not have the `OMS_DYNAMIC_FIELD` field and the `sink.omsDynamicField` parameter is not set, the dynamic field is discarded.

## Limitations

* **Limitations on operations in the source database**

**Do not perform DDL operations that modify database or table schemas during schema migration or full migration. Otherwise, the data migration task may be interrupted.**

* At present, data migration tasks from a Milvus database to OceanBase Database Community Edition do not support full verification and reverse increment.

* Milvus 2.4.5 and later are supported.

* OMS Community Edition supports migrating databases, tables, and columns with ASCII-compliant names that do not contain special characters (spaces, line breaks, or |"'`()=;/&).

* To ensure the performance of a data migration task, we recommend that you migrate no more than 1,000 tables at a time.

## Data type mapping

|    Milvus database     | OceanBase Database Community Edition |
|------------------|------------------------|
|  BOOL         |    BOOL/TINYINT(1)  <br>Boolean type. It stores true or false and describes binary states. |
|  INT8         |   TINYINT  <br>8-bit integer. It stores small-range integer data.|
|  INT16        |   SMALLINT <br>16-bit integer. It stores medium-range integer data.|
|  INT32        |   INT/INTEGER <br>32-bit integer. It stores general integer data such as the quantity of a product or a user ID.|
|  INT64        |   BIGINT  <br>64-bit integer. It stores large-range data such as timestamps or identifiers.|
|  FLOAT        |   FLOAT  <br>32-bit floating point number. It stores data that requires general precision, such as grades or temperatures.|
|  DOUBLE       |   DOUBLE <br>64-bit double-precision floating point number. It stores high-precision data such as financial information or data for scientific computing.|
|  VARCHAR      |   VARCHAR <br>You can specify `max_length` (the value range is 1 to 65,535) to define the maximum number of bytes that the VARCHAR field can store.|
|  FLOAT_VECTOR |   VECTOR <br>Vector data type. It stores 32-bit floating point numbers. It is commonly used to represent real numbers in scientific computing and machine learning. It is suitable for scenarios that require high precision, such as distinguishing similar vectors.|
|  FLOAT16_VECTOR | VECTOR <br>It stores 16-bit half-precision floating point numbers. It is used in deep learning and GPU computing. It can save storage space in scenarios that do not require high precision, such as the low-precision recall phase of a recommendation system. |
|  BFLOAT16_VECTOR | VECTOR <br>It stores 16-bit brain floating point numbers (bfloat16). It is used in scenarios that require fast processing of a large number of vectors, such as large-scale image retrieval. |
|  BINARY_VECTOR  | VARBINARY <br>It stores binary vectors. |
|  SPARSE_FLOAT_VECTOR | JSON <br>It stores sparse vectors. The value has a Map structure similar to KV: `{1: 0.6180500771665887, 0: 0.8255673677331509, 4: 0.4227293590979655, 2: 0.09220348558380687}`. |

## Procedure

1. Create a data migration task.

   1. Log in to the console of OMS Community Edition.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM>Data Migration</UI-TERM>** page, click **<UI-TERM>Create Task</UI-TERM>** in the upper-right corner.

2. On the **</UI-TERM>Select Source and Target<UI-TERM>** page, configure the parameters.

   | Parameter | Description |
   |--------|------------------------------------------------|
   | Migration Task Name | We recommend that you set it to a combination of digits and letters. It must not contain any spaces and cannot exceed 64 characters in length.                                                                                                                                                 |
   | Tag (Optional)      | Click the field and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Use tags to manage data migration tasks](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                                                            |
   | Source     | If you have created a Milvus data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.pages.EndpointPublic.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create a Milvus data source](../800.create-and-manage-data-sources/100.create-a-data-source/1200.create-a-milvus-data-source.md).                          |
   | Target   | If you have created an OceanBase-CE data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).   |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   Options for **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** are **<UI-TERM key="oms-community.Migration.constants.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>**, and **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>**.
   
   | Migration type |      Description            |
   |------|-------------------------------------------------------------------------|
   | Schema Migration | After a schema migration task starts, OMS Community Edition migrates the data object definitions (tables, indexes, constraints, comments, and views) from the source database to the destination database and automatically filters out temporary tables.<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">Manual Table Schema Adjustment Required</UI-TERM>**: OMS Community Edition allows you to customize the table structure. If you select this option, only the table structure SQL statements are obtained during the schema migration phase. After you modify the table structure, the migration task is executed.|
   | Full Migration | After a full migration task starts, OMS Community Edition migrates the existing data in the source database tables to the corresponding tables in the destination database. |
   | Incremental Synchronization | After an incremental synchronization task starts, OMS Community Edition synchronizes the data that has changed in the source database (newly added, modified, or deleted data) to the corresponding tables in the destination database.<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** currently supports only `Insert` and `Delete` in **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>`.  |

4. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** to specify the migration objects. The following procedure describes how to specify migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For information about the procedure for specifying migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** option, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of a table to be migrated, as well as the names of columns in the table, must not contain Chinese characters. </p>
      </li>
      <li>
      <p>If a database or table name contains double dollar signs (&quot;$$&quot;), you cannot create the migration task. </p>
      </li>
      </ul>
      </main>

     OMS Community Edition allows you to import objects, rename objects, and remove one or all migration objects.

     | Operation | Description |
     |---------|---------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.Operator.Store.useStoreAction.Update">OK</UI-TERM>**.<br> **Notice:**<br> The imported objects will overwrite the previously selected objects. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can import a CSV file to rename databases and tables. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the validity check is passed, click **<UI-TERM key="oms-community.components.ProjectLabel.LabelManager.Determine">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                     |
     | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be migrated to the target database during data mapping. <ul><li>To remove a single migration object:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, move the pointer over the target object and click **<UI-TERM key="oms-community.Migration.constants.Remove">Remove</UI-TERM>**.  <li>To remove all migration objects:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.components.Rules2destination.Node.Determine">OK</UI-TERM>**.  </ul>   |

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **Migration Options** page, configure the parameters.

   To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. To view or modify the parameters of the incremental synchronization component, click **<UI-TERM key="oms-community.CommunityParameterForm.components.IncrementalSync.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** section. For more information about the parameters, see the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) section.

   * Full migration

      The following parameters are displayed only if you have selected **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.
      
      |   Parameter   |     Description    |
      |----|----------------------------------|
      | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**. The amount of resources to be consumed by a full migration task varies based on the migration performance. If you select **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |
      | Processing Strategy When Records Exist in Target Object | Valid values: **<UI-TERM key="oms-community.New.components.ParameterForm.Ignore">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**.<ul><li>If you select **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, when the data to be inserted conflicts with the existing data of a target table, OMS Community Edition retains the existing data and records the conflict data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, data is pulled in IN mode for full verification. In this case, the scenario where the target contains more data than the source cannot be verified, and the verification efficiency will be decreased. </p></main></li><li>If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>** and a target table contains data, an error is returned during full migration, indicating that the migration is not allowed. In this case, you must clear the data in the target table before you can continue with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>After an error is returned, if you click **<UI-TERM key="oms-community.Sync.constants.Recovery">Resume</UI-TERM>** in the dialog box, OMS Community Edition ignores this error and continues to migrate data. Proceed with caution. </p></main></li> </ul>|
      | Writing Method | Valid values: **SQL** (specifies to write data to tables by using `INSERT` or `REPLACE`) and **Direct Load** (specifies to write data through direct load). At present, you cannot write vector data by using direct load. |

   * Incremental synchronization

      The following parameters are displayed only if you have selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |   Parameter   |     Description    |
      |----|----------------------------------|
      | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**. The amount of resources to be consumed by an incremental synchronization task varies based on the synchronization performance. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |
      | Incremental Synchronization Start Timestamp | <ul><li>If you have selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** as the migration type, this parameter is not displayed.<li>If you have selected **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** but not **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**, specify a point in time after which the data is to be synchronized. The default value is the current system time. For more information, see [Set an incremental synchronization timestamp](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |

6. Click **<UI-TERM key="oms-community.Migration.New.Precheck">Precheck</UI-TERM>** to start a precheck on the data migration task.

   During the precheck, OMS Community Edition checks the read and write privileges of the database users and the network connectivity of the databases. A data migration task can be started only after it passes all check items. If an error is returned during the precheck, you can perform the following operations:

   * Identify and troubleshoot the problem and then perform the precheck again.

   * Click **<UI-TERM key="oms-community.Operation.components.operationDetail.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.Detail.components.SyncMonitorDrawer.Operation">Actions</UI-TERM>** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.Migration.New.Determine">OK</UI-TERM>**.

7. Click **<UI-TERM key="oms-community.Sync.New.StartATask">Start Task</UI-TERM>**. If you do not need to start the task now, click **<UI-TERM key="oms-community.Detail.components.StructMigration.Save">Save</UI-TERM>** to go to the details page of the task. You can start the task later as needed.

      OMS Community Edition allows you to modify the migration objects when the data migration task is running. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it is executed based on the selected migration types. For more information, see the **<UI-TERM>Migration Details</UI-TERM>** section in the [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) topic.
