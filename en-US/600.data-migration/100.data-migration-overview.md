# Overview

OceanBase Migration Service (OMS) Community Edition supports data migration. You can use this feature to perform real-time data transmission between OceanBase Community Edition, MySQL, TiDB, and PostgreSQL, as well as data migration between MySQL compatible modes of OceanBase Community Edition.

## Background information

Data migration supports online migration. To deploy the OMS Community Edition server, ensure that the server can maintain network connectivity with both the source and target instances. You only need to configure the source and target data sources for migration, select the objects to be migrated, and then start the data migration task.

The OMS Community Edition automatically performs all steps of the data migration task, successfully replicating database objects, existing data, or incremental data from the source database (table) to the target database (table), and ensuring real-time incremental synchronization from the source to the target database.

## Supported migration types

For the specific operations of each migration type, see the documentation of the "Create a data migration task" module.

| **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** |                                    **<UI-TERM key="oms-community.pages.SystemParam.Description">Description</UI-TERM>**                            |
|----------|----------------------------------------------------------------------------------|
| Schema migration     | Migrates the data object definitions (tables, indexes, constraints, comments, and views) from the source database to the target database. It automatically filters out temporary tables. <br>When the source database is not OceanBase Database, it automatically converts and assembles the data types and SQL syntax based on the syntax definition standards of the target OceanBase tenant type, and then copies them to the target database.                                                                                                                                                   |
| Full migration     | Migrates the existing data in the source database tables to the corresponding tables in the target database. On the **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** page, you can view **<UI-TERM key="oms-community.Detail.components.FullMigration.TableObject">Table Objects</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.TableIndex">Table Indexes</UI-TERM>**, and **<UI-TERM key="oms-community.Migration.constants.FullMigrationPerformance">Migration Performance</UI-TERM>**. The full migration status will be marked as completed only when both table objects and table indexes are migrated. <br>On the **<UI-TERM key="oms-community.Migration.constants.TableIndex">Table Indexes</UI-TERM>** page, click **<UI-TERM key="oms-community.Sync.constants.ViewCreationSyntax">View Creation Syntax</UI-TERM>** after the target table object to view the index creation syntax. <br>Full migration plus incremental synchronization ensures the final consistency between the source and target databases. If an object fails during full migration, the specific failure reason will be displayed.                                                                                          |
| Incremental synchronization     | After an incremental synchronization task starts, it synchronizes the changed data (new, modified, or deleted) from the source database to the corresponding tables in the target database. <br> When there are continuous business writes to the source database, OMS Community Edition starts the incremental pull module before the full data migration starts to pull incremental updates from the source instance, parses and packages them, and stores them in OMS Community Edition. <br> After the full data migration is completed, OMS Community Edition starts the incremental data replay module to obtain incremental data from the incremental pull module. The incremental data is filtered, mapped, and converted, and then synchronized to the target instance.                                                                                    |
| Full verification     | After the full data migration is completed and the incremental data is migrated to the target database and is nearly synchronized with the source database, OMS Community Edition automatically initiates a full data verification task for the data tables in the source and target databases. During the incremental data synchronization, you can also initiate a custom data verification. For data with inconsistent verification results, you can re-verify all data in the table or only re-verify the inconsistent data.                                                                                                                                       |
| Forward switchover     | Forward switchover (a standardized and abstracted process of traditional system cutover) does not involve switching the connection of business applications. It is a task flow that OMS Community Edition executes in conjunction with data migration tasks when you switch the application connections. You must complete all steps of forward switchover before switching the application connections to the target database. <br> Forward switchover is an essential step in data migration. It ensures that OMS Community Edition completes the forward migration of data and allows you to start the reverse incremental component based on your business needs. The main tasks involved in forward switchover are as follows: <ol><li> You must confirm that the data migration is completed and wait for the forward synchronization delay to be eliminated. </li><li> OMS Community Edition automatically supplements the check constraints and foreign key constraints that are ignored during the schema migration phase. </li><li> OMS Community Edition automatically deletes the additional hidden columns and unique indexes required for migration. <br> This operation is only applicable to data migration tasks between OceanBase Community Edition instances. For more information, see [Hidden column mechanism of Data Transmission Service](../600.data-migration/1600.migration-function-introduction/800.schema-migration-mechanisms.md). </li><li> You must manually supplement other database objects, such as triggers, functions, and stored procedures, that OMS Community Edition does not support, to the target database. </li><li> If the data migration task has a reverse incremental component, you must manually disable the triggers on the source database and delete the foreign key constraints. </li></ol> |
| Reverse incremental     | After the data migration is completed, you can guide users to start an incremental synchronization task from the target database to the source database (reverse) in OMS Community Edition before the business database is switched. This task synchronizes the changed data generated in the target database after the business switch back to the source business database in real time.   |
