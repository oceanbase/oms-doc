# Migrate data from a StarRocks database to OceanBase Database

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a StarRocks database to OceanBase Database.

## Limitations

* **Limitations on operations on the source database**

    **Do not perform DDL operations on the schema of the database or table during full migration, otherwise the data migration task may be interrupted.**

* The supported StarRocks database versions are V2.3.18 and V3.3.15.

* Data migration from StarRocks to OceanBase Database Community Edition supports only full migration.

* Data source identifiers and user accounts must be globally unique in the OMS system.

* OMS Community Edition supports only migration of databases, tables, and columns with ASCII names that do not contain special characters (|"'`()=;/& and line breaks).

* We recommend that you migrate no more than 1,000 tables in one go to avoid affecting the running of data migration tasks.

* Fields of the ARRAY or MAP type require a custom function (UDF) to convert JSON strings. OMS automatically creates the required UDFs (with names starting with omsudf_) based on the field type. These UDFs will not be automatically deleted after the data migration is complete.

* In the StarRocks external table scenario, the following limitations apply:

  * Migration of data of the BINARY, VARBINARY, and STRUCT types is not supported.

  * The number of specific records in the target table cannot be obtained.

  * OMS creates an external table named `omsext_+ source table name prefix` in the source StarRocks database, and this external table will not be automatically deleted after the data migration is complete.

## Data type mapping

| StarRocks database | OceanBase Database Community Edition |
|-------------------|----------------|
| BIGINT       |   BIGINT |
| BOOLEAN |   BOOLEAN  |
| CHAR    |   CHAR |
| DATE |  DATE  |
| DATETIME | DATETIME |
| DECIMAL | DECIMAL |
| DOUBLE |  DOUBLE |
| FLOAT   |  FLOAT |
| INT | INT |
| SMALLINT | SMALLINT |
| STRING | VARCHAR |
| TINYINT | TINYINT |
| VARCHAR | VARCHAR |
| BINARY/VARBINARY | VARBINARY |
| LARGEINT | BIGINT UNSIGNED <br>Maximum value: 18446744073709551615. If the value stored in the StarRocks database exceeds this limit, it will be stored as 18446744073709551615 in OceanBase Database Community Edition. |
| JSON | JSON |
| MAP | JSON |
| STRUCT |  JSON  |
| ARRAY | JSON |
| BITMAP | STRING <br>Use the `bitmap_to_string` function to read data from the StarRocks database, convert it to a string, and write it to OceanBase Database Community Edition. |
| HLL  | BIGINT <br>Use the `hll_cardinality` function to read data from the StarRocks database, convert it to an integer, and write it to OceanBase Database Community Edition.|

1. Create a data migration task.

    1. Log in to the OMS console.

    2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

    3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and must be no longer than 64 characters.  |
    | Tag     | Click the text box and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source     | If you have created a StarRocks data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create a StarRocks data source](../800.create-and-manage-data-sources/100.create-a-data-source/1700.create-starrocks-data-source.md).|
    | Destination    | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is started, OMS will migrate the existing data in the source database tables to the corresponding tables in the destination database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure match rules, see [Configure match rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The names of the tables to be migrated and the columns in the tables cannot contain Chinese characters.</p>
      </li>
      <li>
      <p>If the database name or table name contains the &quot;$$&quot; character, it will affect the creation of the data migration task.</p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the selected objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When you migrate data from the StarRocks database to OceanBase Database Community Edition, OMS supports importing the migration objects as text, renaming the objects, and removing one or all migration objects.

     |   Operation    |                                                    Steps                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner of the right-side list.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite previous selections. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can rename databases and tables by importing a CSV file. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the validity check is passed, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS supports renaming migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS supports removing one or all selected migration objects during data mapping. <ul><li> Remove a single migration object <br> In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the destination object and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** to remove the migration object.  <li> Remove all migration objects <br> In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>On the <b>Select Migration Type</b> page, select <b>Full Migration</b> to display the following parameters.</p>
      </main>

    |Parameter|Description|
    |----|----------------------------------|
    | Concurrency Speed | The options are **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of a full migration task varies, and the resources required also vary. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your requirements.|
    | Handling Strategy When Records Exist in the Destination Objects | The options are **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li> If you select **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, when data exists in the destination table objects, OMS will write the data to the destination table objects, and record the conflicting data in the logs. <main id="notice" type='notice'><h4>Notice</h4><p>When you select <b>Ignore</b>, the full validation will use the IN mode to pull data, and cannot validate scenarios where data exists in the destination but not in the source. The validation performance will also be degraded. </p></main></li><li> If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, when data exists in the destination table objects, the full migration will fail and prompt that the migration cannot be performed. Proceed with caution. </p></main></li> </ul>|
    | Write Method | The options are **SQL** (write data to the tables by using the `INSERT` or `REPLACE` statement) and **Direct Load** (write data to the tables by using the direct load method). Currently, you cannot write vector data by using the direct load method.|

    If you want to view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see the documentation in the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/300.source-plugin/900.mongodb-source.md) section.

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>**. The system performs a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS checks whether the network connection to the database meets the requirements. You can start a data migration task only after all precheck tasks are completed. If the precheck fails:

   * You can fix the issue and perform the precheck again until the precheck succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column of the failed precheck item. A dialog box appears, prompting you of the impact of skipping this step. If you confirm that you can skip this step, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not want to start the task immediately, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

    OMS supports modifying the migration objects during the running of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, it will be executed based on the selected migration type. For more information, see [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) in the section titled "View Migration Details".
