# Migrate data from a StarRocks database to OceanBase Database

This topic describes how to use OceanBase Migration Service (OMS) to migrate data from a StarRocks database to OceanBase Database.

## Limitations

* **Limitations on the source database**

    **Do not perform DDL operations on the schema of a database or table during full migration. Otherwise, the data migration task may be interrupted.**

* The supported StarRocks database versions are V2.3.18 and V3.3.15.

* At present, data migration from a StarRocks database to OceanBase Database Community Edition supports only full migration.

* The data source identifier and user account must be globally unique in the OMS system.

* OMS Community Edition supports only migrating databases, tables, and columns with ASCII names that do not contain special characters (|"'`()=;/& and newline).

* We recommend that you migrate no more than 1,000 tables at a time to avoid affecting the running of data migration tasks.

* For fields of the ARRAY or MAP type, you must use a user-defined function (UDF) to convert JSON strings. OMS automatically creates the required UDFs (with names starting with omsudf_) based on the field types. These UDFs will not be automatically deleted after data migration.

* In the scenario of external tables in StarRocks, the following limitations apply:

  * You cannot migrate data of the BINARY, VARBINARY, or STRUCT type.

  * You cannot obtain the number of records inserted into the destination table.

  * OMS creates an external table in the source StarRocks database with the name `omsext_+ source table name prefix`. This external table will not be automatically deleted after data migration.

## Data type mapping

| StarRocks database | OceanBase Database |
|-------------------|----------------|
| BIGINT       |   BIGINT |
| BOOLEAN |   BOOLEAN  |
| CHAR    |   CHAR |
| DATE |  DATE  |
| DATETIME | DATETIME |
| DECIMAL | DECIMAL |
| DOUBLE |  DOUBLE |
| FLOAT   |  FLOAT |
| INT | INT |
| SMALLINT | SMALLINT |
| STRING | VARCHAR |
| TINYINT | TINYINT |
| VARCHAR | VARCHAR |
| BINARY/VARBINARY | VARBINARY |
| LARGEINT | BIGINT UNSIGNED <br>Maximum storage is 18446744073709551615. If the value stored in the StarRocks database exceeds this limit, OceanBase Database will still store it as 18446744073709551615. |
| JSON | JSON |
| MAP | JSON |
| STRUCT |  JSON  |
| ARRAY | JSON |
| BITMAP | STRING <br>Use the `bitmap_to_string` function to read data from the StarRocks database, convert it to a string, and write it to OceanBase Database. |
| HLL  | BIGINT <br>Use the `hll_cardinality` function to read data from the StarRocks database, convert it to an integer, and write it to OceanBase Database.|

1. Create a data migration task.

    1. Log in to the OMS console.

    2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

    3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and cannot exceed 64 characters.  |
    | Tag     | Click the text box to select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source     | If you have created a StarRocks data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one. For more information, see [Create a StarRocks data source](../800.create-and-manage-data-sources/100.create-a-data-source/1700.create-starrocks-data-source.md).|
    | Destination    | If you have created an OceanBase Database data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one. For more information, see [Create an OceanBase Database data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is started, OMS will migrate the existing data in the source database tables to the corresponding tables in the destination database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration object and migration scope.

   You can select the migration object by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select the migration object by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure the matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of the table to be migrated and the names of the columns in the table cannot contain Chinese characters.</p>
      </li>
      <li>
      <p>If the name of a database or table contains the &quot;$$&quot; character, the data migration task cannot be created.</p>
      </li>
      </ul>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the selected objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When you migrate data from the StarRocks database to OceanBase Database, OMS supports importing objects, renaming objects, and removing individual or all migration objects.

     |   Operation    |                                                    Procedure                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import object    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li>In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite the previous selection. Proceed with caution.  <li>In the **Import Migration Objects** dialog box, import the objects to be migrated.<br>You can rename databases and tables by importing a CSV file. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the validation is successful, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS supports renaming the name of a migration object. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS supports removing individual or multiple objects that are temporarily selected to the destination. <ul><li>Remove an individual migration object <br>In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the object and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** to remove the object.  <li> Remove all migration objects <br>In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see the documentation in the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/300.source-plugin/900.mongodb-source.md) module.

The performance of a full migration task varies, and the resources required also vary. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>**.|
    | Strategy for handling records in the destination object | The strategy can be **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** or **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li> If you select **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, OMS will write data to the destination table by recording conflicting data in logs and keeping the original data unchanged when the destination table contains data. <main id="notice" type='notice'><h4>Notice</h4><p> If you select <b>Ignore</b>, the full validation will use the IN mode to pull data, and cannot validate scenarios where the destination table contains data that the source table does not. The validation performance will also be degraded. </p></main></li><li> If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, an error will be returned when the destination table contains data, and you must resolve the issue before continuing the migration. <main id="notice" type='notice'><h4>Notice</h4><p> If you click Restore after an error occurs, OMS will ignore the configuration option and continue to migrate the table data.     | Write Method | Includes **SQL** (data is written to the table by using the `INSERT` or `REPLACE` statement) and **Direct Load** (data is written to the table by using the direct load method). Currently, you cannot write vector data to a table by using the direct load method. |

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>**. OMS performs a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS checks whether the network connection between the databases meets the requirements. A data migration task can be started only after all precheck tasks are completed. If the precheck fails:

   * You can troubleshoot and resolve the issue, and then perform the precheck again until it succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column of the failed precheck item. A dialog box appears, prompting you of the specific impact of skipping the operation. After you confirm that you can skip the operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not want to start the task, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

    OMS allows you to modify the migration objects of a data migration task during the task execution. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, the task will be executed in the order of the selected migration types. For more information, see the [View Migration Details](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) topic.
