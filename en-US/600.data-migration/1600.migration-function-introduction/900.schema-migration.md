# Schema migration operations

This topic describes the schema migration operations supported in a data migration task in OceanBase Migration Service (OMS) Community Edition.

## Background

A schema migration task migrates data objects such as tables, indexes, constraints, comments, and views from the source database to the destination database, and automatically filters out temporary tables. If the source database is not an OceanBase database, the data transmission service performs format conversion and encapsulation based on the syntax definition and standard of the type of the destination tenant of OceanBase Database and then replicates the data to the destination database.

After the precheck succeeds, the data migration task proceeds to the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** step. On the details page of the data migration task, you can click the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** tab to view the overall status, start time, end time, and total duration of the schema migration task, as well as the migration progress of tables and views.

If the schema migration task is in the **<UI-TERM key="oms-community.Sync.constants.YunXingZhong">Running</UI-TERM>** or **<UI-TERM key="oms-community.pages.Audit.Failed">Failed</UI-TERM>** state, the operations that you can perform on a target object varies with the state of the object. If the schema migration task is in the **<UI-TERM key="oms-community.Sync.constants.Completed">Completed</UI-TERM>** state, you can only view the syntax used to create the target objects.

| Status | Supported Operation |
|--------------|----------------------|
| Initializing | - |
| DDL statements obtained/Creating/Ready | View Creation Syntax |
| Completed/Completed (with conversion)/Skipped | Remove, and View Creation Syntax |
| Failed | Retry, Skip, Remove, View Details, and Modify Creation Syntax |
| Failed to obtain the DDL statement | Retry, Skip, View, and Modify Creation Syntax |
| Not Supported <br>This state occurs when the destination database does not support the creation syntax used in the source database.  | Skip, Remove, View, and Modify Creation Syntax |

## Prerequisites

You have created and started a data migration task. For more information, see the topic about creating a data migration task between the corresponding data sources in [Data migration](../100.data-migration-overview.md).

## Limitations

* The operations in this topic are applicable to schema migration tasks in the **<UI-TERM key="oms-community.ModifyRecordTable.constants.Running">Running</UI-TERM>** or **<UI-TERM key="oms-community.components.BatchSelect.BatchSwitch.Failed">Failed</UI-TERM>** state. If a schema migration task is in the **<UI-TERM key="oms-community.Sync.constants.Completed">Completed</UI-TERM>** state, you can only view the syntax used to create the target objects.

* A schema migration task can migrate tables, indexes, views, comments, and CHECK constraints, but not temporary tables, events, types, functions, or procedures.

## Retry a single failed object or all failed objects

You can retry a single object or all objects in the **<UI-TERM key="oms-community.components.BatchSelect.BatchSwitch.Failed">Failed</UI-TERM>** or **Failed to obtain the DDL statement** state. You can directly retry an object, or retry an object after you modify it.

* Retry a single failed object: On the **<UI-TERM key="oms-community.Migration.constants.SchemaMigration">Schema Migration</UI-TERM>** page, find the failed object and click **<UI-TERM key="oms-community.ModifyRecordTable.constants.Retry">Retry</UI-TERM>** in the **<UI-TERM key="oms-community.migration.new.components.communityForm.createPlatform.action">Actions</UI-TERM>** column.

* Retry all failed objects

   1. On the **<UI-TERM key="oms-community.Migration.constants.SchemaMigration">Schema Migration</UI-TERM>** page, click **<UI-TERM key="oms-community.Detail.components.StructMigration.RetryAllFailedObjects">Retry All Failed Objects</UI-TERM>** in the upper-right corner.

   2. In the dialog box that appears, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>**.

## Skip a target object

You can skip a target object in the **<UI-TERM key="oms-community.Detail.components.FullMigration.Failed">Failed</UI-TERM>**, **Failed to obtain the DDL statement**, or **<UI-TERM key="oms-community.Sync.constants.NotSupported">Not Supported</UI-TERM>** state.

<main id="notice" type='notice'>
<h4>Notice</h4>
<ul>
<li>You must prepare a corresponding migration object in the destination database before you skip the target object. Otherwise, an error will occur in the <b>Full Migration</b> step. </li>
<li>Once skipped, the target object will not be migrated in the current data migration task. Proceed with caution. </li>
</ul>
</main>

To skip a target object, perform the following operations:

1. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** page, find the target object and click **<UI-TERM key="oms-community.Sync.constants.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.Operation.Machine.Operation">Actions</UI-TERM>** column.

2. In the dialog box that appears, click **<UI-TERM key="oms-community.src.layout.BasicLayout.Confirmation">OK</UI-TERM>**.

## Remove a target object

You can remove a target object in the **<UI-TERM key="oms-community.Migration.constants.Failed">Failed</UI-TERM>**, **<UI-TERM key="oms-community.components.SyncSwitch.DbObjectTable.Completed">Completed</UI-TERM>**, **<UI-TERM key="oms-community.oms-models.structMigration.constants.CompletedWithConversion">Completed (with conversion)</UI-TERM>**, **<UI-TERM key="oms-community.Sync.constants.Skipped">Skipped</UI-TERM>**, **Failed to obtain the DDL statement**, or **<UI-TERM key="oms-community.Migration.constants.BuZhiChi">Not Supported</UI-TERM>** state.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Once removed, the target object will not be migrated in the current data migration task. Proceed with caution. </P>
</main>

1. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** page, find the target object and click **<UI-TERM key="oms-community.Migration.constants.Remove">Remove</UI-TERM>** in the **<UI-TERM key="oms-community.Operation.Connector.Operation">Actions</UI-TERM>** column.

2. In the dialog box that appears, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>**.

## Modify the creation syntax

You can modify the table creation syntax of a target object in the **<UI-TERM key="oms-community.pages.Audit.Failed">Failed</UI-TERM>** or **Failed to obtain the DDL statement** state.

1. On the **<UI-TERM key="oms-community.Migration.constants.SchemaMigration">Schema Migration</UI-TERM>** page, find the target object and choose **<UI-TERM key="oms-community.components.SyncSwitch.DbObjectTable.MoreOperations">More</UI-TERM>** > **<UI-TERM key="oms-community.components.ProjectLabel.LabelManager.Modify">Modify</UI-TERM>** in the **<UI-TERM key="oms-community.Operation.JDBCWriter.Operation">Actions</UI-TERM>** column.

2. In the **<UI-TERM key="oms-community.Detail.components.SQLtab.ModifyTableCreationSyntax">Modify Table Creation Syntax</UI-TERM>** dialog box, check the failed DDL statement and the error message, and modify the definition of the conversion result of the DDL statement.

3. Click **<UI-TERM key="oms-community.biz.EndpointSupplement.Save">Save</UI-TERM>**.

## View creation syntax

You can view the table creation syntax of all target objects except those in the **<UI-TERM key="oms-community.Detail.components.SyncSteps.Initializing">Initializing</UI-TERM>** or **<UI-TERM key="oms-community.src.constants.Failed">Failed</UI-TERM>** state.

On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** page, find the target object and click **<UI-TERM key="oms-community.OCP.components.actionDialogs.View">View</UI-TERM>** in the **<UI-TERM key="oms-community.pages.Endpoint.Operation">Actions</UI-TERM>** column. Fully compatible DDL syntax executed on the OBServer node is directly displayed. Incompatible syntax is converted before it is displayed.

## View details of a failed object

You can view the error details of a target object in the **<UI-TERM key="oms-community.PreCheck.constants.Failed">Failed</UI-TERM>** state.

1. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** page, find the target object and choose **<UI-TERM key="oms-community.Detail.components.SyncMonitorDrawer.MoreOperations">More</UI-TERM>** > **<UI-TERM key="oms-community.Detail.components.StructMigration.ViewDatabaseResponseCodes">View Details</UI-TERM>** in the **<UI-TERM key="oms-community.components.ProjectLabel.LabelManager.Operation">Actions</UI-TERM>** column.

2. In the **<UI-TERM key="oms-community.Detail.components.StructMigration.ViewDetails">View Details</UI-TERM>** dialog box, view the cause of the failure.
