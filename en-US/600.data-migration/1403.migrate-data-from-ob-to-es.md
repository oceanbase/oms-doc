# Migrate data from OceanBase Database Community Edition to an ElasticSearch database

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from OceanBase Database Community Edition to an ElasticSearch database.

## Limitations

* **Limitations on operations in the source database**

   **Do not perform DDL operations that modify database or table schemas during schema migration or full migration. Otherwise, the data migration task may be interrupted.**

* At present, data migration tasks from OceanBase Database Community Edition to an ElasticSearch database do not support full verification and reverse increment, and do not support migrating tables without primary keys.

* The supported versions of Elasticsearch are V7.x and V8.x.

* Data source identifiers and user accounts must be globally unique in OMS.

* OceanBase Database Community Edition supports only migrating databases, tables, and column objects with ASCII-compliant names that do not contain special characters (|"'`()=;/& and line breaks).

* We recommend that you migrate no more than 1,000 tables at a time to avoid impacting the data migration task.

## Considerations

* If you specify columns to migrate when you create a data migration task, only the specified columns are migrated during schema migration.

* In OceanBase Database Community Edition, data of the JSON type is converted to the object type when it is migrated to ElasticSearch. If the task involves full migration and incremental synchronization, make sure that the types of the same-named keys of the JSON data are consistent. If you change the field type in ElasticSearch to text, the data is migrated as a JSON string.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM>New Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, numbers, and letters. The name must not contain spaces and must not exceed 64 characters in length.  |
    | Tag     | Click the field and select the target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete a tag. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source    | If you have created an OceanBase Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|
    | Target    | If you have created an ElasticSearch data source, select it from the drop-down list. If you have not created one, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** can be **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, or **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type |      Description            |
   |------|-------------------------------------------------------------------------|
   | Schema Migration | After a schema migration task is started, OMS Community Edition migrates data object definitions (tables, indexes, constraints, comments, and views) from the source database to the target database and automatically filters out temporary tables.<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">Manual Table Schema Adjustment Required</UI-TERM>**: OMS Community Edition supports customize table schema. If you select this option, OMS Community Edition only obtains the SQL statements for the table schema. After you modify the schema, the migration proceeds.|
   | Full Migration | After a full migration task is started, OMS Community Edition migrates existing data from tables in the source database to tables in the target database. If you select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, we recommend that you collect statistics for OceanBase Community Edition in the source before you migrate data.    |
   | Incremental Synchronization | After an incremental synchronization task is started, OMS Community Edition synchronizes new, modified, or deleted data in the source database to tables in the target database.<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** is supported only for **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>**. For more information, see [DML filtering](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md).  |

4. Click **<UI-TERM key="oms-community.Sync.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** page, select the migration objects and the migration scope.

   You can select migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of a table to be migrated, as well as the names of columns in the table, must not contain Chinese characters. </p>
      </li>
      <li>
      <p>The name of the mapped database is <code>default</code> by default after you select a source object. </p>
      </li>
      <li>
      <p>If the name of a database or table contains the characters "$$", an error occurs when you create a data migration task. </p>
      </li>
      </ul>
      </main>

     OMS Community Edition supports importing objects, renaming table migration objects, configuring row filtering, viewing column information, and removing one or more migration objects.

     |   Operation    |                                   Steps                                                                          |
     |---------|---------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite the previously selected objects. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br>You can rename databases and tables and configure row filtering by importing CSV files. For more information, see [Download and import the settings of migration objects](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the objects pass the validation, click **<UI-TERM key="oms-community.Detail.components.MigrationSteps.Determine">OK</UI-TERM>**.  </ol>    |
     | Rename objects    | OMS Community Edition allows you to rename table migration objects. For more information, see [Rename a database or table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                     |
     | Configure settings     | OMS allows you to configure row filtering and select columns to be migrated.<ul><li> In the text box of the **<UI-TREM>Row Filters</UI-TREM>** section, enter the `WHERE` clause of a standard SQL statement to configure row filtering. For more information, see [Filter data by using SQL conditions](../600.data-migration/1600.migration-function-introduction/600.migration-row-filters.md).<li> In the **<UI-TREM>Select Columns</UI-TREM>** section, select the columns to be migrated.  </ul>                   |
     | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be migrated to the target database during data mapping. <ul><li>To remove a single migration object:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, move the pointer over the target object and click **<UI-TERM key="oms-community.components.ViewObj.DelObject.Remove">Remove</UI-TERM>**.  <li>To remove all migration objects:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.components.ETL.ETLFormDrawer.Determine">OK</UI-TERM>**.  </ul>   |

5. Click **<UI-TERM key="oms-community.Sync.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

   * Schema migration

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |  Parameter  |  Description  |
      |--------------|--------------|
      | Index Shards (Optional)  | The number of index shards. This parameter corresponds to the `number_of_shards` parameter when you create an index in ElasticSearch.       |
      | Index Replicas (Optional)  | The number of index replicas. This parameter corresponds to the `number_of_replicas` parameter when you create an index in ElasticSearch.    |
      | Date Format (Optional)  | The date format. This parameter corresponds to the `format` parameter for date fields when you create an index in ElasticSearch.     |

   * Full migration

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |Parameter|Description|
      |----|----------------------------------|
      | Concurrency Speed | The migration concurrency. Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of full migration varies depending on the migration concurrency. The resources required for a full migration task vary depending on the migration concurrency. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>**.|
      | Processing Strategy When Records Exist in Target Object | Valid values: **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**.<ul><li>If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, when the data to be inserted conflicts with the existing data of a target table, OMS Community Edition retains the existing data and records the conflict data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, data is pulled in IN mode for full verification. In this case, the scenario where the target contains more data than the source cannot be verified, and the verification efficiency will be decreased. </p></main></li><li>If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>** and a target table contains data, an error is returned during full migration, indicating that the migration is not allowed. In this case, you must clear the data in the target table before you can continue with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>After an error is returned, if you click **<UI-TERM key="oms-community.Operation.constants.Recovery">Resume</UI-TERM>** in the dialog box, OMS Community Edition ignores this error and continues to migrate data. Proceed with caution. </p></main></li> </ul>|

   * Incremental synchronization

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |Parameter|Description|
      |----|----------------------------------|
      | Concurrency Speed | The migration concurrency. Valid values: **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of incremental synchronization varies depending on the migration concurrency. The resources required for an incremental synchronization task vary depending on the migration concurrency. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>**.|
      | Incremental Synchronization Start Timestamp | <ul><li> If you have selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** as the migration type, this parameter is not displayed. <li> If you have selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** but not **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**, specify the data to be migrated after a specific point in time. The default value is the current system time. For more information, see [Set the incremental synchronization point in time](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |
      | Incremental Record Retention Time | The duration that incremental parsed files are cached in OMS Community Edition. A longer retention period results in more disk space occupied by the Store component of OMS Community Edition.|

6. Click **<UI-TERM key="oms-community.Migration.New.Precheck">Precheck</UI-TERM>** to perform a precheck on the data migration task.

   On the **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** page, OMS Community Edition checks whether the read and write permissions of the database user and the network connection of the database meet the requirements. You can start a data migration task only after all precheck tasks pass. If an error is returned during the precheck:

   * You can troubleshoot and fix the error, and then perform the precheck again until the precheck succeeds.

   * Click **<UI-TERM key="oms-community.components.BatchSelect.BatchActions.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.Operation.Connector.Operation">Actions</UI-TERM>** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>**.

7. Click **<UI-TERM key="oms-community.Sync.New.StartATask">Start Task</UI-TERM>** to start the data migration task. If you do not need to start the task now, click **<UI-TERM key="oms-community.biz.EndpointSupplement.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects in a data migration task during the migration. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it executes based on the migration type you selected. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
