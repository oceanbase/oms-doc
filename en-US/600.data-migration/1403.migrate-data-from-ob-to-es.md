# Migrate data from OceanBase Database Community Edition to an ElasticSearch database

This topic describes how to use OceanBase Migration Service (OMS) to migrate data from OceanBase Database Community Edition to an ElasticSearch database.

## Limitations

* **Limitations on operations performed on the source database**

   **Do not perform DDL operations for database or table schema changes during full migration. Otherwise, the data migration task may be interrupted.**

* Full validation and reverse incremental migration of data from OceanBase Database Community Edition to ElasticSearch are not supported. Also, migration of tables without primary keys is not supported.

* Data source identifiers and user accounts must be globally unique in OMS.

* OMS Community Edition only supports migrating databases, tables, and column objects with ASCII-compliant names that do not contain special characters (|"'`()=;/& or line breaks).

* We recommend that you migrate no more than 1,000 tables at a time to avoid affecting the operation of the data migration task.

## Considerations

* If you specify columns to migrate when you create a data migration task, only the specified columns are migrated during schema migration.

* In OceanBase Database Community Edition, data of the json type is converted to data of the object type when it is migrated to ElasticSearch. If the task involves full migration and incremental synchronization, ensure that the types of the same-named keys of json data are consistent. If you change the field type in ElasticSearch to text, the data is migrated as a json string.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Migration Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Migration Project Name | We recommend that you use a combination of Chinese characters, numbers, and letters. The name cannot contain spaces and must be less than 64 characters in length.  |
    | Tag     | Click the field and select a destination tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete a tag. For more information, see [Manage data migration projects by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source    | If you have created an OceanBase Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|
    | Destination    | If you have created an ElasticSearch data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** can be **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, or **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type |      Description            |
   |------|-------------------------------------------------------------------------|
   | Schema Migration | After a schema migration task is created, OMS Community Edition migrates the data object definitions (tables, indexes, constraints, comments, and views) from the source database to the destination database and automatically filters out temporary tables.<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">Manual table structure adjustment required</UI-TERM>**: OMS Community Edition allows you to customize the table schema. If you select this option, OMS Community Edition only obtains the schema SQL statements of the tables. After you modify the tables, the migration proceeds.|
   | Full Migration | After a full migration task is created, OMS Community Edition migrates the existing data of the tables from the source database to the corresponding tables in the destination database. If you select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, we recommend that you collect the statistics of OceanBase Community Edition in the source before you migrate data.    |
   | Incremental Synchronization | After an incremental synchronization task is created, OMS Community Edition synchronizes the data that changes in the source database (new data, modified data, and deleted data) to the corresponding tables in the destination database.<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">Incremental Synchronization</UI-TERM>** is supported only for **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>**. For more information, see [DML filtering](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md).  |

4. Click **<UI-TERM key="oms-community.Sync.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select the migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select the migration objects by using **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <li>
      <p>The name of a table to be migrated and the names of columns in the table cannot contain Chinese characters. </p>
      </li>
      <li>
      <p>The default mapping database name is <code>default</code> after you select a source object. </p>
      </li>

     OMS Community Edition allows you to import objects, rename table migration objects, set row filtering, view column information, and remove one or all migration objects.

     |   Operation    |                                   Steps                                                                          |
     |---------|---------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>**.<br> **Notice**: <br> Importing will overwrite the previous operation selection. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br>You can rename databases and tables, set row filtering conditions, and perform other operations by importing CSV files. For more information, see [Download and import the settings of migration objects](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the objects pass the validation, click **<UI-TERM key="oms-community.Detail.components.MigrationSteps.Determine">OK</UI-TERM>**. </ol>    |
     | Rename     | OMS Community Edition allows you to rename the name of a table migration object. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                     |
     | Set      | OMS allows you to set row filtering and select columns to be migrated.<ul><li> In the **<UI-TREM>Row Filtering Condition</UI-TREM>** section, enter the `WHERE` clause of a standard SQL statement in the field to configure row filtering. For more information, see [Filter data by using SQL conditions](../600.data-migration/1600.migration-function-introduction/600.migration-row-filters.md).<li> In the **<UI-TREM>Select Columns</UI-TREM>** section, select the columns to be migrated.  </ul>                   |
     | Remove/Remove All | OMS Community Edition allows you to remove one or multiple objects temporarily selected for migration during data mapping. <ul><li> Remove a single migration object <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the target object and click **<UI-TERM key="oms-community.common.TreeSearch.TargetNode.Remove">Remove</UI-TERM>** that appears. The migration object is removed.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.Operator.Connector.useConnectorAction.MigrationConfirm">OK</UI-TERM>**. The migration objects are removed.  </ul>   |

5. Click **<UI-TERM key="oms-community.Sync.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

   * Schema Migration

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |  Parameter  |  Description  |
      |--------------|--------------|
      | Number of Index Shards (Optional)  | The number of index shards. The value corresponds to the `number_of_shards` parameter when you create an index in ElasticSearch.       |
      | Number of Index Replicas (Optional)  | The number of index replicas. The value corresponds to the `number_of_replicas` parameter when you create an index in ElasticSearch.    |
      | Date Format (Optional)  | The date format. The value corresponds to the `format` parameter of date fields when you create an index in ElasticSearch.     |

   * Full Migration

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |Parameter|Description|
      |----|----------------------------------|
      |Concurrent Speed | The concurrent speed. Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance varies with the migration type. The resources required for the migration task also vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on the actual situation.|
      |Action for Existing Destination Objects | The action to take when destination objects already exist. Valid values: **<UI-TERM key="oms-community.New.components.ParameterForm.Ignore">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li> If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, when the destination table contains data, OMS Community Edition writes data to the destination table by recording conflicting data in the log and retaining the original data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, full verification uses the IN mode to pull data, which cannot verify the scenario where the destination contains data that does not exist in the source. The verification performance will be significantly degraded. </p></main></li><li> If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, when the destination table contains data, an error is reported that migration is not allowed. Please process the destination data and then continue the migration. <main id="notice" type='notice'><h4>Notice</h4><p>If you click Restore after an error occurs, OMS Community Edition will ignore this configuration option and continue to migrate table data. Proceed with caution. </p></main></li> </ul>|

   * Incremental Synchronization

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |Parameter|Description|
      |----|----------------------------------|
      |Concurrent Speed | The concurrent speed. Valid values: **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance varies with the migration type. The resources required for the migration task also vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on the actual situation.|
      |Incremental Synchronization Start Timestamp| <ul><li> If you selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, this parameter does not appear.   <li> If you did not select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, but selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**, specify the data to migrate after a specific point in time. The default value is the current system time. For more information, see [Set the incremental synchronization timestamp](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |
      |Incremental Record Retention Period| The retention period of incremental parse files cached in OMS Community Edition. The longer the configured retention period, the more disk space the OMS Community Edition Store component consumes.  |

6. Click **<UI-TERM key="oms-community.Migration.New.Precheck">Precheck</UI-TERM>** to perform a precheck on the data migration task.

   On the **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** page, OMS Community Edition checks whether the read and write permissions of the database user and the network connection of the database meet the requirements. You can start a data migration task only after all checks pass. If an error is returned during the precheck:

   * You can troubleshoot and resolve the issue, and then perform the precheck again until the precheck succeeds.

   * You can also click **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">Skip</UI-TERM>** in the operation column of the error precheck item. A dialog box appears, prompting you of the specific impact of skipping this operation. If you confirm that you can skip this operation, click **<UI-TERM key="oms-community.Operator.JDBCWriter.useJDBCWriterAction.Update">OK</UI-TERM>** in the dialog box.

7. Click **<UI-TERM key="oms-community.Sync.New.StartATask">Start Task</UI-TERM>**. If you do not need to start the task, click **<UI-TERM key="oms-community.biz.EndpointSupplement.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects during the data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it proceeds in the order of the selected migration type. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
