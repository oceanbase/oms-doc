# Download and import settings of migration objects

OceanBase Migration Service (OMS) Community Edition allows you to download the settings of migration objects in a data migration task and supports automatic configuration and verification of object settings based on imported CSV files. This allows you to promptly save task settings and configure multiple migration tasks at a time. This feature is suitable for renaming and setting hundreds of objects at a time.

## Download object configuration

After you create a data migration task by specifying migration objects, you can download the settings of the objects.

1. Log in to the OMS Community Edition console.

2. In the left-side navigation pane, click **<UI-TERM key="oms-community.layout.constants.DataMigration">Data Migration</UI-TERM>**.

3. On the **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>** page, click the name of the task whose object settings you want to download.

4. On the details page of the task, click the **<UI-TERM key="oms-community.Detail.components.FullMigration.MoreOperations">More</UI-TERM>** icon in the upper-right corner, and then choose **<UI-TERM>Download Task Configuration</UI-TERM>** from the drop-down list.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>If you set the migration object selection mode to <strong>Match Rules</strong> for a migration task, you cannot download the object settings of the task. </p>
    </main>

## Import object settings

OMS Community Edition allows you to rename databases and tables and set row filter conditions by importing CSV files. You can download a template CSV file, modify it as needed, and then import it.

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>If you edit the object information in an Excel file, separate the columns with commas (,), save the file as a CSV file, and then import the CSV file. </p>
  </main>

The imported CSV file must contain the following columns: source database name, source table name, target database name, target table name, column mapping, and row filter condition.

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.components.CustomizedTable.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.Migration.New.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM>New Task</UI-TERM>** in the upper-right corner.

2. Create a migration task based on your business needs. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** page, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>You can import objects only after you select the <strong>Specify Objects</strong> mode. </p>
    </main>

   The specific procedure of creating a data migration task depends on the source and target nodes you select. For more information, see Create a data migration task.

3. In the dialog box that appears, click **<UI-TERM key="oms-community.Detail.components.SyncSteps.Determine">OK</UI-TERM>**.

4. Click **<UI-TERM key="oms-community.components.ImportTransferObj.importCVS">Import CSV File</UI-TERM>** in the lower part of the **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** dialog box, and select a local CSV file to import it.

   You can also click **<UI-TERM>Download CSV Template</UI-TERM>** in the lower part of the dialog box to download the template. Then, configure the settings in the template as needed and click **<UI-TERM key="oms-community.components.ImportTransferObj.importCVS">Import CSV File</UI-TERM>** to import the migration objects.

5. Edit the CSV file as needed.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>
    <p>You can edit the CSV file manually or by using an SQL script. You can also click <strong>Download Task Configuration</strong> on the details page of the task to generate a CSV file. </p>
    </li>
    <li>
    <p>You can enter names of databases or tables in the target database to establish a mapping between the source and target. </p>
    </li>
    </ul>
    </main>

6. Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>** to check whether the source objects exist and whether the row filter conditions are correct. If the verification succeeds, the number of verified tables and views is displayed.

7. Click **<UI-TERM key="oms-community.Operator.Connector.useConnectorAction.Update">OK</UI-TERM>** to return to the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** step of the data migration task.

8. Complete subsequent task settings as prompted.
