# View and modify migration objects

This topic describes how to view and modify the objects of a configured data synchronization task by using OceanBase Migration Service (OMS) Community Edition.

## Background information

If the limitations are met, you can add or remove migration objects of a data migration task during migration. The changes made during the running of the task will be recorded. After an object addition task is completed, it will be integrated with the original task that is associated. After the task is integrated with the original task, the original task runs normally and the object addition task is automatically released.

## Limitations

* For a data migration task whose migration objects are selected only by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option, you can modify its migration objects.

* For a data migration task in the **<UI-TERM key="oms-community.Migration.constants.NotStarted">Not Started</UI-TERM>**, **<UI-TERM key="oms-community.Detail.components.SyncMonitorDrawer.Running">Running</UI-TERM>**, or **<UI-TERM>Stopped</UI-TERM>** state, you can add or remove its migration objects.

* For a data migration task in the **<UI-TERM key="oms-community.Sync.constants.Failed">Failed</UI-TERM>** state, you can only remove its migration objects.

* For a data migration task in the **<UI-TERM key="oms-community.Sync.constants.Modifying">Modifying</UI-TERM>** or **<UI-TERM key="oms-community.ModifyRecordTable.constants.Merging">Integrating</UI-TERM>** state, you cannot modify its migration objects again. |

* If a data migration task is in the **<UI-TERM>Stopped</UI-TERM>** or **<UI-TERM key="oms-community.Audit.constants.Failed">Failed</UI-TERM>** state in the **<UI-TERM>Full Migration</UI-TERM>** or **</UI-TERM>Incremental Synchronization</UI-TERM>** step, you can only remove migration objects.

* In the **<UI-TERM>Reverse Increment</UI-TERM>** step of a data migration task, you can only remove its migration objects.

* For a data migration task in the active-active disaster recovery scenario, you cannot add or remove migration objects.

## View migration objects

1. Log in to the console of OMS Community Edition.

2. In the left-side navigation pane, click **<UI-TERM key="oms-community.src.constants.DataMigration">Data Migration</UI-TERM>**.

3. On the **<UI-TERM key="oms-community.Migration.Detail.DataMigration">Data Migration</UI-TERM>** page, click the name of the target task to go to its details page.

4. Click **<UI-TERM key="oms-community.Migration.constants.ViewObjectsToBeMigrated">View Objects</UI-TERM>** in the upper-right corner and view information on the **<UI-TERM key="oms-community.components.ViewObject.MigrateObjects">Migration Objects</UI-TERM>** and **<UI-TERM key="oms-community.Migration.Detail.ModifyObjectRecords">Object Modifications</UI-TERM>** tabs.

   * The **<UI-TERM key="oms-community.components.ViewObject.MigrateObjects">Migration Objects</UI-TERM>** tab displays the migration objects of the current task. You can click **<UI-TERM>Modify Object</UI-TERM>** and then select **<UI-TERM>Add Object</UI-TERM>** or **<UI-TERM key="oms-community.ModifyRecordTable.constants.ReduceObjects">Remove Objects</UI-TERM>**.

   * The **<UI-TERM key="oms-community.Detail.components.SyncObject.ModifyObjectRecords">Object Modifications</UI-TERM>** tab displays the IDs, types, status, and occurrence time of all object modifications.

## Add migration tasks

1. On the details page of the target task, click **<UI-TERM key="oms-community.Detail.components.SyncObject.ViewObjectsToBeSynchronized">View Objects</UI-TERM>** in the upper-right corner.

2. In the **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.ViewObjectsToBeMigrated">View Objects</UI-TERM>** dialog box, choose **<UI-TERM>Modify Objects</UI-TERM>** > **<UI-TERM>Add Objects</UI-TERM>**.

3. In the **<UI-TERM key="oms-community.components.ViewObject.SourceObject">Source Objects</UI-TERM>** section on the left of the **<UI-TERM>Add Objects</UI-TERM>** dialog box, select the objects to be migrated and click **>** to add them to the list on the right. You can select tables and views of one or more databases as the migration objects.

   After you select the migration objects to add, you can perform operations such as renaming objects, setting row-based filtering, and viewing column information.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>By default, the added objects will inherit all configurations of the data migration task. If you abort the object addition operation, you must manually delete the objects that have been added to the target database. </p>
    </li>
    <li>
    <p>If you specified the schema name or DB name for the source, you can add only the migration objects under the specified schema name or database name. </p>
    </li>
    </ul>
   </main>

4. Then, click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

5. The system automatically performs a precheck on the added migration objects. After the added migration objects pass all check items, click **<UI-TERM key="oms-community.Sync.New.Save">Save</UI-TERM>**.

6. Confirm the information and click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>** in the dialog box that appears.

   * For a paused or failed data migration task, you can cancel the operation and modify the migration objects again. The added migration objects will be migrated to the target database only after the data migration task returns to normal.

   * If you add migration objects for a running data migration task, after you click Save, the added migration objects will be immediately migrated to the target database.

   After the object addition operation begins, records will be generated on the page that appears after you choose **<UI-TERM key="oms-community.Migration.constants.ViewObjectsToBeMigrated">View Objects</UI-TERM>** > **<UI-TERM key="oms-community.Migration.Detail.ModifyObjectRecords">Object Modifications</UI-TERM>**. You can view details of the records on this page. The status of object addition records can be **<UI-TERM key="oms-community.ModifyRecordTable.constants.PendingExecution">Pending</UI-TERM>**, **<UI-TERM key="oms-community.SystemManage.Authorization.contants.Canceled">Canceled</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Modifying">Modifying</UI-TERM>**, **<UI-TERM key="oms-community.Operator.constants.Running">Running</UI-TERM>**, **<UI-TERM key="oms-community.ModifyRecordTable.constants.Terminated">Aborted</UI-TERM>**, **<UI-TERM key="oms-community.ModifyRecordTable.constants.Merging">Integrating</UI-TERM>**, **<UI-TERM key="oms-community.PreCheck.constants.Success">Succeeded</UI-TERM>**, or **<UI-TERM key="oms-community.PreCheck.constants.Failed">Failed</UI-TERM>**. The operations that you can perform on an object addition record and the status of the original task vary with the status of the object addition record.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>If the original data synchronization task is in the <strong>Not Started</strong> state, a modification record in the <strong>Successful</strong> state will be generated for an object addition operation. If the original data synchronization task is in the <strong>Paused</strong> state, a modification record in the <strong>Pending</strong> state will be generated for an object addition operation. </p>
    </main>

   The status of an object addition record changes only when the original data synchronization task is in the Running state, and the status of the original task changes along with the status of the object addition record. The following table describes more information.

   | Status of an object addition record | Supported operations | Status of the original task |
   |---------------|--------------------------------------------------------------|------------|
   | Pending | View details and cancel. | Running |
   | Canceled | N/A | Running |
   | Modifying | N/A | Modifying |
   | Running | View details and abort. | Modifying |
   | Aborted | View details. | Running |
   | Integrating | View details. | Integrating |
   | Succeeded | View details. | Running |
   | Failed | View details and retry.<br>You can also click **<UI-TERM>View Cause</UI-TERM>** to go to the details page of the task and view the cause of the failure.  | Modifying/Integrating |

## Remove migration objects

1. On the details page of the target task, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.ViewObjectsToBeMigrated">View Objects</UI-TERM>** in the upper-right corner.

2. In the **<UI-TERM key="oms-community.Sync.constants.ViewObjectsToBeSynchronized">View Objects</UI-TERM>** dialog box, choose **<UI-TERM>Modify Objects</UI-TERM>** \> **<UI-TERM key="oms-community.components.ViewObj.DelObject.ReduceObjects">Remove Objects</UI-TERM>**.

3. In the **<UI-TERM key="oms-community.components.ViewObj.DelObject.ReduceObjects">Remove Objects</UI-TERM>** dialog box, move the pointer over a migration object that you want to remove in the **<UI-TERM>Target Object</UI-TERM>** section on the right and click **<UI-TERM key="oms-community.Migration.constants.Remove">Remove</UI-TERM>**.

4. In the **<UI-TERM key="oms-community.components.ViewObj.DelObject.ReduceObjects">Remove Objects</UI-TERM>** dialog box, click **<UI-TERM key="oms-community.components.ViewObj.DelObject.Remove">Remove</UI-TERM>**.

5. In the confirmation dialog box that appears, confirm the migration object to remove and click **<UI-TERM key="oms-community.Endpoint.New.Add">OK</UI-TERM>**.

   If the task is in the paused, failed, or running state, after you click OK, the migration object is immediately removed from the target database.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>A removed migration object cannot be recovered, so proceed with caution. </p>
    </li>
    <li>
    <p>The final result of the object removal operation is either succeeded or failed for all migration objects. </p>
    </li>
    </ul>
    </main>

   After the object removal operation begins, records will be generated on the page displayed after you choose **<UI-TERM key="oms-community.Sync.constants.ViewObjectsToBeSynchronized">View Objects</UI-TERM>** \> **<UI-TERM key="oms-community.Detail.components.SyncObject.ModifyObjectRecords">Object Modifications</UI-TERM>**. You can view the details of the records on this page. The status of object removal records can be **<UI-TERM key="oms-community.ModifyRecordTable.constants.PendingExecution">Pending</UI-TERM>**, **<UI-TERM key="oms-community.SystemManage.Authorization.contants.Canceled">Canceled</UI-TERM>**, **<UI-TERM>Modifying, Succeeded</UI-TERM>**, or **<UI-TERM key="oms-community.Detail.components.FullMigration.Failed">Failed</UI-TERM>**. The operations that you can perform on an object removal record and the status of the original task vary with the status of the object removal record.

   | Status of an object removal record | Supported operations | Status of the original task |
   |---------------|--------------------------------------------------------------|------------|
   | Pending | View details and cancel. | Running |
   | Canceled | N/A | Running |
   | Modifying | N/A | Modifying |
   | Succeeded | View details. | Running |
   | Failed | View details and retry.<br>You can also click **<UI-TERM>View Causes</UI-TERM>** to go to the details page of the task and view the cause of the failure.  | Modifying |
