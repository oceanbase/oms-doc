# View details of a data migration task

After you start a data migration task, you can view the basic information, progress, and status of the task on its details page.

## Access the details page

1. Log in to the console of OceanBase Migration Service (OMS) Community Edition.

2. In the left-side navigation pane, click **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.DataMigration">Data Migration</UI-TERM>**.

3. On the **<UI-TERM key="oms-community.src.constants.DataMigration">Data Migration</UI-TERM>** tab, click the name of the target task. On the details page that appears, view the basic information and migration details of the task.

   On the **<UI-TERM key="oms-community.src.constants.DataMigration">Data Migration</UI-TERM>** page, you can search for data migration tasks by tag, status, type, or keyword. A data migration task can be in one of the following states:

   * **<UI-TERM key="oms-community.Sync.constants.NotStarted.5">Not Started</UI-TERM>**: The data migration task has not been started. You can click **<UI-TERM key="oms-community.JDBCWriter.New.Start">Start</UI-TERM>** in the **<UI-TERM key="oms-community.migration.new.components.communityForm.createPlatform.action">Actions</UI-TERM>** column to start the task.

   * **<UI-TERM key="oms-community.Sync.constants.YunXingZhong">Running</UI-TERM>**: The data migration task is in progress. You can view the data migration plan and current progress on the right.

   * **<UI-TERM key="oms-community.ModifyRecordTable.constants.Modifying">Modifying</UI-TERM>**: The migration objects in the migration task are being modified.

   * **<UI-TERM key="oms-community.Migration.constants.Merging">Integrating</UI-TERM>**: The data migration task of the modified migration object is being integrated with the migration object modification task.

   * **Paused**: The data migration task is manually paused. You can click **<UI-TERM key="oms-community.Sync.constants.Recovery">Resume</UI-TERM>** in the **<UI-TERM key="oms-community.Detail.components.FullMigration.Operation">Actions</UI-TERM>** column to resume the task.

   * **<UI-TERM key="oms-community.src.constants.Failed">Failed</UI-TERM>**: The data migration task has failed. You can view where the failure occurred on the right. To view the error message, click the task name to go to the task details page.

   * **<UI-TERM key="oms-community.Operation.Overview.constants.Completed">Completed</UI-TERM>**: The data migration task is completed, and OMS Community Edition has migrated the specified data to the target database in the configured migration mode.

   * **<UI-TERM key="oms-community.src.constants.Releasing">Releasing</UI-TERM>**: The data migration task is being released. You cannot edit a data migration task in this state.

   * **<UI-TERM key="oms-community.src.constants.Released">Released</UI-TERM>**: The data migration task is released. After the task is released, OMS Community Edition terminates the current migration and incremental synchronization task.

## View migration details

The **<UI-TERM key="oms-community.Migration.Detail.MigrationDetails">Migration Details</UI-TERM>** section displays the status, progress, start time, end time, and total duration of all subtasks.

### Schema migration

The definitions of data objects, such as tables, indexes, constraints, comments, and views, are migrated from the source database to the target database. Temporary tables are automatically filtered out. If the source database is not of OceanBase database Community Edition, OMS Community Edition performs SQL format conversion and construction based on the syntax definition and standard of the type of the target tenant of OceanBase Database, and then replicates the data to the target database.

When you advance to the forward switchover step in a data migration task, OMS Community Edition will automatically drop the hidden columns and unique indexes based on the type of the data migration task.

You can view the overall status, start time, end time, total amount of time consumed, and database, table, and view migration progress for a schema migration task on the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>** page. When you migrate data between tenants of OceanBase Database Community Edition, you can view the migration progress of stored procedures and functions. You can also perform the following operations on an object:

* **<UI-TERM key="oms-community.Sync.constants.ViewCreationSyntax">View Creation Syntax</UI-TERM>**: On the **<UI-TERM key="oms-community.Endpoint.Detail.Library">Database</UI-TERM>** or **<UI-TERM key="oms-community.Detail.components.StructMigration.Table">Table</UI-TERM>** tab, you can click **<UI-TERM key="oms-community.Operation.Machine.MachineActions.View">View</UI-TERM>** next to the target object to view the creation syntax of a database, table, or index.

  Compatible DDL syntax executed on the OBServer node is displayed. Incompatible syntax is converted before it is displayed.

* **<UI-TERM>Modify Creation Syntax and Try Again</UI-TERM>**: You can view the error information, check and modify the definition of the conversion result of a failed DDL statement, and then migrate the data to the target database again.

* **<UI-TERM key="oms-community.ModifyRecordTable.constants.Retry">Retry</UI-TERM>**/**<UI-TERM key="oms-community.Detail.components.StructMigration.RetryAllFailedObjects">Retry All Failed Objects</UI-TERM>**: You can retry failed schema migration tasks one by one or retry all failed tasks at a time.

* **<UI-TERM>Export All Schemas</UI-TERM>**: You can export the schema information of all objects and save it to your local storage.

* **<UI-TERM key="oms-community.Sync.constants.Skip">Skip</UI-TERM>**/**<UI-TERM key="oms-community.Detail.components.StructMigration.BatchSkip">Batch Skip</UI-TERM>**: You can skip failed schema migration tasks one by one or skip multiple failed tasks at a time. To skip multiple objects at a time, click **<UI-TERM key="oms-community.Detail.components.StructSync.BatchSkip">Batch Skip</UI-TERM>** in the upper-right corner. If you skip an object, its index is also skipped.

* **<UI-TERM key="oms-community.components.PreCheck.PreCheckTable.Remove">Remove</UI-TERM>**/**<UI-TERM key="oms-community.Detail.components.StructSync.BatchRemoval">Batch Remove</UI-TERM>**: You can remove failed schema migration tasks one by one or remove multiple failed tasks at a time. ### Incremental synchronization

After incremental synchronization starts, data that has been changed (added, modified, or deleted) in the source database is synchronized to the corresponding tables in the target database. When services continuously write data to the source database, OMS Community Edition starts the incremental data pull module to pull incremental data from the source instance, parses and encapsulates the incremental data, and then stores the data. After that, OMS Community Edition starts the full migration.

After the full migration task is completed, OMS Community Edition starts the incremental data replay module to pull incremental data from the incremental data pull module. The incremental data is synchronized to the target instance after being filtered, mapped, and converted. If an Incr-Sync exception occurs after you execute a DDL statement in the source database and the data migration task fails, a page appears, displaying the DDL statement that causes the task failure and the **<UI-TERM key="oms-community.components.SyncSwitch.PreCheckSubStep.Skip">Skip</UI-TERM>** button. You can click **<UI-TERM key="must.AlertTips.commponents.ErrorDetail.Skip">Skip</UI-TERM>** and confirm your operation.

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>This operation may lead to data structure inconsistency between the source and target databases. Proceed with caution. </p>
</main>

The latency is displayed in the following format: X seconds (updated Y seconds ago). Normally, Y is less than 20.

### Forward switchover

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you execute a data migration task in an active-active disaster recovery scenario, forward switchover is not supported. </p>
</main>

Forward switchover is an abstract and standard process of conventional system cutover and does not involve the switchover of application connections. This process includes a series of tasks that are performed by OMS Community Edition for application switchover in a data migration task. You must make sure that the entire forward switchover process is completed before the application connections are switched over to the target database.

Forward switchover is required for data migration. OMS Community Edition ensures the completion of forward data migration in this process, and you can start the reverse increment component based on your business needs. The forward switchover process involves the following operations:

1. You must make sure that data migration is completed and wait until forward synchronization is completed.

2. OMS Community Edition automatically supplements CHECK constraints, FOREIGN KEY constraints, and other objects that are ignored in the schema migration stage.

3. OMS Community Edition automatically drops the additional hidden columns and unique indexes that the migration depends on.

   This operation is required only when you migrate data between tenants of OceanBase Database Community Edition. For more information, see [Hidden column mechanisms](../1600.migration-function-introduction/800.schema-migration-mechanisms.md).

4. You must migrate triggers, functions, and stored procedures in the source database that are not supported by OMS Community Edition to the target database.

5. You must disable triggers and FOREIGN KEY constraints in the source database. This operation is required only when the data migration task involves reverse increment.

The forward switchover process contains the following steps:

![forward-switchover-en](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/forward-switchover-en.png)

1. Start forward switchover.

   In this step, you can start forward switchover, but no operation is performed in the background. After you confirm that data migration is completed, you can click **<UI-TERM key="oms-community.components.SyncSwitch.ConfirmStartSwitch.StartAForwardSwitch">Start Forward Switchover</UI-TERM>** to start the forward switchover process for business cutover.

   If you want to complete forward switchover with a few clicks, you can select **<UI-TERM>Fast Switching</UI-TERM>** to skip the manual confirmation step. After you select this option, OMS Community Edition no longer requires manual confirmation. Proceed with caution.

   Please select **<UI-TERM key="oms-community.CommunityParameterForm.components.ReverseIncrementalSync.ReverseIncrementInitiationSite">Reverse Increment Start Timestamp</UI-TERM>**, including **<UI-TERM>Reverse Incremental Initiation Time</UI-TERM>** and **<UI-TERM>Reverse Store Initiation Time</UI-TERM>**. This parameter is not displayed if only reverse incremental migration or no reverse incremental migration is configured.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Before you start forward switchover, make sure that data writing has stopped in the source database. </p>
   </main>

2. Perform a switchover precheck.

   In this step, OMS checks the following items:

   * Synchronization latency between the source and target databases. If the synchronization latency is within 15 seconds, this check item is passed.

   * Write privilege of the account in the source database. If the data migration task involves reverse increment, OMS additionally checks whether the account configured in the source database has the privilege to write data, to ensure that data can be properly written during reverse increment.

   * Privilege of the account in the target database for incremental data read. If the data migration task involves reverse increment, OMS additionally checks whether the account configured in the target database has the privilege to read data. This ensures that data can be properly written to the target database during reverse increment.

   * Incremental logs in the target database. If the data migration task involves reverse increment, OMS additionally checks whether the incremental logging configuration in the target database meets the log extraction requirements of reverse increment.

   If the switchover precheck is passed, OMS Community Edition automatically performs the next step. If the switchover precheck fails, OMS Community Edition provides two options: **<UI-TERM key="oms-community.components.SyncSwitch.StopSync.TryAgain">Retry</UI-TERM>** and **<UI-TERM key="must.AlertTips.commponents.ErrorDetail.Skip">Skip</UI-TERM>**.
  
   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <p>If you click <strong>Skip</strong>, data loss may occur in the target database, or the reverse increment may fail. Proceed with caution. </p>
   </main>

3. Start the target store.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>This step is available only when the data migration task involves reverse increment. </p>
    </main>

    If the precheck for forward switchover is passed, OMS Community Edition automatically starts incremental log pulling for the target database. This way, OMS Community Edition obtains DML and DDL operations in the target database and parses and saves related log data to prepare for reverse increment. This step takes 3 to 5 minutes.

4. Confirm that data writing has stopped in the source database.

    In this step, OMS checks whether business data is still being written to the source database. If you make sure that no new data is written to the source database, click **<UI-TERM key="oms-community.components.SyncObjectForm.Determine">OK</UI-TERM>** to go to the next step.

5. Confirm the data writing stop timestamp upon synchronization completion.

    In this step, OMS checks whether the target database is synchronized to the data writing stop timestamp in the source database. If not, OMS Community Edition continues to check the target database until it is synchronized to the timestamp. This way, OMS Community Edition makes sure that all data in the target database is updated.

6. Stop forward synchronization.

    In this step, you can stop forward synchronization. After forward synchronization is stopped, any database changes in the source database will no longer be synchronized to the target database. If the service fails to be stopped, OMS Community Edition provides two options: **<UI-TERM key="oms-community.Migration.constants.TryAgain">Retry</UI-TERM>** and **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">Skip</UI-TERM>**.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>You can click <strong>Skip</strong> only after forward synchronization is completed in the background. Otherwise, data in the source database may be unexpectedly written to the target database. Proceed with caution. </p>
    </main>

7. Process database objects.

   In this step, you can process the objects that are ignored in data migration or not supported by OMS Community Edition. This ensures normal operations of your business after the switchover to the target database.

   * Migrate database objects to the target database: You must migrate triggers, functions, and stored procedures in the source database that are not supported by OMS Community Edition to the target database. After you complete the migration, click **<UI-TERM>Mark as Complete</UI-TERM>**.

   * Disable triggers and FOREIGN KEY constraints in the source database: This operation is required only when the data migration task involves reverse increment. It prevents data from being affected by triggers or FOREIGN KEY constraints, to avoid failures of reverse increment synchronization. After you complete this operation, click **<UI-TERM>Mark as Complete</UI-TERM>**.

   * Supplement the objects ignored in schema migration to the target database: OMS Community Edition automatically supplements the objects that are ignored in schema migration to the target database, such as check constraints and FOREIGN KEY constraints. The preceding objects are migrated during schema migration by default.

   * Drop hidden columns and unique indexes added by OMS Community Edition: This operation is required only when you migrate data between tenants of OceanBase Database Community Edition. OMS Community Edition automatically drops the hidden columns and unique indexes that are added to the target database to ensure data consistency. This operation runs automatically, and the amount of time required depends on the amount of data in the target database. OMS Community Edition provides the **<UI-TERM key="must.AlertTips.commponents.ErrorDetail.Skip">Skip</UI-TERM>** option for this operation. If you choose to skip this operation, you need to manually perform the drop operation. Proceed with caution. For more information, see [Hidden column mechanisms](../1600.migration-function-introduction/800.schema-migration-mechanisms.md).

8. Start reverse increment

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>This step is available only when the data migration task involves reverse increment. </p>
    </main>

   In this step, you can start incremental synchronization for the target database to synchronize incremental DML or DDL operations from the target database to the source database in real time. The configuration of incremental synchronization is the same as that specified when the task was created. For more information, see [Incremental synchronization of DDL operations](../1700.supported-ddl-operations-for-incremental-migration-and-limits/100.mysql-to-obmysql/100.mysql-to-obmysql-overview.md).

### Reverse increment

<main id="notice" type='notice'>
  <h4>Notice</h4>
  <p>When you execute a data migration task in an active-active disaster recovery scenario, OMS Community Edition automatically starts reverse increment before full verification based on the settings of incremental synchronization. </p>
</main>

For a data migration task in the **<UI-TERM key="oms-community.Operation.constants.Running">Running</UI-TERM>** state, you can view its latency, current timestamp, and performance of reverse increment in the **<UI-TERM>Reverse Increment</UI-TERM>** section. The latency is displayed in the following format: X seconds (updated Y seconds ago). Normally, Y is less than 20.
  
For a data migration task in the **<UI-TERM key="oms-community.Operation.Overview.constants.Stopped">Stopped</UI-TERM>** or **<UI-TERM key="oms-community.Detail.components.FullMigration.Failed">Failed</UI-TERM>** state, you can enable DDL/DML statistics collection to collect statistics on database operations performed after this feature is enabled. You can also view the specific information about the objects and performance of reverse increment synchronization.
  
* The **<UI-TERM key="oms-community.biz.TableStatistic.SynchronizeObjectStatistics">Synchronization Object Statistics</UI-TERM>** tab displays the statistics about table-level DML statements executed for each reverse increment object in the current task. The numbers displayed in the **<UI-TERM key="oms-community.biz.TableStatistic.ChangeSum">Change Sum</UI-TERM>**, **<UI-TERM key="oms-community.components.BanchView.Delete">Delete</UI-TERM>**, **<UI-TERM>Insert</UI-TERM>**, and **<UI-TERM key="oms-community.components.UpdateCompCfgDrawer.UpdateCompCfgDrawer.Update">Update</UI-TERM>** fields in the section above the **<UI-TERM key="oms-community.biz.TableStatistic.SynchronizeObjectStatistics">Synchronization Object Statistics</UI-TERM>** tab are the sums of the corresponding columns on this tab.  

* The **<UI-TERM key="oms-community.Detail.components.MonitorCard.ReverseIncrementalPerformance">Reverse Increment Performance</UI-TERM>** tab displays the following content:

  * Latency: the latency in synchronizing incremental data from the target database to the source database, in seconds.

  * Migration traffic: the traffic throughput of incremental data synchronization from the target database to the source database, in Kbit/s.

  * Average execution time: the average execution time of an SQL statement, in ms.

  * Average commit time: the average commit time of a transaction, in ms.

  * RPS: the number of rows written to the target per second.
