# Migrate data from a Qdrant database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a Qdrant database to OceanBase Database Community Edition.

## Background information

Qdrant is an open source vector search engine with high performance. It can process and store a large amount of high-dimensional vector data and supports similarity-based quick search. For more information, see [Qdrant documentation](https://qdrant.tech/documentation/quickstart/).

## Limitations

* **Limitations on the source database**

   **Do not perform DDL operations that modify database or table schemas during schema migration or full migration. Otherwise, the data migration task may be interrupted.**

* At present, OMS Community Edition supports only full migration from a Qdrant database to OceanBase Database Community Edition.

* The data source identifiers and user accounts must be globally unique in OMS Community Edition.

* OMS Community Edition supports the migration of only objects whose database name, table name, and column name are ASCII-encoded without special characters. The special characters are line breaks and <code>| " ' ` ( ) = ; / &</code>.

* The vector dimensions must be consistent with the dimensions in the vector type of OceanBase Database Community Edition.

## Procedure

1. Create a data migration task.

   1. Log in to the console of OMS Community Edition.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.src.constants.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Migration Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM>Select Source and Target</UI-TERM>** page, configure the parameters.

   |   Parameter   |     Description    |
   |--------|-----------------------------------------------------------|
   | Data Migration Task Name | We recommend that you set it to a combination of digits and letters. It must not contain any spaces and cannot exceed 64 characters in length.                                                                                                                                 |
   | Tag (Optional)      | Click the field and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Use tags to manage data migration tasks](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                            |
   | Source       | If you have created a Qdrant data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.pages.Endpoint.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create a Qdrant data source](../800.create-and-manage-data-sources/100.create-a-data-source/1100.create-a-qdrant-data-source.md). |
   | Target   | If you have created an OceanBase-CE data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).                                    |

3. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is started, OMS Community Edition migrates the existing data of tables in the source database to corresponding tables in the target database.

5. Click **<UI-TERM key="oms-community.components.ViewObj.AddObject.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** to specify the migration objects. The following procedure describes how to specify migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For information about the procedure for specifying migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** option, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The names of tables to be migrated, as well as the names of columns in the tables, must not contain Chinese characters. </p>
      </li>
      <li>
      <p>If a database or table name contains double dollar signs (&quot;$$&quot;), you cannot create the migration task. </p>
      </li>
      </ul>
      </main>

    ![migration-5-en](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/migration-5-en.png)

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list. You can select tables and views of one or more databases as the migration objects.

      3. Click **>** to add the selected objects to the **<UI-TERM>Target Object(s)</UI-TERM>** list.

     When you migrate data from a Qdrant database to OceanBase Database Community Edition, OMS Community Edition allows you to import objects from text, rename objects, and remove one or all migration objects.

     |   Operation    | Description   |
     |---------|-------|
     | Import objects      | <ol><li>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.<li>In the dialog box that appears, click **<UI-TERM key="oms-community.Operator.JDBCWriter.useJDBCWriterAction.Update">OK</UI-TERM>**. <br>**Notice**<br> This operation will overwrite previous selections. Proceed with caution.  <li>In the **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** dialog box, import the objects to be migrated. <br>You can import CSV files to rename databases/tables and set row filtering conditions. For more information, see [Download and import the settings of migration objects](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).<li>Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.<li>After the validation succeeds, click **<UI-TERM key="oms-community.Detail.components.SyncSteps.Determine">OK</UI-TERM>**. </ol>    |
     | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename a database table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be migrated to the target database during data mapping. <ul><li>To remove a single migration object:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, move the pointer over the target object and click **<UI-TERM key="oms-community.components.ViewObj.DelObject.Remove">Remove</UI-TERM>**.  <li>To remove all migration objects:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.Detail.components.MigrationSteps.Determine">OK</UI-TERM>**.  </ul>   |

6. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM>Migration Type</UI-TERM>** page, configure the parameters.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The following parameters are displayed only if you have selected <b>Full Migration</b> on the <b>Select Migration Type</b> page. </p>
      </main>

      |   Parameter   |     Description    |
      |----|----------------------------------|
      | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The amount of resources to be consumed by a full migration task varies based on the migration performance. If you select **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |
      | Handle Non-empty Tables in Target Database | Valid values: **<UI-TERM>Ignore</UI-TERM>** and **<UI-TERM>Stop Migration</UI-TERM>**.<ul><li>If you select **<UI-TERM>Ignore</UI-TERM>**, when the data to be inserted conflicts with the existing data of a target table, OMS Community Edition retains the existing data and records the conflict data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, data is pulled in IN mode for full verification. In this case, the scenario where the target contains more data than the source cannot be verified, and the verification efficiency will be decreased. </p></main></li><li>If you select **<UI-TERM>Stop Migration</UI-TERM>** and a target table contains data, an error is returned during full migration, indicating that the migration is not allowed. In this case, you must clear the data in the target table before you can continue with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>After an error is returned, if you click **<UI-TERM>Resume</UI-TERM>** in the dialog box, OMS Community Edition ignores this error and continues to migrate data. Proceed with caution. </p></main></li> </ul>|
      | Writing Method | Valid values: **SQL** (specifies to write data to tables by using `INSERT` or `REPLACE`) and **Direct Load** (specifies to write data through direct load). At present, you cannot write vector data by using direct load. |

      To view or modify parameters of the full migration component Full-Import, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md). The following table describes the parameters of the Qdrant data source.

      |   Parameter   |     Description    |
      |--------------|---------------|
      | qdrantId | The ID column of the Qdrant data source mapped to OceanBase Database Community Edition. The default value is `id`. |
      | qdrantVector | The vector column of the Qdrant data source mapped to OceanBase Database Community Edition. The default value is `vec`. |
      | qdrantCollectionName | By default, this parameter is left empty. If you specify this parameter, enter the target column name. |

7. Click **<UI-TERM key="oms-community.Migration.New.Precheck">Precheck</UI-TERM>** to start a precheck on the data migration task.

   During the precheck, OMS Community Edition checks database network connectivity and other items as needed. A data migration task can be started only after it passes all check items. If an error is returned during the precheck, you can perform the following operations:

   * Identify and troubleshoot the problem and then perform the precheck again.

   * Click **<UI-TERM key="oms-community.components.SyncSwitch.PreCheckSubStep.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.Detail.components.SyncMonitorDrawer.Operation">Actions</UI-TERM>** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.components.TreeTransfer.TargetNode.Determine">OK</UI-TERM>**.

8. Click **<UI-TERM key="oms-community.Sync.New.StartATask">Start Task</UI-TERM>**. If you do not need to start the task now, click **<UI-TERM key="oms-community.Endpoint.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can start the task later as needed.

      OMS Community Edition allows you to modify the migration objects when the data migration task is running. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it is executed based on the selected migration types. For more information, see the **<UI-TERM>Migration Details</UI-TERM>** section in the [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) topic.
