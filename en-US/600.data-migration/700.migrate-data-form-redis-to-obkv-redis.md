# Migrate data from a Redis database to an OBKV-Redis database

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a Redis database to an OBKV-Redis database.

## Limitations

* At present, OMS Community Edition supports only full migration from a Redis database to an OBKV-Redis database.

* Redis 2.8.0 and later are supported.

## Considerations

* If the target OBKV-Redis database does not support the data types of source columns, OMS Community Edition uniformly converts the columns into strings.

* If a full migration task is interrupted, duplicate list data appears after you restart the task.

## Procedure

1. Create a data migration task.

   1. Log in to the console of OMS Community Edition.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.components.CustomizedTable.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Migration Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM>Select Source and Target</UI-TERM>** page, configure the parameters.

   | Parameter | Description |
   |--------|------------------------------------------------|
   | Data Migration Task Name | We recommend that you set it to a combination of digits and letters. It must not contain any spaces and cannot exceed 64 characters in length.                                                                                                                                                 |
   | Tag (Optional)      | Click the field and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Use tags to manage data migration tasks](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                                                            |
   | Source     | If you have created a Redis data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create a Redis data source](../800.create-and-manage-data-sources/100.create-a-data-source/1300.create-a-redis-data-source.md).                          |
   | Target    | If you have created an OBKV-Redis data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right.   |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is started, OMS Community Edition migrates the existing data of tables in the source database to corresponding tables in the target database.

4. Click **<UI-TERM key="oms-community.components.ViewObj.AddObject.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** to specify the migration objects. The following procedure describes how to specify migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For information about the procedure for specifying migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** option, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li>
   <p>The names of tables to be migrated, as well as the names of columns in the tables, must not contain Chinese characters. </p>
   </li>
   <li>
   <p>If a database or table name contains double dollar signs (&quot;$$&quot;), you cannot create the migration task. </p>
   </li>
   </ul>
   </main>

     OMS Community Edition also allows you to rename objects, set row filters, view column information, and remove a single migration object or all migration objects.

     | Operation | Description |
     |---------|---------------------------------------------------------------------------------------------------|
     | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename a database table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).  <br>Note that the new table name must also be in the format of `TableName$ColumnFamilyName`.                     |
     | Configure settings | OMS Community Edition allows you to filter rows by using `WHERE` conditions. For more information, see [Use SQL conditions to filter data](../600.data-migration/1600.migration-function-introduction/600.migration-row-filters.md). <br>You can also view column information of the migration objects in the **<UI-TERM key="oms-community.biz.ETL.ETLDescription.ViewColumns">View Column</UI-TERM>** section.                      |
     | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be migrated to the target database during data mapping. <ul><li>To remove a single migration object:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, move the pointer over the target object and click **<UI-TERM key="oms-community.components.PreCheck.PreCheckTable.Remove">Remove</UI-TERM>**.  <li>To remove all migration objects:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>**.  </ul>   |

5. Click **<UI-TERM key="oms-community.components.ViewObj.AddObject.NextStep">Next</UI-TERM>**. On the **Migration Options** page, configure the parameters for full migration.

    |   Parameter   |     Description    |
    |----|----------------------------------|
    | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The amount of resources to be consumed by a full migration task varies based on the migration performance. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |

    To view or modify parameters of the full migration component Full-Import, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md).

6. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to start a precheck on the data migration task.

   During the precheck, OMS Community Edition checks the read and write privileges of the database users and the network connectivity of the databases. A data migration task can be started only after it passes all check items. If an error is returned during the precheck, you can perform the following operations:

   * Identify and troubleshoot the problem and then perform the precheck again.

   * Click **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.components.MigrationPreTable.Operation">Actions</UI-TERM>** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.Operator.Connector.useConnectorAction.Update">OK</UI-TERM>**.

7. Click **<UI-TERM key="oms-community.components.MigrationPreTable.StartAProject">Start Task</UI-TERM>**. If you do not need to start the task now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can start the task later as needed.

      OMS Community Edition allows you to modify the migration objects when the data migration task is running. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it is executed based on the selected migration types. For more information, see the **</UI-TERM>Migration Details</UI-TERM>** section in the [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) topic.
