# Migrate data from a Hive database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a Hive database to OceanBase Database Community Edition.

## Background information

OMS Community Edition allows you to migrate data from a Hive database in the following modes:

* Hive external table mode, where you can migrate data from a Hive database to OceanBase Database Community Edition by using Hive external tables.

* Spark local mode, where you can start a Spark container in the migration process of OMS Community Edition and migrate data from a Hive database to OceanBase Database Community Edition in the Spark container.

* Spark cluster mode, where the migration process of OMS Community Edition submits a data migration task to a Spark cluster to migrate data from a Hive database to OceanBase Database Community Edition.

## Limitations

* **Limitations on the source database:**

   **Do not perform DDL operations that modify database or table schemas during full migration. Otherwise, the data migration task may be interrupted.**

* At present, OMS Community Edition supports only Hive 3.1.3.

* At present, OMS Community Edition supports only full migration from a Hive database to OceanBase Database Community Edition.

* The data source identifiers and user accounts must be globally unique in OMS Community Edition.

* OMS Community Edition supports the migration of only objects whose database name, table name, and column name are ASCII-encoded without special characters. The special characters are line breaks and <code>| " ' ` ( ) = ; / &</code>.

* To ensure the performance of a data migration task, we recommend that you migrate no more than 1,000 tables at a time.

## Data type mappings

|    Hive database     | OceanBase Database Community Edition |
|----------------|------------------------------------|
| TINYINT      |       TINYINT                      |
| SMALLINT      |       SMALLINT                     |
| INT            |       INT                          |
| BIGINT         |        BIGINT                      |
| BOOLEAN <br>Valid values: `true` and `false`.   |        BOOLEAN/TINYINT(1)    <br>Valid values: `0` and `1`.           |
| FLOAT         |       FLOAT                        |
| DOUBLE         |        DOUBLE                    |
| DECIMAL      |       DECIMAL                     |
| STRING        |       LONGTEXT/TINYTEXT/MEDIUMTEXT/TEXT/VARCHAR/CHAR <br>You can select from the supported mapped-to data types in OceanBase Database Community Edition as needed.                       |
| VARCHAR      |       VARCHAR                     |
| CHAR      |          CHAR                  |
| TIMESTAMP      |       TIMESTAMP                     |
| TIMESTAMP WITH LOCAL TIME ZONE      |  TIMESTAMP  <ul><li>Hive supports this data type in external table mode, but will discard the time zone information. To retain the time zone information, replace the TIMESTAMP data type with the VARCHAR data type in OceanBase Database Community Edition. <li>Hive does not support this data type in Spark local mode or Spark cluster mode. </ul> |
|  DATE     |    DATE                        |
|  BINARY     |  <ul><li>BINARY: A maximum of 255 bytes are supported. <li>TINYBLOB: A maximum of 255 bytes are supported. <li>BLOB: A maximum of 65,535 bytes (approximately 64 KB) are supported. <li>MEDIUMBLOB: A maximum of 16,777,215 bytes (approximately 16 MB) are supported. <li>LONGBLOB: A maximum of 4,294,967,295 bytes (approximately 4 GB) are supported. </ul> |
|  STRUCT    |     JSON  <br>Hive supports this data type in external table mode. For example, data of the STRUCT<field1:STRING, field2:INT> type follows a format similar to ["example",42].                   |
| MAP      |   JSON <br>Hive supports this data type in external table mode. For example, data of the MAP<STRING, INT> type follows a format similar to {"key1":1,"key2":2}.                        |
| ARRAY     |   JSON  <br>Hive supports this data type in external table mode. For example, data of the ARRAY\<STRING> type follows a format similar to ["item1","item2","item3"].                       |
| UNIONTYPE      |   JSON <br>Hive supports this data type in external table mode. For example, {1:9.9} in a Hive database is converted to {"tag": 1, "object": 9.9} after migration to OceanBase Database Community Edition.                        |

## Procedure

1. Create a data migration task.

   1. Log in to the console of OMS Community Edition.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.New.components.EndpointForm.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">New Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination">Select Source and Target</UI-TERM>** page, configure the parameters.

   |   Parameter   |     Description    |
   |--------|-----------------------------------------------------------|
   | Data Migration Task Name | We recommend that you set it to a combination of digits and letters. It must not contain any spaces and cannot exceed 64 characters in length.                                                                                                                                 |
   | Tag (Optional)      | Click the field and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Use tags to manage data migration tasks](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).                                            |
   | Source     | If you have created a Hive data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create a Hive data source](../800.create-and-manage-data-sources/100.create-a-data-source/1400.create-hive-data-source.md). |
   | Target   | If you have created an OceanBase-CE data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information about the parameters, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).                                    |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is started, OMS Community Edition migrates the existing data of tables in the source database to corresponding tables in the target database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** to specify the migration objects. The following procedure describes how to specify migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For information about the procedure for specifying migration objects by using the **Match Rules** option, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of a table to be migrated, as well as the names of columns in the table, must not contain Chinese characters. </p>
      </li>
      <li>
      <p>If a database or table name contains double dollar signs (&quot;$$&quot;), you cannot create the migration task. </p>
      </li>
      </ul>

      1. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list. You can select tables and views of one or more databases as the migration objects.

      3. Click **\>** to add the selected objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When you migrate data from a Hive database to OceanBase Database Community Edition, OMS Community Edition allows you to import objects from text, rename objects, and remove one or all migration objects.

     |   Operation    |                                                    Description                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects      | <ol><li> In the right-side pane of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li>In the dialog box that appears, click **<UI-TERM key="oms-community.components.ETL.ETLFormDrawer.Determine">OK</UI-TERM>**. <br>**Notice**<br>This operation will overwrite previous selections. Proceed with caution.  <li>In the **Import Objects** dialog box, import the objects to be migrated. <br>You can import CSV files to rename databases/tables. For more information, see [Download and import the settings of migration objects](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li>Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li>After the validation succeeds, click **<UI-TERM key="oms-community.Endpoint.New.Add">OK</UI-TERM>**. </ol>    |
     | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename a database table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be migrated to the target database during data mapping. <ul><li>To remove a single migration object:<br>In the right-side pane of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, move the pointer over the target object and click **<UI-TERM key="oms-community.EndpointPublic.components.KafkaForm.Remove">Remove</UI-TERM>**.  <li>To remove all migration objects:<br>In the right-side pane of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.components.FullValidation.UpdateValidatingSqlDrawer.Determine">OK</UI-TERM>**.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.MigrationOptions">Migration Options</UI-TERM>** page, configure the parameters.

The resources consumed by a full migration task depends on the migration performance. If you select **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |
      | Handle Non-empty Tables in Target Database | Valid values: **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**.<ul><li>If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, when the data to be inserted conflicts with the existing data of a target table, OMS Community Edition retains the existing data and records the conflict data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, data is pulled in IN mode for full verification.       To view or modify parameters of the full migration component Full-Import, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md).

7. Click **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** to start a precheck on the data migration task.

   During the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** stage, OMS Community Edition checks database network connectivity and other items as needed. A data migration task can be started only after it passes all check items. If an error is returned during the precheck, you can perform the following operations:

   * Identify and troubleshoot the issue and then perform the precheck again.

   * Click **<UI-TERM key="oms-community.Sync.constants.Skip">Skip</UI-TERM>** in the **Actions** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.Operator.Connector.StartConnectorModal.StartConfirm">OK</UI-TERM>**.

8. Click **<UI-TERM key="oms-community.Sync.New.StartATask">Start Task</UI-TERM>**. If you do not need to start the task now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the task. You can start the task later as needed.

      OMS Community Edition allows you to modify the migration objects when the data migration task is running. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it is executed based on the selected migration types. For more information, see the **View migration details** section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
