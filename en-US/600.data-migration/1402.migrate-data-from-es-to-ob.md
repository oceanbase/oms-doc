# Migrate data from an ElasticSearch database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from an ElasticSearch database to OceanBase Database Community Edition.

## Limitations

* **Limitations on the source database**

   **Do not perform DDL operations that change database or schema structures during full data migration. Otherwise, the data migration task may be interrupted.**

* Only full data migration is supported when you migrate data from an ElasticSearch database to an OceanBase Community Edition database.

* Data source identifiers and user accounts must be unique in the OMS system.

* OMS Community Edition only supports migrating databases, tables, and column objects with ASCII-compliant names that do not contain special characters (|"'`()=;/& and spaces).

* We recommend that you do not migrate more than 1,000 tables at a time to avoid impacting the migration task.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Migration Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM>Select Source and Destination</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Task Name | We recommend that you use Chinese, English, and numbers. The task name cannot contain spaces and must be 64 characters or less.  |
    | Tag     | Click the field and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source     | If you have created an ElasticSearch data source, select one from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list. The right-side dialog box allows you to create a data source. For more information, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md).|
    | Destination    | If you have created an OceanBase Community Edition data source, select one from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list. The right-side dialog box allows you to create a data source. For more information, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

   After the full migration starts, OMS Community Edition migrates the existing data in the source table to the corresponding table in the destination database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and scope.

   You can select migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** options. This topic describes the procedure for selecting migration objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For information about how to configure matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of a table to be migrated, as well as the names of columns in the table, must not contain Chinese characters. </p>
      </li>
      <li>
      <p>If the name of a database or table contains the characters &quot;$$&quot;, the data migration task cannot be created. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the source objects to migrate in the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the selected objects to the **<UI-TERM>Target Object(s)</UI-TERM>** list.

     When you migrate data from an ElasticSearch database to an OceanBase Community Edition database, OMS Community Edition allows you to import objects by using text, rename objects, and remove one or all migration objects.

     |   Operation    |                                                    Procedure                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li>In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice**: <br> The import operation will overwrite the previous selection. Proceed with caution.  <li>In the **Import Migration Objects** dialog box, import the objects to be migrated. <br>You can rename the database and tables by importing a CSV file. For more information, see [Download and import settings of migration objects](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li>Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li>After the validation succeeds, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.</ol>    |
     | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename database and table objects](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove objects | OMS Community Edition allows you to remove one or more selected objects from the destination database during data mapping. <ul><li>Remove a single migration object <br>In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the target object and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** in the drop-down list.  <li> Remove all migration objects <br>In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The parameters described below will only be displayed after you select <b>Full Migration</b> on the <b>Select Migration Type</b> page. </p>
      </main>

    |Parameter|Description|
    |----|----------------------------------|
    | Concurrency | Valid values: **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of a full migration task varies with the concurrency speed. The resources required for a full migration task also vary with the concurrency speed. If you set the concurrency speed to **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set the **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** parameters based on your business requirements. |
    | Handling strategy when the destination object contains records | Valid values: **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li>If you set the value to **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, OMS Community Edition will log the conflicting data and retain the original data when original data conflicts with data to be written to the table during full verification. <main id="notice" type='notice'><h4>Notice</h4><p>If you set the value to <b>Ignore</b>, full verification will use the IN mode to fetch data, which cannot detect cases where the destination contains data not present in the source, and the verification performance will be degraded to some extent.</p></main></li><li>If you set the value to **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, OMS Community Edition will report an error and stop migration when the destination contains data. Make sure that the destination data is properly handled before you continue the migration. <main id="notice" type='notice'><h4>Notice</h4><p>If you click Resume after an error occurs, OMS Community Edition will ignore this setting and continue to migrate table data. Proceed with caution.</p></main></li> </ul>|
    | Write Method | Valid values: **SQL**, which means to write data to tables by using `INSERT` or `REPLACE` statements, and **Direct Load**, which means to write data to tables by using direct load. At present, data of vector types cannot be written to tables by using the direct load method. |

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** > **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner. For more information about the parameters, see [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md).
