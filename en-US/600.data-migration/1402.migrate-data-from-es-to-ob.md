# Migrate data from an ElasticSearch database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from an ElasticSearch database to OceanBase Database Community Edition.

## Limitations

* **Limitations on operations of the source database**

   **Do not perform DDL operations for database or schema changes during full migration. Otherwise, data migration tasks may be interrupted.**

* At present, data migration from an ElasticSearch database to OceanBase Database Community Edition is supported only for full migration.

* Data source identifiers and user accounts must be globally unique in OMS.

* OMS Community Edition supports only migrating databases, tables, and column objects with ASCII-compliant names that do not contain special characters (|"'`()=;/& and line breaks).

* We recommend that you do not migrate more than 1,000 tables at a time to avoid affecting the operation of data migration tasks.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Migration Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, numbers, and letters. The name must not contain spaces and must be less than 64 characters in length.  |
    | Tag     | Click the field and select the target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete a tag. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source  | If you have created an ElasticSearch data source, select it from the drop-down list. If you have not created one, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md).|
    | Destination | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If you have not created one, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is created, OMS Community Edition migrates the existing data in the source database tables to the corresponding tables in the destination database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration object and migration scope.

   You can select the migration object from **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select the migration object from **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure the matching rules, see [Configure the matching rules for a migration object](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of a table to be migrated and the names of columns in the table must not contain Chinese characters. </p>
      </li>
      <li>
      <p>If the name of a database or table contains the "$$" character, the data migration task cannot be created. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the migration object from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the migration object to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target  Object(s)</UI-TERM>** list.

     When you migrate data from an ElasticSearch database to OceanBase Database Community Edition, OMS Community Edition allows you to import objects, rename objects, and remove one or more migration objects.

     |   Operation    |                                                    Steps                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner of the right-side list.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite the previously selected objects. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br>You can also rename databases and tables by importing CSV files. For more information, see [Download and import the settings of a migration object](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the objects pass the validation, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.  </ol>    |
     | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS Community Edition allows you to remove one or more objects temporarily selected for migration to the destination database during data mapping. <ul><li> Remove a single migration object <br> Hover the pointer over the destination object in the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** to remove the migration object.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The following parameters are displayed only if you select <b>Full Migration</b> on the <b>Select Migration Type</b> page. </p>
      </main>

    |Parameter|Description|
    |----|----------------------------------|
    | Concurrency | The options are **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of a full migration task varies depending on the migration objects. The resources required for a full migration task also vary depending on the migration objects. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on the actual situation. |
    | Handling Strategy When a Destination Object Already Exists | The options are **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**: <ul><li> If you select **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, when the destination table contains data, OMS Community Edition writes data to the destination table by recording the conflicting data in the log and retaining the original data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, full verification uses the IN mode to pull data, which means that the scenario where the destination contains data not in the source cannot be verified, and the verification performance will be significantly degraded. </p></main></li><li> If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, when the destination table contains data, a full migration task will report an error indicating that migration is not allowed. Proceed to handle the destination data before you continue with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>If you click Restore after an error occurs, OMS Community Edition will ignore this configuration option and continue to migrate the table data. Proceed with caution. </p></main></li> </ul>|
    | Write Method | The options are **SQL** (data is written to a table by using `INSERT` or `REPLACE`) and **Direct Load** (data is written to a table by using direct load). At present, direct load is not supported for vector data. |

    If you need to view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md).

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to perform a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** section, OMS Community Edition checks whether the network connection to the database meets the requirements. You can start a data migration task only after all the check items pass. If an error is returned during the precheck:

   * You can troubleshoot and fix the error, and then perform the precheck again until the precheck succeeds.

   * You can click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the operation column of the error precheck item. A dialog box appears, prompting you to confirm whether to skip this operation. Click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box to confirm.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>** to start the data migration task. If you do not need to start the task now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects in a data migration task during the migration. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it executes based on the migration type you selected. For more information, see the "View migration details" section in [View the details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
