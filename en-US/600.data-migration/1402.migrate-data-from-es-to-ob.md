# Migrate data from an ElasticSearch database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from an ElasticSearch database to OceanBase Database Community Edition.

## Background information

OMS Community Edition V4.2.13-CE and later support incremental synchronization from an ElasticSearch database to OceanBase Community Edition by using the Translog plugin or _seq_no pagination query. If you have installed the Translog plugin in your ElasticSearch cluster, you can obtain DELETE data. However, you must restart the ElasticSearch cluster and enable the `index.soft_deletes.enabled` parameter to retain historical operations for Translog tracing. If you have not installed the Translog plugin in your ElasticSearch cluster, you cannot obtain DELETE data.

### Plugin installation

```shell
# After you install the plugin, you can obtain DELETE data during incremental synchronization.
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-7x-7.6.2.zip
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-8x-8.8.1.zip

# View the installed plugins.
bin/elasticsearch-plugin list
# The plugin names are as follows.
oms-es-ccr-plugin-7x
oms-es-ccr-plugin-8x

# After you install the plugin, you must restart the ElasticSearch server.
```

## Limitations

* **Limitations on operations in the source database**

   **Do not perform DDL operations such as schema changes on the source database during full migration. Otherwise, the data migration task may be interrupted.**

* Currently, data migration from an ElasticSearch database to OceanBase Community Edition supports only full migration and incremental synchronization of DML operations.

* Currently, ElasticSearch databases of versions V7.x and V8.x are supported.

* Data source identifiers and user accounts must be globally unique in the OMS system.

* OMS Community Edition supports only migration of databases, tables, and columns whose names are ASCII characters and do not contain special characters (spaces, line breaks, or |"'`()=;/&).

* We recommend that you migrate no more than 1,000 tables in one go to avoid affecting the running of the data migration task.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    | Parameter | Description |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and must be no longer than 64 characters.  |
    | Tag     | Click the text box and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source | If you have created an ElasticSearch data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears. For more information, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md).|
    | Destination    | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type | Description |
   |------|------------------------|
   | Full Migration | After a full migration task starts, OMS Community Edition migrates the existing data of the source database tables to the corresponding tables in the destination database.|
   | Incremental Synchronization | After an incremental synchronization task starts, OMS Community Edition synchronizes the data that has changed in the source database (new, modified, or deleted) to the corresponding tables in the destination database.<br>**<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** has **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>**, which includes `Insert`, `Delete`, and `Update`. You can select the required option based on your needs. For more information, see [DML filtering](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md). |

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and migration scope.

   You can select migration objects from **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select migration objects from **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of the table to be migrated and the names of the columns in the table cannot contain Chinese characters. </p>
      </li>
      <li>
      <p>If the database name or table name contains the &quot;$$&quot; character, the creation of the data migration task is affected. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **>** to add the selected objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can rename databases and tables by importing a CSV file.      | Rename     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS Community Edition allows you to remove individual or multiple objects temporarily selected to the target database. <ul><li> Remove a single migration object <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the target object and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>**.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>**.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. To view or modify the parameters of the incremental synchronization component, click **<UI-TERM>Store Configuration Details</UI-TERM>** or **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** section. For more information about the parameters, see the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) module.

    * Full migration

The performance of full migration varies, and the resources required for full migration tasks also vary. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|

    * Incremental synchronization

      On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** to display the following parameters.

      |Parameter|Description|
      |----|----------------------------------|
      |Concurrency| Includes **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of incremental synchronization varies, and the resources required for incremental synchronization tasks also vary. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|
      |Incremental Synchronization Start Time| <ul><li> If you selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, this parameter is not displayed.   <li> If you did not select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, but selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**, please specify the migration of data after a specific time point. The default value is the current system time. For more information, see [Set the incremental synchronization start time](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |
      |Incremental Record Retention Time| The duration for which incremental parsing files are cached in OMS Community Edition. The longer the retention time, the more disk space the OMS Community Edition Store component consumes.  |

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to precheck the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS Community Edition checks whether the network connection to the database meets the requirements. You can start the data migration task only after all precheck tasks are completed. If an error is reported during the precheck:

   * You can troubleshoot and fix the issue, and then re-execute the precheck until it succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column of the error pre-check item. A dialog box pops up to prompt you of the specific impact of skipping this operation. After you confirm that you can skip this operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not need to start the task for now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>**. The system jumps to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects during the execution of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, the system executes the task based on the selected migration type. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
