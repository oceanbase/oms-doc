# Migrate data from an ElasticSearch database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from an ElasticSearch database to OceanBase Database Community Edition.

## Background information

OMS Community Edition V4.2.13-CE and later versions support incremental synchronization from an ElasticSearch database to OceanBase Database Community Edition by installing the Translog plugin or using _seq_no pagination. If you have installed the Translog plugin in your ElasticSearch cluster, you can obtain DELETE data. However, you must restart the ElasticSearch cluster and enable the `index.soft_deletes.enabled` parameter to retain historical operations for Translog tracing. If you have not installed the Translog plugin in your ElasticSearch cluster, you cannot obtain DELETE data.

### Plugin installation

```shell
# After installing the plugin, incremental synchronization can obtain DELETE data
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-7x-7.6.2.zip
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-8x-8.8.1.zip

# View the installed plugins
bin/elasticsearch-plugin list
# The plugin name of OMS is as follows
oms-es-ccr-plugin-7x
oms-es-ccr-plugin-8x

# After the plugin is installed, you need to restart the ElasticSearch server
```

## Limitations

* **Limitations on operations in the source database**

   **Do not perform DDL operations that modify database or table schemas during full migration. Otherwise, the data migration task may be interrupted.**

* At present, data migration tasks from an ElasticSearch database to OceanBase Database Community Edition support only full migration and incremental synchronization DML.

* The supported versions of Elasticsearch are V7.x and V8.x.

* Data source identifiers and user accounts must be globally unique in OMS.

* OMS Community Edition supports migrating databases, tables, and columns with ASCII-compliant names that do not contain special characters (spaces, line breaks, or |"'`()=;/&).

* We recommend that you migrate no more than 1,000 tables at a time to avoid impacting the data migration task.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM>Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    |   Parameter   |                             Description                                                      |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, numbers, and letters. The name must not contain spaces and must not exceed 64 characters in length.  |
    | Tag     | Click the field and select the target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete a tag. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source  | If you have created an ElasticSearch data source, select it from the drop-down list. If you have not created one, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md).|
    | Target | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If you have not created one, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   Options of **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type |      Description            |
   |------|------------------------|
   | Full Migration | After a full migration task is created, OMS Community Edition migrates the existing data in the source database tables to the corresponding tables in the target database.|
   | Incremental Synchronization | After an incremental synchronization task is created, OMS Community Edition synchronizes the data that has changed in the source database (newly added, modified, or deleted data) to the corresponding tables in the target database.<br>**<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** DMLs include `Insert`, `Delete`, and `Update`. You can select as needed. For more information, see [DML Filtering](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md). |

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration object and migration scope.

   You can select the migration object from **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select the migration object from **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**. For more information about how to configure matching rules, see [Configure matching rules for a migration object](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of a table to be migrated, as well as the names of columns in the table, must not contain Chinese characters. </p>
      </li>
      <li>
      <p>If the name of a database or table contains the characters "$$", an error occurs when you create a data migration task. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the migration object from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the migration object to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When you migrate data from an ElasticSearch database to OceanBase Database Community Edition, OMS Community Edition allows you to import objects, rename objects, and remove one or more migration objects.

     |   Operation    |                                                    Steps                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner of the right-side list.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite the previously selected objects. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br>You can also rename databases and tables by importing CSV files.      | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS Community Edition allows you to remove one or more objects temporarily selected for migration to the target database during data mapping. <ul><li> Remove a single migration object <br> Hover the pointer over the target object in the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** to remove the migration object.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

   To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. To view or modify the parameters of the incremental synchronization component, click **<UI-TERM>Store Configuration Details</UI-TERM>** or **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** section as needed. For more information about the parameters, see the documentation in the [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) module.

   * Full migration

      The following parameters are displayed only if you select <b>Full Migration</b> on the <b>Select Migration Type</b> page. </p>

      |Parameter|Description|
      |----|----------------------------------|
      | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of a full migration task varies depending on the migration objects. The resources required for a full migration task also vary depending on the migration objects. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on the actual situation. |
      | Processing Strategy When Records Exist in Target Object | Valid values: **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**.<ul><li>If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, when the data to be inserted conflicts with the existing data of a target table, OMS Community Edition retains the existing data and records the conflict data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, data is pulled in IN mode for full verification. In this case, the scenario where the target contains more data than the source cannot be verified, and the verification efficiency will be decreased. </p></main></li><li>If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>** and a target table contains data, an error is returned during full migration, indicating that the migration is not allowed. In this case, you must clear the data in the target table before you can continue with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>After an error is returned, if you click **<UI-TERM key="oms-community.Operation.constants.Recovery">Resume</UI-TERM>** in the dialog box, OMS Community Edition ignores this error and continues to migrate data. Proceed with caution. </p></main></li> </ul>|
      | Write Method | Valid values: **SQL** (data is written to a table by using `INSERT` or `REPLACE`) and **Direct Load** (data is written to a table by using direct load). At present, direct load is not supported for vector data. |

   * Incremental synchronization

      The following parameters are displayed only if you select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |Parameter|Description|
      |----|----------------------------------|
      | Concurrency Speed | The migration concurrency. Valid values: **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of incremental synchronization varies depending on the migration concurrency. The resources required for an incremental synchronization task vary depending on the migration concurrency. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>**.|
      | Incremental Synchronization Start Timestamp | <ul><li> If you have selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** as the migration type, this parameter is not displayed. <li> If you have selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** but not **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**, specify the data to be migrated after a specific point in time. The default value is the current system time. For more information, see [Set the incremental synchronization point in time](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |
      | Incremental Record Retention Time | The duration that incremental parsed files are cached in OMS Community Edition. A longer retention period results in more disk space occupied by the Store component of OMS Community Edition.|

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to perform a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** section, OMS Community Edition checks whether the network connection to the database meets the requirements. You can start a data migration task only after all the check items pass. If an error is returned during the precheck:

   * You can troubleshoot and fix the error, and then perform the precheck again until the precheck succeeds.

   * Click **<UI-TERM key="oms-community.components.BatchSelect.BatchActions.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.Operation.Connector.Operation">Actions</UI-TERM>** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">OK</UI-TERM>**.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>** to start the data migration task. If you do not need to start the task now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects in a data migration task during the migration. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it executes based on the migration type you selected. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
