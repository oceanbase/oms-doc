# Migrate data from an ElasticSearch database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from an ElasticSearch database to OceanBase Database Community Edition.

## Background information

OMS Community Edition V4.2.13-CE and later versions support incremental synchronization from an ElasticSearch database to OceanBase Database Community Edition through two methods: installing the Translog plugin and using _seq_no pagination queries. If you have installed the Translog plugin in your ElasticSearch cluster, you can retrieve DELETE data. However, you must restart the ElasticSearch cluster and enable `index.soft_deletes.enabled` to retain historical operations for Translog tracking. If the Translog plugin is not installed in the ElasticSearch cluster, DELETE data cannot be retrieved.

### Plugin installation method

```shell
# After the plugin is installed, incremental synchronization can retrieve DELETE data.
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-7x-7.6.2.zip
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-8x-8.8.1.zip
bin/elasticsearch-plugin install file:///data/1/soft/oms-es-ccr-plugin-9x-9.4.3.zip

# View Installed Plugins
bin/elasticsearch-plugin list
# The plugin names of OMS are as follows:
oms-es-ccr-plugin-7x
oms-es-ccr-plugin-8x
oms-es-ccr-plugin-9x

# After the plugin is installed, you need to restart the ElasticSearch server.
```

## Limitations

* **Limitations on the source database**

   **Do not perform DDL operations that modify database or table schemas during schema migration or full migration. Otherwise, the data migration task may be interrupted.**

* Currently, data migration tasks from an ElasticSearch database to OceanBase Database Community Edition support schema migration, full migration, full verification, and incremental synchronization.

* Currently supported Elasticsearch database versions are V7.x, V8.x, and V9.x.

* Data source identifiers and user accounts must be globally unique within the OMS system.

* OMS Community Edition only supports migrating objects whose database, table, and column names are ASCII-compliant and do not contain special characters (including line breaks, spaces, and |"'`()=;/&).

* It is recommended that you do not migrate more than 1,000 tables at a time to avoid impacting the operation of the data migration task.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    | Parameter | Description |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | It is recommended to use a combination of Chinese characters, numbers, and letters. The name cannot contain spaces and must not exceed 64 characters in length. |
    | Tag | Click the text box and select a target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md). |
    | Source | If you have created an ElasticSearch data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one in the dialog box on the right. For parameter details, see [Create an ElasticSearch data source](../800.create-and-manage-data-sources/100.create-a-data-source/1500.create-es-data-source.md). |
    | Destination | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one in the dialog box on the right. For parameter details, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md). |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">Schema Migration</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>**, **<UI-TERM key="oms-community.Operation.constants.FullVerification">Full Verification</UI-TERM>**, and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type | Description |
   |------|------------------------|
   | Schema Migration | After a schema migration task starts, OMS Community Edition migrates the data object definitions (such as tables, indexes, constraints, comments, and views) from the source database to the destination database and automatically filters out temporary tables.<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">Manual Table Schema Adjustment Required</UI-TERM>**: OMS Community Edition supports user-defined table structures. Select this option if you need to manually adjust the table structure. The schema migration will only retrieve the SQL for the table structure and start execution after you make the modifications. |
   | Full Migration | After a full migration task starts, OMS Community Edition migrates the existing data from the source database tables to the corresponding tables in the destination database. |
   | Incremental Synchronization | After an incremental synchronization task starts, OMS Community Edition synchronizes the changed data (inserts, modifications, or deletions) from the source database to the corresponding tables in the destination database.<br>The **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>** option of **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** includes `INSERT`, `DELETE`, and `UPDATE`. You can choose the appropriate option based on your requirements. For more information, see [DML filtering](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md). |
   | Full Verification | After full migration is completed and incremental data is synchronized to the destination and is roughly caught up with the source, OMS Community Edition automatically initiates a full data verification task for the data tables configured in the source and destination databases.<ul><li>If you select **<UI-TERM key="oms-community.Sync.constants.FullVerification">Full Verification</UI-TERM>**, we recommend that you collect statistics from OceanBase Database Community Edition on both the source and destination before full verification starts. For more information, see [Collect statistics manually](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001379954).</li><li>If you selected **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** and not all DML options are selected for **<UI-TERM key="oms-community.components.DBVerbTypeCheckGroup.DataChangeDml">DML Synchronization</UI-TERM>**, OMS Community Edition does not support full data verification in this scenario.</li></ul> |

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to have the system perform a precheck on the data migration task.

   During the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS Community Edition checks whether the database's network connection meets requirements. The data migration task can only be started after all checks pass. If the precheck reports an error:

   * You can troubleshoot and resolve the issue, then re-execute the precheck until it succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column for the erroneous precheck item. A dialog box appears, explaining the specific impact of skipping this operation. After confirming it is okay to skip, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not need to start the task immediately, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the data migration task details page, where you can start it manually later.

      OMS Community Edition supports modifying migration objects during the execution of a data migration task. For details, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, it is executed sequentially based on the selected migration type. For details, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
