# Migrate data from a Doris database to OceanBase Database

This topic describes how to migrate data from a Doris database to OceanBase Database by using OceanBase Migration Service (OMS) Community Edition.

## Limitations

* **Limitations on the source database**

   **Do not perform DDL operations that change the schema of a database or table during full data migration. Otherwise, the data migration task may be interrupted.**

* At present, only full data migration is supported from a Doris database to OceanBase Database Community Edition.

* OMS Community Edition supports Doris databases of V1.x and later.

* Data source identifiers and user accounts must be globally unique within the OMS Community Edition system.

* OMS Community Edition supports only databases, tables, and columns with ASCII-compliant names that do not contain special characters (|"'`()=;/& and line breaks).

* We recommend that you migrate no more than 1,000 tables in a single migration task to avoid affecting the migration task.

## Considerations

After you set the timezone of a Doris database to +08:00, an error `invalid format: Fixed/UTC+08:00:00` may be returned when you query some system tables. OMS Community Edition sets `set time_zone = '+08:00'` when it generates component configurations and then queries the system tables for the error. If no error is returned, the default value of `source.timezone` is +08:00. If an error is returned, the default value of `source.timezone` is Asia/Shanghai.

## Data type mapping

|  Doris database  | OceanBase Database Community Edition  |
|----------------|-------------------|
| BOOLEAN  | BOOLEAN |
| TINYINT | TINYINT |
| SMALLINT | SMALLINT |
| INT | INT |
| BIGINT |  BIGINT |
| LARGEINT |  BIGINT UNSIGNED |
| FLOAT | FLOAT |
| DOUBLE |  DOUBLE |
| DECIMAL |  DECIMAL |
| DATE | DATE |
| DATETIME |  DATETIME |
| CHAR |  CHAR |
| VARCHAR |  VARCHAR |
| STRING | VARCHAR |
| ARRAY | ARRAY |
| MAP | VARCHAR |
| STRUCT |  JSON |
| JSON | JSON |
| VARIANT |  JSON |
| BITMAP | STRING <br>Use the `bitmap_to_string` function to read data from a Doris database, convert the data to a string, and write the data to OceanBase Database Community Edition. |
| HLL | BIGINT <br>Use the `hll_cardinality` function to read data from a Doris database, convert the data to an integer, and write the data to OceanBase Database Community Edition. |

## Procedure

1. Create a data migration task.

    1. Log in to the OMS Community Edition console.

    2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

    3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    | Parameter | Description |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name must not contain spaces and must be no longer than 64 characters.  |
    | Tag     | Click the text box and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md). |
    | Source  | If you have created a Doris data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create a Doris data source](../800.create-and-manage-data-sources/100.create-a-data-source/1800.create-doris-data-source.md). |
    | Destination    | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md). |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

   After a full migration task is started, OMS Community Edition migrates the existing data of the source database tables to the corresponding tables in the destination database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration object and migration scope.

   You can select the migration object from the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** sections. This topic describes how to select the migration object from the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** section. For more information about how to configure the matching rules, see [Configure the matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The names of the tables and columns to be migrated cannot contain Chinese characters. </p>
      </li>
      <li>
      <p>If the database name or table name contains the &quot;$$&quot; character, the creation of the data migration task is affected. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the selected objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When you migrate data from a Doris database to OceanBase Database Community Edition, OMS Community Edition allows you to import the migration objects as text, rename the migration objects, and remove individual or all migration objects.

     |   Action    |                                                    Procedure                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite previous selections. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can import a CSV file to perform operations such as renaming a database or table. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the legality check is passed, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS Community Edition supports renaming migration objects. For more information, see [Rename a database or table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS Community Edition supports removing a single or multiple objects temporarily selected to the target end during data mapping. <ul><li> Remove a single migration object <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the target object and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** to remove the migration object.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see the documentation in the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) module.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>On the <b>Choose Migration Type</b> page, the following parameters are displayed only when <b>Full Migration</b> is selected. </p>
      </main>

    |Parameter|Description|
    |----|----------------------------------|
    |Concurrent speed|The value can be **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, or **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of a full migration task and the resources required for the task vary. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can specify the **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** values.|
    |Handling strategy when target objects exist|The value can be **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** or **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li>Specify **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**. If the target table contains data and the data in the source table conflicts with the data to be written to the target table, OMS Community Edition writes the data in the source table to the target table and records the conflicting data in the log. <main id="notice" type='notice'><h4>Notice</h4><p>If you specify <b>Ignore</b>, full verification will pull data in IN mode, and cannot verify scenarios where the target table contains data that the source table does not contain. The verification performance will be degraded. </p></main></li><li>Specify **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**. If the target table contains data, an error is returned when you perform a full migration. You must resolve the error before you can continue the migration. <main id="notice" type='notice'><h4>Notice</h4><p>If you click Restore after an error occurs, OMS Community Edition ignores the configuration option and continues to migrate the table data. Proceed with caution. </p></main></li> </ul>|
    |Write mode|The value can be **SQL** (data is written to the table by using the `INSERT` or `REPLACE` statement) or **Direct Load** (data is written to the table by using direct load). At present, you cannot write vector data by using direct load.|

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>**. The system performs a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS Community Edition checks whether the network connection between the databases meets the requirements. A data migration task can be started only after all precheck tasks are completed. If an error is returned during the precheck:

   * You can resolve the error and re-execute the precheck until the precheck succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column of the error item. A dialog box pops up to prompt you of the impact of skipping the operation. After you confirm that you can skip the operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>**.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not want to start the task, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>**. The system jumps to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects during the execution of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, the task is executed based on the migration type you selected. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
