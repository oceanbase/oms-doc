# Migrate data from a ClickHouse database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a ClickHouse database to OceanBase Database Community Edition.

## Limitations

* **Limitations on the source database**

   **Do not perform DDL operations for schema changes on the source database during full migration. Otherwise, the data migration task may be interrupted.**

* At present, only full migration is supported for data migration tasks from a ClickHouse database to OceanBase Database Community Edition.

* At present, OMS Community Edition supports ClickHouse database V22.x and later.

* Data source identifiers and user accounts must be globally unique in OMS Community Edition.

* OMS Community Edition supports only migrating databases, tables, and columns with ASCII-compliant names that do not contain special characters (including line breaks, spaces, and |"'`()=;/&).

## Considerations

* We recommend that you migrate no more than 1,000 tables in one migration task. Otherwise, the data migration task may be affected.

* By default, OMS Community Edition slices data based on the primary key of a ClickHouse database. However, the primary key of a ClickHouse database is not unique. Therefore, duplicate data may be generated when you resume a suspended data migration task.

* In the external table mode, OMS Community Edition creates remote databases of OceanBase Database Community Edition named `omsext_xxx` in the ClickHouse database. After the data migration is completed, OMS Community Edition does not automatically delete the remote databases. You need to delete them manually.

## Procedure

1. Create a data migration task.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.src.constants.DataMigration">Data Migration</UI-TERM>** page, click **<UI-TERM>Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    | Parameter | Description |
    |--------------|------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and must be no longer than 64 characters. |
    | Tags | Click the text box and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md). |
    | Source | If you have created a ClickHouse data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create a ClickHouse data source](../800.create-and-manage-data-sources/100.create-a-data-source/1900.create-clickhouse-data-source.md). |
    | Target | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md). |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>**.

    After a full migration task is started, OMS Community Edition migrates the existing data in the source database to the corresponding tables in the target database.

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration object and migration scope.

    You can select the migration object by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** options. This topic describes how to select the migration object by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For more information about how to configure the matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of the table to be migrated and the names of the columns in the table cannot contain Chinese characters. </p>
      </li>
      <li>
      <p>If the database name or table name contains the &quot;$$&quot; character, the data migration task cannot be created. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the migration objects from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the migration objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

    When you migrate data from a ClickHouse database to OceanBase Database Community Edition, OMS Community Edition allows you to import objects by using text, rename objects, and remove one or all migration objects.

    |   Operation    | Description   |
    |---------|-------|
    | Import objects      | <ol><li>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.<li>In the dialog box that appears, click **<UI-TERM key="oms-community.Operator.JDBCWriter.useJDBCWriterAction.Update">OK</UI-TERM>**. <br>**Notice**<br> This operation will overwrite previous selections. Proceed with caution.  <li>In the **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** dialog box, import the objects to be migrated. <br>You can import CSV files to rename databases/tables and set row filtering conditions. For more information, see [Download and import the settings of migration objects](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).<li>Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.<li>After the validation succeeds, click **<UI-TERM key="oms-community.Detail.components.SyncSteps.Determine">OK</UI-TERM>**. </ol>    |
    | Rename objects     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename a database table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
    | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be migrated to the target database during data mapping. <ul><li>To remove a single migration object:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, move the pointer over the target object and click **<UI-TERM key="oms-community.components.ViewObj.DelObject.Remove">Remove</UI-TERM>**.  <li>To remove all migration objects:<br>In the list on the right of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.Detail.components.MigrationSteps.Determine">OK</UI-TERM>**.  </ul>   |

6. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. For more information about the parameters, see the [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) module.

    <main id="notice" type='notice'>
      <h4>Notice</h4>
      <p>The following parameters are displayed only if you select <b>Full Migration</b> on the <b>Select Migration Type</b> page. </p>
      </main>

    |Parameter|Description|
    |----|----------------------------------|
    | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The amount of resources to be consumed by a full migration task varies based on the migration performance. If you select **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |
    | Processing Strategy When Records Exist in Target Object | Valid values: **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**.<ul><li>If you select **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>**, when the data to be inserted conflicts with the existing data of a target table, OMS Community Edition retains the existing data and records the conflict data. <main id="notice" type='notice'><h4>Notice</h4><p>If you select <b>Ignore</b>, data is pulled in IN mode for full verification. In this case, the scenario where the target contains more data than the source cannot be verified, and the verification efficiency will be decreased. </p></main></li><li>If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>** and a target table contains data, an error is returned during full migration, indicating that the migration is not allowed. In this case, you must clear the data in the target table before you can continue with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>After an error is returned, if you click **<UI-TERM key="oms-community.Operation.constants.Recovery">Resume</UI-TERM>** in the dialog box, OMS Community Edition ignores this error and continues to migrate data. Proceed with caution. </p></main></li> </ul>|
    | Writing Method | Valid values: **SQL** (specifies to write data to tables by using `INSERT` or `REPLACE`) and **Direct Load** (specifies to write data through direct load). At present, you cannot write vector data by using direct load. |

7. Click **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>**. The system performs a precheck on the data migration task.

    In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS Community Edition checks whether the network connection between the databases meets the requirements. You can start a data migration task only after all precheck tasks are completed. If an error is returned during the precheck:

    * You can troubleshoot and resolve the issue, and then perform the precheck again until the precheck is successful.

    * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column of the error item. A dialog box pops up to prompt you of the impact of skipping the operation. After you confirm that you want to skip the operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>**.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not want to start the task now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>**. The system jumps to the details page of the data migration task. You can manually start the task as needed.

      OMS Community Edition allows you to modify the migration objects during the execution of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is initiated, the system executes the migration task based on the selected migration type. For more information, see the "View migration details" section in [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
