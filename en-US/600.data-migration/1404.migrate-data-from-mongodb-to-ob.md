# Migrate data from a MongoDB database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a MongoDB database to OceanBase Database Community Edition.

## Limitations

* **Limitations on the source database**

    **Do not perform DDL operations that modify database or table schemas during full migration. Otherwise, the data migration task may be interrupted.**

* Data migration tasks from a MongoDB database to OceanBase Database Community Edition currently support only full migration and incremental synchronization of DML operations.

* Currently supported MongoDB database versions are V3.x, V4.0.0, V4.4.6, V5.0.0, V6.0.0, V7.0.22, and V8.0.15.

* Data source identifiers and user accounts must be globally unique within the OMS system.

* OMS Community Edition only supports migrating objects whose database, table, and column names are in ASCII and do not contain special characters (including line breaks, spaces, and |"'`()=;/&).

* It is recommended that you do not migrate more than 1,000 tables at a time to avoid affecting the operation of the data migration task.

* Oplog must be enabled for MongoDB incremental migration.

* The MongoDB data source user must have read permission on the local database (for example, must have the read role applied to the local database) so that the incremental component can read from the local.oplog.rs file.

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Starting from version 7.0, MongoDB has stricter access controls for the local database. Even if a user has roles such as root, explicit read permission on local must be granted; otherwise, an "not authorized on local" error will be returned.</p>
    </main>

## Data type mappings

| MongoDB Database | OceanBase Database Community Edition |
| --------------- | ------------------ |
| double | double |
| string | string |
| object | text |
| array | text<br>array |
| binary data | binary |
| objectId | varchar |
| boolean | tinyint |
| date | datetime |
| regular expression | varchar |
| JavaScript | text |
| timestamp | timestamp |
| integer | bigint |
| decimal | decimal |

## Procedure

1. Create a data migration task.

    1. Log in to the OMS Community Edition console.

    2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

    3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    | Parameter | Description |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | It is recommended to use a combination of Chinese characters, numbers, and letters. The name cannot contain spaces and must not exceed 64 characters. |
    | Tag | Click the text box and select a target tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md). |
    | Source | If you have created a MongoDB data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one in the dialog box on the right. For parameter details, see [Create a MongoDB data source](../800.create-and-manage-data-sources/100.create-a-data-source/1600.create-mongodb-data-source.md). |
    | Destination | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list to create one in the dialog box on the right. For parameter details, see [Create an OceanBase-CE data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md). |

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

    The **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type | Description |
   |------|------------------------|
   | Full Migration | After a full migration task starts, OMS Community Edition migrates the existing data from the source database tables to the corresponding tables in the destination database. |
   | Incremental Synchronization | After an incremental synchronization task starts, OMS Community Edition synchronizes the changed data (inserts, modifications, or deletions) from the source database to the corresponding tables in the destination database.<br>The **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>** option of **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** includes `Insert`, `Delete`, and `Update`. You can choose as needed. For more information, see [Filter DML operations](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md). |
   | Full Verification | After full migration is completed, incremental data is synchronized to the destination and is roughly caught up with the source, OMS Community Edition automatically initiates a full data verification task for the data tables configured in the source and destination databases.<ul><li>If you select **<UI-TERM key="oms-community.Sync.constants.FullVerification">Full Verification</UI-TERM>**, we recommend that you collect statistics from OceanBase Database Community Edition on both the source and destination before full verification starts. For more information, see [Manually collect statistics](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002017252).</li><li>If you selected **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** and not all DML operations are selected for the **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsDetail.DataChangeDml">DML Synchronization</UI-TERM>** option, OMS Community Edition does not support full data verification in this scenario.</li></ul> |

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration objects and scope.

   You can select migration objects through two methods: **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>**. This topic describes how to select migration objects using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** method. For details on configuring match rules, see [Configure match rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Note</h4>
      <ul>
      <li>
      <p>The names of tables to be migrated and the column names within them must not contain Chinese characters.</p>
      </li>
      <li>
      <p>If the database name or table name contains the character "$$", it will affect the creation of the data migration task.</p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add it to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When migrating data from a MongoDB database to OceanBase Database Community Edition, OMS Community Edition supports importing objects via text, renaming object names, and removing single or all migration objects.

     |   Operation    |                                                    Step                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import Objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li>In the dialog box, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Note:**<br> The import will overwrite previous operation selections. Proceed with caution.  <li>In the **Import Migration Objects** dialog box, import the objects to be migrated.<br>You can rename databases and tables by importing a CSV file. For more information, see [Download and import migration object configurations](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After passing the legality validation, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS Community Edition supports renaming migration object names. For more information, see [Rename a database or table](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Settings      | You can select columns to exclude in the **<UI-TERM key="oms-community.biz.ETL.ETLFormDrawer.Set">Settings</UI-TERM>** > **<UI-TERM key="oms-community.biz.ETL.ETLFormDrawer.ViewColumns">View Column</UI-TERM>** section so that they are not migrated later. |
     | Remove/Remove All | OMS Community Edition allows you to remove one or more objects temporarily selected for migration to the target during data mapping. <ul><li>Remove a single migration object <br>In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the mouse over the target object and click the displayed **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>** to remove the migration object.  <li> Remove all migration objects <br>In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>** to remove all migration objects.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. To view or modify the parameters of the incremental synchronization component, click **<UI-TERM>Store Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** section or **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** as needed. For parameter descriptions, see the documentation in the [Component parameters](../900.o-m-manual/400.components/500.component-parameters/300.source-plugin/900.mongodb-source.md) module.

    * Full Migration

      <main id="notice" type='notice'>
        <h4>Note</h4>
        <p>The following parameters are displayed only if you have selected <b>Full Migration</b> on the <b>Select Migration Type</b> page.</p>
        </main>

        |Parameter|Description|
        |----|----------------------------------|
        | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. Different full migration speeds result in different performances and resource requirements. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|
        | Processing Strategy When Target Object Has Records | Valid values: **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li>If you select **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, when data exists in the target table object and conflicts with the data to be written, OMS Community Edition logs the conflicting data and retains the original data unchanged.<main id="notice" type='notice'><h4>Note</h4><p>If you select <b>Ignore</b>, full verification will pull data in IN mode, which cannot verify scenarios where the target has data not present in the source, and verification performance will be degraded to some extent.</p></main></li><li>If you select **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**, when data exists in the target table object, full migration will report an error indicating that migration is not allowed. Please handle the data at the target before continuing the migration.<main id="notice" type='notice'><h4>Note</h4><p>If you click Resume after an error occurs, OMS Community Edition will ignore this configuration option and continue migrating table data. Proceed with caution.</p></main></li> </ul>|
        | Write Method | Valid values: **SQL** (writes to the table using `INSERT` or `REPLACE`) and **Direct Load** (writes via direct load). Currently, writing vector-type data via direct load is not supported.|

      The following parameters are displayed only if you have selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page.

      |Parameter|Description|
      |----|----------------------------------|
      | Concurrency Speed | Includes **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance and required resources for incremental synchronization vary with the speed. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|
      |Incremental Synchronization Start Timestamp| <ul><li> If **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** was selected as the migration type, this parameter is not displayed.   <li> If **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** was not selected but **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** was selected, specify a point in time after which data should be migrated. The default is the current system time. For details, see [Set an incremental synchronization timestamp](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |
      |Incremental Record Retention Time| The duration for which incremental parsed files are cached in OMS Community Edition. A longer configured retention time requires more disk space for the OMS Community Edition Store component.  |

    * Full Verification

      The following parameters are displayed only if **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** and **<UI-TERM key="oms-community.Operation.constants.FullVerification">Full Verification</UI-TERM>** are selected.

      |Parameter|Description|
      |----|----------------------------------|
      | Concurrency Speed | Includes **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. Resource configuration for the Full-Verification component limits resource consumption during the full verification phase of a task. When you select **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to have the system perform a precheck on the data migration task.

   During the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS Community Edition checks whether the database's network connection meets requirements. The data migration task can only start after all checks pass. If the precheck reports an error:

   * You can troubleshoot and resolve the issue, then re-execute the precheck until it succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants Skipping">Skip</UI-TERM>** in the Actions column for the erroneous precheck item. A dialog box appears, explaining the specific impact of skipping this operation. After confirming it is okay to skip, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not need to start the task immediately, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the data migration task details page, where you can start it manually later.

    OMS Community Edition supports modifying migration objects during the execution of a data migration task. For details, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After a data migration task is started, it is executed sequentially according to the selected migration type. For details, see the content in the "View migration details" section of [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
