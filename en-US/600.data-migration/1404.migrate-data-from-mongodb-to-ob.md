# Migrate data from a MongoDB database to OceanBase Database Community Edition

This topic describes how to use OceanBase Migration Service (OMS) Community Edition to migrate data from a MongoDB database to OceanBase Database Community Edition.

## Limitations

* **Limitations on the source database**

    **Do not perform DDL operations on the schema of a database or table during full migration. Otherwise, the data migration task may be interrupted.**

* At present, data migration from a MongoDB database to OceanBase Database Community Edition supports only full migration and incremental synchronization of DML statements.

* The supported MongoDB database versions are V3.x, V4.0.0, V4.4.6, V5.0.0, V6.0.0, V7.0.22, and V8.0.15.

* To enable incremental migration for MongoDB, you must enable the oplog.

* The data source identifier and user account must be globally unique in the OMS system.

* OMS Community Edition supports only the migration of databases, tables, and columns whose names are in ASCII and do not contain special characters (spaces, line breaks, or |"'`()=;/&).

* We recommend that you migrate no more than 1,000 tables in one go to avoid affecting the running of the data migration task.

* To read data from the local.oplog.rs collection, you must have the read privilege on the local database (for example, the read role granted to the local database).

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>Starting from MongoDB 7.0, access to the local database is more restricted. Even if you have the root role, you must explicitly grant the read privilege on the local database. Otherwise, the following error is returned: not authorized on local.</p>
    </main>

## Procedure

1. Create a data migration task.

    1. Log in to the OMS Community Edition console.

    2. In the left-side navigation pane, click **<UI-TERM key="oms-community.SystemParam.contants.DataMigration">Data Migration</UI-TERM>**.

    3. On the **<UI-TERM key="oms-community.pages.Migration.MigrationProject">Migration Tasks</UI-TERM>** page, click **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">Create Task</UI-TERM>** in the upper-right corner.

2. On the **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">Select Source and Target</UI-TERM>** page, configure the parameters.

    | Parameter | Description |
    |--------|-----------------------------------------------------------|
    | Migration Task Name | We recommend that you use a combination of Chinese characters, digits, and letters. The name cannot contain spaces and must be no longer than 64 characters.  |
    | Tags     | Click the text box and select a tag from the drop-down list. You can also click **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, or delete tags. For more information, see [Manage data migration tasks by using tags](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md).|
    | Source     | If you have created a MongoDB data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create a MongoDB data source](../800.create-and-manage-data-sources/100.create-a-data-source/1600.create-mongodb-data-source.md).|
    | Destination    | If you have created an OceanBase Database Community Edition data source, select it from the drop-down list. If not, click **<UI-TERM key="oms-community.components.EndpointSelect.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create a data source in the dialog box that appears. For more information, see [Create an OceanBase Database Community Edition data source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).|

3. Click **<UI-TERM key="oms-community.StepsForm.demo.Next">Next</UI-TERM>**.

4. On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, configure the parameters.

    **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">Migration Type</UI-TERM>** includes **<UI-TERM key="oms-community.Migration.constants.FullMigration">Full Migration</UI-TERM>** and **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**.

   | Migration Type | Description |
   |------|------------------------|
   | Full Migration | After a full migration task is started, OMS Community Edition migrates the existing data in the source database tables to the corresponding tables in the destination database.|
   | Incremental Synchronization | After an incremental synchronization task is started, OMS Community Edition synchronizes the data that has changed in the source database (added, modified, or deleted) to the corresponding tables in the destination database.<br>**<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** has the **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">DML Synchronization</UI-TERM>** option, which includes `Insert`, `Delete`, and `Update`. You can select the required option as needed. For more information, see [DML filtering](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md). |

5. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** page, select the migration object and migration scope.

   You can select the migration object from the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** and **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** sections. This topic describes how to select the migration object from the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** section. For more information about how to configure the matching rules, see [Configure matching rules for migration objects](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md).

      <main id="notice" type='notice'>
      <h4>Notice</h4>
      <ul>
      <li>
      <p>The name of the table to be migrated and the names of the columns in the table cannot contain Chinese characters. </p>
      </li>
      <li>
      <p>If the name of a database or table contains the &quot;$$&quot; character, the data migration task cannot be created. </p>
      </li>
      </ul>
      </main>

      1. In the **<UI-TERM key="oms-community.Migration.New.SelectObject">Select Migration Objects</UI-TERM>** section, select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>**.

      2. In the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, select the objects to be migrated from the **<UI-TERM key="oms-community.common.Transfer.SourceObject">Source Object(s)</UI-TERM>** list.

      3. Click **\>** to add the objects to the **<UI-TERM key="oms-community.common.Transfer.TargetObject">Target Object(s)</UI-TERM>** list.

     When you migrate data from a MongoDB database to OceanBase Database Community Edition, OMS Community Edition allows you to import objects, rename objects, and remove individual or all migration objects.

     |   Operation    |                                                    Steps                                                     |
     |---------|-----------------------------------------------------------------------------------------------------------|
     | Import objects    | <ol><li> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.   <li> In the dialog box that appears, click **<UI-TERM key="oms-community.components.ResetPassword.ResetOwnPassword.Determine">OK</UI-TERM>**.<br> **Notice:**<br> Importing objects will overwrite previous selections. Proceed with caution.  <li> In the **Import Migration Objects** dialog box, import the objects to be migrated.<br> You can also rename databases and tables by importing CSV files. For more information, see [Download and import migration object settings](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md).   <li> Click **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">Validate</UI-TERM>**.   <li> After the validity check is passed, click **<UI-TERM key="oms-community.pages.User.Confirmation">OK</UI-TERM>**.</ol>    |
     | Rename     | OMS Community Edition allows you to rename migration objects. For more information, see [Rename databases and tables](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md).                       |
     | Remove/Remove All | OMS Community Edition allows you to remove individual or multiple objects temporarily selected to the target from the data mapping. <ul><li> Remove an individual migration object <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, hover the pointer over the target object and click **<UI-TERM key="oms-community.Sync.constants.Remove">Remove</UI-TERM>**.  <li> Remove all migration objects <br> In the right-side list of the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">Specify Migration Scope</UI-TERM>** section, click **<UI-TERM key="oms-community.Transfer.target.RemoveAll">Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM key="oms-community.pages.Endpoint.Confirmation">OK</UI-TERM>**.  </ul>   |

6. Click **<UI-TERM key="oms-community.Migration.New.Next">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">Migration Type</UI-TERM>** page, configure the parameters.

    To view or modify the parameters of the full migration component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** section. To view or modify the parameters of the incremental synchronization component, click **<UI-TERM>Store Configuration Details</UI-TERM>** or **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrIncrementalConfigurationDetails">Configuration Details of incr Increment</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** section. For more information about the parameters, see the documentation in the [Component Parameters](../900.o-m-manual/400.components/500.component-parameters/300.source-plugin/900.mongodb-source.md) module.

    * Full migration

      <main id="notice" type='notice'>
        <h4>Notice</h4>
        <p>The following parameters are displayed only when you select <b>Full Migration</b> on the <b>Select Migration Type</b> page. </p>
        </main>

        |Parameter|Description|
        |----|----------------------------------|
        |Concurrent Speed| Includes **<UI-TERM key="oms-community.Migration.constants.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of full migration varies, and the resources required for full migration tasks also vary. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|
        |Handling Strategy When Target Objects Exist| The handling strategy includes **<UI-TERM key="must.PreCheck.constants.Skip">Ignore</UI-TERM>** and **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">Stop Migration</UI-TERM>**:<ul><li>When you select **<UI-TERM key="oms-community.Operation.constants.Ignore">Ignore</UI-TERM>**, if the target table contains data and the original data conflicts with the data to be written, OMS Community Edition will record the conflicting data in a log and retain the original data unchanged. <main id="notice" type='notice'><h4>Notice</h4><p>When you select <b>Ignore</b>, the full validation will use the IN mode to pull data. This means that it cannot validate scenarios where the target contains data that the source does not. Please process the target data before continuing with the migration. <main id="notice" type='notice'><h4>Notice</h4><p>If an error occurs and you click Restore, OMS Community Edition will ignore this configuration option and continue migrating the table data. Proceed with caution. </p></main></li> </ul>|
        |Write Mode| Includes **SQL** (data is written to the table by using the `INSERT` or `REPLACE` statement) and **Direct Load** (data is written by using the direct load method). Currently, you cannot write vector data by using the direct load method.|

    * Incremental Synchronization

      On the **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">Select Migration Type</UI-TERM>** page, select **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** to display the following parameters.

      |Parameter|Description|
      |----|----------------------------------|
      |Concurrent Speed| Includes **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.New.components.ParameterForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**. The performance of incremental synchronization varies, and the resources required for incremental synchronization tasks also vary. When you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** based on your actual situation.|
      |Incremental Synchronization Start Point| <ul><li> If you selected **<UI-TERM key="oms-community.Operation.constants.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, this parameter is not displayed.   <li> If you did not select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">Full Migration</UI-TERM>** when you selected the migration type, but selected **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">Incremental Synchronization</UI-TERM>**, specify the migration of data after a specific point in time. By default, the current system time is used. For more information, see [Set the incremental synchronization start point](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md).  |
      |Incremental Record Retention Time| The duration for which incremental parsing files are cached in OMS Community Edition. The longer the configured retention time, the more disk space the OMS Community Edition Store component consumes.  |

7. Click **<UI-TERM key="oms-community.SystemParam.contants.Precheck">Precheck</UI-TERM>** to perform a precheck on the data migration task.

   In the **<UI-TERM key="oms-community.Sync.New.Precheck">Precheck</UI-TERM>** step, OMS Community Edition checks whether the network connection to the database meets the requirements. You can start a data migration task only after all precheck tasks are completed. If an error is reported during the precheck:

   * You can troubleshoot and fix the issue, and then perform the precheck again until it succeeds.

   * You can also click **<UI-TERM key="oms-community.Migration.constants.Skip">Skip</UI-TERM>** in the Actions column of the error precheck item. A dialog box pops up to prompt you of the specific impact of skipping the current operation. After you confirm that you can skip the operation, click **<UI-TERM key="oms-community.Migration.hooks.useMigrationParams.Determine">OK</UI-TERM>** in the dialog box.

8. Click **<UI-TERM key="oms-community.components.PreCheck.PreCheckDrawer.StartATask">Start Task</UI-TERM>**. If you do not want to start the task at this time, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the data migration task. You can manually start the task as needed.

    In OMS Community Edition, you can modify the migration objects during the execution of a data migration task. For more information, see [View and modify migration objects](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md). After the data migration task is started, it will be executed based on the selected migration type. For more information, see the section [View migration details](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) in the topic [View details of a data migration task](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md).
