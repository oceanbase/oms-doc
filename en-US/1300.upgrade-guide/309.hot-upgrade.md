# Hot upgrade of OMS Community Edition

This topic describes how to hot upgrade OceanBase Migration Service (OMS) Community Edition without affecting data migration and data synchronization tasks.

## Limitations

* The version of OMS Community Edition must be greater than or equal to V4.2.1.

* Before and during a hot upgrade, ensure that no new tasks are being created in OMS Community Edition.

* After a successful hot upgrade, refresh the browser or delete data to view the features of the upgraded version. For information about how to delete data, see the "Common Issues" section.

* After a successful hot upgrade, new data migration or synchronization tasks will have the features of the upgraded version.

* Existing tasks remain unchanged after a hot upgrade, especially for new configurations added in the upgraded version, which will not be present in existing tasks from the previous version.

* When performing a forward switch after a successful hot upgrade, the incremental start point feature is invalid. This feature was added in OMS Community Edition V4.2.11-CE and is only supported for new data migration tasks.

## Procedure

1. Log in to the host where OMS Community Edition is installed.

2. Run the following command to obtain the hot upgrade script from the new image.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>Before obtaining the hot upgrade script, make sure that you have loaded the new image as OMS_IMAGE. </p>
    </main>

    ```shell
    sudo docker run -d --net host --name oms-config-tool ${OMS_IMAGE} bash \
    && sudo docker cp oms-config-tool:/root/docker_dump_file_from_image.sh . \
    && sudo docker cp oms-config-tool:/root/docker_copy_dumpfile_to_container.sh . \
    && sudo docker cp oms-config-tool:/root/docker_copy_dumpfile_rollback.sh . \
    && sudo docker rm -f oms-config-tool
    ```

3. In a multi-node upgrade scenario, if you have enabled the HA feature, disable it first. For more information, see [Modify the HA feature configurations](../1000.system-management/400.system-parameters/200.modify-ha-configurations.md).

4. Back up the metadata of OMS Community Edition.

    ```shell
    mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false rm_4211 > /home/admin/rm_4211.sql

    mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_4211 > /home/admin/cm_4211.sql

    mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_hb_4211 > /home/admin/cm_hb_4211.sql
    ```

    Parameter description

    :::collapse

    |           Parameter            |                                   Description                                   |
    |-------------------------|------------------------------------------------------------------------|
    | -h                      | The host information to be exported.                                                             |
    | -P                      | The port number for connecting to the database.                                                             |
    | -u                      | The username for connecting to the database.                                                              |
    | -p                      | The password for connecting to the database.                                                              |
    | --triggers              | Specifies whether to export triggers. The default value is false (no export).                                                  |
    | rm_4211, cm_4211, cm_hb_4211 | The values of these parameters are the SQL files for backing up the rm, cm, and cm_hb databases. The format is `Database name > Path to store the SQL file.sql`. Replace the values with those in your environment. |

    :::

5. Copy the new image file to the host directory.

    ```shell
    sh docker_dump_file_from_image.sh ${OMS_IMAGE}
    ```

6. Enter the OMS Community Edition container and pause the management service.

    ```shell
    supervisorctl stop nginx oms_console oms_drc_cm oms_drc_supervisor sshd
    ```

7. Copy the new image file to the OMS Community Edition container.

    ```shell
    sh docker_copy_dumpfile_to_container.sh ${OMS Community Edition container name}
    ```

8. Run the hot upgrade script `sh /root/docker_hot_update_init.sh`.

    ```shell
    sudo docker exec -it ${OMS Community Edition container name} /root/docker_hot_update_init.sh
    ```

    If the hot upgrade script fails, you can use `docker_copy_dumpfile_rollback.sh` to roll back. The command is as follows.

    <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>You can use this script only if steps 1 to 7 are executed successfully but step 8 fails. Otherwise, the rollback script will clear the original files because no backup files are available. </p>
    </main>

    ```shell
    sh docker_copy_dumpfile_rollback.sh ${OMS Community Edition container name} /home/admin/logs/backup2025xxxx
    sudo docker exec -it ${OMS Community Edition container name} /root/docker_init.sh
    ```

    <main id="notice" type='explain'>
    <h4>Note</h4>
    <p><code>/home/admin/logs/backup2025xxxx</code> specifies the directory where <code>docker_copy_dumpfile_rollback.sh</code> backs up the information of the previous version of OMS Community Edition before the upgrade. By default, the directory is <code>/home/admin/logs</code>, and the backup files are prefixed with <code>backup</code>. </p>
    </main>

## FAQ

### Failed to access OMS Community Edition

* Problem description

  After a hot upgrade, you may encounter the following two issues when you access OMS Community Edition.

  * The `HTTP Status 500 – Internal Server Error` error is returned.

    <img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-ce/omsce10.png" width="500">

  * The login username is not displayed.

    <img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-ce/omsce11-zh.png" width="500">

* Solution

  1. Go to the website settings page.

     <img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-ce/omsce12-zh.png" width="500">

  2. Click Delete Data.

     <img src="https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-ce/omsce13-zh.png" width="500">

### Hot upgrade OMS Community Edition V4.2.1-CE to V4.2.13-CE

Before you hot upgrade OMS Community Edition V4.2.1-CE to V4.2.13-CE, if the OceanBase Store component of a newly created task is not started or failed, you need to add the `drc_frame.dbversion` parameter to the OceanBase Store parameters to specify the version number of OceanBase Database after the upgrade.
