# Upgrade OMS Community Edition to V4.2.12-CE

This topic describes how to upgrade OceanBase Migration Service (OMS) Community Edition to V4.2.12-CE.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Currently, OMS Community Edition V4.2.0-CE to V4.2.11-CE can be upgraded to V4.2.12-CE. OMS Community Edition earlier than V4.2.0-CE cannot be upgraded to V4.2.12-CE. </p>
</main>

## Upgrade steps

1. Load the downloaded OMS Community Edition installation package into the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

2. Back up the database.

   1. Pause the OMS Community Edition V4.2.11-CE container, and record the time as T1.

      ```shell
      sudo docker stop ${CONTAINER_NAME}
      ```

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>CONTAINER_NAME</code> is the name of the container. </p>
      </main>

   2. Log in to the CM heartbeat database specified in the configuration file, delete some unnecessary records in the database, and save backup time.

      ```shell
      # Log in to the CM heartbeat database specified in the configuration file.
      mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -Dcm_hb_4211

      # Delete unnecessary records.
      # The heatbeat_sequence table is used to report heartbeats and obtain the auto-increment ID.
      delete from heatbeat_sequence where id < (select max(id) from heatbeat_sequence);

      ```

   3. Execute the following command to manually back up the rm, cm, and cm_hb databases as SQL files, and confirm that the sizes of the three files are not 0.

      ```shell
      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false rm_4211 > /home/admin/rm_4211.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_4211 > /home/admin/cm_4211.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_hb_4211 > /home/admin/cm_hb_4211.sql
      ```

      Backup parameters

      :::collapse

      |           Parameter            |                                   Description                                   |
      |-------------------------|------------------------------------------------------------------------|
      | -h                      | The host information to be exported.                                                             |
      | -P                      | The port number for connecting to the database.                                                             |
      | -u                      | The username for connecting to the database.                                                              |
      | -p                      | The password for connecting to the database.                                                              |
      | --triggers              | Specifies whether to export triggers. The default value is false, which indicates that triggers are not exported.                                                  |
      | rm_4211, cm_4211, and cm_hb_4211 | The following example shows how to back up the rm, cm, and cm_hb databases as SQL files. The format is `database name > path for storing the SQL file.sql`. Replace the values with those in your environment. |

      :::

3. Start the OMS Community Edition V4.2.12-CE container.

   OMS Community Edition supports accessing the OMS Community Edition console over HTTP or HTTPS. If you want to access OMS Community Edition securely, you can provide an HTTPS certificate and mount it to the specified directory in the container. If you access OMS Community Edition over HTTP, you do not need to configure anything.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li>
   <p>When you start the OMS Community Edition V4.2.12-CE container, the paths of the three mounted disks must be the same as those before the upgrade.<br>You can execute the <code>sudo docker inspect ${CONTAINER_NAME} | grep -A5 'Binds'</code> command to view the paths of the mounted disks of the previous OMS Community Edition container.</p>
   </li>
   <li>
   <p>The OMS Community Edition V3.3.1-CE and later versions support the <code>-e IS_UPGRADE=true</code> parameter. This parameter is only applicable to upgrade scenarios, and must be added in upgrade scenarios.</p>
   </li>
   <li>
    <p>Replace <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> with the actual image name imported by executing the <code>docker load -i</code> command.</p>
    </li
   </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # The following two parameters must be set if you mount an HTTPS certificate to the OMS container.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   -e IS_UPGRADE=true \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

   Startup parameters

   :::collapse

   |           Parameter            |                                                                                                        Description                                                                                                         |
   |-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | OMS_HOST_IP             | The IP address of the host.                                                                                                                                                                                                       |
   | CONTAINER_NAME          | The name of the container.                                                                                                                                        |
   | IMAGE_TAG               | After you use Docker to load the OMS Community Edition installation package, run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image. This is the unique identifier of the loaded image, which is `<OMS_IMAGE>`.                 |
   | /data/oms/oms_logs <br> /data/oms/oms_store   <br> /data/oms/oms_run      | You can replace `/data/oms/oms_logs`, `/data/oms/oms_store`, and `/data/oms/oms_run` with the mount directories created on the OMS Community Edition deployment server. These directories store the log files generated during the operation of OMS Community Edition, the files generated by the log pull component and the synchronization component, and persist the data on the local server. <br>**Notice:**<br>  The mount directories must remain unchanged during subsequent re-deployments and upgrades. |
   | /home/admin/logs <br>  /home/ds/store  <br> /home/ds/run         | `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run` are fixed directories in the container. You cannot modify the paths.         |
   | /data/oms/https_crt (Optional)<br>/data/oms/https_key (Optional) | The mount directory for HTTPS certificates in the OMS Community Edition container. If you mount an HTTPS certificate, the Nginx service in the OMS Community Edition container will run in HTTPS mode. You must access OMS Community Edition in HTTPS mode to use the console service.                                                                                         |
   | IS_UPGRADE              | In upgrade scenarios, set `IS_UPGRADE=true`. Note that `IS_UPGRADE` must be in uppercase.                                                                                                                                                                                     |
   | privileged              | Grants extended permissions to the container.                                                                                                                                                                                                        |
   | pids-limit              | Configures the process number limit for the container. -1 indicates no limit.                                                                                                                                                                                              |
   | ulimit nproc            | Configures the upper limit of the number of user processes.                                                                                                                                                                                                       |

   :::

4. View the initialization execution result. If `OMS service start successfully` appears, the upgrade is completed.

   ```shell
   docker logs -f ${CONTAINER_NAME}
   ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><code>CONTAINER_NAME</code> is the name of the container. </p>
   </main>

5. After the upgrade is completed, check whether the machine list is normal and whether all machines are in the **<UI-TERM key="oms-community.Operation.constants.Online">Online</UI-TERM>** state.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.Welcome.constants.OMMonitoring">OPS & Monitoring</UI-TERM>** \> **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.Machine">Server</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.Operation.Machine.MachineList">Servers</UI-TERM>** page, check whether the machine list is normal and whether all machines are in the **<UI-TERM key="oms-community.Operation.constants.Online">Online</UI-TERM>** state.

6. (Optional) If you need to roll back the upgrade, perform the following steps:

    1. Pause the new container after the upgrade and record the time T3.

          ```shell
          sudo docker stop ${CONTAINER_NAME}
          ```

    2. Connect to the metadata database and execute the following command:

          ```shell
          drop database rm_4211;
          drop database cm_4211;
          drop database cm_hb_4211;

          create database rm_4211;
          create database cm_4211;
          create database cm_hb_4211;
          ```

    3. Restore the backed-up SQL file to the original database.

          ```shell
          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/rm_4211.sql" -Drm_4211

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_4211.sql" -Dcm_4211

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_hb_4211.sql" -Dcm_hb_4211
          ```

    4. Restart the OMS Community Edition V4.2.11-CE container.

          ```shell
          sudo docker restart ${CONTAINER_NAME}
          ```

7. After the upgrade is completed, clear the browser cache and then log in.
