# Upgrade OMS Community Edition to V4.2.12-CE

This topic describes how to upgrade OceanBase Migration Service (OMS) Community Edition to V4.2.12-CE.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>OMS Community Edition V4.2.0-CE through V4.2.11-CE can be upgraded to V4.2.12-CE. OMS Community Edition earlier than V4.2.0-CE cannot be upgraded to V4.2.12-CE. </p>
</main>

## Upgrade steps

1. If HA is enabled, disable HA.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** \> **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.layout.constants.SystemParameters">System Parameters</UI-TERM>** page, find `ha.config`.

   4. Click the edit icon next to the parameter name **<UI-TERM key="oms-community.pages.SystemParam.Value">Value</UI-TERM>**.

   5. In the **<UI-TERM key="oms-community.pages.SystemParam.ModifyAValue">Modify Value</UI-TERM>** dialog box, set `enable` to `false` to disable HA.

2. Load the downloaded OMS Community Edition installation package to the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

3. Back up the database.

   1. Log in to IP1 and IP2, and pause the OMS Community Edition V4.2.11-CE containers on both servers.

      ```shell
      sudo docker stop ${CONTAINER_NAME}
      ```

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>CONTAINER_NAME</code> is the name of the container. </p>
      </main>

   2. Log in to the CM heartbeat database in the configuration file, delete some unnecessary records in the database to save backup time.

      ```shell
      # Log in to the CM heartbeat database in the configuration file.
      mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -Dcm_hb_4211

      # Delete unnecessary records.
      # heatbeat_sequence is used to report heartbeats and obtain an auto-increment ID.
      delete from heatbeat_sequence where id < (select max(id) from heatbeat_sequence);
      ```

   3. Run the following command to manually back up the rm, cm, and cm_hb databases as SQL files, and make sure that the file sizes are not 0.

      In a multi-region scenario, the cm_hb database in each region must be backed up. For example, if there are two regions, you must back up four databases: rm, cm, cm_hb1, and cm_hb2.

      ```shell
      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false rm_4211 > /home/admin/rm_4211.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_4211 > /home/admin/cm_4211.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_hb_4211 > /home/admin/cm_hb_4211.sql
      ```

      Backup parameters

      :::collapse

      |           Parameter            |                                   Description                                   |
      |-------------------------|------------------------------------------------------------------------|
      | -h                      | The host information to be exported.                                                             |
      | -P                      | The port number for connecting to the database.                                                             |
      | -u                      | The username for connecting to the database.                                                              |
      | -p                      | The password for connecting to the database.                                                              |
      | --triggers              | Specifies whether to export triggers. The default value is false, which indicates that triggers are not exported.                                                  |
      | rm_4211, cm_4211, cm_hb_4211 | The format is `Database name > Storage path of the SQL file`, which indicates that the rm, cm, and cm_hb databases are backed up as SQL files. Replace the values with those in your environment. |

      :::

4. Start the OMS Community Edition V4.2.12-CE container.

   OMS Community Edition supports accessing the OMS Community Edition console over HTTP or HTTPS. If you want to securely access OMS Community Edition, you can configure an HTTPS self-signed certificate and mount it to the specified directory in the container. If you access OMS Community Edition over HTTP, you do not need to configure a certificate.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li>
   <p>When you start the OMS Community Edition V4.2.12-CE container, the paths of the three mount points of OMS Community Edition must be the same as those before the upgrade.<br>You can run the <code>sudo docker inspect ${CONTAINER_NAME} | grep -A5 'Binds'</code> command to view the paths of the mount points of the previous OMS Community Edition container.</p>
   </li>
   <li>
   <p>OMS Community Edition V3.3.1-CE and later versions support the <code>-e IS_UPGRADE=true</code> parameter. This parameter is applicable only to upgrade scenarios and must be added when you perform an upgrade. </p>
   </li>
   <li>
    <p>Replace <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> with the name of the image actually imported by running the <code>docker load -i</code> command. </p>
    </li
   </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # The following two parameters must be set when the HTTPS certificate is mounted in the OMS container.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   -e IS_UPGRADE=true \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

   Parameters

   :::collapse

   |           Parameter            |                                                                                                        Description                                                                                                         |
   |-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | OMS_HOST_IP             | The IP address of the host node. <br>**Notice:**<br>  The `OMS_HOST_IP` of each node varies.                                                                                                                                      |
   | CONTAINER_NAME          | The name of the container.                                                                                                                                          |
   | IMAGE_TAG             | After you load the OMS Community Edition installation package using Docker, run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the corresponding image. This serves as the unique identifier of the loaded image, represented as `<OMS_IMAGE>`.                                                                                          |
   | /data/oms/oms_logs <br> /data/oms/oms_store   <br> /data/oms/oms_run      | You can replace `/data/oms/oms_logs`, `/data/oms/oms_store`, and `/data/oms/oms_run` with custom mount directories based on your deployment. The log files of OMS Community Edition will be stored in the `/data/oms/oms_logs` directory. The files generated by the log pull component and synchronization component will be stored in the `/data/oms/oms_store` directory. The files required for OMS Community Edition will be stored in the `/data/oms/oms_run` directory. The files will be persisted on the local server.  <br>**Notice:**<br>  The mount directory must remain in its original location in subsequent redeployment and upgrades. |
   | /home/admin/logs <br>  /home/ds/store  <br> /home/ds/run         | The paths of the following directories in the container cannot be modified: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`.         |
   | /data/oms/https_crt (optional)<br>/data/oms/https_key (optional) | The mounting path of the HTTPS certificate in the OMS Community Edition container. If you mount an HTTPS certificate, the Nginx service in the OMS Community Edition container will run in HTTPS mode. You can access the OMS Community Edition console only in HTTPS mode.                                                                                                               |
   | IS_UPGRADE              | In upgrade mode, you must set `IS_UPGRADE=true`. Note that the value of `IS_UPGRADE` must be in uppercase.                                                                                                                                                                                      |
   | privileged              | Assign extended privileges to the container.                                                                                                                                                                                                        |
   | pids-limit              | Configure the number of processes in the container. A value of -1 indicates that no limit is applied.                                                                                                                                                                                              |
   | ulimit nproc            | Specifies the upper limit for the number of processes.                                                                                                                                                                                                       |

   :::

5. Check the initialization execution result. When the `OMS service start successfully` message appears, the upgrade is complete.

   ```shell
   docker logs -f ${CONTAINER_NAME}
   ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><code>CONTAINER_NAME</code> is the name of the container that you created. </p>
   </main>

6. After the upgrade is complete, check whether the list of machines is normal and all the machines are in the **<UI-TERM key="oms-community.Operation.constants.Online">Online</UI-TERM>** state.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.Welcome.constants.OMMonitoring">OPS & Monitoring</UI-TERM>** \> **<UI-TERM key="oms-community.Operation.Machine.Machine">Server</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.Operation.Machine.MachineList">Servers</UI-TERM>** page, check whether the list of machines is normal. Also, check whether all the machines are in the **<UI-TERM key="oms-community.Operation.constants.Online">Online</UI-TERM>** state.

7. After you upgrade both nodes, go to the **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>** page and enable the HA feature and set the related parameters.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** \> **<UI-TERM key="oms-community.layout.constants.SystemParameters">System Parameters</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemParameters">System Parameters</UI-TERM>** page, find `ha.config`.

   4. Click the edit icon in the **<UI-TERM key="oms-community.pages.SystemParam.Value">Value</UI-TERM>** column of the parameter.

   5. In the **<UI-TERM key="oms-community.pages.SystemParam.ModifyAValue">Modify Value</UI-TERM>** dialog box, set `enable` to `true` to enable the HA feature and record the time as T2.

      You can also set `perceiveStoreClientCheckpoint` to `true`. If you do so, you do not need to record T1 and T2.

   6. If you set `perceiveStoreClientCheckpoint` to `false`, you must modify the value of `refetchStoreIntervalMin` (the time for which data is pulled back, in minutes) based on your business requirements. The value must be greater than the difference between T2 and T1.

      If you set `perceiveStoreClientCheckpoint` to `true`, you can leave `refetchStoreIntervalMin` as its default value. HA starts the Store component based on the earliest timestamp of the downstream component minus the value of `refetchStoreIntervalMin`. For example, if the earliest timestamp of the downstream connector or JDBC connector is 12:00:00 and the value of `refetchStoreIntervalMin` is 30 minutes, HA starts the Store component at 11:30:00.

      After you enable the HA feature, HA processes the components as shown in the following table.

      :::collapse

      <table>
         <tr>
         <td><b>Pre-upgrade task/component status</b></td>
         <td><b>Post-upgrade status (HA not enabled)</b></td>
         <td><b>Post-upgrade status (HA enabled)</b></td>
         </tr>
         <tr>
         <td>The task is running normally.  <ul>  <li>The Incr-Sync component is running normally. <li>The Store component is running normally. </ul>     </td>
         <td rowspan="2">The task status remains unchanged. <ul> <li>The Incr-Sync component is faulty. </li> <li> The Store component is faulty.   </ul> </td>
         <td  rowspan="2">The task status remains unchanged.
         <ul><li> HA automatically starts the Incr-Sync component. </li><li> HA creates a new Store component based on the configuration. For more information, see <a href="../1000.system-management/400.system-parameters/200.modify-ha-configurations.md">Modify HA configurations</a>. </li> </ul>
         </td>
         </tr>
         <tr>
         <td>The task fails. <ul> <li>The Incr-Sync component is faulty. <li> The Store component is faulty. </li>     </td>
         </tr>
         <tr>
         <td>The task is paused. <ul>    <li>The Incr-Sync component is paused. <li>The Store component is running normally. </ul>    </td>
         <td>The task status remains unchanged. <ul> <li>The Incr-Sync component is paused. <li> The Store component is faulty.   </ul> </td>
         <td> The task status remains unchanged.
         <ul>
         <li>The Incr-Sync component is paused. </li>
         <li> HA creates a new Store component based on the configuration. For more information, see <a href="../1000.system-management/400.system-parameters/200.modify-ha-configurations.md">Modify HA configurations</a>. </li>
         </ul>
         </td>
         </tr>
      </table>

      :::

8. (Optional) If you want to roll back the upgrade, perform the following steps.

    1. Disable the HA feature based on the steps in 1.

    2. Pause the new container and record the time as T3.

          ```shell
          sudo docker stop ${CONTAINER_NAME}
          ```

    3. Connect to the MetaStore database and execute the following command.

          ```shell
          drop database rm_4211;
          drop database cm_4211;
          drop database cm_hb_4211;

          create database rm_4211;
          create database cm_4211;
          create database cm_hb_4211;
          ```

    4. Restore the backed-up database SQL file to the original database.

          ```shell
          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/rm_4211.sql" -Drm_4211

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_4211.sql" -Dcm_4211

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_hb_4211.sql" -Dcm_hb_4211
          ```

    5. Restart the OMS Community Edition V4.2.11-CE container.

          ```shell
          sudo docker restart ${CONTAINER_NAME}
          ```

    6. On the **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>** page, enable the HA feature and set the `refetchStoreIntervalMin` parameter.

       If you perform a rollback, the HA feature will automatically fail over the Store. However, you may need to manually restore the Incr-Sync/Full-Import component.

9. After the upgrade is complete, clear your browser cache and then log in.
