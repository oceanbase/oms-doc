# Multi-node upgrade

This topic describes how to upgrade OceanBase Migration Service (OMS) Community Edition to V4.2.13-CE in a multi-node deployment.

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>Currently, you can upgrade OMS Community Edition V4.2.0-CE to V4.2.12-CE to V4.2.13-CE, but cannot upgrade OMS Community Edition earlier than V4.2.0-CE to V4.2.13-CE. </p>
</main>

## Upgrade steps

1. If the high availability (HA) feature is enabled, disable it.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** \> **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.layout.constants.SystemParameters">System Parameters</UI-TERM>** page, find `ha.config`.

   4. Click the edit icon next to the parameter name **<UI-TERM key="oms-community.pages.SystemParam.Value">Value</UI-TERM>**.

   5. In the **<UI-TERM key="oms-community.pages.SystemParam.ModifyAValue">Modify Value</UI-TERM>** dialog box, set `enable` to `false` to disable the HA feature.

2. Load the downloaded OMS Community Edition installation package to the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

3. Back up the database.

   1. Log in to IP1 and IP2, and pause the OMS Community Edition V4.2.12-CE containers on both servers.

      ```shell
      sudo docker stop ${CONTAINER_NAME}
      ```

      <main id="notice" type='explain'>
      <h4>Note</h4>
      <p><code>CONTAINER_NAME</code> is the name of the container. </p>
      </main>

   2. Log in to the CM heartbeat database in the configuration file and delete some unnecessary records in the database to save backup time.

      ```shell
      # Log in to the CM heartbeat database in the configuration file
      mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -Dcm_hb_4212

      # Delete unnecessary records
      # heatbeat_sequence is used to report heartbeats and obtain auto-incremental IDs.
      delete from heatbeat_sequence where id < (select max(id) from heatbeat_sequence);
      ```

   3. Execute the following commands to manually back up the rm, cm, and cm_hb databases to SQL files and confirm that the sizes of the files are not 0.

      In a multi-region scenario, the cm_hb databases in all regions must be backed up. For example, if there are two regions, you must back up four databases: rm, cm, cm_hb1, and cm_hb2.

      ```shell
      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false rm_4212 > /home/admin/rm_4212.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_4212 > /home/admin/cm_4212.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_hb_4212 > /home/admin/cm_hb_4212.sql
      ```

      Backup parameters

      :::collapse

      |           Parameter            |                                   Description                                   |
      |-------------------------|------------------------------------------------------------------------|
      | -h                      | The host information to be exported.                                                             |
      | -P                      | The port number for connecting to the database.                                                             |
      | -u                      | The username for connecting to the database.                                                              |
      | -p                      | The password for connecting to the database.                                                              |
      | --triggers              | Specifies whether to export triggers. The default value is false (no triggers are exported).                                                  |
      | rm_4212, cm_4212, cm_hb_4212 | The names of the databases to be backed up to SQL files, in the format of `Database name > Path to store the SQL file.sql`. Replace the values with those in your environment. |

      :::

4. Start the OMS Community Edition V4.2.13-CE container.

   OMS Community Edition supports accessing the OMS Community Edition console over HTTP or HTTPS. If you want to securely access OMS Community Edition, you can configure an HTTPS self-signed certificate and mount it to a specified directory in the container. If you access OMS Community Edition over HTTP, you do not need to configure a certificate.

   <main id="notice" type='notice'>
   <h4>Notice</h4>
   <ul>
   <li>
   <p>When you start the OMS Community Edition V4.2.13-CE container, the paths of the three mount directories of OMS Community Edition must be the same as those before the upgrade.<br>You can execute the <code>sudo docker inspect ${CONTAINER_NAME} | grep -A5 'Binds'</code> command to view the paths of the mount directories of the previous OMS Community Edition container.</p>
   </li>
   <li>
   <p>OMS Community Edition V3.3.1-CE and later versions support the <code>-e IS_UPGRADE=true</code> parameter. This parameter is applicable only to upgrade scenarios and must be added in upgrade scenarios. </p>
   </li>
   <li>
    <p>Replace <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> with the actual image name imported by executing the <code>docker load -i</code> command. </p>
    </li
   </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # The following two parameters are required only if you mount an HTTPS certificate into the OMS container.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   -e IS_UPGRADE=true \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

   Start-up parameters

   :::collapse

   |           Parameter            |                                                                                                        Description                                                                                                         |
   |-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | OMS_HOST_IP             | The IP address of the host. <br>**Note:**<br>  The `OMS_HOST_IP` values vary for each node.                                                                                                                                      |
   | CONTAINER_NAME          | The name of the container that created the container.                                                                                                                                          |
   | IMAGE_TAG               | After you load the OMS Community Edition installation package by using Docker, you can obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image by running the `docker images` command. The obtained value is the unique identifier of the loaded image, `<OMS_IMAGE>`.                                                                                                      |
   | /data/oms/oms_logs <br> /data/oms/oms_store   <br> /data/oms/oms_run      | `/data/oms/oms_logs`、`/data/oms/oms_store` and `/data/oms/oms_run` can be replaced with the mounting directories that you create for your community OMS instance.  The mounting directories are used for storing the log files generated during the operation of the community OMS instance, the files generated by the file pulling component, and the files generated by the synchronization component, respectively, for persistence in the local storage. <br>**Notice:**<br> In future re-deployments and upgrades, the mounting directories must be retained. |
   | /home/admin/logs <br>  /home/ds/store  <br> /home/ds/run         | `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run` are fixed paths in the container, and the paths cannot be modified.         |
   | /data/oms/https_crt (optional)<br>/data/oms/https_key (optional) | The mounting location of the HTTPS certificate in the OMS Community Edition container. If an HTTPS certificate is mounted, Nginx in the container runs in HTTPS mode. You must use HTTPS to access OMS Community Edition console services.                                                                                           |
   | IS_UPGRADE              | If you are using this parameter to upgrade the system, you must set `IS_UPGRADE=true`. Note that `IS_UPGRADE` must be in uppercase.                                                                                                                                                                                      |
   | privileged              | Grant extended permissions to the container.                                                                                                                                                                                                        |
   | pids-limit              | Configures the process limit for the container. Use -1 to indicate that no limit is imposed.                                                                                                                                                                                              |
   | ulimit nproc            | Specify the maximum number of user processes.                                                                                                                                                                                                       |

   :::

5. Check the initialization execution result. When the message `OMS service start successfully` appears, the upgrade is complete.

   ```shell
   docker logs -f ${CONTAINER_NAME}
   ```

   <main id="notice" type='explain'>
   <h4>Note</h4>
   <p><code>CONTAINER_NAME</code> is the name of the container that you created. </p>
   </main>

6. After the upgrade is complete, make sure that the machine list is normal and all machines are in the **<UI-TERM key="oms-community.Operation.constants.Online">Online</UI-TERM>** state.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.Welcome.constants.OMMonitoring">OPS & Monitoring</UI-TERM>** \> **<UI-TERM key="oms-community.Operation.Machine.Machine">Server</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.Operation.Machine.MachineList">Servers</UI-TERM>** page, check whether the machine list is normal. Make sure that the status of all machines is **<UI-TERM key="oms-community.Operation.constants.Online">Online</UI-TERM>**.

7. After you upgrade the two nodes, go to the **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>** page and enable the HA feature, and set the related parameters.

   1. Log in to the OMS Community Edition console.

   2. In the left-side navigation pane, choose **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">System Management</UI-TERM>** \> **<UI-TERM key="oms-community.layout.constants.SystemParameters">System Parameters</UI-TERM>**.

   3. On the **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemParameters">System Parameters</UI-TERM>** page, find `ha.config`.

   4. Click the edit icon next to the parameter name **<UI-TERM key="oms-community.pages.SystemParam.Value">Value</UI-TERM>**.

   5. In the **<UI-TERM key="oms-community.pages.SystemParam.ModifyAValue">Modify Value</UI-TERM>** dialog box, set `enable` to `true` to enable the HA feature, and record the time as T2.

      You can also set `perceiveStoreClientCheckpoint` to `true`. In this case, you do not need to record T1 and T2.

   6. If you set `perceiveStoreClientCheckpoint` to `false`, you must modify the value of `refetchStoreIntervalMin` (the time for which the system pulls data, in minutes) to a value greater than the difference between T2 and T1.

      If you set `perceiveStoreClientCheckpoint` to `true`, you can leave `refetchStoreIntervalMin` as the default value. HA starts the Store component based on the earliest time of the downstream component minus the value of `refetchStoreIntervalMin`. For example, if the earliest request time of the downstream connector/jdbc-connector is 12:00:00 and the value of `refetchStoreIntervalMin` is 30 minutes, HA starts the Store component at 11:30:00.

      After you enable the HA feature, HA performs the following operations on the components, as shown in the following table.

      :::collapse

      <table>
         <tr>
         <td><b>Pre-upgrade task/component status</b></td>
         <td><b>Post-upgrade (HA disabled)</b></td>
         <td><b>Post-upgrade (HA enabled)</b></td>
         </tr>
         <tr>
         <td>The task is running normally. <ul>  <li>The Incr-Sync component is running normally. <li>The Store component is running normally. </ul>     </td>
         <td rowspan="2">The task status remains unchanged. <ul> <li>The Incr-Sync component is abnormal. </li> <li> The Store component is abnormal.   </ul> </td>
         <td  rowspan="2">The task status remains unchanged.
         <ul><li> HA automatically starts the Incr-Sync component. </li><li> HA creates a new Store component based on the configuration. For more information, see <a href="../1000.system-management/400.system-parameters/200.modify-ha-configurations.md">Modify HA configurations</a>. </li> </ul>
         </td>
         </tr>
         <tr>
         <td>The task fails. <ul> <li>The Incr-Sync component is abnormal. <li> The Store component is abnormal. </li>     </td>
         </tr>
         <tr>
         <td>The task is paused. <ul>    <li>The Incr-Sync component is paused. <li>The Store component is running normally. </ul>    </td>
         <td>The task status remains unchanged. <ul><li>The Incr-Sync component is paused. <li>The Store component is abnormal.   </ul> </td>
         <td>The task status remains unchanged.
         <ul>
         <li>The Incr-Sync component is paused. </li>
         <li> HA creates a new Store component based on the configuration. For more information, see <a href="../1000.system-management/400.system-parameters/200.modify-ha-configurations.md">Modify HA configurations</a>. </li>
         </ul>
         </td>
         </tr>
      </table>

      :::

8. (Optional) If you want to roll back the upgrade, perform the following steps.

    1. Disable the HA feature based on the steps in step 1.

    2. Pause the new container after the upgrade and record the time as T3.

          ```shell
          sudo docker stop ${CONTAINER_NAME}
          ```

    3. Connect to the meta database and run the following command.

          ```shell
          drop database rm_4212;
          drop database cm_4212;
          drop database cm_hb_4212;

          create database rm_4212;
          create database cm_4212;
          create database cm_hb_4212;
          ```

    4. Restore the backed-up database SQL file to the original database.

          ```shell
          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/rm_4212.sql" -Drm_4212

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_4212.sql" -Dcm_4212

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_hb_4212.sql" -Dcm_hb_4212
          ```

    5. Restart the OMS Community Edition V4.2.12-CE container.

          ```shell
          sudo docker restart ${CONTAINER_NAME}
          ```

    6. On the **<UI-TERM key="oms-community.Audit.constants.SystemParameters">System Parameters</UI-TERM>** page, enable the HA feature and set the `refetchStoreIntervalMin` parameter.

       If you perform a rollback, the HA feature will automatically fail over the Store, but you may need to manually restore the Incr-Sync/Full-Import component.

9. After the upgrade, clear your browser cache and log in.
