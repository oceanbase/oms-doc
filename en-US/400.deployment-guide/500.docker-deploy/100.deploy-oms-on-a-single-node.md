# Single-node deployment

This topic describes how to deploy OceanBase Migration Service (OMS) Community Edition in a single-node environment using the OMS Community Edition deployment tool.

## Prerequisites

* Make sure that the installation environment meets the system and network requirements. For more information, see [System and network requirements](../200.system-requirements.md).

* Prepare a MetaDB cluster as the metadata database for OMS Community Edition.

* Download the OMS Community Edition installation package. The installation package is a `tar.gz` file that starts with oms. Download address: [OceanBase Database Community Edition Download Center](https://open.oceanbase.com/softwareCenter/community).

* Load the OMS Community Edition installation package to the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

* Prepare a directory to mount the OMS Community Edition container. The OMS Community Edition creates three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of the OMS Community Edition.

* (Optional) Prepare a time series database to store the performance monitoring data and DDL/DML statistics of the OMS Community Edition.

## Glossary

In the following topics, some commands and prompt messages contain variables that you need to replace. Variables are enclosed in `<>` and are explained as follows:

* OMS Community Edition container mounting directory: For more information, see the description of the OMS Community Edition container mounting directory in the prerequisites.

* Host IP address: the IP address of the host on which the script is executed. In a single-node scenario, it is resolved to the corresponding IP address in the CM configuration information by default.

* OMS_IMAGE: After loading the OMS Community Edition installation package using Docker, you can obtain the corresponding image ID or [REPOSITORY:TAG] by running the `docker images` command. This image ID or [REPOSITORY:TAG] serves as the unique identifier for the loaded image, denoted as `<OMS_IMAGE>`. For example:

   ```shell
   $sudo docker images
   REPOSITORY                               TAG                 IMAGE ID          
   work.oceanbase-dev.com/obartifact-store/oms feature_4.0.0-ce    2786e8a6eccd        
   ```

   In this case, `<OMS_IMAGE>` can be `work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce` or `2786e8a6eccd`. In the following topics, replace `<OMS_IMAGE>` with the appropriate value.

* Existing `config.yaml` configuration file address: the address of the existing `config.yaml` configuration file.

## Deployment process (without a configuration file)

If you do not have a configuration file for OMS Community Edition, we recommend that you generate a new configuration file and deploy OMS Community Edition by using the process without a configuration file. If you have a configuration file, we recommend that you deploy OMS Community Edition by using the process with a configuration file.

1. Log in to the OMS deployment server.

2. (Optional) Deploy a time series database.

   If you want OMS to collect and display monitoring data, deploy a time series database. If you do not want to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the `docker_remote_deploy.sh` script from the loaded image.

   ```shell
   sudo docker run -d --net host --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Here is an example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_3.4.0 bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS container mount directory> -i <Local IP address> -d <OMS_IMAGE>
   ```

   In this case, the OMS Community Edition deployment tool automatically checks whether the CPU, memory, and disk resources meet the requirements. If any of the resources do not meet the requirements, the corresponding resource is insufficient, which affects the data migration speed.

5. Complete the deployment as prompted. Press Enter after each input.

   1. Select the deployment mode.

      Select **Single Region and Single Node**.

   2. Select the task.

      Select **No configuration file, deploy OMS Community Edition from scratch**.

   3. Enter the following MetaDB configuration information.

      1. Enter the IP address, port, username, and password of the metadata database as prompted.

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>The password of the metadata database user cannot be empty. It cannot contain special characters, including line breaks, spaces, and |"'`()=;/&[]{}.</p>
         </main>

      2. Enter a prefix for the OMS Community Edition metadata database.

         For example, if the prefix is set to oms, the names of the created metadata databases are oms_rm, oms_cm, and oms_cm_hb.

      3. Confirm the configuration information.

         Enter y to confirm that the configuration information is correct. Enter n to re-enter the configuration information.

         If the following prompt appears: **The corresponding database name already exists in the metadata database. Is this okay?**, it indicates that the database name you entered already exists in the MetaDB cluster. This situation may be caused by repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment, or enter n to re-enter the configuration information.

         If you enter y, the following prompt appears: **The corresponding database name already exists in the metadata database. Do you want to reinitialize the metadata database?** Enter y to reinitialize the metadata database.

   4. Enter the following OMS Community Edition configuration information.

      1. Set whether to customize the component port numbers and configure the related parameters.

         Enter y to customize the component port numbers. Enter the port numbers of Nginx, GHANA, CM, Supervisor, and sshd services as prompted.

      2. Confirm whether the default IP address is correct.

         The displayed IP address corresponds to the **Local IP address** you entered when you started the deployment script. If the IP address is correct, enter y. If you need to modify the IP address, enter n.

      3. View the OMS Community Edition configuration information. Pay attention to whether the IP address in `cm_url` is the local IP address and whether the custom port number is correct. If the information is correct, enter y. If you need to modify the information, enter n.

   5. Confirm whether to monitor the historical data of OMS Community Edition.

      * If you deployed a time series database in the **(Optional) Deploy a time series database** step, enter y in this step and go to the **Configure the time series database** step to enable monitoring of the historical data of OMS Community Edition.

      * If you did not deploy a time series database in the **(Optional) Deploy a time series database** step, enter n in this step and go to the **Enable the audit log feature and configure the related SLS parameters** step. In this case, OMS Community Edition does not support monitoring historical data after deployment.

   6. Configure the time series database.

      Enter the following time series database configuration information:

      1. Is a time series database service already deployed?

         Enter y if a time series database service is deployed. Enter n otherwise.

      2. Select the type of the time series database: select "INFLUXDB".

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>Only INFLUXDB is supported as the time series database. </p>
         </main>

      3. Enter the URL, username, and password of the time series database as prompted.

      4. Confirm the displayed configuration information.

         Enter y to confirm that the configuration information is correct. Enter n to modify the configuration information.

   7. Enable the audit log feature of OMS Community Edition and write the audit logs to the SLS service.

      Enter y to enable the audit log feature. In this case, go to the **Enter the SLS parameters** step.

      Enter n to skip enabling the audit log feature. In this case, OMS Community Edition does not support the audit log feature after deployment.

   8. Enter the SLS parameters.

       1. Enter the SLS parameters as prompted.

       2. Confirm the displayed configuration information.

            Enter y to confirm that the configuration information is correct. Enter n to modify the configuration information.

   9. If the configuration file check is passed, view all the configuration information. If the information is correct, enter n. If you need to modify the information, enter y.

       If the configuration file check is not passed, modify the configuration information as prompted.

   10. Enter the mount directory for OMS Community Edition on the node with the IP address <Node IP>:

       Enter a directory with sufficient capacity as the mount directory for the OMS Community Edition container.

   11. Confirm whether the image name of OMS Community Edition is <OMS_IMAGE>.

         Enter y to confirm that the image name is correct. Enter n to modify the image name.

   12. Confirm whether to mount an HTTPS certificate to the OMS Community Edition container.

         Enter y to mount an HTTPS certificate. Enter the https_key and https_crt directories as prompted. Enter n to skip mounting an HTTPS certificate.

   13. Confirm whether the path for writing the config.yaml file on the node with the IP address <Node IP> is correct.

         Enter y to confirm that the path is correct. Enter n to modify the path.

   14. Start the deployment.

         * During the deployment, run the `docker logs -f <OMS Community Edition container name>` command to view the initialization progress.

            To view all the startup initialization logs, run the `docker logs <OMS Community Edition container name>` command.

         * If the deployment fails, log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

         * If the OMS container fails to start, you cannot obtain the log information.

## Deployment process (with configuration file)

If you already have an OMS configuration file, you can use the deployment tool to validate the existing configuration file without re-entering the settings. The deployment will proceed based on the existing configuration file.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For more information about the settings in the <code>config.yaml</code> configuration file, see the "Template and example of the configuration file" section below. </p>
   </main>

1. Log in to the OMS deployment server.

2. (Optional) Deploy a time series database.

   If you want OMS to collect and display monitoring data, deploy a time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Start the deployment tool using the deployment script.

   ```shell
   bash docker_remote_deploy.sh -o <OMS container mount directory> -c <Existing config.yaml configuration file address> -i <Local IP address> -d <OMS_IMAGE>
   ```

   At this point, the OMS Community Edition deployment tool will automatically validate the resources for CPU, Memory, and Disk. If any of these resources do not meet the requirements, it will prompt you that the corresponding resource is insufficient, which may affect the data migration speed.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The existing config.yaml configuration file address after <code>-c</code> must be an absolute path. </p>
   </main>

5. Complete the deployment based on the tool's prompts. Press Enter after each input to proceed.

   1. Select the deployment mode.

      Here, select **Single Region Single Node**.

   2. Select the task you need to perform.

      Here, select **Use the reference configuration file passed in by the [-c] option to start the configuration based on the reference configuration file**.

   3. If the prompt **The database name already exists in the metadata database! Is this okay?** appears, it indicates that the database name you entered already exists in the metadata database of the existing configuration file. This situation may be caused by repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment or enter n to re-enter the configuration information.

      If you enter y, the system will prompt you **The database name already exists in the metadata database. Do you want to reinitialize the metadata database?** Enter y to indicate that you want to reinitialize the metadata database.

   4. If the configuration file check is passed, all the configuration information will be displayed. If you confirm that there are no errors, enter n. If you need to modify the configuration, enter y.

      If the configuration file check is not passed, modify the configuration information based on the prompt.

   5. Enter the mount directory for the OMS Community Edition container on the node <Node IP>:

      Enter a directory with sufficient capacity as the mount directory for the OMS Community Edition container.

   6. Confirm whether the image name for deploying the OMS Community Edition is <OMS_IMAGE>.

      If you confirm that there are no errors, enter y. If you need to modify the image name, enter n.

   7. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

      If you need to mount an HTTPS certificate, enter y and enter the https_key and https_crt directories based on the prompt. If you do not need to mount an HTTPS certificate, enter n.

   8. Start the deployment.

         * During the deployment, you can run the `docker logs -f <OMS Community Edition container name>` command to view the initialization progress.

            If you want to view all startup initialization logs, you can run the `docker logs <OMS Community Edition container name>` command.

         * If the deployment fails, log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

         * If the OMS container fails to start, you cannot obtain the log information.

After the deployment is completed, if you need to modify the configuration, perform the following steps:

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file based on your business needs.

3. Go to the `/root` directory and run the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Run the `supervisorctl restart oms_console oms_drc_supervisor` command.

## Template and example of the configuration file

### Configuration file template

<main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>The mandatory parameters in the template must be replaced with actual values of the target environment. Optional parameters are commented out in the template. You can modify them as needed. </p>
    </li>
    <li>
    <p>In the <code>config.yaml</code> file, a space must be added after the colon (:) in the Key: Value format. </p>
    </li>
    </ul>
  </main>

```yaml
# OMS Community Edition metadata database information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# Users can customize the names of the following three databases. When OMS Community Edition is deployed, these three databases are created in the metadata database.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition configuration
# In a single-node deployment, set this parameter to the IP address of the current OMS Community Edition server (we recommend that you use the private IP address).
cm_url: ${cm_url}
cm_location: ${cm_location}
# In a single-node deployment, you do not need to set the cm_region parameter.
# cm_region: ${cm_region}
# In a single-node deployment, you do not need to set the cm_region_cn parameter.
# cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - ${cm_nodes}

# Time series database configuration
# The default value is false. Set this parameter to true if you want to enable the metric reporting feature.
# tsdb_enabled: false
# If tsdb_enabled is set to true, uncomment and modify the following parameters as needed.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}

# Port numbers of custom components
# Specify the port number of the GHANA service.
ghana_server_port: xxxxx
# Specify the port number of the Nginx service.
nginx_server_port: xxxxx
# Specify the port number of the CM service.
cm_server_port: xxxxx
# Specify the port number of the Supervisor service.
supervisor_server_port: xxxxx
# Specify the port number of the sshd service.
sshd_server_port: xxxxx
```

Configuration parameters

| oms_meta_port       | The port number of the metadata database.                                                                                                                                                                                                                                                      | Yes                |
| oms_meta_user       | The username of the metadata database.                                                                                                                                                                                                                                                     | Yes                |
| oms_meta_password   | The password of the metadata database.    <main id="notice" type='notice'><h4>Notice</h4><p>The password of the metadata database cannot be empty. Special characters (including line breaks, spaces, and \|"'`()=;/&[]{}) are not supported. </p></main>                                                                                                                                                                                                                    | Yes                |
| drc_rm_db           | The name of the database in the management console.                                                                                                                                                                                                                                                   | Yes                |
| drc_cm_db           | The name of the metadata database of the cluster management service.                                                                                                                                                                                                                                                 | Yes                |
| drc_cm_heartbeat_db | The name of the heartbeat database of the cluster management service.                                                                                                                                                                                                                                                 | Yes                |
| cm_url              | The address of the cluster management service of OMS Community Edition. For example, `http://xxx.xxx.xxx.1:8088`. <br>**Note:** <br> In single-node deployment, the address is usually set to the IP address of the OMS Community Edition server. We recommend that you do not use `http://127.0.0.1:8088`. <br>The access address of the OMS Community Edition console is `IP address of the host where OMS is deployed:8089`. For example, `http://xxx.xxx.xxx.1:8089` or `https://xxx.xxx.xxx.1:8089`. <br>Port 8088 is used for scheduling, and port 8089 is used for web access. | Yes                |
| cm_location         | The region code, which ranges from 0 to 127. Each region is represented by a unique number. You can select any region.                                                                                                                                                                                                                           | Yes                |
| cm_region           | The region, such as cn-jiangsu. <br>**Notice:**<br>  If you use OMS Community Edition in a disaster recovery active-active scenario with Alibaba Cloud MSHA, use the region information of Alibaba Cloud as the value of `cm_region`.                                                                                                                                           | No                 |
| cm_region_cn        | The Chinese name of the region. For example, Jiangsu.                                                                                                                                                                                                                                                 | No                 |
| cm_nodes            | The IP address list of the cluster management service of OMS Community Edition.                                                                                                                                                                                                                                           | Yes                |
| cm_is_default       | Specifies whether to use the default cluster management service of OMS Community Edition.                                                                                                                                                                                                                                             | No. Default value: `true`    |
| tsdb_enabled        | Specifies whether to enable the metric reporting feature (monitoring capability). Valid values: `true` and `false`.                                                                                                                                                                                                                       | No. Default value: `false`   |
| tsdb_service        | The type of the time series database. Valid values: `INFLUXDB` and `CERESDB`.                                                                                                                                                                                                                          | No. Default value: `INFLUXDB` |
| tsdb_url            | The IP address of the server where InfluxDB is deployed. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your actual environment.                                                                                                                                                                                                    | No                 |
| tsdb_username       | The username of the time series database. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your actual environment. After you deploy the time series database, you must manually create a time series database user and specify the username and password.                                                                                                                                                        | No                 |
| tsdb_password       | The password of the time series database. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your actual environment.              | No                 |
| ghana_server_port | The port number of the GHANA service. If not specified, the default port number 8090 is used. |No|
| nginx_server_port | The port number of the Nginx service. If not specified, the default port number 8089 is used. |No|
| cm_server_port    | The port number of the CM service. If not specified, the default port number 8088 is used. |No|
| supervisor_server_port | The port number of the Supervisor service. If not specified, the default port number 9000 is used. |No|
| sshd_server_port | The port number of the sshd service. If not specified, the default port number 2023 is used. |No|

### Sample configuration file

Replace the parameter values with those of your deployment target environment.

```yaml
oms_meta_host: xxx.xxx.xxx.1
oms_meta_port: 2883
oms_meta_user: oms_meta_user
oms_meta_password: ********
drc_rm_db: oms_rm
drc_cm_db: oms_cm
drc_cm_heartbeat_db: oms_cm_heartbeat
cm_url: http://xxx.xxx.xxx.2:8088
cm_location: 100
cm_region: cn-anhui
cm_region_cn: Anhui
cm_is_default: true
cm_nodes:
  - xxx.xxx.xxx.2
tsdb_service: 'INFLUXDB'
tsdb_enabled: true
tsdb_url: 'xxx.xxx.xxx.4:8086'
tsdb_username: username
tsdb_password: *******
ghana_server_port: xxxxx
nginx_server_port: xxxxx
cm_server_port: xxxxx
supervisor_server_port: xxxxx
sshd_server_port: xxxxx
```
