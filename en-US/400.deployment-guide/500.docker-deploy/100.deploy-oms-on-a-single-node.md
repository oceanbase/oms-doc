# Single-node deployment

This topic describes how to deploy OceanBase Migration Service (OMS) Community Edition by using the OMS Community Edition deployment tool on a single node.

## Prerequisites

* The installation environment meets the system and network requirements. For more information, see [System and network requirements](../200.system-requirements.md).

* A MetaDB cluster is prepared as the metadata repository for OMS Community Edition.

* The OMS Community Edition installation package is obtained. The installation package is usually a `tar.gz` file that starts with oms. Download address: [OceanBase Community Edition download center](https://open.oceanbase.com/softwareCenter/community).

* The downloaded OMS Community Edition installation package is loaded to the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

* A directory for mounting the OMS Community Edition container is prepared. The OMS Community Edition creates three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of the OMS Community Edition.

* (Optional) A time-series database is prepared to store the performance monitoring data and DDL/DML statistical data of the OMS Community Edition.

## Glossary

In the following topics, some commands and prompt information contain variable names that you need to replace. Variable names are enclosed in `<>` and are explained as follows:

* OMS Community Edition container mounting directory: For more information, see the "Prerequisites" section.

* Host IP address: The IP address of the host where the script is executed. In a single-node scenario, it is resolved to the corresponding IP address in the CM configuration information by default.

* OMS_IMAGE: After loading the OMS Community Edition installation package using Docker, you can use the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image. This identifier is represented as `<OMS_IMAGE>`. For example:

   ```shell
   $sudo docker images
   REPOSITORY                               TAG                 IMAGE ID          
   work.oceanbase-dev.com/obartifact-store/oms feature_4.0.0-ce    2786e8a6eccd        
   ```

   In this case, `<OMS_IMAGE>` can be `work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce` or `2786e8a6eccd`. In the subsequent topics, replace `<OMS_IMAGE>` with the appropriate value.

* Existing `config.yaml` configuration file address: If you need to deploy based on an existing `config.yaml` configuration file, this is the address of the existing configuration file.

## Deployment process (without a configuration file)

If you do not have a configuration file for OMS Community Edition, we recommend that you generate a new configuration file and deploy OMS Community Edition. If you have a configuration file, we recommend that you deploy OMS Community Edition by using the configuration file.

1. Log in to the OMS deployment server.

2. (Optional) Deploy a time-series database.

   If you want OMS to collect and display monitoring data, deploy a time-series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time-series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --net host --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Here is an example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_3.4.0 bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS container mount directory> -i <Local IP address> -d <OMS_IMAGE>
   ```

   In this case, the OMS Community Edition deployment tool automatically checks the CPU, memory, and disk resources. If any of the resources do not meet the requirements, the corresponding resource is insufficient, which affects the data migration speed.

5. Complete the deployment based on the prompts. Press Enter after each input.

   1. Select the deployment mode:

      Select **Single Region Single Node**.

   2. Select the task:

      Select **No configuration file, deploy OMS Community Edition from scratch**.

   3. Enter the following MetaDB configuration information:

      1. Enter the IP address, port number, username, and password of the metadata database.

      2. Set a prefix for the metadata database of OMS Community Edition.

         For example, if the prefix is set to oms, the names of the created metadata databases are oms_rm, oms_cm, and oms_cm_hb.

      3. Confirm the configuration information.

         Enter y to confirm that the configuration information is correct. Enter n to re-enter the configuration information.

         If the prompt **The corresponding database name already exists in the metadata database. Is this okay?** appears, it indicates that the database name you entered already exists in the MetaDB cluster. This may be due to repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment, or enter n to re-enter the configuration information.

         If you enter y, the prompt **The corresponding database name already exists in the metadata database. Do you want to reinitialize the metadata database?** appears. Enter y to reinitialize the metadata database.

   4. Enter the following OMS Community Edition configuration information:

      1. Set whether to customize the port numbers of components and configure the related parameters.

         Enter y to customize the port numbers of components. Enter the port numbers of Nginx, GHANA, CM, Supervisor, and sshd services.

      2. Confirm whether the default IP address is correct.

         The displayed IP address corresponds to the **Local IP address** you entered when you started the deployment script. If the IP address is correct, enter y. If you need to modify the IP address, enter n.

      3. View the OMS Community Edition configuration information. Pay attention to whether the IP address in `cm_url` is the local IP address and whether the custom port numbers are correct. If the information is correct, enter y. If you need to modify the information, enter n.

   5. Confirm whether to monitor the historical data of OMS Community Edition.

      * If you deployed a time-series database in the **(Optional) Deploy a time-series database** step, enter y and jump to the **Configure the time-series database** step to enable the monitoring of the historical data of OMS Community Edition.

      * If you did not deploy a time-series database in the **(Optional) Deploy a time-series database** step, enter n and jump to the **Enable the audit log feature and configure the related SLS parameters** step. In this case, the deployed OMS Community Edition does not support the monitoring of historical data.

   6. Configure the time-series database.

      Enter the following time-series database configuration information:

      1. Is a time-series database service already deployed?

         Enter y if a time-series database service is already deployed. Enter n otherwise.

      2. Select the type of the time-series database: select "INFLUXDB".

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>Currently, only INFLUXDB is supported as the time-series database. </p>
         </main>

      3. Enter the URL, username, and password of the time-series database.

      4. Confirm all the displayed configuration information.

         If the information is correct, enter y. If you need to modify the information, enter n.

   7. Do you want to enable the audit log feature of OMS Community Edition and write the audit logs to the SLS service?

      If you enter y, the audit log feature is enabled. In this case, jump to the **Enter the SLS parameters** step.

      If you enter n, the deployment starts. In this case, the deployed OMS Community Edition does not support the audit log feature.

   8. Enter the SLS parameters.

       1. Enter the SLS parameters.

       2. Confirm all the displayed configuration information.

            If the information is correct, enter y. If you need to modify the information, enter n.

   9. If the configuration file is validated, all the configuration information is displayed. If the information is correct, enter n. If you need to modify the information, enter y.

       If the configuration file is not validated, modify the configuration information based on the prompt.

   10. Enter the mount directory for OMS Community Edition on the node <Node IP>:

       Enter a directory with sufficient capacity as the mount directory for the OMS Community Edition container.

   11. Confirm whether the image name <OMS_IMAGE> for OMS Community Edition is correct.

         If the image name is correct, enter y. If you need to modify the image name, enter n.

   12. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

         If you need to mount an HTTPS certificate, enter y and enter the https_key and https_crt directories based on the prompt. If you do not need to mount an HTTPS certificate, enter n.

   13. Confirm whether the config.yaml file on the node <Node IP> can be written to the specified path.

         If the path is correct, enter y. If you need to modify the path, enter n.

   14. Start the deployment.

         * During the deployment, you can run the `docker logs -f <OMS Community Edition container name>` command to view the initialization status.

            To view all the initialization logs, run the `docker logs <OMS Community Edition container name>` command.

         * If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

         * If the OMS container fails to start, you cannot obtain the log information.

## Deployment process (with configuration file)

If you have an existing OMS configuration file, you can use the deployment tool to validate the previous configuration file without re-entering the configuration. The deployment will be based on the previous configuration file.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>For information about the settings in the <code>config.yaml</code> file, see the <a href="#template">Template and Example</a> section. </p>
   </main>

1. Log in to the OMS deployment server.

2. (Optional) Deploy a time series database.

   If you want OMS to collect and display monitoring data, deploy a time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS container mount directory> -c <Existing config.yaml file path> -i <Local IP address> -d <OMS_IMAGE>
   ```

   At this point, the OMS Community Edition deployment tool will automatically validate the resources of CPU, Memory, and Disk. If any of the resources do not meet the requirements, it will prompt that the corresponding resource is insufficient, which will affect the data migration speed.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <p>The path of the existing <code>config.yaml</code> file specified after <code>-c</code> must be an absolute path. </p>
   </main>

5. Complete the deployment based on the prompts provided by the tool. Press Enter to proceed to the next step after each input.

   1. Select the deployment mode.

      Here, select **Single Region and Single Node**.

   2. Select the task you want to perform.

      Here, select **Use the reference configuration file provided by the [-c] option to start the configuration**.

   3. If the prompt **The database name already exists in the meta database! Is this okay?** appears, it indicates that the database name you entered already exists in the meta database of the original configuration file. This situation may be caused by repeated deployment or OMS Community Edition upgrade. Please confirm and enter y to continue the deployment, or enter n to re-enter the configuration information.

      If you enter y, it will prompt you **The database name already exists in the meta database. Do you want to re-initialize the meta database?** Enter y to indicate that you need to re-initialize the meta database.

   4. If the configuration file is validated, all the configuration information will be displayed. If you confirm that it is correct, enter n. If you need to modify the configuration, enter y.

      If the configuration file is not validated, please modify the configuration information according to the prompt.

   5. Enter the mount directory for the OMS Community Edition container on node <Node IP>:

      Enter a directory with a large capacity as the mount directory for the OMS Community Edition container.

   6. Confirm whether the image name for deploying OMS Community Edition is <OMS_IMAGE>.

      If you confirm that it is correct, enter y. If you need to modify it, enter n.

   7. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

      If you need to, enter y and enter the https_key and https_crt directories according to the prompt. If you do not need to, enter n.

   8. Start the deployment.

         * During the deployment, you can run the `docker logs -f <OMS Community Edition container name>` command to view the initialization status.

            If you want to view all the initialization logs, you can run the `docker logs <OMS Community Edition container name>` command.

         * If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

         * If the OMS container fails to start, you cannot obtain the logs.

After the deployment is completed, if you need to modify the configuration, perform the following steps:

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file based on your business requirements.

3. Run the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Run the `supervisorctl restart oms_console oms_drc_supervisor` command.

## Templates and examples of configuration files

### Configuration file template

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>The required parameters in the template must be replaced with the actual values of the target environment where you deploy the service. Optional parameters are commented in the template. You can modify them as needed. </p>
    </li>
    <li>
    <p>In the <code>config.yaml</code> file, the colon (:) in the Key:Value pair must be followed by a space. </p>
    </li>
    </ul>
  </main>

```yaml
# OMS Community Edition metadata database information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# You can customize the names of the following three databases. When you deploy OMS Community Edition, the three databases are created in the metadata database.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition configuration
# In single-node deployment, the IP address of the current OMS Community Edition server is usually configured as the value. We recommend that you use the private IP address.
cm_url: ${cm_url}
cm_location: ${cm_location}
# In single-node deployment, you do not need to set cm_region.
# cm_region: ${cm_region}
# In single-node deployment, you do not need to set cm_region_cn.
# cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - ${cm_nodes}

# Time-series database configuration
# The default value is false. Set this parameter to true if you want to enable the metrics reporting feature.
# tsdb_enabled: false
# If tsdb_enabled is set to true, you need to uncomment the following parameters and set them to the actual values.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}

# Port numbers of user-defined components
# Port number of the GHANA service
ghana_server_port: xxxxx
# Port number of the Nginx service
nginx_server_port: xxxxx
# Port number of the CM service
cm_server_port: xxxxx
# Port number of the Supervisor service
supervisor_server_port: xxxxx
# Port number of the sshd service
sshd_server_port: xxxxx
```

Configuration parameters

:::collapse

|         Parameter          |                            Description                     |       Required        |
|---------------------|----------------------------------------------------------------------------------------------|-------------------|
| oms_meta_host       | The IP address of the metadata database, which can be MySQL or OceanBase Database Community Edition.                  | Required                |
| oms_meta_port       | The port number of the metadata database.                                                                                                                                                                                                                                                      | Required                |
| oms_meta_user       | The username of the metadata database.                                                                                                                                                                                                                                                     | Required                |
| oms_meta_password   | The password of the metadata database.                                                                                                                                                                                                                                                     | Required                |
| drc_rm_db           | The name of the database for the management console.                                                                                                                                                                                                                                                   | Required                |
| drc_cm_db           | The name of the metadata database for the cluster management service.                                                                                                                                                                                                                                                 | Required                |
| drc_cm_heartbeat_db | The name of the heartbeat database for the cluster management service.                                                                                                                                                                                                                                                 | Required                |
| cm_url              | The address of the cluster management service of OMS Community Edition. For example, `http://xxx.xxx.xxx.1:8088`. <br>**Note:** <br> In single-node deployment, the IP address of the current OMS Community Edition server is usually configured as the value. We recommend that you do not use `http://127.0.0.1:8088`. <br>The address for accessing the OMS Community Edition console is `IP address of the host where OMS is deployed:8089`. For example, `http://xxx.xxx.xxx.1:8089`. <br>Port 8088 is for scheduling, and port 8089 is for web access. | Required                |
| cm_location         | The region code. The value is an integer between 0 and 127. Each region is represented by a unique number. You can select the region as needed.                                                                                                                                                                                                                           | Required                |
| cm_region           | The region. For example, cn-jiangsu. <br>**Notice:**<br> If you use the service in the disaster recovery active-active scenario with Alibaba Cloud MSHA, use the region information of Alibaba Cloud as the value of `cm_region`.                                                                                                                                           | Optional                |
| cm_region_cn        | The Chinese name of the region. For example, Jiangsu.                                                                                                                                                                                                                                                 | Optional                |
| cm_nodes            | The IP address list of the cluster management service of OMS Community Edition.                                                                                                                                                                                                                                           | Required                |
| cm_is_default       | Indicates whether to use the default cluster management service of OMS Community Edition.                                                                                                                                                                                                                                             | Optional. Default value: `true`    |
| tsdb_enabled        | Indicates whether to enable the metrics reporting feature (monitoring capability). Valid values: `true` and `false`.                                                                                                                                                                                                                       | Optional. Default value: `false`   |
| tsdb_service        | The type of the time-series database. Valid values: `INFLUXDB` and `CERESDB`.                                                                                                                                                                                                                          | Optional. Default value: `INFLUXDB` |
| tsdb_url            | The IP address of the server where InfluxDB is deployed. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your environment.                                                                                                                                                                                                    | Optional                |
| tsdb_username       | The username of the time-series database. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your environment. After you deploy the time-series database, you must manually create a user for the time-series database and specify the username and password.                                                                                                                                                        | Optional                |
| tsdb_password       | The password of the time-series database. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your environment.              | Optional                |
| ghana_server_port | The port number of the GHANA service. If not specified, the default port number 8090 is used. |Optional|
| nginx_server_port | The port number of the Nginx service. If not specified, the default port number 8089 is used. |Optional|
| cm_server_port    | The port number of the CM service. If not specified, the default port number 8088 is used. |Optional|
| supervisor_server_port | The port number of the Supervisor service. If not specified, the default port number 9000 is used. |Optional|
| sshd_server_port | The port number of the sshd service. If not specified, the default port number 2023 is used. |Optional|

:::

```yaml

drc_rm_db: oms_rm
drc_cm_db: oms_cm
drc_cm_heartbeat_db: oms_cm_heartbeat

cm_region_cn: Anhui
cm_is_default: true
cm_nodes:
  - xxx.xxx.xxx.2
tsdb_service: 'INFLUXDB'
tsdb_enabled: true
tsdb_url: 'xxx.xxx.xxx.4:8086'
tsdb_username: username
tsdb_password: *******
```
