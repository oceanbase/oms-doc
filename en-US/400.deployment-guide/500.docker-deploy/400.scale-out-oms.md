# Scale out

This topic describes how to scale out a cluster in a single region and a single node, and how to scale out a cluster in a single region with multiple nodes.

## Expand a single-node cluster to a multi-node cluster

Expanding a single-node cluster to a multi-node cluster involves two scenarios:

* The initial node has a VIP as the `cm_url`.

* The initial node has a physical IP address as the `cm_url`.

### Initial node has a VIP as the `cm_url`

The specific steps are the same as those for deploying a single node. For more information, see [Deploy OMS Community Edition on a single node](../500.docker-deploy/100.deploy-oms-on-a-single-node.md).

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>When you start the container, set the value of <code>-e OMS_HOST_IP</code> to the IP address of the current server. </p>
  </main>

Assume that the initial node has `cm_nodes` set to xxx.xxx.xxx.1 and the expanded node has `cm_nodes` set to xxx.xxx.xxx.2. The `config.yaml` file is configured as follows.

```yaml
# OMS Community Edition metadata database information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# When you expand a single-node cluster to a multi-node cluster, the names of the following three databases must be consistent with those of the initial node.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition cluster configuration
cm_url: http://VIP:8088
cm_location: ${cm_location}
cm_region: ${cm_region}
cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - xxx.xxx.xxx.1
 - xxx.xxx.xxx.2

# Time series database configuration
# The default value is false. If you want to enable the metric reporting feature, set this parameter to true and remove the comment mark before the parameter.
# tsdb_enabled: false
# If tsdb_enabled is set to true, remove the comment mark before the following parameters and set the values based on your business requirements.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}
```

### Initial node has a physical IP address as the `cm_url`

In this scenario, you need to correct the databases. The procedure is as follows:

<main id="notice" type='explain'>
<h4>Note</h4>
<p>You need to correct the <code>location_cm</code>, <code>host</code>, and <code>resource_group</code> tables in the <code>drc_cm_db</code> database, and the <code>cluster_info</code> table in the <code>drc_rm_db</code> database. </p>
</main>

1. Configure a VIP, SLB, or domain name and bind all physical IP addresses in the current region.

   For example, the VIP is bound to the physical IP addresses xxx.xxx.xxx.1 and xxx.xxx.xxx.2.

2. Stop the processes in the original container. For example, stop the processes in the oms_330 container.

   ```shell
   sudo docker exec -it oms_330 bash  
   supervisorctl stop all
   ```

3. Take the `drc_rm_db` database and the `cluster_info` table as an example. Log in to the database and perform the following steps:

   1. Query the data in the `cluster_info` table for backup.

      ```shell
      select * from cluster_info;
      ```

   2. Delete the data in the `cluster_info` table.

      ```shell
      delete from cluster_info;
      ```

4. Modify the configuration file in the oms_330 container.

   ```shell
   # /home/admin/conf/config.yaml is a fixed directory in the Docker container.
   sudo vi /home/admin/conf/config.yaml

   # Modify the cm_url address and add cm_nodes:
   cm_url: http://VIP:8088
   cm_nodes:
    - xxx.xxx.xxx.1
    - xxx.xxx.xxx.2
   ```

5. Perform the initialization operation again.

   ```shell
   sudo sh /root/docker_init.sh
   ```

   After the initialization is completed, check whether the `cm_url` address in the `cluster_info` table is the VIP address.

6. Copy the same configuration file and start the OMS Community Edition container on another server.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>When you start the container, set the value of <code>-e OMS_HOST_IP</code> to the IP address of the current server. </p>
    </li>
    <li>
    <p>Replace <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> with the name of the image actually imported by executing the <code>docker load -i</code> command. </p>
    </li
    </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # Set the following two parameters only when you mount the HTTPS certificate in the OMS Community Edition container.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

## Expand a single-region deployment to a multi-region deployment

The steps for expanding a single-region deployment to a multi-region deployment are the same as those for deploying a single node. The difference is that in the `config.yaml` file, the `drc_cm_heartbeat_db` parameter must be different from the initial OMS Community Edition database. Additionally, you must modify the `cm_url`, `cm_location`, `cm_region`, `cm_region_cn`, `cm_is_default`, and `cm_nodes` parameters to match the new region.

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy the time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy the time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Prepare the configuration file.

   Edit the OMS Community Edition startup configuration file in the appropriate directory. For example, you can create the configuration file as `/root/config.yaml`.

   Make sure to replace the required parameters with the actual values of your deployment target environment. For example, if you are expanding the machine xxx.xxx.xxx.xx1 to the Jiangsu region, the `config.yaml` file is configured as follows.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>In the <code>config.yaml</code> file, the colon after the Key: Value must be followed by a space. </p>
   </main>

   ```yaml
   # OMS metadata information
   oms_meta_host: ${oms_meta_host}
   oms_meta_port: ${oms_meta_port}
   oms_meta_user: ${oms_meta_user}
   oms_meta_password: ${oms_meta_password}

   # The configurations of drc_rm_db, drc_cm_db, and the initial node remain the same.
   drc_rm_db: ${drc_rm_db}
   drc_cm_db: ${drc_cm_db}
   # The drc_cm_heartbeat_db parameter must be different from the heartbeat_db database of the initial node.
   drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

   # OMS Community Edition cluster configuration
   # Fill in the parameters with the configurations of the expanded region.
   cm_url: http://xxx.xxx.xxx.1:8088
   cm_location: ${cm_location}
   cm_region: cn-jiangsu
   cm_region_cn: Jiangsu
   cm_is_default: true
   cm_nodes:
    - xxx.xxx.xxx.1

   # Time series database configuration
   # The default value is false. If you want to enable the metric reporting feature, set this parameter to true and remove the comment before it.
   # tsdb_enabled: false
   # If tsdb_enabled is set to true, remove the comment before the following parameters and fill in the values based on your actual situation.
   # tsdb_service: 'INFLUXDB'
   # tsdb_url: '${tsdb_url}'
   # tsdb_username: ${tsdb_user}
   # tsdb_password: ${tsdb_password}
   ```

   Parameter description

   :::collapse

   |         Parameter          |                                 Description                   |       Required      |
   |---------------------|-------------------------------------------------------------|-------------------|
   | oms_meta_host       | The IP address of the metadata database, which can be a MySQL database or an OceanBase Database in MySQL compatible mode.                                            | Yes                |
   | oms_meta_port       | The port number of the metadata database.                                                                                                                                                                   | Yes                |
   | oms_meta_user       | The username of the metadata database.                                                                                                                                                                  | Yes                |
   | oms_meta_password   | The password of the metadata database. <main id="notice" type='notice'><h4>Notice</h4><p>The password of the metadata database cannot be empty, and it does not support special characters (including line breaks, spaces, and \|"'`()=;/&[]{}). </p></main>                                                                                                                                                                    | Yes                |
   | drc_rm_db           | The name of the database in the management console.    | drc_cm_db           | The name of the metadata database for the cluster management service.    | drc_cm_heartbeat_db | The name of the heartbeat database for the cluster management service.    | cm_url              | The address of the cluster management service of the OMS Community Edition.    | cm_location         | The region code, which ranges from \[0,127\]. Each region is assigned a unique number. You can choose any number.                                                                                                                                        | Yes                |
   | cm_region           | The region, for example, cn-jiangsu. <br> **Notice:**<br>   If you are using the OMS Community Edition in a disaster recovery active-active scenario with Alibaba Cloud MSHA, use the region information of Alibaba Cloud as the `cm_region` value.                                                        | No                 |

   | cm_nodes            | The IP address list of the cluster management service of the OMS Community Edition.    | cm_is_default       | Indicates whether the OMS Community Edition cluster management service is the default one. <br> **Notice:**<br>   When multiple regions are configured, only one region can be set to `true` for `cm_is_default`, indicating the default OMS Community Edition cluster management service.                                                    | No. Default value: `true`    |

   | tsdb_password       | The password of the time series database. 4. Load the downloaded OMS Community Edition installation package into the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

5. Run the following command to start the container.

   OMS Community Edition supports access to the OMS Community Edition console via HTTP or HTTPS protocols. If you want to securely access OMS Community Edition, you can provide an HTTPS certificate and mount it to the specified directory within the container. If you use the HTTP protocol to access OMS Community Edition, no configuration is required.

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # Only when you mount an HTTPS certificate to the OMS Community Edition container, you need to set the following two parameters
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

6. Enter the new container.

   ```shell
   docker exec -it  ${CONTAINER_NAME} bash  
   ```

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p><code>CONTAINER_NAME</code> is the name of the container that you created. </p>
   </main>

7. In the root directory, perform metadata initialization.

   ```shell
   bash /root/docker_init.sh
   ```

   After you execute the command, the initialization process proceeds as follows:

   1. Initialize data in the metadata database.

   2. Generate configuration files for each component.

   3. Restart all components.

   4. Initialize the resource tags and resource groups in the OMS Community Edition.

   During the execution of `docker_init.sh`, pay attention to the command-line output. After the initialization is successful, the system displays **【End】All initialization steps are completed.**.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The initialization process takes 2 to 4 minutes. Do not interrupt the process. </p>
   </main>

## Multi-node scaling in a single region

### Initial environment is set up with two nodes in a single region, with cm_url set to VIP

This topic uses OMS Community Edition V4.2.7-CE as an example to describe how to expand `docker_remote_deploy.sh` in a single region with multiple nodes.

1. Pull the OMS Community Edition V4.2.7-CE image and obtain the deployment script from the loaded image.

   ```shell
   sudo docker pull <OMS_IMAGE>

   sudo docker run -d --net host --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

2. Use the deployment script to start the deployment tool.

   ```shell
   sudo sh docker_remote_deploy.sh -o <OMS container mount directory> -i <local IP address> -d <OMS_IMAGE>
   ```

3. Follow the tool's prompts to deploy the two nodes in a single region. For more information, see [Deploy OMS in a single region with multiple nodes](../500.docker-deploy/200.deploy-oms-on-multiple-nodes-in-a-single-region.md).

4. Wait for the initialization steps to complete and log in to the OMS Community Edition console to confirm.

### Step 2: Scale out the cluster

For example, when the cm_url of the primary node is set to the VIP `http://xxx.xxx.xxx.1:1188` and the cm_nodes of the added node is set to xxx.xxx.xxx.2, you can perform the following operations to expand the nodes in the same region.

1. Configure VIPs, SLBs, or domains and bind them to the added and expanded nodes.

2. Copy the configuration file to the scaled-out node and add the new node xxx.xxx.xxx.2 to the `cm_nodes` parameter in the copied `config.yaml` file.

3. Execute the command to launch the container.

   ```shell
   OMS_HOST_IP=xxx.xxx.xxx.2
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # You must specify the following two parameters if you mount an HTTPS certificate in the OMS container.
   #-v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   #-v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

   Startup parameters

   :::collapse

   |           Parameter            |                                                                                                        Description                                                                                                         |
   |-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | OMS_HOST_IP             | The IP address of the host. The value of this parameter must be set to the IP address of the current expansion machine.                                                                                                                                     |
   | CONTAINER_NAME          | The name of the container. The value is in the format of oms_xxx. Please fill in xxx based on the specific version.                                                       |
   | IMAGE_TAG               | After you load the OMS Community Edition installation package by using Docker, you can run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image.    | /data/oms/oms_logs <br> /data/oms/oms_store   <br> /data/oms/oms_run      | You can replace `/data/oms/oms_logs`, `/data/oms/oms_store`, and `/data/oms/oms_run` with the mount directories created on the OMS Community Edition deployment machine.    | /data/oms/https_crt (optional)<br>/data/oms/https_key (optional) | The mount path of the HTTPS certificate in the OMS Community Edition container. 4. Enter the container.

   ```shell
   docker exec -it  ${CONTAINER_NAME} bash  
   ```

5. In the `root` directory, execute the metadata initialization operation.

   ```shell
   bash /root/docker_init.sh
   ```

6. Wait for the initialization to complete and log in to the OMS Community Edition console to confirm.
