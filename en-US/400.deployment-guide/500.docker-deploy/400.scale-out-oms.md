# Scale out

This topic describes how to scale out a single region and a single node, and how to scale out multiple nodes in a single region.

## Expand a single-node cluster to a multi-node cluster

You can expand a single-node cluster to a multi-node cluster in the following scenarios:

* The initial node is configured with a VIP as the cm_url.

* The initial node is configured with the IP address of a physical server as the cm_url.

### The cm_url of the initial environment is set to the VIP

The specific steps are the same as those for single-node deployment. For more information, see [Deploy OMS on a single node](../500.docker-deploy/100.deploy-oms-on-a-single-node.md).

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>When you start a container, set the value of <code>-e OMS_HOST_IP</code> to the IP address of the current server. </p>
  </main>

The following example shows the configuration of the `config.yaml` file. The `cm_nodes` of the initial node is set to xxx.xxx.xxx.1, and the `cm_nodes` of the expanded node is set to xxx.xxx.xxx.2.

```yaml
# OMS Community Edition metadata information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# When you expand a single node to multiple nodes, the names of the following three databases must be consistent with those of the initial node.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition cluster configuration
cm_url: http://VIP:8088
cm_location: ${cm_location}
cm_region: ${cm_region}
cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - xxx.xxx.xxx.1
 - xxx.xxx.xxx.2

# Time series database configuration
# The default value is false. If you want to enable the metric reporting feature, set this parameter to true and remove the preceding #.
# tsdb_enabled: false
# When tsdb_enabled is set to true, remove the preceding # from the following parameters and set the values based on your actual configuration.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}
```

### The initial environment configuration uses the IP address of a physical server as the cm_url.

In this scenario, you need to correct the database. Perform the following steps.

<main id="notice" type='explain'>
<h4>Note</h4>
<p>You need to correct the <code>location_cm</code>, <code>host</code>, and <code>resource_group</code> tables in the <code>drc_cm_db</code> database, and the <code>cluster_info</code> table in the <code>drc_rm_db</code> database. </p>
</main>

1. Configure the VIP, SLB, or domain name and bind all the IP addresses of the physical servers in the current region.

   For example, the VIP is bound to the IP addresses of the physical servers, such as xxx.xxx.xxx.1 and xxx.xxx.xxx.2.

2. Stop the processes in the original container. For example, stop the processes in the oms_330 container.

   ```shell
   sudo docker exec -it oms_330 bash  
   supervisorctl stop all
   ```

3. Take the <code>drc_rm_db</code> database and the <code>cluster_info</code> table as an example. Log in to the database and perform the following steps.

   1. Query the data in the <code>cluster_info</code> table for backup.

      ```shell
      select * from cluster_info;
      ```

   2. Delete the data in the <code>cluster_info</code> table.

      ```shell
      delete from cluster_info;
      ```

4. Modify the configuration file in the oms_330 container.

   ```shell
   # /home/admin/conf/config.yaml is a fixed directory in Docker.
   sudo vi /home/admin/conf/config.yaml

   # Modify the cm_url address and add cm_nodes:
   cm_url: http://VIP:8088
   cm_nodes:
    - xxx.xxx.xxx.1
    - xxx.xxx.xxx.2
   ```

5. Reinitialize the system.

   ```shell
   sudo sh /root/docker_init.sh
   ```

   After the initialization is complete, confirm that the cm_url address of the <code>cluster_info</code> table in the database is the VIP address.

6. Copy the same configuration file and start the OMS Community Edition container on another server.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>When you start the container, set the value of <code>-e OMS_HOST_IP</code> to the IP address of the current server. </p>
    </li>
    <li>
    <p>Replace <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> with the name of the image that is actually imported by executing the <code>docker load -i</code> command. </p>
    </li
    </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # Mount the HTTPS certificate in the OMS Community Edition container.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

## Expand a single-region single-node environment to a multi-region single-node environment

The operation steps for expanding a single-region single-node environment to a multi-region single-node environment are the same as those for deploying a single node. The difference is that in the `config.yaml` file, the `drc_cm_heartbeat_db` parameter must be different from the initial OMS Community Edition database. You also need to modify the `cm_url, cm_location`, `cm_region`, `cm_region_cn`, `cm_is_default`, and `cm_nodes` parameters to the new region's configuration.

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy the time-series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy the time-series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy the time-series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Prepare the configuration file.

   Edit the OMS Community Edition startup configuration file in the appropriate directory. For example, you can create the configuration file as `/root/config.yaml`.

   Please replace the required parameters with the actual values of your target environment. For example, when expanding the machine xxx.xxx.xxx.xx1 to the Jiangsu region, the `config.yaml` file is configured as follows.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>In the <code>config.yaml</code> file, the colon (:) after the key must be followed by a space. </p>
   </main>

   ```yaml
   # OMS metadata information
   oms_meta_host: ${oms_meta_host}
   oms_meta_port: ${oms_meta_port}
   oms_meta_user: ${oms_meta_user}
   oms_meta_password: ${oms_meta_password}

   # The configurations of drc_rm_db and drc_cm_db are the same as those of the initial node.
   drc_rm_db: ${drc_rm_db}
   drc_cm_db: ${drc_cm_db}
   # drc_cm_heartbeat_db must be different from the heartbeat_db database of the initial node.
   drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

   # OMS Community Edition cluster configuration
   # Fill in the configurations of the expanded region.
   cm_url: http://xxx.xxx.xxx.1:8088
   cm_location: ${cm_location}
   cm_region: cn-jiangsu
   cm_region_cn: Jiangsu
   cm_is_default: true
   cm_nodes:
    - xxx.xxx.xxx.1

   # Time-series database configuration
   # The default value is false. If you want to enable the metrics reporting feature, set it to true and remove the comment before the parameter.
   # tsdb_enabled: false
   # When tsdb_enabled is set to true, remove the comments before the following parameters and fill in the actual values.
   # tsdb_service: 'INFLUXDB'
   # tsdb_url: '${tsdb_url}'
   # tsdb_username: ${tsdb_user}
   # tsdb_password: ${tsdb_password}
   ```

   Configuration parameters

   :::collapse

   |         Parameter          |                                 Description                   |       Required      |
   |---------------------|-------------------------------------------------------------|-------------------|
   | oms_meta_host       | The IP address of the metadata database, which can be MySQL or OceanBase Database in MySQL compatible mode.                                            | Yes                |
   | oms_meta_port       | The port number of the metadata database.                                                                                                                                                                   | Yes                |
   | oms_meta_user       | The username of the metadata database.                                                                                                                                                                  | Yes                |
   | oms_meta_password   | The password of the metadata database.                                                                                                                                                                  | Yes                |
   | drc_rm_db           | The name of the database of the management console. It must be the same as that of the initial node.                                                                                                                                                  | Yes                |
   | drc_cm_db           | The name of the metadata database of the cluster management service.    | drc_cm_heartbeat_db | The name of the heartbeat database of the cluster management service.    | cm_url              | The address of the OMS Community Edition cluster management service.    | cm_location         | The region code. The value ranges from 0 to 127. Each region has a unique number, which you can choose.                                                                                                                                        | Yes                |
   | cm_region           | The region, for example, cn-jiangsu. <br> **Note:**<br>   If you use OMS Community Edition in a disaster recovery active-active scenario with Alibaba Cloud MSHA, use the region information of Alibaba Cloud as `cm_region`.                                                        | No                |
   | cm_region_cn        | The Chinese name of the region. For example, Jiangsu.                                                                                                                                                              | No                |
   | cm_nodes            | The IP addresses of the OMS Community Edition cluster management service. In the example, they are xxx.xxx.xxx.1.                                                                                                                                       | Yes                |
   | cm_is_default       | Specifies whether to set the OMS Community Edition cluster management service as the default one. <br> **Note:**<br>   When multiple regions are configured, only one region can be set to `true` for `cm_is_default`, which indicates the default OMS Community Edition cluster management service.                                                    | No. Default value: `true`    |
   | tsdb_enabled        | Indicates whether to enable the metrics reporting feature (monitoring capability).    | tsdb_service        | The type of the time-series database. Valid values: `INFLUXDB` and `CERESDB`.                                                                                                                                       | No. Default value: `INFLUXDB` |
   | tsdb_url            | The IP address of the server where InfluxDB is deployed.    | tsdb_username       | The username of the time-series database. When `tsdb_enabled` is set to `true`, modify this parameter based on your environment. After you deploy the time-series database, you must manually create a user for the time-series database and fill in the username and password.                                                                      | No                |
   | tsdb_password       | The password of the time-series database. When `tsdb_enabled` is set to `true`, modify this parameter based on your environment.                                                                                                                          | No                |

   :::

4. Load the downloaded OMS Community Edition installation package into the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

5. Run the following command to start the container.

   OMS Community Edition supports accessing the OMS Community Edition console over HTTP or HTTPS. If you want to securely access OMS Community Edition, you can provide an HTTPS certificate and mount it to a specified directory in the container. If you access OMS Community Edition over HTTP, you do not need to configure an HTTPS certificate.

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # Mount the HTTPS certificate to the OMS Community Edition container only when you want to access OMS Community Edition over HTTPS.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

   Starting parameters

   :::collapse

   |           Parameter            |                                                 Description                                                    |
   |-------------------------|----------------------------------------------------------|
   | OMS_HOST_IP             | The IP address of the host.                                                                                                                                                                                                       |
   | CONTAINER_NAME          | The name of the container. The format is oms_xxx. Please fill in xxx based on the specific version.                                                            |
   | IMAGE_TAG               | After you load the OMS installation package by using Docker, run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image.    | /data/oms/oms_logs <br> /data/oms/oms_store <br>  /data/oms/oms_run  | `/data/oms/oms_logs`, `/data/oms/oms_store`, and `/data/oms/oms_run` can be replaced with the mount directories created on your OMS Community Edition deployment server.    | /home/admin/logs <br> /home/ds/store<br>  /home/ds/run       | `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run` are fixed directories in the container. 6. Enter the new container.

   ```shell
   docker exec -it  ${CONTAINER_NAME} bash  
   ```

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p><code>CONTAINER_NAME</code> is the name of the container. </p>
   </main>

7. In the root directory, run the metadata initialization operation.

   ```shell
   bash /root/docker_init.sh
   ```

   After you run the command, the initialization process is as follows:

   1. Initialize data in the metadata database.

   2. Generate the configuration files of each component.

   3. Restart all components.

   4. Initialize the resource tags and resource groups of OMS Community Edition.

   During the execution of `docker_init.sh`, pay attention to the output in the command line. After the execution is successful, the system will prompt you **【End】All initialization steps have been executed successfully**.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The initialization process takes 2 to 4 minutes. Please wait patiently and do not interrupt the execution. </p>
   </main>

## Expand the number of nodes in a region

### The initial environment is configured with two nodes in one region, and cm_url is set to the VIP.

This topic uses OMS Community Edition V4.2.7-CE as an example to describe how to expand the `docker_remote_deploy.sh` script for multi-node deployment in one region.

1. Pull the OMS Community Edition V4.2.7-CE image and obtain the deployment script from the loaded image.

   ```shell
   sudo docker pull <OMS_IMAGE>

   sudo docker run -d --net host --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

2. Run the deployment script to start the deployment tool.

   ```shell
   sudo sh docker_remote_deploy.sh -o <OMS container mount directory> -i <local IP address> -d <OMS_IMAGE>
   ```

3. Follow the prompts to deploy two nodes in one region. For more information, see [Deploy OMS on multiple nodes in one region](../500.docker-deploy/200.deploy-oms-on-multiple-nodes-in-a-single-region.md).

4. Wait for the initialization to complete and log in to the OMS Community Edition console to verify the deployment.

### Resizing steps

The cm_url of the initial node is set to the VIP `http://xxx.xxx.xxx.1:1188`, and the cm_nodes of the additional nodes is set to xxx.xxx.xxx.2. This document describes how to expand a cluster across multiple nodes in the same region.

1. Create VIPs, configure SLBs, or bind domains, and add nodes that are expanded in size.

Copy the same configuration file to the expandable server, and add the expandable node xxx.xxx.xxx.2 to the `cm_nodes` parameter in the copied `config.yaml` file.

3. Run the command to start the container.

   ```shell
   OMS_HOST_IP=xxx.xxx.xxx.2
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # Only set the following parameters in an OMS container to mount an HTTPS certificate.
   #-v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   #-v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

   | CONTAINER_NAME          | The name of the container that you created. The format is oms_xxx, where xxx indicates the container ID, which must be consistent with the container ID in the specific version.                                                       |
   | IMAGE_TAG               | After you load the OMS Community Edition installation package into Docker, run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] corresponding to the loaded image. 4. Enter the container.

   ```shell
   docker exec -it  ${CONTAINER_NAME} bash
   ```

5. In the `root` directory, perform a metadata initialization operation.

   ```shell

   ```

6. Wait for the initialization steps to execute and log in to the OMS Community Edition console to confirm.
