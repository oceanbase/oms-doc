# Scale out

This topic describes how to scale out a single-node instance in a single region and a multi-node instance in a single region.

## Expand a single-node cluster to a multi-node cluster

Expanding a single-node cluster to a multi-node cluster involves two scenarios:

* The initial node is configured with a VIP as the `cm_url`.

* The initial node is configured with a physical server IP address as the `cm_url`.

### Initial node is configured with a VIP as the `cm_url`

The specific steps are the same as those for deploying a single-node cluster. For more information, see [Deploy a single-node cluster](../500.docker-deploy/100.deploy-oms-on-a-single-node.md).

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>When you start a container, set the value of <code>-e OMS_HOST_IP</code> to the IP address of the current server. </p>
  </main>

Assume that the initial node has `cm_nodes` set to xxx.xxx.xxx.1 and the expanded node has `cm_nodes` set to xxx.xxx.xxx.2. The `config.yaml` file is configured as follows.

```yaml
# OMS Community Edition metadata database information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# When you expand a single-node cluster to a multi-node cluster, set the following three database names to the same values as those in the initial node.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition cluster configuration
cm_url: http://VIP:8088
cm_location: ${cm_location}
cm_region: ${cm_region}
cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - xxx.xxx.xxx.1
 - xxx.xxx.xxx.2

# Time series database configuration
# The default value is false. If you want to enable metric reporting, set this parameter to true and remove the comment mark (#) before it.
# tsdb_enabled: false
# When tsdb_enabled is set to true, remove the comment mark (#) before the following parameters and set the values based on your business requirements.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}
```

### Initial node is configured with a physical server IP address as the `cm_url`

In this scenario, you need to correct the database. The procedure is as follows:

<main id="notice" type='explain'>
<h4>Note</h4>
<p>You need to correct the <code>location_cm</code>, <code>host</code>, and <code>resource_group</code> tables in the <code>drc_cm_db</code> database, and the <code>cluster_info</code> table in the <code>drc_rm_db</code> database. </p>
</main>

1. Configure a VIP, SLB, or domain name and bind the IP addresses of all physical servers in the current region.

   For example, the VIP is bound to the IP addresses of the physical servers xxx.xxx.xxx.1 and xxx.xxx.xxx.2.

2. Stop the processes in the original container. For example, stop the processes in the oms_330 container.

   ```shell
   sudo docker exec -it oms_330 bash  
   supervisorctl stop all
   ```

3. Take the `drc_rm_db` database and the `cluster_info` table as an example. Log in to the database and perform the following steps:

   1. Query the data in the `cluster_info` table as a backup.

      ```shell
      select * from cluster_info;
      ```

   2. Delete the data in the `cluster_info` table.

      ```shell
      delete from cluster_info;
      ```

4. Modify the configuration file in the oms_330 container.

   ```shell
   # /home/admin/conf/config.yaml is a fixed directory in the Docker container.
   sudo vi /home/admin/conf/config.yaml

   # Modify the cm_url address and add cm_nodes:
   cm_url: http://VIP:8088
   cm_nodes:
    - xxx.xxx.xxx.1
    - xxx.xxx.xxx.2
   ```

5. Perform the initialization operation again.

   ```shell
   sudo sh /root/docker_init.sh
   ```

   After the initialization is complete, verify that the `cm_url` address in the `cluster_info` table is set to the VIP address.

6. Copy the same configuration file and start the OMS Community Edition container on another server.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>When you start a container, set the value of <code>-e OMS_HOST_IP</code> to the IP address of the current server. </p>
    </li>
    <li>
    <p>Replace <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> with the name of the image that you actually imported by running the <code>docker load -i</code> command. </p>
    </li
    </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # If SSL is enabled for the OMS metadata database, set the following three parameters.
   -v /data/oms/ssl/ca.pem:/home/admin/meta_ssl/ca.pem
   -v /data/oms/ssl/client-cert.pem:/home/admin/meta_ssl/client-cert.pem
   -v /data/oms/ssl/client-key.pem:/home/admin/meta_ssl/client-key.pem
   # If you mount an HTTPS certificate for the OMS Community Edition container, set the following two parameters.
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}
   ```

## Expand a single-region deployment to a multi-region deployment

When you expand a single-region deployment to a multi-region deployment, the steps are the same as those for deploying a single node. The difference is that in the `config.yaml` file, the `drc_cm_heartbeat_db` parameter must be different from the heartbeat database of the initial OMS Community Edition node. You also need to modify the `cm_url`, `cm_location`, `cm_region`, `cm_region_cn`, `cm_is_default`, and `cm_nodes` parameters to the values of the new region.

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy the time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy the time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Prepare the configuration file.

   Edit the OMS Community Edition startup configuration file in an appropriate directory. For example, you can create the configuration file as `/root/config.yaml`.

   Make sure to replace the required parameters with the actual values of the target environment. For example, if you want to expand the initial node xxx.xxx.xxx.xx1 to the Jiangsu region, the `config.yaml` file is configured as follows.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>After the colon in the <code>config.yaml</code> file, you must add a space. </p>
   </main>

   ```yaml
   # OMS metadata information
   oms_meta_host: ${oms_meta_host}
   oms_meta_port: ${oms_meta_port}
   oms_meta_user: ${oms_meta_user}
   oms_meta_password: ${oms_meta_password}

   # The configurations of drc_rm_db and drc_cm_db are the same as those of the initial node.
   drc_rm_db: ${drc_rm_db}
   drc_cm_db: ${drc_cm_db}
   # The drc_cm_heartbeat_db parameter must be different from the heartbeat database of the initial node.
   drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

   # OMS Community Edition cluster configuration
   # Fill in the values of the new region for the following parameters.
   cm_url: http://xxx.xxx.xxx.1:8088
   cm_location: ${cm_location}
   cm_region: cn-jiangsu
   cm_region_cn: Jiangsu
   cm_is_default: true
   cm_nodes:
    - xxx.xxx.xxx.1

   # Time series database configuration
   # The default value is false. If you want to enable the metric reporting feature, set this parameter to true and remove the preceding # sign.
   # tsdb_enabled: false
   # If tsdb_enabled is set to true, remove the preceding # sign and fill in the following parameters based on your actual situation.
   # tsdb_service: 'INFLUXDB'
   # tsdb_url: '${tsdb_url}'
   # tsdb_username: ${tsdb_user}
   # tsdb_password: ${tsdb_password}
   ```

   Parameter description

4. Load the downloaded OMS Community Edition installation package into the local image repository of the Docker container.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

5. Execute the following command to start the container.

   OMS Community Edition supports access to the OMS Community Edition console via HTTP or HTTPS protocols. If you want to securely access OMS Community Edition, you can provide an HTTPS certificate and mount it to the specified directory within the container. If you use the HTTP protocol to access OMS Community Edition, no configuration is required.

   ```shell
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \

   --privileged=true \
   ```

7. In the root directory, run the metadata initialization command.

   ```shell
   bash /root/docker_init.sh
   ```

   The command execution process is as follows:

   1. Initialize data in the MetaDB.

   2. Generate the configuration files of each component.

   3. Restart all components.

   4. Initialize the resource tags and resource groups of OMS Community Edition.

   During the execution of `docker_init.sh`, pay attention to the output on the command line. After the command is executed successfully, the system will prompt you **【End】All initialization steps have been executed successfully**.

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p>The execution process will take 2 to 4 minutes. Please wait patiently and do not interrupt the execution.</p>

## Expand across multiple nodes in a single region

### Initial environment configuration is two nodes in a single region, with cm_url set to VIP

This topic uses OMS Community Edition V4.2.7-CE as an example to describe how to scale out `docker_remote_deploy.sh` in a single region with multiple nodes.

1. Pull the OMS Community Edition V4.2.7-CE image and obtain the deployment script from the loaded image.

   ```shell
   sudo docker pull <OMS_IMAGE>

   sudo docker run -d --net host --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

2. Start the deployment tool using the deployment script.

   ```shell
   sudo sh docker_remote_deploy.sh -o <OMS container mount directory> -i <local IP address> -d <OMS_IMAGE>
   ```

3. Complete the deployment of two nodes in a single region based on the tool's prompts. For more information, see [Deploy OMS in a single region with multiple nodes](../500.docker-deploy/200.deploy-oms-on-multiple-nodes-in-a-single-region.md).

4. Wait for the initialization steps to complete and then log in to the OMS Community Edition console to confirm.

### Steps to scale out

Assume that the initial node is configured with the cm_url as the VIP `http://xxx.xxx.xxx.1:1188` and the cm_nodes of the scaled-out node is xxx.xxx.xxx.2. The steps to scale out across multiple nodes in the same region are as follows:

1. Configure the VIP, SLB, or domain name, and bind the new scaled-out node.

2. Copy the same configuration file to the scaled-out node and add the new node xxx.xxx.xxx.2 to the `cm_nodes` parameter in the copied `config.yaml` file.

3. Run the command to start the container.

   ```shell
   OMS_HOST_IP=xxx.xxx.xxx.2

   IMAGE_TAG=feature_x.x.x-ce

   -v /data/oms/ssl/client-key.pem:/home/admin/meta_ssl/client-key.pem
   # Set the following two parameters only when HTTPS certificates are mounted in the OMS container.
   #-v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt
   #-v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   ```
