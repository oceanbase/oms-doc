# Check the deployment status

After you install OMS Community Edition on the deployment server, you must enter Docker to view the running status of each service and determine whether OMS Community Edition is running normally on the deployment server.

## Procedure

1. Enter the Docker container.

   ```shell
   docker exec -it ${CONTAINER_NAME} bash
   ```

   <main id="notice" type='notice'>
    <h4>Notice</h4>
    <p><code>CONTAINER_NAME</code> is the name of the container. </p>
   </main>

2. Run the `supervisorctl status` command to obtain the output information and confirm that the status of each service is RUNNING.

   If the status of each service is RUNNING, OMS Community Edition is running normally in the environment.

   ```shell
   # supervisorctl status
   nginx                            RUNNING   pid 905, uptime 3 days, 5:40:09
   oms_console                      RUNNING   pid 907, uptime 3 days, 5:39:59
   oms_drc_cm                       RUNNING   pid 971, uptime 3 days, 5:39:49
   oms_drc_supervisor               RUNNING   pid 1223, uptime 3 days, 5:39:38
   sshd                             RUNNING   pid 1419, uptime 3 days, 5:39:27
   ```

   OMS Community Edition consists of the management components and data migration components. The management components include console, cm, and supervisor. If the management components fail to start, it might be due to memory issues. You can modify the startup configuration of the components as follows:

   1. Based on the output information obtained in the preceding step, confirm whether the management components have started.

   2. Go to the `/etc/supervisor/conf.d/` directory and run the `ll` command to obtain the names of the initialization files of the management components.

      ```shell
      # cd /etc/supervisor/conf.d/
      # ll
      total 20
      -rw-r--r-- 1 root root 285 Jan 13 15:37 base.ini
      -rw-r--r-- 1 root root 338 Jan 13 15:37 drc_cm.ini
      -rw-r--r-- 1 root root 397 Jan 13 15:37 drc_supervisor.ini
      -rw-r--r-- 1 root root 351 Jan 13 15:37 oms_console.ini
      -rw-r--r-- 1 root root 316 Jan 13 15:37 oms_nginx.ini
      ```

   3. Run the `cat` command to obtain the startup scripts of the components based on your requirements. In the command, the content after bash is the startup script.

      * Run the `cat oms_console.ini` command to obtain the startup script of console, which is `/home/admin/conf/command/start_oms_console.sh`.

      * Run the `cat drc_cm.ini` command to obtain the startup script of cm, which is `/home/admin/conf/command/start_oms_cm.sh`.

      * Run the `cat drc_supervisor.ini` command to obtain the startup script of supervisor, which is `/home/ds/supervisor/service.sh`.

   4. Modify the JVM startup memory configuration of the startup script of the management component.

   5. Run the `supervisorctl restart` command to restart the management component.

      If the `docker_init.sh` script fails to run, you can modify the configuration and run the `docker_init.sh` script again.

3. Log in to the OMS Community Edition console and go to the **<UI-TERM key="oms-community.Operation.Machine.MachineList">Servers</UI-TERM>** page to confirm whether the number of machines meets the expected value.

   For more information, see [Log in to the OMS Community Edition console](../../500.oms-console/100.log-on-to-the-oms-console.md) and [View machine information](../../900.o-m-manual/300.server/100.view-server-information.md).
