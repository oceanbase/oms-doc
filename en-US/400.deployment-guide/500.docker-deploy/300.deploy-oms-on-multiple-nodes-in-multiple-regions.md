# Deploy OMS Community Edition in multiple regions and nodes

This topic describes how to deploy OMS Community Edition in multiple regions and nodes by using the OMS Community Edition deployment tool.

## Background information

As more users use OMS Community Edition for data migration, the user scenarios supported by OMS Community Edition are also expanding. In addition to the widely used single-region data migration and large-scale data synchronization scenarios, OMS Community Edition also supports data synchronization between multiple regions and data migration or active-active synchronization between different cities.

![architecture10-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/architecture10-zh.jpg)

In a multi-region scenario, you can deploy one or more nodes in each region. If multiple OMS Community Edition nodes are deployed in a region, they form a highly available environment. OMS Community Edition starts the corresponding functional components on the appropriate nodes based on the specific task scenarios.

For example, if you need to synchronize data from Hangzhou to Heilongjiang, OMS Community Edition starts the incremental log capture component Store on a node in Hangzhou and the incremental synchronization component Incr-Sync on a node in Heilongjiang.

The following table describes the multi-node deployment:

* To deploy multiple nodes, you can first deploy a single node and then scale out to multiple nodes. For more information, see [Scale out OMS Community Edition](../500.docker-deploy/400.scale-out-oms.md).

* In a multi-region and multi-node deployment environment, you need to apply for a VIP in each region as the mount point for the OMS Community Edition management console. Additionally, you need to configure the mapping rules for ports 8088 and 8089 on the VIP network strategy.

  After you apply for a VIP, you can still access the OMS Community Edition management console through the VIP even if an OMS Community Edition node fails.

## Prerequisites

* The installation environment meets the system and network requirements. For more information, see [System and network requirements](../200.system-requirements.md).

* A MetaDB cluster is prepared as the metadata database for OMS Community Edition.

* The deployment machine can communicate with all other nodes.

* In a multi-node deployment scenario, ensure that the network is interconnected and that you can obtain root privileges for each node by providing the username and password.

* The OMS Community Edition installation package is obtained. The installation package is typically a `tar.gz` file that starts with `oms`. Download address: [OceanBase Community Edition download center](https://open.oceanbase.com/softwareCenter/community).

* The downloaded OMS Community Edition installation package is loaded into the local image repository of the Docker container on each node.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

* A directory for mounting the OMS Community Edition container is prepared. OMS Community Edition will create three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of OMS during runtime.

* (Optional) A time-series database is prepared to store the performance monitoring data and DDL/DML statistical information of OMS Community Edition.

## Definitions

In the following topics, some commands and prompts contain variables that you need to replace. The variables are enclosed in `<>` and are described as follows:

* OMS Community Edition container mounting directory: For more information, see the description of the OMS Community Edition container mounting directory in the prerequisites.

* Host IP address: the IP address of the host where the script is executed.

* OMS_IMAGE: After you load the OMS Community Edition installation package by using Docker, you can run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image. The [IMAGE ID] or [REPOSITORY:TAG] is the unique identifier of the loaded image, which is denoted as `<OMS_IMAGE>`. Example:

   ```shell
   $sudo docker images
   REPOSITORY                               TAG                 IMAGE ID          
   work.oceanbase-dev.com/obartifact-store/oms feature_4.0.0-ce    2786e8a6eccd        
   ```

   In this example, `<OMS_IMAGE>` can be `work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce` or `2786e8a6eccd`. In the following topics, replace `<OMS_IMAGE>` in the commands with the preceding values.

* Address of the existing `config.yaml` file: the address of the existing `config.yaml` file that you want to use for deployment.

## Deployment process (without a configuration file)

If you do not have a configuration file for OMS Community Edition, we recommend that you generate a new configuration file and deploy OMS Community Edition. If you have a configuration file, we recommend that you deploy OMS Community Edition by using the configuration file.

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy a time-series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy a time-series database. If you do not want to display monitoring data, skip this step. For more information, see [Deploy a time-series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the `docker_remote_deploy.sh` script from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Here is an example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mounting directory> -i <Local IP address> -d <OMS_IMAGE>
   ```

   The OMS Community Edition deployment tool automatically checks the CPU, memory, and disk resources. If any of these resources do not meet the requirements, it prompts you that the corresponding resources are insufficient, which affects the data migration speed.

5. Complete the deployment based on the tool prompts. Press Enter after each input.

   1. Select a deployment mode.

      Here, select **Multi-region**.

   2. Select the task you want to perform:

      Here, select **No configuration file, deploy OMS Community Edition from scratch, and generate a configuration file**.

   3. Enter the following MetaDB cluster configuration information:

       1. Enter the IP address, port, username, and password of the metadata database.

       2. Enter the prefix for the OMS Community Edition metadata database.

          For example, if the prefix is set to oms, the created metadata databases are oms_rm, oms_cm, and oms_cm_hb.

       3. Confirm the configuration information.

          Enter y to confirm that the configuration information is correct. Enter n to re-enter the configuration information.

         If the prompt **The corresponding database name already exists in the metadata database. Is this okay?** appears, it indicates that the database name you entered already exists in the MetaDB cluster. This may be due to repeated deployment or OMS Community Edition upgrades. After you confirm, enter y to continue the deployment, or enter n to re-enter the configuration information.

         If you enter y, the prompt **The corresponding database name already exists in the metadata database. Do you want to reinitialize the metadata database?** appears. Enter y to reinitialize the metadata database.

   4. Enter the following OMS Community Edition cluster configuration information:

       1. Enter the English region identifier. For example, cn-hangzhou.

       2. Enter the Chinese region identifier. For example, Hangzhou.

       3. Specify whether to configure the port numbers of custom components and configure the related parameters.

          Enter y to configure the port numbers of custom components. Enter the port numbers of Nginx, GHANA, CM, Supervisor, and sshd services based on the interface prompts.

       4. Enter the address of the OMS Community Edition cluster management service, which is the same VIP or domain name mounted on all CM servers in the current region. The original parameter name is `cm-url`.

          Enter the VIP domain name as the `cm-url` address. You can enter the IP address and port number in the URL separately or enter them in the format of <IP address>:<port number> using a colon (:) to separate them.

          <main id="notice" type='explain'>
          <h4>Note</h4>
          <p>The <code>http://</code> prefix is optional.</p>
          </main>

       5. Enter the IP addresses of all servers in the local region, separated by commas (,).

       6. Enter a region ID for the current region (<Chinese region identifier>). The range is [0,127].

          The region ID is used to distinguish different regions.

       7. In multi-region mode, specify whether to prioritize accessing the local region.

          In multi-region mode, only one region can be set to `true`. If you want to prioritize accessing the local region, enter y. If you do not want to prioritize accessing the local region, enter n.

       8. Confirm the displayed OMS Community Edition cluster configuration information.

          If the configuration information is correct, enter y. If you need to modify the configuration information, enter n.

   5. Confirm whether to monitor the historical data of OMS Community Edition.

       * If you deployed a time-series database in the **(Optional) Deploy a time-series database** step, enter y in this step and proceed to the **Configure the time-series database** step to enable the monitoring of OMS Community Edition historical data.

       * If you did not deploy a time-series database in the **(Optional) Deploy a time-series database** step, enter n in this step and proceed to the **Enable the audit log feature and configure the related SLS parameters** step. After the deployment, OMS Community Edition does not support monitoring historical data.

   6. Configure the time-series database.

      Enter the following time-series database configuration information:

      1. Is a time-series database service already deployed?

         Enter y if a time-series database service is already deployed. Enter n otherwise.

      2. Select the type of the time-series database: INFLUXDB.

         <main id="notice" type='notice'>
         <h4>Note</h4>
         <p>Only INFLUXDB is supported as the time-series database. </p>
         </main>

      3. Enter the URL, username, and password of the time-series database. For more information, see [Deploy a time-series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

      4. Confirm the displayed configuration information.

          If the configuration information is correct, enter y. If you need to modify the configuration information, enter n.

   7. Do you want to enable the audit log feature of OMS Community Edition and write the audit logs to the SLS service?

      If you enter y, the audit log feature is enabled. Then, you proceed to the **Enter the SLS parameters** step.

      If you enter n, the deployment starts. After the deployment, OMS Community Edition does not support the audit log feature.

   8. Enter the SLS parameters.

       1. Enter the SLS parameters based on the prompts.

       2. Confirm the displayed configuration information.

      If the configuration information is correct, enter y. If you need to modify the configuration information, enter n.

   9. If the configuration file passes the check, all the configuration information is displayed. If the configuration information is correct, enter n. If you need to modify the configuration information, enter y.

      If the configuration file does not pass the check, modify the configuration information based on the prompts.

   10. Deploy and configure each node in sequence.

       1. Enter the mounting directory for OMS Community Edition on the node with the IP address <Node IP>:

          Enter a directory with a large capacity as the mounting directory for the OMS Community Edition container.

       2. Confirm whether the image name for deploying OMS Community Edition is <OMS_IMAGE>.

          If the image name is correct, enter y. If you need to modify the image name, enter n.

       3. Confirm whether to mount an HTTPS certificate to the OMS Community Edition container.

          If you need to mount an HTTPS certificate, enter y and enter the directories of the https_key and https_crt certificates based on the prompts. If you do not need to mount an HTTPS certificate, enter n.

       4. If the node is a remote node, check whether the IP address of the node to be deployed is different from that of the machine where the deployment tool is executed. If the node is a remote node that can be connected to by using SSH and the user has the `sudo` permission on the remote node, enter y to execute the script on the remote node.

          If you enter y, confirm whether the port of the node can be connected to by using SSH. If the port can be connected to, enter the username and password for logging in to the remote node based on the prompts.

          If you enter an empty password, the prompt **You have entered an empty password. Do you want to use the trusted login method?** appears. If you enter y, re-enter the `sudo` password of the node user. If you do not need to enter a password, press Enter.

       5. Confirm whether the configuration file config.yaml on the node with the IP address <Node IP> can be written to.

          If the configuration file can be written to, enter y. If you need to modify the configuration file, enter n.

       6. Start the deployment.

            * During the deployment, you can run the `docker logs -f <OMS Community Edition container name>` command to view the initialization status.

               To view all startup initialization logs, run the `docker logs <OMS Community Edition container name>` command.

            * If the deployment fails, log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

            * If the OMS container fails to start, you cannot obtain the log information.

   11. Confirm whether to deploy OMS Community Edition in a new region.

         After the deployment, the prompt **The deployment of regions [<English region identifier 1>,<English region identifier 2>……] is completed. Do you want to deploy OMS Community Edition in a new region?** appears.

         If you want to deploy OMS Community Edition in a new region, enter y to continue the deployment. If you do not want to deploy OMS Community Edition in a new region, enter n to end the deployment.

   12. Enter the OMS Community Edition cluster configuration information.

       1. Enter the English region identifier. For example, cn-hangzhou.

       2. Enter the Chinese region identifier. For example, Hangzhou.

       3. Enter a region ID for the current region (<Chinese region identifier>). The range is [0,127].

            The region ID is used to distinguish different regions.

   13. Display the prompt information, which contains the existing region names and IDs, to ensure that the subsequent inputs are not repeated.

   14. Repeat the deployment steps for each node in the region.

         If the deployment fails, log in to the running OMS Community Edition container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information. If the OMS container fails to start, you cannot obtain the log information.

## Deployment process (with configuration file)

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy a time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy a time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -c <Existing config.yaml configuration file address> -i <Local IP address> -d <OMS_IMAGE>
   ```

   The OMS Community Edition deployment tool will automatically verify the CPU, memory, and disk resources. If any of these resources are insufficient, it will prompt you that the corresponding resource is insufficient, which will affect the data migration speed.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>The existing config.yaml configuration file address specified after <code>-c</code> must be an absolute path.</li>
    <li>For information about the settings of the <code>config.yaml</code> configuration file, see the <a href="#config-file">Configuration file template and example</a> section.</li>
    </ul>
   </main>

5. Follow the prompts to complete the deployment. Press Enter to proceed to the next step after each input.

    1. Select a deployment mode.

       Select **Multi-region**.

    2. Select the task to be performed.

       Select **Start configuration based on the reference configuration file passed in by the script [-c] option**.

    3. If the prompt **The database name already exists in the MetaDB. Is this okay?** appears, it indicates that the database name you entered already exists in the MetaDB of the existing configuration file. This situation may occur due to repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment or enter n to re-enter the configuration information.

    4. If the configuration file is verified, all the configuration information will be displayed. If you confirm that the information is correct, enter n. If you need to modify the information, enter y.

       If the configuration file is not verified, modify the configuration information as prompted.

    5. Start deploying each node in sequence.

        1. Enter the mount directory for deploying OMS Community Edition on node <Node IP>:

           Enter a directory with a large capacity as the mount directory for the OMS Community Edition container.

        2. Confirm whether the image name for deploying OMS is <OMS_IMAGE>.

           If you confirm that the image name is correct, enter y. If you need to modify the image name, enter n.

        3. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

           If you need to mount an HTTPS certificate, enter y and enter the https_key and https_crt directories as prompted. If you do not need to mount an HTTPS certificate, enter n.

        4. If the node is a remote node, the deployment tool will check whether the IP address of the node to be deployed is different from the IP address of the current deployment tool. If the IP addresses are different, the deployment tool will prompt you whether to execute the script remotely (the remote node must be able to connect to the deployment tool through SSH, and the user must have the `sudo` permission on the remote node).

            If you enter y, confirm whether the port of the node can be connected to the deployment tool through SSH. If the port can be connected to the deployment tool, enter the username and password of the remote node as prompted.

            If the password you entered is empty, the deployment tool will prompt you whether to use trusted login. If you enter y, re-enter the `sudo` password of the node user (if no password is required, press Enter directly).

        5. Confirm whether the path for writing the config.yaml file under <Node IP> is correct.

            If you confirm that the path is correct, enter y. If you need to modify the path, enter n.

    6. Confirm whether to deploy in a new region.

        After the deployment is completed, the deployment tool will prompt you: The deployment of regions [<English region ID 1>,<English region ID 2>……] is completed. Do you want to deploy in a new region?

        If you want to deploy in a new region, enter y to continue the deployment. If you do not want to deploy in a new region, enter n to end the deployment process.

    7. Enter the cluster configuration information of OMS Community Edition.

        1. Enter the English region ID. For example, cn-hangzhou.

        2. Enter the Chinese region ID. For example, Hangzhou.

        3. Enter a region ID for the current region (<Chinese region ID>), which ranges from [0,127].

            The region ID is used to distinguish different regions.

    8. Display the prompt information, which contains the existing region name and region ID, to ensure that the subsequent input is not repeated.

    9. Repeat the deployment steps for each node in this region.

         If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information. If the OMS container fails to start, you cannot obtain the log information.

After the deployment is completed, if you want to modify the configuration, perform the following steps:

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>In a multi-region and multi-node scenario, you need to manually modify the configuration of each node. </p>
</main>

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file based on your business requirements.

3. Run the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Run the `supervisorctl restart oms_console oms_drc_supervisor` command.

## Templates and examples of configuration files

### Configuration file template

    <h4>Notice</h4>
    <ul>
    <li>
    <p>For the <code>cm_is_default</code> parameter, in a multi-region scenario, only one region can have its nodes configured as <code>true</code>, and all other regions must be configured as <code>false</code>. In a multi-node scenario, you must execute the commands sequentially.</p>

    <li>

This topic provides a `config.yaml` configuration file template and example for multi-region and multi-node deployment. It uses two nodes in Hangzhou and two nodes in Heilongjiang as examples.

* To deploy OMS Community Edition in Hangzhou, the `config.yaml` file template is as follows:

   ```yaml
   # OMS metadata information
   oms_meta_host: ${oms_meta_host}
   oms_meta_port: ${oms_meta_port}
   oms_meta_user: ${oms_meta_user}
   oms_meta_password: ${oms_meta_password}

   # You can customize the names of the following three databases. OMS Community Edition will create these databases in the metadata database.
   drc_rm_db: ${drc_rm_db}
   drc_cm_db: ${drc_cm_db}
   drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

   # Fill in the configuration of the OMS Community Edition cluster in Hangzhou.
   # In a multi-region and multi-node deployment, the cm_url parameter must be set to a VIP or domain name that belongs to all CMs in the current region.
   cm_url: ${cm_url}
   cm_location: ${cm_location}
   cm_region: ${cm_region}
   cm_region_cn: ${cm_region_cn}
   cm_is_default: true
   cm_nodes:
    - ${host_ip1}
    -  ${host_ip2}

   # Time series database configuration
   # The default value is false. Set it to true if you want to enable the metric reporting feature.
   # tsdb_enabled: false
   # If tsdb_enabled is set to true, uncomment the following parameters and set them according to your actual environment.
   # tsdb_service: 'INFLUXDB'
   # tsdb_url: '${tsdb_url}'
   # tsdb_username: ${tsdb_user}
   # tsdb_password: ${tsdb_password}

   # User-defined component port numbers
   # Specify the port number for the GHANA service.
   ghana_server_port: xxxxx
   # Specify the port number for the Nginx service.
   nginx_server_port: xxxxx
   # Specify the port number for the CM service.
   cm_server_port: xxxxx
   # Specify the port number for the Supervisor service.
   supervisor_server_port: xxxxx
   # Specify the port number for the sshd service.
   sshd_server_port: xxxxx
   ```

   Parameter description

   |         Parameter          |                                                                                                                                                Description                                                                                                                                                |       Required        |

   | oms_meta_port       | The port number of the metadata database.                                                                                                                                                                                                                                                                                        | Yes                |
   | oms_meta_user       | The username of the metadata database.                                                                                                                                                                                                                                                                                       | Yes                |
   | oms_meta_password   | The password of the metadata database.                                                                                                                                                                                                                                                                                       | Yes                |
   | drc_rm_db           | The name of the database for the management console.                                                                                                                                                                                                                                                                                     | Yes                |
   | drc_cm_db           | The name of the database for the cluster management service.                                                                                                                                                                                                                                                                                    | Yes                |
   | drc_cm_heartbeat_db | The name of the heartbeat database for the cluster management service.                                                                                                                                                                                                                                                                                    | Yes                |
   | cm_url              | The URL of the OMS Community Edition cluster management service. For example, `http://VIP:8088`. <br>**Note:**<br> In a multi-region and multi-node deployment, `cm_url` must be set to a VIP or domain name that belongs to all CMs in the current region. For example, `http://xxx.xxx.xxx.1:8089`. 8088 is the port number of the scheduling program, and 8089 is the port number of the web address. | Yes                |
   | cm_location         | The region code. The value ranges from 0 to 127.    | cm_nodes            | The IP address list of the OMS Community Edition cluster management service.    | cm_is_default       | Indicates whether the OMS Community Edition cluster management service is the default one.                                                                                                                                                                                                                                                                               | No. Default value: `true`    |
   | tsdb_service        | The type of the time series database. Valid values: `INFLUXDB` and `CERESDB`.                                                                                                                                                                                                                                                            | No. Default value: `INFLUXDB` |
   | tsdb_enabled        | Indicates whether to enable the metric reporting feature (monitoring capability). Valid values: `true` and `false`.                                                                                                                                                                                                                                                         | No. Default value: `false`   |
   | tsdb_url            | The IP address of the host where InfluxDB is deployed. Modify this parameter according to your actual environment.    | nginx_server_port | The port number of the Nginx service. If not specified, the default port number 8089 is used. |No|
   | cm_server_port    | The port number of the CM service. If not specified, the default port number 8088 is used. |No|
   | supervisor_server_port | The port number of the Supervisor service. If not specified, the default port number 9000 is used. |No|
   | sshd_server_port | The port number of the sshd service. If not specified, the default port number 2023 is used. |No|

* To deploy OMS Community Edition in Heilongjiang, the `config.yaml` file template is as follows:

   The deployment steps in Heilongjiang and Hangzhou are the same. You only need to modify the `config.yaml` file. The different parameters are `drc_cm_heartbeat_db`, `cm_url`, `cm_location`, `cm_region`, `cm_region_cn`, `cm_is_default`, and `cm_nodes`.

   drc_cm_db: ${drc_cm_db}
