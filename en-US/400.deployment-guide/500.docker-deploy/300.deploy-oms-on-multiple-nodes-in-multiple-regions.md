# Deploy OMS Community Edition across multiple regions and nodes

This topic describes how to deploy OMS Community Edition across multiple regions and nodes by using the OMS Community Edition deployment tool.

## Background information

As more users use OMS Community Edition for data migration, the user scenarios supported by OMS Community Edition are also increasing. In addition to the widely used single-region data migration and big data synchronization scenarios, OMS Community Edition also supports data synchronization between multiple regions, data migration between cities in different regions, and active-active synchronization.

![architecture10-zh](https://obbusiness-private.oss-cn-shanghai.aliyuncs.com/doc/img/oms/oms-enterprise/architecture10-zh.jpg)

In a multi-region scenario, you can deploy one or more nodes in each region. If you deploy multiple OMS Community Edition nodes in a region, they form a highly available environment. OMS Community Edition starts the corresponding functional components on the appropriate nodes based on the specific task scenario.

For example, if you need to synchronize data from Hangzhou to Heilongjiang, OMS Community Edition starts the incremental log capture component Store on a node in Hangzhou and the incremental synchronization component Incr-Sync on a node in Heilongjiang.

The following table describes the multi-node deployment:

* To implement multi-node deployment, you can first deploy a single node and then scale out to multiple nodes. For more information, see [Scale out OMS Community Edition](../500.docker-deploy/400.scale-out-oms.md).

* In a multi-region and multi-node deployment environment, you need to apply for a VIP in each region as the mounting point for the OMS Community Edition management console. Additionally, you need to configure port mapping rules for ports 8088 and 8089 on the VIP network policy.

  After you apply for a VIP, you can still access the OMS Community Edition management console through the VIP even if an OMS Community Edition node fails.

## Prerequisites

* The installation environment meets the system and network requirements. For more information, see [System and network requirements](../200.system-requirements.md).

* A MetaDB cluster is prepared as the metadata database for OMS Community Edition.

* The machine where OMS Community Edition is deployed can communicate with all other nodes.

* In a multi-node deployment scenario, ensure that the network is interconnected and that you can obtain root privileges for each node by entering the username and password.

* The OMS Community Edition installation package is obtained. The installation package is a `tar.gz` file starting with oms. Download address: [OceanBase Community Edition Download Center](https://open.oceanbase.com/softwareCenter/community).

* The OMS Community Edition installation package is loaded into the local image repository of the Docker container on each node.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

* A directory is prepared for mounting the OMS Community Edition container. OMS Community Edition creates three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of OMS during runtime.

* (Optional) A time series database is prepared to store the performance monitoring and DDL/DML statistical data of OMS Community Edition.

## Glossary

In the following topics, some commands and prompts contain variables that you need to replace. Variables are enclosed in `<>` and are explained as follows:

* OMS Community Edition container mounting directory: For more information, see the description of the OMS Community Edition container mounting directory in the prerequisites.

* Host IP address: the IP address of the host on which the script is executed.

* OMS_IMAGE: After you load the OMS Community Edition installation package by using Docker, you can run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image. The [IMAGE ID] or [REPOSITORY:TAG] is the unique identifier of the image, which is represented as `<OMS_IMAGE>`. For example:

   ```shell
   $sudo docker images
   REPOSITORY                               TAG                 IMAGE ID          
   work.oceanbase-dev.com/obartifact-store/oms feature_4.0.0-ce    2786e8a6eccd        
   ```

   In this example, `<OMS_IMAGE>` can be `work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce` or `2786e8a6eccd`. In the following topics, replace `<OMS_IMAGE>` in the commands with the preceding value.

* Existing `config.yaml` configuration file address: the address of the existing `config.yaml` configuration file that you want to use for deployment.

## Deployment process (without configuration file)

If you do not have a configuration file for OMS Community Edition, we recommend that you generate a new configuration file and deploy OMS Community Edition. If you have a configuration file, we recommend that you deploy OMS Community Edition by using the configuration file.

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy a time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy a time series database. If you do not want to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image:

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Here is an example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mounting directory> -i <Local IP address> -d <OMS_IMAGE>
   ```

   OMS Community Edition automatically checks the CPU, memory, and disk resources. If any of the resources are insufficient, it will prompt you to increase the corresponding resources, which will affect the data migration speed.

5. Complete the deployment as prompted. Press Enter after each input.

   1. Select the deployment mode.

      Select **Multi-region**.

   2. Select the task to be performed.

      Select **No configuration file, deploy OMS Community Edition from scratch, and generate a configuration file**.

   3. Enter the following MetaDB cluster configuration information:

       1. Enter the IP address, port, username, and password of the metadata database.

            <main id="notice" type='notice'>
            <h4>Notice</h4>
            <p>The password of the metadata database user cannot be empty, and it cannot contain special characters (including line breaks, spaces, and |"'`()=;/&[]{}). </p>
            </main>

       2. Enter the prefix for the OMS Community Edition metadata database.

          For example, if the prefix is set to oms, the created metadata databases will be named oms_rm, oms_cm, and oms_cm_hb.

       3. Confirm the configuration information.

          Enter y to confirm that the above configuration information is correct. Enter n to re-enter the configuration information.

         If you see the prompt **The corresponding database name already exists in the metadata database! Is this okay?**, it indicates that the database name you entered already exists in the MetaDB cluster. This may be due to repeated deployment or OMS Community Edition upgrade. Please confirm and enter y to continue the deployment, or enter n to re-enter the configuration information.

         If you enter y, you will be prompted **The corresponding database name already exists in the metadata database. Do you want to reinitialize the metadata database?**. Enter y to reinitialize the metadata database.

   4. Enter the following OMS Community Edition cluster configuration information:

       1. Enter the English region identifier. For example, cn-hangzhou.

       2. Enter the Chinese region identifier. For example, Hangzhou.

       3. Set whether to customize the component port numbers and configure the related parameters.

          Enter y to customize the component port numbers. Enter the port numbers for the Nginx, GHANA, CM, Supervisor, and sshd services as prompted.

       4. Enter the address of the OMS Community Edition cluster management service, which is the VIP or domain name mounted to all CM servers in the current region. The original configuration item name is `cm-url`.

          Enter the VIP domain name as the `cm-url` address. You can enter the IP address and port number of the URL separately or use a colon (:) to connect them in one input. Enter <IP address>:<Port number>.

          <main id="notice" type='explain'>
          <h4>Note</h4>
          <p>The <code>http://</code> prefix is optional. </p>
          </main>

       5. Enter the IP addresses of all servers in the local region, separated by commas (,).

       6. Enter a region ID for the current region (<Chinese region identifier>), which ranges from [0,127].

          The region ID is used to distinguish different regions.

       7. In multi-region deployment mode, set whether to prioritize accessing the local region.

          In multi-region mode, only one region can have this parameter set to `true`. Enter y to prioritize accessing the local region. Enter n if you do not need to prioritize accessing the local region.

       8. Confirm the displayed OMS Community Edition cluster configuration information.

          Enter y to confirm that the configuration information is correct. Enter n to modify the configuration information.

   5. Confirm whether to monitor the historical data of OMS Community Edition.

       * If you deployed a time series database in the **(Optional) Deploy a time series database** step, enter y in this step and proceed to the **Configure the time series database** step to enable monitoring of the historical data of OMS Community Edition.

       * If you did not deploy a time series database in the **(Optional) Deploy a time series database** step, enter n in this step and proceed to the **Enable the audit log feature and configure the related SLS parameters** step. In this case, the deployed OMS Community Edition does not support monitoring historical data.

   6. Configure the time series database.

      Enter the following time series database configuration information:

      1. Is there a deployed time series database service?

         Enter y if there is one, or n if there is not.

      2. Select the type of the time series database: select "INFLUXDB".

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>Only INFLUXDB is supported. </p>
         </main>

      3. Enter the URL, username, and password of the time series database. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

      4. Confirm all the displayed configuration items.

          Enter y to confirm that the configuration information is correct. Enter n to modify the configuration information.

   7. Do you want to enable the audit log feature of OMS Community Edition and write the audit logs to the SLS service?

      If you enter y, the audit log feature is enabled. Then, proceed to the **Enter the SLS parameters** step.

      If you enter n, the deployment starts. In this case, the deployed OMS Community Edition does not support the audit log feature.

   8. Enter the SLS parameters.

       1. Enter the SLS parameters as prompted.

       2. Confirm all the displayed configuration items.

      Enter y to confirm that the configuration information is correct. Enter n to modify the configuration information.

   9. If the configuration file passes the check, all the configuration information will be displayed. Enter n to confirm that the configuration information is correct. Enter y to modify the configuration information.

      If the configuration file does not pass the check, modify the configuration information as prompted.

   10. Deploy and execute the configuration for each node in sequence.

       1. Enter the mounting directory for deploying OMS Community Edition on the node with the IP address <Node IP>:

          Enter a directory with sufficient capacity as the mounting directory for the OMS Community Edition container.

       2. Confirm whether the image name for deploying OMS Community Edition is <OMS_IMAGE>.

          Enter y to confirm that the image name is correct. Enter n to modify the image name.

       3. Confirm whether to mount an HTTPS certificate to the OMS Community Edition container.

          Enter y to mount an HTTPS certificate and enter the https_key and https_crt directories as prompted. Enter n if you do not need to mount an HTTPS certificate.

       4. If the node is a remote node, check whether the IP address of the node to be deployed is different from the IP address of the machine where the deployment tool is executed. If the node is a remote node that can be connected to via SSH and the user has the `sudo` permission on the remote node, enter y to execute the script remotely.

          If you enter y, confirm whether the port of the node can be connected to via SSH. If the port is supported, enter the username and password for logging in to the remote node as prompted.

          If you enter an empty password, you will be prompted whether to use trusted login. If you enter y, re-enter the `sudo` password of the node user. If no password is required, press Enter directly.

       5. Confirm whether the config.yaml file under <Node IP> can be written to the specified path.

          Enter y to confirm that the path is correct. Enter n to modify the path.

       6. Start the deployment.

            * During the deployment, you can run the `docker logs -f <OMS Community Edition container name>` command to view the initialization status.

               To view all initialization logs, you can run the `docker logs <OMS Community Edition container name>` command.

            * If the deployment fails, you can log in to the running OMS container and check the `.log` files in the `/home/admin/logs` directory that start with `docker_init` to obtain log information.

            * If the OMS container fails to start, you cannot obtain the logs.

   11. Confirm whether you need to deploy to a new region.

         After the deployment is completed, a prompt will appear: Deployment for the regions [<English region ID 1>,<English region ID 2>……] is completed. Do you need to deploy to a new region?

         If you need to deploy, enter y to continue. If you do not need to deploy, enter n to end the deployment process.

   12. Enter the cluster configuration information for the OMS Community Edition.

       1. Enter the English region ID. For example, cn-hangzhou.

       2. Enter the Chinese region ID. For example, Hangzhou.

       3. Set a region ID for the current region (<Chinese region ID>). The range is [0,127].

            This ID is used to distinguish between different regions.

   13. Display a prompt that includes the existing region names and IDs to ensure that the input is not repeated.

   14. Repeat the deployment steps for each node in this region.

         If the deployment fails, you can log in to the running OMS Community Edition container and check the `.log` files in the `/home/admin/logs` directory that start with `docker_init` to obtain log information. If the OMS container fails to start, you cannot obtain the logs.

## Deployment process (with configuration file)

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy the time series database.

   If you want to collect and display monitoring data in OMS Community Edition, deploy the time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy the time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -c <Existing config.yaml configuration file path> -i <Local IP address> -d <OMS_IMAGE>
   ```

   The OMS Community Edition deployment tool automatically verifies the CPU, memory, and disk resources. If any of these resources are insufficient, it will prompt you of the resource shortage, which may affect the data migration speed.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>The path specified after <code>-c</code> must be an absolute path.</li>
    <li>For more information about the settings in the <code>config.yaml</code> configuration file, see the <a href="#template">Template and example of the configuration file</a> section below.</li>
    </ul>
   </main>

5. Follow the prompts to complete the deployment. Press Enter after each input.

    1. Select the deployment mode.

       Select **Multi-region**.

    2. Select the task you want to perform.

       Select **Use the reference configuration file provided by the [-c] option to start the configuration**.

    3. If the prompt **The database name already exists in the MetaDB! Continue?** appears, it indicates that the database name you entered already exists in the MetaDB of the existing configuration file. This may be due to repeated deployment or OMS Community Edition upgrade. Please confirm and enter y to continue the deployment, or enter n to re-enter the configuration information.

    4. If the configuration file check passes, all configuration information will be displayed. If confirmed, enter n. If you need to modify, enter y.

       If the configuration file check fails, modify the configuration information according to the prompt.

    5. Start deploying each node one by one.

        1. Enter the mount directory for OMS Community Edition on node <Node IP>:

           Enter a directory with sufficient capacity as the mount directory for the OMS Community Edition container.

        2. Confirm whether the image name for deploying OMS is <OMS_IMAGE>.

           If confirmed, enter y. If you need to modify, enter n.

        3. Confirm whether to mount the HTTPS certificate in the OMS Community Edition container.

           If needed, enter y and enter the https_key and https_crt directories according to the prompt. If not needed, enter n.

        4. If the node is a remote node, check whether the IP address of the node to be deployed is different from the IP address of the machine where the deployment tool is executed. If the remote node can be connected via SSH and the user has the `sudo` permission on the remote node, enter y to execute the script remotely.

            If you enter y, confirm whether the port of the node can be connected via SSH. If it can be connected, enter the username and password of the remote node according to the prompt.

            If you enter an empty password, the system will prompt you whether to use trusted login. If you enter y, re-enter the `sudo` password of the node user (if no password is required, press Enter directly).

        5. Confirm whether the path for writing the config.yaml file under <Node IP> is correct.

            If confirmed, enter y. If you need to modify, enter n.

    6. Confirm whether to deploy in a new region.

        After deployment, the system will prompt: The deployment of the following regions has been completed: [<English region ID 1>,<English region ID 2>……]. Do you want to deploy in a new region?

        If you want to deploy, enter y to continue. If not, enter n to end the deployment process.

    7. Enter the cluster configuration information for OMS Community Edition.

        1. Enter the English region ID. For example, cn-hangzhou.

        2. Enter the Chinese region ID. For example, Hangzhou.

        3. Set a region ID for the current region (<Chinese region ID>). The range is [0,127].

            This ID is used to distinguish different regions.

    8. Display the prompt information, including the existing region names and IDs, to ensure that the subsequent inputs are not repeated.

    9. Repeat the deployment steps for each node in this region.

         If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information. If the OMS container fails to start, you cannot obtain the logs.

After the deployment is completed, if you need to modify the configuration, perform the following steps:

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>In a multi-region and multi-node scenario, you need to manually modify the configuration for each node.</p>
</main>

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file according to your business needs.

3. Enter the `/root` directory and execute the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Execute the `supervisorctl restart oms_console oms_drc_supervisor` command.

### Configuration file template

This topic provides a `config.yaml` configuration file template and example for multi-region and multi-node deployment. It deploys two nodes in Hangzhou and two nodes in Heilongjiang.

* To deploy the OMS Community Edition in Hangzhou, the `config.yaml` configuration file template is as follows:

   ```yaml
   # OMS metadata database information
   oms_meta_host: ${oms_meta_host}
   oms_meta_port: ${oms_meta_port}
   oms_meta_user: ${oms_meta_user}
   oms_meta_password: ${oms_meta_password}

   # You can customize the following three databases. When you deploy the OMS Community Edition, these three databases are created in the metadata database.
   drc_rm_db: ${drc_rm_db}
   drc_cm_db: ${drc_cm_db}
   drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

   # Fill in the configuration of the OMS Community Edition cluster in Hangzhou.
   # In multi-region and multi-node deployment, the cm_url parameter must be set to the VIP or domain name of one of the CM nodes in the current region.
   cm_url: ${cm_url}
   cm_location: ${cm_location}
   cm_region: ${cm_region}
   cm_region_cn: ${cm_region_cn}
   cm_is_default: true
   cm_nodes:
    - ${host_ip1}
    -  ${host_ip2}

   # Time series database configuration
   # The default value is false. Set it to true if you want to enable the metric reporting feature.
   # tsdb_enabled: false
   # When tsdb_enabled is set to true, uncomment and fill in the following parameters based on your actual situation.
   # tsdb_service: 'INFLUXDB'
   # tsdb_url: '${tsdb_url}'
   # tsdb_username: ${tsdb_user}
   # tsdb_password: ${tsdb_password}

   # Custom port numbers for user-defined components
   # Specify the port number for the GHANA service.
   ghana_server_port: xxxxx
   # Specify the port number for the Nginx service.
   nginx_server_port: xxxxx
   # Specify the port number for the CM service.
   cm_server_port: xxxxx
   # Specify the port number for the Supervisor service.
   supervisor_server_port: xxxxx
   # Specify the port number for the sshd service.
   sshd_server_port: xxxxx
   ```

* Deploy OMS Community Edition in Heilongjiang. The `config.yaml` template is as follows:

   The deployment process in Heilongjiang is the same as in Hangzhou. You only need to modify the `config.yaml` file. The different parameters are `drc_cm_heartbeat_db`, `cm_url`, `cm_location`, `cm_region`, `cm_region_cn`, `cm_is_default`, and `cm_nodes`.

    <h4>Notice</h4>
    <ul>
    <li>
    <p>In a multi-region scenario, only one region can have the <code>cm_is_default</code> parameter set to <code>true</code>. All other regions must have this parameter set to <code>false</code>.</p>
    </li>
    <li>
    <p>If you need to deploy multiple nodes in Heilongjiang, list all the IP addresses of the nodes in the <code>cm_nodes</code> parameter.</p>

   ```yaml
   # OMS Community Edition metadata database information
   oms_meta_host: ${meta_ip}
   oms_meta_port: ${meta_port}
   oms_meta_user: ${meta_user}
   oms_meta_password: ${meta_password}

   # You can customize the names of the following three databases. OMS Community Edition will create these databases in the metadata database.
   drc_rm_db: ${drc_rm_db}
   drc_cm_db: ${drc_cm_db}
   drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

   # Fill in the configuration for OMS Community Edition in Heilongjiang.
   # In a multi-region, multi-node deployment, set the cm_url parameter to the VIP or domain name of one of the CM nodes in the current region.
   ```
