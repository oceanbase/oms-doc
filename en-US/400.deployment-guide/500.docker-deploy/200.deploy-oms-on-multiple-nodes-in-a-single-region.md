# Deploy OMS Community Edition across multiple nodes in a single region

This topic describes how to deploy OMS Community Edition across multiple nodes in a single region by using the OMS Community Edition deployment tool.

## Background information

* To implement a multi-node deployment, you can first deploy a single node and then scale out to multiple nodes.

* If you choose the deployment method with a configuration file, note that the configuration information for a single-node deployment and a multi-node deployment (the configuration information in `config.yaml`) is slightly different. For more information, see the following section on "Templates and examples of the configuration file".

* In a multi-node deployment environment, you need to apply for a VIP as the mount point for the OMS Community Edition console. Additionally, you need to configure the mapping rules for ports 8088 and 8089 on the VIP network policy.

  After applying for the VIP, you can still access the OMS Community Edition console even if one of the OMS Community Edition nodes fails.

## Prerequisites

* Make sure that the installation environment meets the system and network requirements. For more information, see [System and network requirements](../200.system-requirements.md).

* A MetaDB cluster has been prepared as the metadata database for OMS Community Edition.

* The deployment server can communicate with all other nodes.

* In a multi-node deployment scenario, make sure that the nodes are interconnected and that you can obtain root privileges for each node by entering the username and password.

* You have downloaded the OMS Community Edition installation package. The installation package is a `tar.gz` file that starts with oms. Download address: [OceanBase Community Edition Download Center](https://open.oceanbase.com/softwareCenter/community).

* You have loaded the OMS Community Edition installation package into the local image repository of the Docker container on each node.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

* A directory for mounting the OMS Community Edition container has been prepared. OMS Community Edition will create three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of OMS during runtime.

* (Optional) A time series database has been prepared to store the performance monitoring data and DDL/DML statistics of OMS Community Edition.

## Glossary

In the subsequent topics, some commands and prompts contain variables that you need to replace. Variables are enclosed in `<>` and are explained as follows:

* OMS Community Edition container mounting directory: For more information, see the description of the OMS Community Edition container mounting directory in the prerequisites.

* Host IP address: The IP address of the host on which the script is executed.

* OMS_IMAGE: After you load the OMS Community Edition installation package by using Docker, you can run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image. The obtained [IMAGE ID] or [REPOSITORY:TAG] is the unique identifier of the loaded image, which is represented as `<OMS_IMAGE>`. Here is an example:

   ```shell
   $sudo docker images
   REPOSITORY                               TAG                 IMAGE ID          
   work.oceanbase-dev.com/obartifact-store/oms feature_4.0.0-ce    2786e8a6eccd        
   ```

   In this example, `<OMS_IMAGE>` can be `work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce` or `2786e8a6eccd`. In the subsequent topics, replace `<OMS_IMAGE>` in the commands with the values mentioned above.

* Address of the existing `config.yaml` configuration file: If you want to deploy OMS Community Edition based on the existing `config.yaml` configuration file, specify the address of the existing configuration file.

## Deployment process (without configuration files)

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy the time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy the time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy the time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_4.0-ce bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -i <Local IP address> -d <OMS_IMAGE>
   ```

   At this point, the OMS Community Edition deployment tool will automatically verify the resources for CPU, Memory, and Disk. If any of these resources are not met, it will prompt that the corresponding resource is insufficient, which will affect the data migration speed.

5. Complete the deployment according to the tool's prompts. Press Enter to proceed to the next step after each input.

   1. Select the deployment mode.

      Select **Multi-node in a single region**.

   2. Select the task you want to perform.

      Select **No configuration file, deploy OMS Community Edition from scratch, starting with the generation of the configuration file**.

   3. Enter the following MetaDB cluster configuration information:

      1. Enter the IP address, port, username, and password of the metadata database in sequence.

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>The password for the metadata database user cannot be empty and does not support special characters (including line breaks, spaces, and |"'`()=;/&[]{}). </p>
         </main>

      2. Set a prefix for the OMS Community Edition metadata database.

         For example, if the prefix is set to oms, the final created metadata database names are oms_rm, oms_cm, and oms_cm_hb.

      3. Confirm the configuration information.

         Enter y to confirm that the above configuration information is correct. Enter n to re-enter the configuration information.

         If the prompt **The corresponding database name already exists in the metadata database! Is this okay?** appears, it indicates that the database name you entered already exists in the MetaDB cluster. This may be due to repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment, or enter n to re-enter the configuration information.

         If you enter y, you will be prompted **The corresponding database name already exists in the metadata database. Do you want to reinitialize the metadata database?** Enter y to reinitialize the metadata database.

   4. Enter the following OMS Community Edition cluster configuration information:

      1. Set whether to customize the component port numbers and configure the related parameters.

         Enter y to indicate that you need to customize the component port numbers. Enter the port numbers for Nginx, GHANA, CM, Supervisor, and sshd services in sequence according to the interface prompts.

      2. Enter the address of the OMS Community Edition cluster management service, which is the same VIP or domain name mounted on all CM machines in the current region. The original configuration item name is `cm-url`.

         Enter the VIP domain name as the `cm-url` address. You can enter the IP address and port number of the URL in sequence, or use a colon (:) to connect them and enter <IP address>:<Port number> at once.

         <main id="notice" type='explain'>
         <h4>Note</h4>
         <p>The <code>http://</code> prefix is optional. </p>
         </main>

      3. Enter the IP addresses of all machines in the local region, separated by commas (,).

      4. Confirm the displayed OMS Community Edition cluster configuration information.

         Enter y if the configuration information is correct. Enter n to modify it.

   5. Confirm whether to monitor the historical data of OMS Community Edition.

      * If you deployed the time series database in the **(Optional) Deploy the time series database** step, enter y in this step and proceed to the **Configure the time series database** step to enable monitoring of the historical data of OMS Community Edition.

      * If you did not deploy the time series database in the **(Optional) Deploy the time series database** step, enter n in this step and proceed to the **Enable the audit log feature and configure the related SLS parameters** step. In this case, the deployed OMS Community Edition does not support monitoring historical data.

   6. Configure the time series database.

      Enter the following time series database configuration information:

      1. Is there an already deployed time series database service?

         Enter y if there is one, or n if there is not.

      2. Select the type of the time series database: select "INFLUXDB".

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>Only INFLUXDB is supported for the time series database. </p>
         </main>

      3. Enter the URL, username, and password of the time series database in sequence according to the prompts.

      4. Confirm all the displayed configuration items.

         Enter y if the configuration information is correct. Enter n to modify it.

   7. Do you want to enable the audit log feature for OMS Community Edition and write the audit logs to the SLS service?

      If you enter y, the audit log feature is enabled. Then, you will proceed to the **Enter the SLS parameters** step.

      If you enter n, the deployment will start. In this case, the deployed OMS Community Edition does not support the audit log feature.

   8. Enter the SLS parameters.

      1. Enter the SLS parameters as prompted.

      2. Confirm all the displayed configuration items.

      Enter y if the configuration information is correct. Enter n to modify it.

   9. If the configuration file check passes, all the configuration information will be displayed. If you confirm that the configuration information is correct, enter n. If you need to modify it, enter y.

       If the configuration file check fails, modify the configuration information as prompted.

   10. Deploy and configure each node in sequence.

       1. Enter the mount directory for deploying OMS Community Edition on the node with the specified IP address:

          Enter a directory with sufficient capacity as the mount directory for the OMS Community Edition container.

       2. Confirm whether the image name for deploying OMS Community Edition is <OMS_IMAGE>.

          Enter y if the image name is correct. Enter n to modify it.

       3. Confirm whether to mount the HTTPS certificate in the OMS Community Edition container.

          If you need to mount the HTTPS certificate, enter y and enter the https_key and https_crt directories as prompted. If you do not need to mount the HTTPS certificate, enter n.

       4. If the node is a remote node, check whether the IP address of the node to be deployed is different from the IP address of the machine where the deployment tool is executed. If the IP addresses are different, you need to execute the script on the remote node. The remote node must be able to connect to the deployment tool through SSH, and you must have the `sudo` permission on the remote node.

          If you enter y, confirm whether the port of the node can be connected to through SSH. After you set the port to support SSH connection, enter the username and password for logging in to the remote node as prompted.

          If you enter an empty password, you will be prompted whether to use the trusted login method. If you enter y, re-enter the `sudo` password for the node user. If you do not need a password, press Enter directly.

       5. Confirm whether the config.yaml file under <Node IP> will be written to the specified path.

          Enter y if the path is correct. Enter n to modify it.

       6. Start the deployment.

            * During the deployment, you can execute the command `docker logs -f <OMS Community Edition container name>` to view the initialization progress.

               If you need to view all the startup initialization logs, you can execute the command `docker logs <OMS Community Edition container name>`.

            * If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

            * If the OMS container fails to start, you cannot obtain the log information.

## Deployment process (with configuration file)

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy a time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy a time series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -c <Existing config.yaml configuration file path> -i <Local IP address> -d <OMS_IMAGE>
   ```

   At this point, the OMS Community Edition deployment tool will automatically verify the resources for CPU, Memory, and Disk. If any of these resources do not meet the requirements, it will prompt you that the corresponding resources are insufficient, which will affect the data migration speed.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>The existing config.yaml configuration file path specified after <code>-c</code> must be an absolute path.</li>
    <li>For more information about the settings in the <code>config.yaml</code> configuration file, see the <a href="#config">Template and example of the configuration file</a> section.</li>
    </ul>
   </main>

5. Follow the prompts to complete the deployment. Press Enter after each input.

   1. Select the deployment mode.

      Select **Multi-node in a single region**.

   2. Select the task you want to perform.

      Select **Start configuration based on a reference configuration file passed in by the [-c] option**.

   3. If the prompt **The corresponding database name already exists in the MetaDB! Is this okay?** appears, it indicates that the database name you entered already exists in the MetaDB of the existing configuration file. This situation may be caused by repeated deployment or OMS upgrade. After you confirm, enter y to continue the deployment or n to re-enter the configuration information.

   4. If the configuration file check is passed, all the configuration information will be displayed. If you confirm that the information is correct, enter n. If you need to modify the information, enter y.

      If the configuration file check is not passed, modify the configuration information based on the prompt.

   5. Configure and execute the deployment for each node in sequence.

      1. Enter the mount directory for the OMS Community Edition container to be deployed on node <Node IP>:

         Enter a directory with sufficient capacity as the mount directory for the OMS Community Edition container.

         If the node is a remote node, you will be prompted to enter the username and password for logging in to the remote node. The corresponding user must have sudo privileges on the remote node.

      2. Confirm whether the image name for deploying OMS Community Edition is <OMS_IMAGE>.

         If you confirm that the image name is correct, enter y. If you need to modify the image name, enter n.

      3. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

         If you need to mount an HTTPS certificate, enter y and enter the https_key and https_crt directories based on the prompt. If you do not need to mount an HTTPS certificate, enter n.

      4. If the node is a remote node, the deployment tool will check whether the IP address of the node to be deployed is different from the IP address of the machine where the deployment tool is executed. If the IP addresses are different, the deployment tool will prompt you to execute the script remotely (the remote node must be able to connect to the deployment tool through SSH, and the user must have sudo privileges on the remote node).

          If you enter y, confirm whether the port of the node can be connected to through SSH. After you enable the port, enter the username and password for logging in to the remote node based on the prompt.

          If you enter an empty password, the deployment tool will prompt you whether to use trusted login. If you enter y, re-enter the sudo password of the node user (if no password is required, just press Enter).

      5. Confirm whether the path for writing the config.yaml file under <Node IP> is correct.

          If you confirm that the path is correct, enter y. If you need to modify the path, enter n.

      If the deployment fails, you can log in to the running OMS Community Edition container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain log information. If the OMS container fails to start, you cannot obtain log information.

After the deployment is completed, if you need to modify the configuration, perform the following steps:

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>In the multi-node in a single region scenario, you need to manually modify the configuration of each node.</p>
</main>

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file based on your business requirements.

3. Go to the `/root` directory and run the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Run the `supervisorctl restart oms_console oms_drc_supervisor` command.

## Template and sample of the configuration file

### Configuration file template

<main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>When you deploy the system in a multi-node mode, all nodes must use the same configuration file. In the configuration file, you must specify the IP addresses of multiple nodes in the <code>cm_nodes</code> parameter, and set the <code>cm_url</code> parameter to the VIP address corresponding to port 8088. </p>
    </li>
    <li>
    <p>You must replace the required parameters in the template with the actual values in your deployment environment. Optional parameters are commented in the template. You can modify them as needed. </p>
    </li>
    <li>
    <p>In the <code>config.yaml</code> file, a space must be added after the colon in the Key: Value pair. </p>
    </li>
    </ul>
  </main>

```yaml
# OMS metadata database information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# You can customize the names of the following three databases. When you deploy OMS Community Edition, these three databases are created in the metadata database.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition cluster configuration
# When you deploy the system in a multi-node mode in a single region, set the cm_url parameter to the VIP or domain name of all CM nodes in the current region.
cm_url: ${cm_url}
cm_location: ${cm_location}
# When you deploy the system in a single region, you do not need to set the cm_region parameter.
# cm_region: ${cm_region}
# When you deploy the system in a single region, you do not need to set the cm_region_cn parameter.
# cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - ${host_ip1}
 - ${host_ip2}

# Time series database configuration
# The default value is false. If you want to enable the metric reporting feature, set this parameter to true and remove the comment before it.
# tsdb_enabled: false
# When tsdb_enabled is set to true, remove the comment before the following parameters and set them to the actual values.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}

# User-defined component port numbers
# Specify the port number of the GHANA service.
ghana_server_port: xxxxx
# Specify the port number of the Nginx service.
nginx_server_port: xxxxx
# Specify the port number of the CM service.
cm_server_port: xxxxx
# Specify the port number of the Supervisor service.
supervisor_server_port: xxxxx
# Specify the port number of the sshd service.
sshd_server_port: xxxxx
```
