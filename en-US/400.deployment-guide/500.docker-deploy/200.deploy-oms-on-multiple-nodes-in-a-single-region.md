# Deploy OMS Community Edition in a single region with multiple nodes

This topic describes how to deploy OMS Community Edition in a single region with multiple nodes by using the OMS Community Edition deployment tool.

## Background information

* To implement a multi-node deployment, you can first deploy a single node and then expand it to multiple nodes.

* If you choose the deployment method with a configuration file, note that the configuration information for single-node and multi-node deployments (in the `config.yaml` file) is slightly different. For details, see the "Template and Sample" section below.

* In a multi-node deployment environment, you need to apply for a VIP as the mount point for the OMS Community Edition console. Additionally, you need to configure the mapping rules for ports 8088 and 8089 on the VIP network policy.

  After you apply for a VIP, you can still access the OMS Community Edition console through the VIP even if an OMS Community Edition node fails.

## Prerequisites

* Make sure that the installation environment meets the system and network requirements. For more information, see [System and network requirements](../200.system-requirements.md).

* A MetaDB cluster has been prepared as the metadata storage for OMS Community Edition.

* The deployment machine can communicate with all other nodes.

* In a multi-node deployment scenario, ensure that the nodes are interconnected and that you can obtain root privileges for each node by entering the username and password.

* The OMS Community Edition installation package has been downloaded. The installation package is usually a `tar.gz` file that starts with oms. Download address: [OceanBase Community Edition download center](https://open.oceanbase.com/softwareCenter/community).

* The downloaded OMS Community Edition installation package has been loaded to the local image repository of the Docker container on each node.

   ```shell
   docker load -i <OMS Community Edition installation package>
   ```

* A directory for mounting the OMS Community Edition container has been prepared. The OMS Community Edition will create three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of OMS during runtime.

* (Optional) A time-series database has been prepared to store the performance metrics and DDL/DML statistical information of OMS Community Edition.

## Terms

In the subsequent topics, some commands and prompts contain variables that you need to replace. Variables are enclosed in `<>` and are explained as follows:

* OMS Community Edition container mounting directory: For more information, see the description of the OMS Community Edition container mounting directory in the prerequisites.

* Host IP address: The IP address of the host where the script is executed.

* OMS_IMAGE: After you load the OMS Community Edition installation package by using Docker, run the `docker images` command to obtain the [IMAGE ID] or [REPOSITORY:TAG] of the loaded image. The obtained value is the unique identifier of the image, which is `<OMS_IMAGE>`. Example:

   ```shell
   $sudo docker images
   REPOSITORY                               TAG                 IMAGE ID          
   work.oceanbase-dev.com/obartifact-store/oms feature_4.0.0-ce    2786e8a6eccd        
   ```

   In this example, `<OMS_IMAGE>` can be `work.oceanbase-dev.com/obartifact-store/oms:feature_4.0.0-ce` or `2786e8a6eccd`. In the subsequent topics, replace `<OMS_IMAGE>` with the value in the preceding example.

* Existing `config.yaml` configuration file address: If you want to deploy OMS based on an existing `config.yaml` configuration file, specify the address of the existing configuration file.

## Deployment process (without configuration file)

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy the time-series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy the time-series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time-series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Execute the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Here is an example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_4.0-ce bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Start the deployment tool by using the deployment script.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -i <Local IP address> -d <OMS_IMAGE>
   ```

   In this case, the OMS Community Edition deployment tool automatically verifies the resources of the CPU, memory, and disk. If any of the resources do not meet the requirements, the corresponding resource is insufficient, which affects the data migration speed.

5. Complete the deployment based on the prompts provided by the tool. Press Enter after each input to proceed.

   1. Select the deployment mode.

      Here, select **Multi-node in a single region**.

   2. Select the task to be performed.

      Here, select **No configuration file, deploy OMS Community Edition from scratch**.

   3. Enter the following MetaDB cluster configuration information:

      1. Enter the IP address, port, username, and password of the metadata database in sequence based on the prompts.

      2. Set the prefix for the OMS Community Edition metadata database.

         For example, if the prefix is set to oms, the names of the created metadata databases are oms_rm, oms_cm, and oms_cm_hb.

      3. Confirm the configuration information.

         Enter y to confirm that the above configuration information is correct. Enter n to re-enter the configuration information.

         If the prompt **The corresponding database name already exists in the metadata database! Is that okay?** appears, it indicates that the database name you entered already exists in the MetaDB cluster. This may be caused by repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment, or enter n to re-enter the configuration information.

         If you enter y, the prompt **The corresponding database name already exists in the metadata database. Do you want to reinitialize the metadata database?** appears. Enter y to reinitialize the metadata database.

   4. Enter the following OMS Community Edition cluster configuration information:

      1. Set whether to customize the port numbers of the components and configure the related parameters.

         Enter y to customize the port numbers of the components. Based on the interface prompts, enter the port numbers of Nginx, GHANA, CM, Supervisor, and sshd services in sequence.

      2. Enter the address of the OMS Community Edition cluster management service, which is the same VIP or domain name mounted to all CM machines in the current region. The original parameter name is `cm-url`.

         Enter the VIP domain name as the `cm-url` address. You can enter the IP address and port number in the URL in sequence, or use a colon (:) to connect them and enter <IP address>:<Port number> at one time.

         <main id="notice" type='explain'>
         <h4>Note</h4>
         <p>The <code>http://</code> prefix is optional. </p>
         </main>

      3. Enter the IP addresses of all machines in the local region, separated by commas (,).

      4. Confirm the displayed OMS Community Edition cluster configuration information.

         Enter y if you confirm that the information is correct. Enter n to modify the information.

   5. Confirm whether to monitor the historical data of OMS Community Edition.

      * If you selected to deploy the time-series database in the **(Optional) Deploy the time-series database** step, enter y and go to the **Configure the time-series database** step to enable monitoring of the historical data of OMS Community Edition.

      * If you did not select to deploy the time-series database in the **(Optional) Deploy the time-series database** step, enter n and go to the **Enable the audit log feature and configure the related SLS parameters** step. In this case, the deployed OMS Community Edition does not support monitoring historical data.

   6. Configure the time-series database.

      Enter the following time-series database configuration information:

      1. Is the time-series database service already deployed?

         Enter y if the time-series database service is already deployed. Enter n if it is not.

      2. Select the type of the time-series database: select "INFLUXDB".

         <main id="notice" type='notice'>
         <h4>Notice</h4>
         <p>Only the INFLUXDB time-series database is supported. </p>
         </main>

      3. Enter the URL, username, and password of the time-series database based on the prompts.

      4. Confirm all the displayed configuration information.

         Enter y if you confirm that the information is correct. Enter n to modify the information.

   7. Do you want to enable the audit log feature of OMS Community Edition and write the audit logs to the SLS service?

      If you enter y, the audit log feature is enabled. In this case, go to the **Enter the SLS parameters** step.

      If you enter n, the deployment starts. In this case, the deployed OMS Community Edition does not support the audit log feature.

   8. Enter the SLS parameters.

      1. Enter the SLS parameters based on the prompts.

      2. Confirm all the displayed configuration information.

      Enter y if you confirm that the information is correct. Enter n to modify the information.

   9. If the configuration file is checked, all the configuration information is displayed. If you confirm that the information is correct, enter n. If you need to modify the information, enter y.

       If the configuration file is not checked, modify the configuration information based on the prompts.

   10. Deploy and configure each node in sequence.

       1. Enter the mount directory for OMS Community Edition on the node with the IP address <Node IP>:

          Enter a directory with a large capacity as the mount directory for the OMS Community Edition container.

       2. Confirm whether the image name of OMS Community Edition is <OMS_IMAGE>.

          Enter y if you confirm that the information is correct. Enter n to modify the information.

       3. Confirm whether to mount the HTTPS certificate to the OMS Community Edition container.

          If you need to mount the certificate, enter y and enter the https_key and https_crt directories based on the prompts. If you do not need to mount the certificate, enter n.

       4. If the node is a remote node, check whether the IP address of the node to be deployed is different from the IP address of the machine where the deployment tool is executed. If the remote node can be connected to by using SSH and the user has the `sudo` permission on the remote node, enter y to execute the script remotely.

          If you enter y, confirm whether the port of the node can be connected to by using SSH. If the port can be connected to, enter the username and password of the remote node based on the interface prompts.

          If you enter an empty password, a prompt appears that asks whether to use the trusted login method. If you enter y, re-enter the `sudo` password of the node user. If you do not need to enter a password, press Enter.

       5. Confirm whether the path for writing the config.yaml file under <Node IP> is correct.

          Enter y if you confirm that the information is correct. Enter n to modify the information.

       6. Start the deployment.

            * During the deployment, you can execute the `docker logs -f <OMS Community Edition container name>` command to view the initialization status.

               To view all the startup initialization logs, execute the `docker logs <OMS Community Edition container name>` command.

            * If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

            * If the OMS container fails to start, you cannot obtain the log information.

## Deployment process (with configuration file)

1. Log in to the OMS Community Edition deployment server.

2. (Optional) Deploy a time-series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy a time-series database. If you do not need to display monitoring data, skip this step. For more information, see [Deploy a time-series database](../500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -c <Existing config.yaml configuration file address> -i <Local IP address> -d <OMS_IMAGE>
   ```

   At this point, the OMS Community Edition deployment tool will automatically check the CPU, memory, and disk resources. If any of these resources are insufficient, it will prompt you that the corresponding resource is insufficient, which will affect the data migration speed.

   <main id="notice" type='explain'>
    <h4>Note</h4>
    <ul>
    <li>The existing config.yaml configuration file address after <code>-c</code> must be an absolute path.</li>
    <li>For the settings of the <code>config.yaml</code> configuration file, see the <a href="#template">Template and Example of the Configuration File</a> section below.</li>
    </ul>
   </main>

5. Complete the deployment as prompted by the tool. Press Enter after each input to proceed to the next step.

   1. Select the deployment mode.

      Select **Multi-node in a single region**.

   2. Select the task you want to perform.

      Select **Use the reference configuration file provided by the script [-c] option to start the configuration**.

   3. If the prompt **The database name already exists in the MetaDB! Is this okay?** appears, it indicates that the database name you entered already exists in the MetaDB of the original configuration file. This situation may be caused by repeated deployment or OMS upgrade. After you confirm, enter y to continue the deployment or enter n to re-enter the configuration information.

   4. If the configuration file check is passed, all the configuration information will be displayed. If you confirm that the information is correct, enter n. If you need to modify the information, enter y.

      If the configuration file check is not passed, modify the configuration information as prompted.

   5. Deploy and configure each node in sequence and execute the deployment.

      1. Enter the mount directory for the OMS Community Edition container to be deployed on node <Node IP>:

         Enter a directory with a large capacity as the mount directory for the OMS Community Edition container.

         If the node is a remote node, you will be prompted to enter the username and password for logging in to the remote node. The corresponding user must have sudo privileges on the remote node.

      2. Confirm whether the image name for deploying OMS Community Edition is <OMS_IMAGE>.

         If you confirm that the image name is correct, enter y. If you need to modify the image name, enter n.

      3. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

         If you need to mount an HTTPS certificate, enter y and enter the https_key and https_crt directories as prompted. If you do not need to mount an HTTPS certificate, enter n.

      4. If the node is a remote node, the deployment tool will check whether the IP address of the node to be deployed is different from the IP address of the current deployment tool. If the IP addresses are different, you will be prompted to execute the script remotely (the remote node must be able to connect to the deployment tool through SSH, and the user must have sudo privileges on the remote node).

          If you enter y, confirm whether the port of the node can be connected to the deployment tool through SSH. After you set the port to support the connection, enter the username and password for logging in to the remote node as prompted.

          If the password you enter is empty, you will be prompted whether to use trusted login. If you enter y, re-enter the password for the user with sudo privileges on the node (if no password is required, press Enter directly).

      5. Confirm whether the path for writing the config.yaml file under <Node IP> is correct.

          If you confirm that the path is correct, enter y. If you need to modify the path, enter n.

      If the deployment fails, you can log in to the running OMS Community Edition container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information. If the OMS container fails to start, you cannot obtain the log information.

After the deployment is completed, if you want to modify the configuration, perform the following steps:

<main id="notice" type='notice'>
<h4>Notice</h4>
<p>In the multi-node deployment scenario, you need to manually modify the configuration of each node.</p>
</main>

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file based on your business needs.

3. Run the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Run the `supervisorctl restart oms_console oms_drc_supervisor` command.

## Templates and examples of configuration files

### Configuration file template

  <main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>When you deploy the system in a multi-node mode, all nodes must use the same configuration file. In the configuration file, you must specify the IP addresses of multiple nodes in the <code>cm_nodes</code> parameter, and set the <code>cm_url</code> parameter to the VIP address corresponding to port 8088.</p>
    </li>
    <li>
    <p>The required parameters in the template must be replaced with the actual values of the target environment. Optional parameters are commented out in the template. You can modify them as needed.</p>
    </li>
    <li>
    <p>In the <code>config.yaml</code> file, the Key: Value format must have a space after the colon.</p>
    </li>
    </ul>
  </main>

```yaml
# OMS metadata information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# You can customize the following three databases. When you deploy OMS Community Edition, these three databases are created in the metadata database.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition cluster configuration
# When you deploy the system in a multi-node mode in a single region, set the cm_url parameter to the VIP or domain name of one CM node in the current region.
cm_url: ${cm_url}
cm_location: ${cm_location}
# When you deploy the system in a single region, you do not need to set the cm_region parameter.
# cm_region: ${cm_region}
# When you deploy the system in a single region, you do not need to set the cm_region_cn parameter.
# cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - ${host_ip1}
 - ${host_ip2}

# Time series database configuration
# The default value is false. If you want to enable the metrics reporting feature, set the value to true and remove the comment mark before the parameter.
# tsdb_enabled: false
# If the value of tsdb_enabled is true, remove the comment mark before the following parameters and set the values based on your actual environment.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}

# Port numbers of user-defined components
# Specify the port number of the GHANA service.
ghana_server_port: xxxxx
# Specify the port number of the Nginx service.
nginx_server_port: xxxxx
# Specify the port number of the CM service.
cm_server_port: xxxxx
# Specify the port number of the Supervisor service.
supervisor_server_port: xxxxx
# Specify the port number of the sshd service.
sshd_server_port: xxxxx
```
