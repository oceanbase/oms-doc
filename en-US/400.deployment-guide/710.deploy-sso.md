# Access OMS Community Edition by using the OIDC protocol to implement SSO

OceanBase Migration Service (OMS) Community Edition is compatible with the OAuth 2.0 authentication center and supports the OpenID Connect (OIDC) protocol. Currently, only the authorization code (authorization-code) mode is supported. This topic describes the configurations that you need to update to access OMS Community Edition by using the OIDC protocol and implement the SSO feature.

## Get the configuration of the authentication center

You need to add an application in the SSO service to obtain the application ID, application key, and other configurations required for OIDC.

|            Parameter     |     Description       |
|---------------------|----------------|
|    clientId    | The application ID.|
|    clientSecret | The application key.|
|   scope   | The permission ID, which is a string in the format of `ID1,ID2,...`. The string must contain `openid`. For example, `openid,profile`. |
| ClientAuthenticationMethod | The authentication method. Valid values: `client_secret_basic` (recommended) and `basic`.|
| jwk_set_uri | The URI for decoding JWKs. |
| authorization_uri | The authorization endpoint.|
| token_uri | The token endpoint. |

## Configure the callback URL

If your SSO system has a white list for login callback URLs, you need to configure the white list.

The login callback URL is configured as: `http://{serverDomain}/login/oauth2/code/oms`, where `serverDomain` is the domain name of your deployed OMS Community Edition.

## Deploy OMS Community Edition

This topic describes how to log in to OMS Community Edition by using single sign-on (SSO) in a single-node deployment scenario. For more information about how to deploy OMS Community Edition in a multi-node deployment scenario in a single region or across regions, see the [Deploy OMS Community Edition in a multi-node deployment scenario in a single region](../400.deployment-guide/500.docker-deploy/200.deploy-oms-on-multiple-nodes-in-a-single-region.md) topic.

### Prerequisites

* The installation environment meets the system and network requirements. For more information, see [System and network requirements](../400.deployment-guide/200.system-requirements.md).

* You have prepared a MetaDB cluster as the metadata database for OMS Community Edition.

* You have obtained the OMS Community Edition installation package, which is usually a `tar.gz` file that starts with oms.

* You have loaded the OMS Community Edition installation package to the local image repository of the Docker container.

   `docker load -i <OMS Community Edition installation package>`

* You have prepared a directory to mount the OMS Community Edition container. OMS Community Edition will create three mapped directories: `/home/admin/logs`, `/home/ds/store`, and `/home/ds/run`, to store the components and log information of OMS Community Edition.

* (Optional) You have prepared a time series database to store the performance monitoring data and DDL/DML statistics of OMS Community Edition.

### Procedure

1. Log in to the server where OMS Community Edition is deployed.

2. (Optional) Deploy a time series database.

   If you want OMS Community Edition to collect and display monitoring data, deploy a time series database. If you do not want to display monitoring data, skip this step. For more information, see [Deploy a time series database](../400.deployment-guide/500.docker-deploy/600.deploy-a-time-series-database.md).

3. Run the following command to obtain the deployment script `docker_remote_deploy.sh` from the loaded image.

   ```shell
   sudo docker run -d --net host --name oms-config-tool <OMS_IMAGE> bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

   Here is an example:

   ```shell
   sudo docker run -d --net host --name oms-config-tool work.oceanbase-dev.com/obartifact-store/oms:feature_3.4.0 bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy.sh . && sudo docker rm -f oms-config-tool
   ```

4. Run the deployment script to start the deployment tool.

   ```shell
   bash docker_remote_deploy.sh -o <OMS Community Edition container mount directory> -c <Existing config.yaml file address> -i <Local IP address> -d <OMS_IMAGE>
   ```

   The OMS Community Edition deployment tool automatically verifies the resources of CPU, memory, and disk. If any of these resources are insufficient, the corresponding resource shortage will be prompted, which will affect the data migration speed.

5. Complete the deployment based on the prompts. Press Enter after each input.

   1. Select the deployment mode.

      Select **Single Region Single Node**.

   2. Select the task to perform.

      Select **Use the reference configuration file passed in by the [-c] option to start the configuration**.

   3. If the prompt **The database name already exists in the metadata database. Continue?** appears, it indicates that the database name you entered already exists in the MetaDB of the existing configuration file. This situation may be caused by repeated deployment or OMS Community Edition upgrade. After you confirm, enter y to continue the deployment, or enter n to re-enter the configuration information.

   4. If the configuration file is validated, all the configuration information will be displayed. If you confirm that the information is correct, enter n. If you need to modify the information, enter y.

      If the configuration file is not validated, modify the configuration information based on the prompt.

   5. Enter the mount directory for the OMS Community Edition container to be deployed on the node <Node IP>.

      Enter a directory with a large capacity as the mount directory for the OMS Community Edition container.

   6. Confirm whether the image name of OMS Community Edition is <OMS_IMAGE>.

      If you confirm that the image name is correct, enter y. If you need to modify the image name, enter n.

   7. Confirm whether to mount an HTTPS certificate in the OMS Community Edition container.

      If you need to mount an HTTPS certificate, enter y and enter the https_key and https_crt directories based on the prompt. If you do not need to mount an HTTPS certificate, enter n.

   8. Start the deployment.

         * During the deployment, you can run the `docker logs -f <OMS Community Edition container name>` command to view the initialization status.

            To view all the startup initialization logs, run the `docker logs <OMS Community Edition container name>` command.

         * If the deployment fails, you can log in to the running OMS container and view the `.log` files with the `docker_init` prefix in the `/home/admin/logs` directory to obtain the log information.

         * If the OMS container fails to start, you cannot obtain the log information.

After the deployment is completed, if you need to modify the configuration, perform the following steps:

1. Log in to the running OMS Community Edition container.

2. Modify the `/home/admin/conf/config.yaml` file based on your business requirements.

3. Go to the `/root` directory and run the `python -m omsflow.scripts.units.oms_init_manager --init-config-file` command.

4. Run the `supervisorctl restart oms_console oms_drc_supervisor` command.

## Template and example of configuration files

### Template

<main id="notice" type='notice'>
    <h4>Notice</h4>
    <ul>
    <li>
    <p>Replace the required parameters in the template with the actual values of the target environment where you deploy OMS. Optional parameters are commented in the template. You can modify them as needed. </p>
    </li>
    <li>
    <p>For the Key: Value pairs in the <code>config.yaml</code> file, a space must be added after the colon. </p>
    </li>
    </ul>
</main>

```yaml
# OMS Community Edition metadata database information
oms_meta_host: ${oms_meta_host}
oms_meta_port: ${oms_meta_port}
oms_meta_user: ${oms_meta_user}
oms_meta_password: ${oms_meta_password}

# You can customize the names of the following three databases. OMS Community Edition creates these databases in the metadata database when it is deployed.
drc_rm_db: ${drc_rm_db}
drc_cm_db: ${drc_cm_db}
drc_cm_heartbeat_db: ${drc_cm_heartbeat_db}

# OMS Community Edition cluster configuration
# In single-node deployment, the IP address of the current OMS Community Edition server is usually configured (we recommend that you use the private IP address).
cm_url: ${cm_url}
cm_location: ${cm_location}
# In single-node deployment, you do not need to set the cm_region parameter.
# cm_region: ${cm_region}
# In single-node deployment, you do not need to set the cm_region_cn parameter.
# cm_region_cn: ${cm_region_cn}
cm_is_default: true
cm_nodes:
 - ${cm_nodes}

# Time series database configuration
# The default value is false. Set this parameter to true if you want to enable the metric reporting feature.
# tsdb_enabled: false
# If tsdb_enabled is set to true, uncomment the following parameters and set them to the actual values.
# tsdb_service: 'INFLUXDB'
# tsdb_url: '${tsdb_url}'
# tsdb_username: ${tsdb_user}
# tsdb_password: ${tsdb_password}

# The following parameters are required when you log in to OMS Community Edition by using single sign-on (SSO).
oms_iam_auth: OAUTH2
oms_oauth2_user_account_name_field: nickname
oms_oauth2_sso_login_url: http://oms.example.org:8090/omsp/oauth2/authorization/oms?oms_back_url=http://oms.example.org:8089
spring_security_oauth2_client_registration_oms_client_id: xxx
spring_security_oauth2_client_registration_oms_client_secret: xxx
spring_security_oauth2_client_registration_oms_redirect_uri: http://oms.example.org:8090/omsp/login/oauth2/code/{registrationId}
spring_security_oauth2_client_registration_oms_authorization_grant_type: authorization_code
spring_security_oauth2_client_registration_oms_scope: openid,profile
spring_security_oauth2_client_registration_oms_clientAuthenticationMethod: client_secret_basic
spring_security_oauth2_client_registration_oms_provider: oms
spring_security_oauth2_client_provider_jwk_set_uri: https:xxx.com
spring_security_oauth2_client_provider_authorization_uri: https://xxxx/api/auth
spring_security_oauth2_client_provider_token_uri: https://xxx/api/token
```

Parameter description

:::collapse

|         Parameter          |                            Description                     |       Required        |
|---------------------|-------------------------------------------|---------------------------------------------------|
| oms_meta_host       | The IP address of the metadata database, which can be a MySQL database or an OceanBase Database in MySQL mode.<br> **Notice:** <br> OceanBase Database must be V2.0 or later.        | Yes                |
| oms_meta_port       | The port number of the metadata database.              | Yes                |
| oms_meta_user       | The username of the metadata database.        | Yes                |
| oms_meta_password   | The password of the metadata database. <main id="notice" type='notice'><h4>Notice</h4><p>The password of the metadata database cannot be empty and cannot contain special characters (including line breaks, spaces, and \|"'`()=;/&[]{}). </p></main>       | Yes                |
| drc_rm_db           | The name of the database in the management console.       | Yes                |
| drc_cm_db           | The name of the metadata database of the cluster management service.                | Yes                |
| drc_cm_heartbeat_db | The name of the heartbeat database of the cluster management service.                 | Yes                |
| cm_url              | The URL of the cluster management service of OMS Community Edition. Example: `http://xxx.xxx.xxx.xxx:8088`.<br>**Note:** <br> In a single-node deployment, the IP address of the current OMS Community Edition server is usually configured. We recommend that you do not use `http://127.0.0.1:8088`. <br>The URL of the OMS console is `IP address of the host where OMS is deployed:8089`. Example: `http (https)://xxx.xxx.xxx.xxx:8089`. <br>Port 8088 is used for scheduling, and port 8089 is used for web access. Port 8088 must be used here. | Yes                |
| cm_location         | The region code, which ranges from 0 to 127. Each region is assigned a unique number. You can choose the region code.            | Yes                |
| cm_region           | The region, such as cn-jiangsu. <br>**Notice:**<br>  If you use the OMS Community Edition with MSHA of Alibaba Cloud in a disaster recovery active-active scenario, use the region information of Alibaba Cloud as `cm_region`.                          | No                |
| cm_region_cn        | The Chinese name of the region. Example: Jiangsu.                        | No                |
| cm_nodes            | The IP address list of the cluster management service of OMS Community Edition.                    | Yes                |
| cm_is_default       | Specifies whether to use the cluster management service of OMS Community Edition as the default one.                          | No. Default value: `true`    |
| tsdb_enabled        | Specifies whether to enable the monitoring feature. Valid values: `true` and `false`.                           | No. Default value: `false`   |
| tsdb_service        | The type of the time series database. Valid values: `INFLUXDB` and `CERESDB`.                       | No. Default value: `INFLUXDB` |
| tsdb_url            | The IP address of the server where InfluxDB is deployed. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your actual environment.                | No                |
| tsdb_username       | The username of the time series database. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your actual environment. After you deploy the time series database, you must manually create a user for the time series database and specify the username and password.                            | No                |
| tsdb_password       | The password of the time series database. If `tsdb_enabled` is set to `true`, you must modify this parameter based on your actual environment.                 | No                |
| oms_iam_auth | The login method. Valid values: OAUTH2 and LOCAL. OAUTH2 supports the password mode.  | Yes                |
| oms_oauth2_user_account_name_field | The field used to obtain the username from the ID token. Example: nick or nickname.  | Yes                |
| oms_oauth2_sso_login_url | The URL for redirecting to single sign-on (SSO) by using the OpenID Connect (OIDC) protocol. The URL format is `http://{cm_url}/omsp/oauth2/authorization/oms?oms_back_url={serverDomain}`. Here, `{serverDomain}` is the user domain, and `oms_back_url` is the frontend page after login. | Yes                |
|spring_security_oauth2_client_registration_oms_client_id | The client ID of the application. | Yes                |
|spring_security_oauth2_client_registration_oms_client_secret | The client secret of the application.  | Yes                |
| spring_security_oauth2_client_registration_oms_redirect_uri | The `redirectUrl` configured in the step of configuring the callback URL. The URL format is `http://{serverDomain}/omsp/login/oauth2/code/{registrationId}`.<br>Here, {serverDomain} is the user domain, and {registrationId} is not required. | Yes                |
|  spring_security_oauth2_client_registration_oms_authorization_grant_type | The authorization type used when the OMS Community Edition interacts with the OAuth2 authorization server. Only the `authorization_code` mode is supported.  | Yes                |
| spring_security_oauth2_client_registration_oms_scope | The permission identifier, which is separated by commas (,). It must contain `openid`.  |Yes|
|spring_security_oauth2_client_registration_oms_provider | The name of the authorization service provider. You can customize the name. Example: oidc.  | Yes                |
| spring_security_oauth2_client_provider_jwk_set_uri |  The URL used for decoding the JWK. | Yes                |
| spring_security_oauth2_client_provider_authorization_uri |  The authorization endpoint. | Yes                |
| spring_security_oauth2_client_provider_token_uri | The endpoint for obtaining credentials.  | Yes                |
