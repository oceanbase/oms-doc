# Create a task to synchronize data from OceanBase Database Community Edition to a RocketMQ instance

Message Queue for Apache RocketMQ is a distributed message-oriented middleware built by Alibaba Cloud based on Apache RocketMQ. It features low latency, high concurrency, and high reliability. The data synchronization feature of OceanBase Migration Service (OMS) Community Edition allows you to synchronize data between a physical table in OceanBase Database Community Edition and a RocketMQ data source in real time, extending the message processing capability.

For more information about the data formats for OceanBase Database Community Edition, see [Data formats](../700.data-synchronization/1200.sync-function-introduction/700.data-formats.md).

## Prerequisites

You have created a dedicated database user for data synchronization in the source OceanBase Database Community Edition and granted the required privileges to the user. For more information, see [Create a database user](../800.create-and-manage-data-sources/300.create-a-database-user.md).

## Limitations

* OMS Community Edition supports instances of RocketMQ 4.x or 5.x, including RocketMQ Enterprise Edition and RocketMQ Community Edition.

* Only physical tables can be synchronized.

* During data synchronization, OMS Community Edition allows you to drop a table before creating a new one. In other words, you can execute `DROP TABLE` and then execute `CREATE TABLE`. In OMS Community Edition, you cannot create a new table by renaming a table. In other words, you cannot execute `RENAME TABLE a TO a_tmp`.

* The name of a table to be synchronized, as well as the names of columns in the table, must not contain Chinese characters.

* The data source identifiers and user accounts must be globally unique in OMS Community Edition.

* OMS Community Edition supports the synchronization of only objects whose database name, table name, and column name are ASCII-encoded without special characters. The special characters are line breaks and <code>| " ' ` ( ) = ; / &</code>.

* The source cannot be a standby OceanBase database.

## Considerations

* To ensure the performance of a data synchronization task, we recommend that you synchronize no more than 1,000 tables at a time.

* If the source is of an OceanBase Database Community Edition version in the range of V4.0.0 to V4.3.X, excluding V4.2.5 BP1, and you have selected **<UI-TERM>Incremental Synchronization</UI-TERM>**, you need to configure the `STORED` attribute for generated columns. For more information, see [Generated column operations](https://en.oceanbase.com/docs/common-oceanbase-database-10000000001784256). Otherwise, information about generated columns will not be saved in incremental logs, which may lead to exceptions during incremental data synchronization.

* Take note of the following items when an updated row contains a LOB column:

  * If the LOB column is updated, do not use the value stored in the LOB column before the `UPDATE` or `DELETE` operation.

      The following data types are stored in LOB columns: JSON, GIS, XML, user-defined type (UDT), and TEXT such as LONGTEXT and MEDIUMTEXT.

  * If the LOB column is not updated, the value stored in the LOB column before and after the `UPDATE` or `DELETE` operation is NULL.

* When data transfer is resumed for a task, some data (within the last minute) may be duplicated in the RocketMQ instance. Therefore, deduplication is required in downstream systems.

* If the clocks between nodes or between the client and the server are out of synchronization, the latency may be inaccurate during incremental synchronization.

   For example, if the clock is earlier than the standard time, the latency can be negative. If the clock is later than the standard time, the latency can be positive.

* If the `binlog_row_image` value is not `FULL` when the application starts, you can set it to `FULL`. After that, you must restart the application. Otherwise, OceanBase Community Edition will lack log information, which leads to issues with data synchronization. The command for setting the value is as follows:

   ```shell
   set global binlog_row_image = 'FULL';
   ```

## Procedure

1. Create a data synchronization task.

   1. Log in to the console of OMS Community Edition.

   2. In the left navigation bar, click **Data Synchronization**.

   3. On the **Data Synchronization** page, click **Create a Synchronization Task** in the upper right corner.

2. On the **<UI-TERM>Select Source and Target</UI-TERM>** page, configure the parameters.

   | Parameter | Description |
   |--------|---------------------------------------------------------------------------|
   | Task Name | We recommend that you set it to a combination of digits and letters. It must not contain any spaces and cannot exceed 64 characters in length.                                                                                                            |
   | Label     | Click the text box and select the target label from the drop-down list. You can also click **<UI-TERM key="oms-v2.components.ProjectLabel.LabelSelect.ManageTags">Manage Tags</UI-TERM>** to create, modify, and delete labels. For more information, see [Manage data synchronization tasks using labels](1100.manage-a-data-synchronization-projects/300.use-tags-to-manage-data-synchronization-projects.md).                           |
   | Source End | If you have already created an OceanBase-CE data source, please select it from the drop-down list. If not, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and add it in the dialog box on the right. For parameter details, see [Create an OceanBase-CE Data Source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md). |
   | Target | If you have created a RocketMQ data source, select it from the drop-down list. Otherwise, click **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">New Data Source</UI-TERM>** in the drop-down list and create one in the dialog box that appears on the right. For more information, see [Create a RocketMQ data source](../800.create-and-manage-data-sources/100.create-a-data-source/600.create-a-rocketmq-data-source.md).       |

3. Click **Next Step** on the **Select Synchronization Type** page to choose the synchronization type for the current data synchronization task.

   The synchronization type supports **Full Synchronization** and **Incremental Synchronization**, while **Incremental Synchronization** only supports **Synchronizing DML** (including `Insert`, `Delete`, and `Update`). Please select based on your business needs. For more details, see [DML Filtering](../700.data-synchronization/1200.sync-function-introduction/100.sync-dml.md).

4. (Optional) Click **Next**.

   When the source is OceanBase Community Edition, incremental synchronization requires configuring **OCP** (optional), **DRC User Username**, and **Password**.

   If you select **Incremental Synchronization** but the source OceanBase Community Edition is not configured with the corresponding parameters, a dialog box named **Data Source Supplementary Information** will pop up to remind you to configure it. For details about the parameters, see [Create a New OceanBase-CE Data Source](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md).

   After the supplement is completed, click **<UI-TERM key="oms-community.biz.EndpointSupplement.TestConnectivity">Test connectivity</UI-TERM>**. After the connection test is successful, click **<UI-TERM key="oms-community.Endpoint.New.Save">Save</UI-TERM>**.

5. Click **Next Step** to go to the **Select Synchronization Object** page, and select the synchronization scope.

   You can select **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** or **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** to specify the synchronization objects. The following procedure describes how to specify synchronization objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">Specify Objects</UI-TERM>** option. For information about the procedure for specifying synchronization objects by using the **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">Match Rules</UI-TERM>** option, see [Configure matching rules for synchronization objects](../700.data-synchronization/1200.sync-function-introduction/300.configure-matching-rules-for-sync-objects.md).

   When you synchronize data from OceanBase Database Community Edition to a RocketMQ instance, you can synchronize data from multiple tables to multiple topics.

   1. In the left-side pane, select the objects to be synchronized.

   2. Click **>**.

   3. Click the **<UI-TERM key="oms-community.Transfer.sync.TopicForm.ExistingTopic">Existing Topics</UI-TERM>** drop-down list in the **<UI-TERM key="oms-community.Transfer.sync.MapObjectsToTopics">Map Object to Topic</UI-TERM>** dialog box and select the target topic.

      You can also enter the name of an existing topic and select it after it appears.

   4. Click **<UI-TERM key="oms-community.Operator.Connector.useConnectorAction.Update">OK</UI-TERM>**.

      When you synchronize data from OceanBase Database Community Edition to a RocketMQ instance, OMS Community Edition allows you to import objects from text and perform the following operations on the objects in the target database: change topics, set row filtering conditions, and remove a single object or all objects. Objects in the target database are listed in the structure of Topic \> Database \> Table.

      | Operation | Description |
      |----------|------------------------------------|
      | Import objects     | <ol><li>In the list on the right, click **<UI-TERM key="oms-community.components.Transfer.ImportObjects">Import Objects</UI-TERM>** in the upper-right corner.  <li>In the dialog box that appears, click **<UI-TERM key="oms-community.biz.AccountAuthorization.Ok">OK</UI-TERM>**. <br>**Notice**: <br>This operation will overwrite previous selections. Proceed with caution.   <li>In the **<UI-TERM>Import Synchronization Objects</UI-TERM>** dialog box, import the objects to be synchronized. <br>You can import CSV files to rename databases/tables and set row filtering conditions.       | Change topics | OMS Community Edition allows you to change the topic for objects in the target database. For more information, see [Change the topic](1200.sync-function-introduction/400.topic-rename.md).                                                    |
      | Configure settings | OMS Community Edition allows you to configure row-based filtering, select sharding columns, and select columns to be synchronized. <ol><li>In the list on the right, move the pointer over the object that you want to set.   <li>Click **<UI-TERM>Settings</UI-TERM>**.   <li>In the **<UI-TERM>Settings</UI-TERM>** dialog box, you can perform the following operations: <ul><li>In the **<UI-TERM>Row Filters</UI-TERM>** section, specify a standard SQL `WHERE` clause to filter data by row. For more information, see [Use SQL conditions to filter data](1200.sync-function-introduction/500.sync-row-filters.md).   <li>Select the sharding columns that you want to use from the **<UI-TERM>Sharding Columns</UI-TERM>** drop-down list. Sharding columns can be used for the following purposes:<ul><li>Load balancing: Threads used for sending messages can be recognized based on the sharding columns if the target table supports concurrent writes.   <li>Orderliness: OMS Community Edition ensures that messages are received in order if the values of the sharding columns are the same.       | Remove one or all objects | OMS Community Edition allows you to remove a single object or all objects to be synchronized to the target database during data mapping. <ul><li>Remove a single synchronization object <br>In the list on the right, move the pointer over the object that you want to remove, and click **<UI-TERM>Remove</UI-TERM>** to remove the synchronization object.   <li>Remove all synchronization objects<br>In the list on the right, click **<UI-TERM>Remove All</UI-TERM>** in the upper-right corner. In the dialog box that appears, click **<UI-TERM>OK</UI-TERM>** to remove all synchronization objects.      |

6. Click **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">Next</UI-TERM>**. On the **<UI-TERM key="oms-community.Sync.New.SynchronizationOptions">Synchronization Options</UI-TERM>** page, configure the following parameters.

   To view or modify parameters of the Connector or Incr-Sync component, click **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">Configuration Details</UI-TERM>** in the upper-right corner of the **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.FullSynchronization">Full synchronization</UI-TERM>** or **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">Incremental Synchronization</UI-TERM>** section. For more information about the parameters, see [Component parameters](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md).

   * Full synchronization

      The following parameters are displayed only if you have selected **<UI-TERM key="oms-community.SyncParameter.components.FullSyncForm.FullSynchronization">Full Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Sync.New.SelectSynchronizationType">Select Synchronization Type</UI-TERM>** page.

      | Parameter | Description |
      |------------|-------------------------------------------------------------|
      | Concurrent Speed | Includes **Stable**, **Normal**, **Fast**, and **Custom**. The performance of full synchronization varies, and the resources required for full synchronization tasks also differ. When you select **Custom**, you can set **Read Concurrency**, **Write Concurrency**, and **JVM Memory** based on actual conditions. |

   * Incremental synchronization

      The following parameters are displayed only if you have selected **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.IncrementalSynchronization">Incremental Synchronization</UI-TERM>** on the **<UI-TERM key="oms-community.Sync.New.SelectSynchronizationType">Select Synchronization Type</UI-TERM>** page.

      | Parameter | Description |
      |------------|-------------------------------------------------------------|
      | Concurrency Speed | Valid values: **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">Stable</UI-TERM>**, **<UI-TERM key="oms-community.Migration.constants.Normal">Normal</UI-TERM>**, **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Quick">Fast</UI-TERM>**, and **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">Custom</UI-TERM>**. The amount of resources to be consumed by an incremental synchronization task depends on the synchronization performance. If you select **<UI-TERM key="oms-community.pages.Audit.Custom">Custom</UI-TERM>**, you can set **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">Read Concurrency</UI-TERM>**, **<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">Write Concurrency</UI-TERM>**, and **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM Memory</UI-TERM>** as needed. |
      | Incremental Synchronization Start Timestamp | <ul><li>If you have selected **<UI-TERM>Full Synchronization</UI-TERM>** as the synchronization type, this parameter is not displayed.   <li>If you did not select **<UI-TERM>Full Synchronization</UI-TERM>** as the synchronization type, set this parameter to a certain point in time, which is the current system time by default. For more information, see [Set an incremental synchronization timestamp](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md). </ul> |

   * Advanced options
  
      | Parameter | Description |
      |------------|-------------------------------------------------------------|
      | Serialization Method | The message format for synchronizing data to a RocketMQ instance. Valid values: **Default**, **Canal**, **Dataworks** (version 2.0 supported), **SharePlex**, **DefaultExtendColumnType**, **Debezium**, **DebeziumFlatten**, and **DebeziumSmt**. For more information, see [Data formats](1200.sync-function-introduction/700.data-formats.md).   <br>**Notice**<br>At present, only MySQL-compatible tenants of OceanBase Database support **Debezium**, **DebeziumFlatten**, and **DebeziumSmt**.  |
      | Partitioning Rules | The rule for synchronizing data from the source database to a RocketMQ instance. At present, it can be set only to **Hash**. <br>**Hash** indicates that OMS Community Edition uses a hash algorithm to select the message queue for RocketMQ based on the value of the primary key or sharding column.  |
      | Business System Identification (Optional) | The identifier that identifies the source business system of data. The business system identifier consists of 1 to 20 characters.                             |

   * Target

      |     Parameter     |                                                  Description    |
      |------------|------------------------------------------------------------------------------------------|
      | Enter the name of the producer group | Specifies a producer group that can write data into multiple topics.        |
      | Whether to Allow Message Tracing | Specifies whether to allow message tracing. If message tracing is enabled, you can trace the complete task information, including the node time and status, of a message in its entire lifecycle from transmission to the RocketMQ server by the producer to consumption by consumers. The message tracing feature provides data support for troubleshooting in the production environment.                     |

7. Click **<UI-TERM>Pre-check</UI-TERM>**.

   During the precheck, OMS Community Edition detects the connection with the target data source. If an error is returned during the precheck, you can perform the following operations:

   * Identify and troubleshoot the problem and then perform the precheck again.

   * Click **<UI-TERM key="must.AlertTips.commponents.ErrorDetail.Skip">Skip</UI-TERM>** in the **<UI-TERM key="oms-community.components.ModifyRecordTable.Operation">Actions</UI-TERM>** column of the failed precheck item. In the dialog box that prompts the consequences of the operation, click **<UI-TERM key="oms-community.Migration.New.Determine">OK</UI-TERM>**.

8. Click **<UI-TERM key="oms-community.components.MigrationPreTable.StartAProject">Start Task</UI-TERM>**. If you do not need to start the task now, click **<UI-TERM key="oms-community.Migration.New.Save">Save</UI-TERM>** to go to the details page of the task. You can start the task later as needed.

   OMS Community Edition allows you to modify the synchronization objects when the data synchronization task is running. For more information, see [View and modify synchronization objects](1100.manage-a-data-synchronization-projects/200.view-and-modify-objects-to-be-synchronized.md). After the data synchronization task is started, it will be executed based on the selected synchronization types. For more information, see the **<UI-TERM>View Synchronization Details</UI-TERM>** section in the [View details of a data synchronization task](1100.manage-a-data-synchronization-projects/100.view-details-of-a-data-synchronization-project.md) topic.

   If the data synchronization task encounters an execution exception due to a network failure or slow startup of processes, you can click **<UI-TERM>Resume</UI-TERM>** on the **<UI-TERM key="oms-community.pages.Sync.SynchronizationProjectList">Synchronization Tasks</UI-TERM>** or **<UI-TERM key="oms-community.Detail.components.FullMigration.Detail">Details</UI-TERM>** page of the synchronization task.
