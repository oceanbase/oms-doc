# 多地域多节点部署

本文以杭州和北京地域为例，为您介绍如何在多地域多节点中使用 k8s 部署 OceanBase 迁移服务（OceanBase Migration Service，OMS）社区版。

## 名词解释

OMS_IMAGE：使用 Docker 加载 OMS 社区版安装包后，通过 `docker images` 命令获取到加载的相应镜像的 [IMAGE ID] 或 [REPOSITORY:TAG]，即为相应加载后镜像的唯一标识符 `<OMS_IMAGE>`。示例如下：

```shell
$sudo docker images
REPOSITORY                               TAG                 IMAGE ID          
work.oceanbase-dev.com/oceanbase/oms:feature_4.2.11_ce    2786e8a6eccd        
```

则 `<OMS_IMAGE>` 可以是：`work.oceanbase-dev.com/oceanbase/oms:feature_4.2.11_ce` 或 `2786e8a6eccd`。在后续指南中请替换相关命令中的 ${OMS_IMAGE} 为上述值。

## 部署 OMS 社区版

1. 进入 k8s 环境，准备各地域的配置文件。

    下述示例配置文件未指定 Pod 启动所在的节点。如果您需要指定 Pod 所在的节点，首先需要明确 k8s 中的 node 上是否存在表示其所在机房的 label。如果存在，则可以使用该 label 指定 OMS 启动使用的机房。查看 k8s 中 node 所在机房包含的 label 的命令如下。

    ```shell
    kubectl get nodes --show-labels
    NAME                                 STATUS   ROLES                  AGE   VERSION        LABELS
    sqaxxxx.sa128   Ready    control-plane,master   37d   v1.31.1+k3s1   beta.kubernetes.io/arch=amd64,beta.kubernetes.io/instance-type=k3s,beta.kubernetes.io/os=linux,kubernetes.io/arch=amd64,kubernetes.io/hostname=sqaxxxx.sa128,kubernetes.io/os=linux,node-role.kubernetes.io/control-plane=true,node-role.kubernetes.io/master=true,node.kubernetes.io/instance-type=k3s,zone=zone1
    ```

    杭州和北京地域的配置文件示例如下。请根据您部署的目标环境替换参数的实际值。其中 `kind: Namespace` 中的 `name` 需要和其他类型 `kind` 中的 `namespace` 名称一致。

    * 杭州地域

        ```yaml
        apiVersion: v1
        kind: Namespace
        metadata:
        name: omsregion-1
        ---
        apiVersion: v1
        kind: ConfigMap
        metadata:
        name: oms-config
        namespace: omsregion-1
        data:
        config.yaml: |
            "apsara_audit_enable": "false"
            "apsara_audit_sls_access_key": ""
            "apsara_audit_sls_access_secret": ""
            "apsara_audit_sls_endpoint": ""
            "apsara_audit_sls_ops_site_topic": ""
            "apsara_audit_sls_user_site_topic": ""
            "cm_is_default": !!bool "true"
            # 地域码，每个地域一个数字。
            "cm_location": "0"
            # 节点地址，格式为 ${pod_name}.${service_name}.${namespace_name}.svc。
            # pod_name 为 kind: StatefulSet 中的 name 加上 -ID，ID 编号从 0 开始。例如多节点部署中 replicas 为 2，则 pod_name 分别为 oms-0、oms-1。
            # service_name 为第一个 kind: Service 中的 name。
            # namespace_name 为 kind: Namespace 中的 name。
            "cm_nodes":
            - "oms-0.oms-service.omsregion-1.svc"
            - "oms-1.oms-service.omsregion-1.svc"
            "cm_region": "hangzhou"
            "cm_region_cn": "杭州"
            "cm_server_port": "8088"
            # 格式为 http://${service_name}.${namespace_name}.svc:8088。
            "cm_url": "http://oms-service.omsregion-1.svc:8088"
            "drc_cm_db": "cm_db_name"
            "drc_cm_heartbeat_db": "cm_hb_name"
            "drc_rm_db": "rm_db_name"
            "ghana_server_port": "8090"
            "init_db": "true"
            "nginx_server_port": "8089"
            "oms_meta_host": "xxx.xxx.xxx.1"
            "oms_meta_password": "oms_meta_password"
            "oms_meta_port": "2881"
            "oms_meta_user": "xxx@tenant_name"
            "sshd_server_port": "2023"
            "supervisor_server_port": "9000"
            "tsdb_enabled": "true"
            "tsdb_password": "tsdb_password"
            "tsdb_service": "INFLUXDB"
            "tsdb_url": "xxx.xxx.xxx.2:8086"
            "tsdb_username": "tsdb_username"
        ---
        apiVersion: v1
        kind: Service
        metadata:
        name: oms-service
        namespace: omsregion-1
        spec:
        clusterIP: None
        selector:
            app: oms
        ---
        apiVersion: v1
        kind: Service
        metadata:
        name: oms-service-nodeport
        namespace: omsregion-1
        spec:
        type: NodePort
        selector:
            app: oms
        ports:
            - name: nginx
            protocol: TCP
            port: 8089
            targetPort: 8089
            - name: ghana
            protocol: TCP
            port: 8090
            targetPort: 8090
            - name: cm
            protocol: TCP
            port: 8088
            targetPort: 8088
            - name: sshd
            protocol: TCP
            port: 2023
            targetPort: 2023
        ---
        apiVersion: apps/v1
        kind: StatefulSet
        metadata:
        name: oms
        namespace: omsregion-1
        labels:
            app: oms
        spec:
        replicas: 2
        serviceName: "oms-service"
        selector:
            matchLabels:
            app: oms
        template:
            metadata:
            labels:
                app: oms
            spec:
            # 增加 node 的选择项目，用于指定在哪个机房启动 OMS 社区版。node 上需要 label：zone=zone1
            nodeSelector: 
            zone: "zone1"
            initContainers:
            - name: copy-config
                image: busybox:1.35
                command: ['sh', '-c', 'cp /config-ro/config.yaml /work/config.yaml']
                volumeMounts:
                - name: config-volume
                mountPath: /config-ro
                readOnly: true
                - name: writable-config
                mountPath: /work
            containers:
            - name: oms
                image: ${OMS_IMAGE}
                env:
                - name: POD_NAME
                valueFrom:
                    fieldRef:
                    fieldPath: metadata.name
                - name: OMS_HOST_IP
                # POD_NAME 表示当前 Pod 的名称，无需改动。oms-service.omsregion-1 请根据实际的 ${service_name} 和 ${namespace_name} 进行修改。
                value: $(POD_NAME).oms-service.omsregion-1.svc
                - name: HOST_DOCKER_VERSION
                value: "20.10.7"
                ports:
                - containerPort: 8088
                - containerPort: 8089
                - containerPort: 8090
                - containerPort: 9000
                - containerPort: 2023
                volumeMounts:
                - name: writable-config
                mountPath: /home/admin/conf/config.yaml
                subPath: config.yaml
                - name: logs-volume
                mountPath: /home/admin/logs
                - name: store-volume
                mountPath: /home/ds/store
                - name: run-volume
                mountPath: /home/ds/run
            volumes:
            - name: config-volume
                configMap:
                name: oms-config
            - name: writable-config
                emptyDir: {}
        # 磁盘容量配置，请根据实际情况调大下面三个挂载盘的容量大小
        # logs-volume 推荐最低 200Gi
        # store-volume 推荐最低 500Gi。store-volume 存储时为增量数据，请尽量将值调大。
        # run-volume 推荐最低 300Gi
        volumeClaimTemplates:
        - metadata:
            name: logs-volume
            spec:
            accessModes: [ "ReadWriteOnce" ]
            storageClassName: "local-path"
            resources:
                requests:
                storage: 200Gi
        - metadata:
            name: store-volume
            spec:
            accessModes: [ "ReadWriteOnce" ]
            storageClassName: "local-path"
            resources:
                requests:
                storage: 500Gi
        - metadata:
            name: run-volume
            spec:
            accessModes: [ "ReadWriteOnce" ]
            storageClassName: "local-path"
            resources:
                requests:
                storage: 300Gi
        ```

2. 分别在杭州和北京地域安装 OMS 社区版。

    例如，杭州地域的配置文件名称为 `oms-k8s-statefulset-region-1`，北京地域的配置文件名称为 `oms-k8s-statefulset-region-2`，则安装命令如下。

    ```shell
    kubectl apply -f oms-k8s-statefulset-region-1.yaml
    kubectl apply -f oms-k8s-statefulset-region-2.yaml
    ```

    如果您需要查看节点详情，可以执行下述命令。

    ```shell
    kubectl get pods -n omsregion-1
    kubectl get pods -n omsregion-2

    # 查看 OMS 社区版安装的日志详情
    kubectl logs -f oms-0 -n omsregion-1
    kubectl logs -f oms-1 -n omsregion-1
    ```

3. 查看对外访问端口。8089 映射的端口便是浏览器访问 OMS 社区版管控端口。

    ```shell
    kubectl get svc -n omsregion-1
    kubectl get svc -n omsregion-2ßßß
    ```

## 卸载 OMS 社区版

如果您需要卸载 OMS 社区版，可以执行下述命令。

```shell
kubectl delete -f ${配置文件名称}
```

例如：

```shell
kubectl delete -f oms-k8s-statefulset-region-1.yaml
kubectl delete -f oms-k8s-statefulset-region-2.yaml
```
