# 如何处理因存在 LOB 字段导致全量迁移失败的问题

## 问题描述

Oracle 数据库至 OceanBase 数据库 Oracle 兼容模式的全量迁移阶段报错内存 OOM。

## 可能原因

迁移的表中存在 LOB 大字段列。

## 解决方法

如果是含有 LOB 字段类型的表情况，您可以通过调小并发和每次查询数据量，同时调大内存的方式来解决。操作如下：

1. 登录 OMS 社区版控制台。

2. 在左侧导航栏，单击 **<UI-TERM key="oms-community.utils.hooks.useLayoutMenus.SystemManagement">系统管理</UI-TERM>** \> **<UI-TERM key="oms-community.Audit.constants.SystemParameters">系统参数</UI-TERM>**。

3. 单击目标参数 `migration.checker.params.*` **<UI-TERM key="oms-community.pages.SystemParam.Value">取值</UI-TERM>** 列下的编辑图标。

    `migration.checker.params.*` 包括 `migration.checker.params.fast`（快速档位）、`migration.checker.params.normal`（正常档位）和 `migration.checker.params.steady`（平稳档位），您需要根据创建数据迁移任务时在 **<UI-TERM key="oms-community.Migration.New.MigrationOptions">迁移选项</UI-TERM>** 页面选择的 **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.FullMigrationConcurrency">全量迁移并发速度</UI-TERM>** 的档位来确定需要编辑的参数。此处以 `migration.checker.params.fast` 为例。

4. 在 **<UI-TERM key="oms-community.pages.SystemParam.ModifyAValue">修改取值</UI-TERM>** 对话框，配置下列参数的 **<UI-TERM key="oms-community.pages.SystemParam.Value">取值</UI-TERM>**。

    |参数|描述|修改取值|
    |---------|---------|--------|
    |`limitator.platform.threads.number`|支持并发的线程数|调小|
    |`limitator.select.batch.max`|每次查询的记录数|调小|
    |`limitator.image.insert.batch.max`|每次插入的记录数|调小|
    |`task.checker_jvm_param`|Checker 组件的 JVM 参数配置|调大<br>例如，-server -Xms64g -Xmx64g -Xmn48g -Xss256k|

5. 单击 **<UI-TERM key="oms-community.Detail.components.SyncSteps.Determine">确定</UI-TERM>**。
