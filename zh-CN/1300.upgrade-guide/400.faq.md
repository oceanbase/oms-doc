# 常见问题

本文为您汇总升级 OMS 社区版版本过程中会遇到的常见问题。

## 目前支持哪些版本升级至 OMS 社区版 V4.2.3-CE？

目前支持 OMS 社区版 V4.1.0-CE 和 V4.2.2-CE 直接升级至 V4.2.3-CE，不支持其他版本直接升级至 V4.2.3-CE。

如果是 OMS 社区版 V4.1.0-CE 之前的版本，您需要先升级至 V4.1.0-CE，再升级至 V4.2.3-CE。

## 升级过程中，是否必须备份原数据库？

强烈建议您在开始升级前备份原数据库。备份原数据库后，您可以更放心地进行升级操作。一旦升级失败，您可以及时启动旧版本 OMS 社区版的容器。

如果您不备份原数据库，新数据库的名称需要和原数据库的名称保持一致，且需要做好升级一旦失败则无法回滚的准备。

## 如何控制回拉时间？

您可以开启 HA 功能，会自动新建一个新的 Store。新建 Store 的前提是 Subtopic 下的 Store 数量未超过 `ha.config` 系统参数中 `subtopicStoreNumberThreshold` 设定的阈值，其默认值为 5 个。

1. 登录 OMS 社区版控制台。

2. 在左侧导航栏，单击 **系统管理** > **系统参数**。

3. 在 `系统参数` 页面，单击 `ha.config` 取值列后的编辑图标。

4. 在 `修改取值` 对话框中，设置 `enable` 为 `true`，开启 HA 功能。

5. 设置 `perceiveStoreClientCheckpoint` 为 `true`，开启 Store HA 监控下游组件消费。

    如果您设置 `perceiveStoreClientCheckpoint` 为 `false`，则需要自行设置 HA Store 的回拉时间。即配置 `refetchStoreIntervalMin` 参数，单位为分钟。

    例如，在原容器中您关注的任务均实时的情况下，您在下午 4:00 停止原容器，升级完成的时间为下午 5:00，则建议您设置 `refetchStoreIntervalMin` = 90 min。即 60（停机至当前的时间间隔）+ 30（根据业务流量设置的冗余时间）的总和。

## 如果升级前修改了部分进程的配置参数，升级后修改的参数是否存在？

* 如果修改的是 Full-Import、Incr-Sync 或 Full-Verification 组件的参数，升级成功后，修改的参数依然存在。

* 如果修改的是 Store 参数（例如，白名单），所有参数的修改都会更新 Subtopic。升级成功后，修改的参数依然存在。

## 从 V4.1.0-CE 升级至 V4.2.3-CE 的常见问题

* 数据同步项目中多启动一个 Store 组件。

    为避免资源的浪费，您可以在数据同步项目的 **查看组件监控** 页面，暂停多余的 Store 组件。您也可以在 **运维监控** > **组件** 页面对 Store 组件进行管理。

* 数据迁移项目运行时，Incr-Sync 组件出现异常，报错：`com.oceanbase.oms.store.client.HttpBadResponseException: java.lang.RuntimeException: no active store under MYSQL_p_5****_reverse`。

    该报错出现的原因是 Incr-Sync 组件写入数据需要依赖 Store 组件，而在数据迁移过程中，Incr-Sync 组件和 Store 组件是同时创建的。如果 Store 组件还未启动时，Incr-Sync 组件已经启动，便会导致 Incr-Sync 组件无法找到所依赖的 Store 组件，从而发生报错。

    解决方法如下：

    1. 进入数据迁移项目的详情页面。

    2. 单击页面右上角的 **查看组件监控**。

    3. 在 **查看组件监控** 面板，单击 Incr-Sync 组件后的 **启动**。

* 数据迁移项目的反向增量任务中，反向 Store 组件和反向 Incr-Sync 组件均为启动成功。

    解决方法一：

    1. 进入当前数据迁移项目的详情页面。

    2. 单击 **正向切换** 页签，进入正向切换阶段。

    3. 在 **启动目标端 Store** 步骤，单击 **启动目标端 Store 失败** 下方的 **重试**。

    4. 重试成功后，再次重试启动反向增量即可。

    解决方法二：

    如果正向切换页面中的启动目标端 Store 步骤不支持重试操作，您可以通过修改 OMS 社区版元数据库中的数据来触发后台自动调度，以启动组件。

    1. 查询 OMS 社区版元数据 rm 库。

        ```SQL
        SELECT * FROM oms_step WHERE project_id = '当前项目的 ID';
        ```

    2. 获取 `step_name` 为 `TRANSFER_APP_SWITCH`（正向切换）的 ID。

    3. 通过获取的 ID 来查询 `oms_task` 表。

        ```SQL
        SELECT * FROM oms_task WHERE task_group= 'id'
        ```

        您会查询到很多种任务类型，只需要关注 `task_type` 为 `CREATE_DEST_STORE`（创建反向 Store 组件） 和 `CREATE_REVERSE_SYNC`（创建反向 Incr-Sync 组件）的两条数据。

    4. 找到 `task_type` 为 `CREATE_DEST_STORE` 的数据，将 `task_status` 的值修改为 `PENDING`，以启动 Store 组件。

        请查看 `retry_count`（表示重试的次数）是否大于 `max_retry_count`（表示最多可以重试的次数，默认为 3 次）。如果 `retry_count` 的值大于 `max_retry_count`，则不会触发自动重试，您可以将 `retry_count` 修改为 0。

        后台调度完成后，`CREATE_DEST_STORE` 的 `task_status` 值会变为 `FINISHED`。您可以在项目的 **查看组件监控** 页面，查看是否启动成功。

    5. 找到 `task_type` 为 `CREATE_REVERSE_SYNC` 的数据，将 `task_status` 的值修改为 `PENDING`，以启动 Incr-Sync 组件。

        等待后台调度完成，您可以在项目的 **查看组件监控** 页面，查看是否启动成功。

* 在数据迁移项目中的增量同步阶段，组件没有启动。

    您可以通过修改 OMS 社区版元数据库中的数据来触发后台自动调度，以启动组件。

    1. 查询 OMS 社区版元数据 rm 库。

       ```SQL
       SELECT * FROM oms_step WHERE project_id = '当前项目的 ID';
       ```

    2. 找到 `step_name` 为 `TRANSFER_INCR_LOG_PULL`（启动正向 Store 组件）的数据，将 `step_status` 的值修改为 `FAILED`，`step_info` 的值修改为 `{}`。

    3. 修改成功后，等待后台调度重试启动组件。您可以在项目的 **查看组件监控** 页面，查看刚启动的 Store 组件，`TRANSFER_INCR_LOG_PULL` 的 `task_status` 值也会变为 `FINISHED`。

    4. 再次查询 OMS 社区版元数据 rm 库。

        ```SQL
        SELECT * FROM oms_step WHERE project_id = '当前项目的 ID';
        ```

    5. 找到 `step_name` 为 `INCR_TRANSFER`（启动正向 Incr-Sync 组件）的数据，将 `step_status` 的值修改为 `FAILED`，`step_info` 的值修改为 `{}`。

    6. 修改成功后，等待后台调度重试启动组件。您可以在项目的 **查看组件监控** 页面，查看刚启动的 Incr-Sync 组件，`INCR_TRANSFER` 的 `task_status` 值也会变为 `MONITORING`。
