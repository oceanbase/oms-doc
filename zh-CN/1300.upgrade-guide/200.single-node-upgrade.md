# 单节点升级

本文为您介绍如何单节点升级 OceanBase 迁移服务（OceanBase Migration Service，OMS）社区版至 V4.2.3-CE。

## 背景信息

目前 OMS 社区版 V4.2.3-CE 的版本升级包含以下两种场景，其他版本不支持直接升级至 V4.2.3-CE。

* 当前版本为 V4.2.2-CE

* 当前版本为 V4.1.0-CE

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <p>您可以根据本文的操作，将 OMS 社区版 V4.1.0-CE 直接升级至 V4.2.3-CE。如果是 OMS 社区版 V4.1.0-CE 之前的版本，您需要先升级至 V4.1.0-CE，再升级至 V4.2.3-CE。</p>
   </main>

## 从 V4.2.2-CE 升级至 V4.2.3-CE

1. 备份数据库。

   1. 暂停 OMS 社区版 V4.2.2-CE 旧容器，记录时间 T1。

      ```shell
      sudo docker stop ${CONTAINER_NAME}
      ```

      <main id="notice" type='explain'>
      <h4>说明</h4>
      <p><code>CONTAINER_NAME</code> 为创建容器的名称。</p>
      </main>

   2. 登录配置文件中的 CM 心跳库，删除数据库中部分无用记录，节省备份时间。

      ```shell
      # 登录配置文件中的 CM 心跳库
      mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -Dcm_hb_422
      
      # 删除无用的记录
      # heatbeat_sequence 用于汇报心跳，获取自增 ID
      delete from heatbeat_sequence where id < (select max(id) from heatbeat_sequence); 

      ```

   3. 执行下述命令，手工备份 rm、cm 和 cm_hb 库为 SQL 文件，并确认三个文件的大小不为 0。

      ```shell
      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false rm_422 > /home/admin/rm_422.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_422 > /home/admin/cm_422.sql

      mysqldump -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> --triggers=false cm_hb_422 > /home/admin/cm_hb_422.sql
      ```

      |           参数            |                                   描述                                   |
      |-------------------------|------------------------------------------------------------------------|
      | -h                      | 需要导出的主机信息。                                                             |
      | -P                      | 连接数据库的端口号。                                                             |
      | -u                      | 指定连接的用户名。                                                              |
      | -p                      | 连接数据库的密码。                                                              |
      | --triggers              | 导出触发器，默认为 false（不导出）。                                                  |
      | rm_422、cm_422、cm_hb_422 | 此处为备份 rm、cm 和 cm_hb 库为 SQL 文件，格式为 `库名 > 存储 SQL 文件的路径.sql`，请替换为实际环境中的值。 |

2. 加载下载的 OMS 社区版安装包至 Docker 容器的本地镜像仓库。

   ```shell
   docker load -i <OMS 社区版安装包>
   ```

3. 启动 OMS 社区版 V4.2.3-CE 新容器。

   OMS 社区版支持通过 HTTP 协议和 HTTPS 协议访问 OMS 社区版控制台。如果您想要安全访问 OMS 社区版，可以提供 HTTPS 证书，并将其挂载至容器内的指定目录。如果使用 HTTP 协议访问 OMS 社区版，则无需配置。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <ul>
   <li>
   <p>启动 OMS 社区版 V4.2.3-CE 新容器时，OMS 社区版三个挂载盘的路径需要与升级前保持完全一致。<br>您可以执行 <code>sudo docker inspect ${CONTAINER_NAME} | grep -A5 'Binds'</code> 命令，查看之前旧 OMS 社区版容器的挂载盘路径。</p>
   </li>
   <li>
   <p>OMS 社区版 V3.3.1-CE 及之后版本新增参数 <code>-e IS_UPGRADE=true</code>。该参数仅适用于升级场景，且升级场景下必须添加该参数。</p>
   </li>
   <li>
    <p>请替换 <code>work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG}</code> 为执行 <code>docker load -i</code> 命令实际导入的镜像名称。</p>
    </li>
   </ul>
   </main>

   ```shell
   OMS_HOST_IP=xxx
   CONTAINER_NAME=oms_xxx
   IMAGE_TAG=feature_x.x.x-ce

   docker run -dit --net host \
   -v /data/config.yaml:/home/admin/conf/config.yaml \
   -v /data/oms/oms_logs:/home/admin/logs \
   -v /data/oms/oms_store:/home/ds/store \
   -v /data/oms/oms_run:/home/ds/run \
   # 仅在 OMS 容器中挂载 HTTPS 证书时，需要设置如下两个参数
   -v /data/oms/https_crt:/etc/pki/nginx/oms_server.crt 
   -v /data/oms/https_key:/etc/pki/nginx/oms_server.key
   -e OMS_HOST_IP=${OMS_HOST_IP} \
   -e IS_UPGRADE=true \
   --privileged=true \
   --pids-limit -1 \
   --ulimit nproc=65535:65535 \
   --name ${CONTAINER_NAME} \
   work.oceanbase-dev.com/obartifact-store/oms:${IMAGE_TAG} 
   ```

   |           参数            |                                                                                                        描述                                                                                                         |
   |-------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
   | OMS_HOST_IP             | 宿主机的 IP 地址。                                                                                                                                                                                                       |
   | CONTAINER_NAME          | 创建容器的名称。                                                                                                                                        |
   | IMAGE_TAG               | 使用 Docker 加载 OMS 社区版安装包后，通过 `docker images` 命令获取到加载的相应镜像的 [IMAGE ID] 或 [REPOSITORY:TAG]，即为相应加载后镜像的唯一标识符 `<OMS_IMAGE>`。                 |
   | /data/oms/oms_logs <br> /data/oms/oms_store   <br> /data/oms/oms_run      | `/data/oms/oms_logs`、`/data/oms/oms_store` 和 `/data/oms/oms_run` 可以替换为在您的 OMS 社区版部署机器上创建的挂载目录，分别存放 OMS 社区版运行过程中产生的日志文件、日志拉取组件和同步组件生成的文件，在本机进行持久化。 <br>**注意：**<br>  在后续的版本重新部署、升级中，挂载目录的位置必须保持不变。 |
   | /home/admin/logs <br>  /home/ds/store  <br> /home/ds/run         | `/home/admin/logs`、`/home/ds/store` 和 `/home/ds/run` 为容器内的固定目录，路径不可以修改。         |
   | /data/oms/https_crt（可选）<br>/data/oms/https_key（可选） | HTTPS 证书在 OMS 社区版容器内的挂载位置。 如果挂载了 HTTPS 证书，OMS 社区版容器内的 Nginx 服务将会运行在 HTTPS 模式下。您必须以 HTTPS 模式访问，才可以使用 OMS 社区版的控制台服务。                                                                                         |
   | IS_UPGRADE              | 升级场景下，必须设置 `IS_UPGRADE=true`。请注意 `IS_UPGRADE` 需要为大写。                                                                                                                                                                                     |
   | privileged              | 为容器授予扩展权限。                                                                                                                                                                                                        |
   | pids-limit              | 配置容器的进程数限制，-1 表示不限制。                                                                                                                                                                                              |
   | ulimit nproc            | 配置用户进程数的上限。                                                                                                                                                                                                       |

4. 进入新容器。

   ```shell
   docker exec -it ${CONTAINER_NAME} bash  
   ```

   <main id="notice" type='explain'>
   <h4>说明</h4>
   <p><code>CONTAINER_NAME</code> 为创建容器的名称。</p>
   </main>

5. 在 `root` 目录下，执行元数据初始化操作。

   ```shell
   sleep 300
   bash /root/docker_init.sh
   ```

   执行上述命令后，脚本会自动将 OMS 社区版三个数据库的 Schema 变更执行到数据库中。

   如果执行上述命令报错 `Version before 4.1.1 is not allowed to upgrade.`，请进行以下操作。

   1. 确认升级的 OMS 社区版不是 V4.1.1 之前的版本。

   2. 在 `rm` 库中执行下述 SQL 语句。

      ```sql
      CREATE TABLE IF NOT EXISTS `oms_version` (    
         `version` varchar(64) NOT NULL COMMENT '版本',    
         `gmt_modified` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,    
         PRIMARY KEY (`version`)
         ) DEFAULT CHARSET = utf8mb4 COMMENT = '版本表';
      
      REPLACE INTO `oms_version`(`version`) VALUES('x.x.x-CE');  --此处填写实际升级之前的 OMS 社区版版本号
      ```

   3. 再次执行初始化命令。

6. `docker_init.sh` 脚本执行完成后，请确认机器列表是否正常，且机器均处于 **在线** 状态。

   1. 登录 OMS 社区版控制台。

   2. 在左侧导航栏，单击 **运维监控** \> **机器**。

   3. 在 **机器列表** 页面，查看机器列表是否正常。同时，请确认机器的状态均为 **在线**。

7. （可选）如果您需要进行回滚操作，请执行以下步骤。

    1. 暂停升级后的新容器，记录时间 T3。

          ```shell
          sudo docker stop ${CONTAINER_NAME}
          ```

    2. 连接元数据库，执行下述命令。

          ```shell
          drop database rm_422;
          drop database cm_422;
          drop database cm_hb_422;

          create database rm_422;
          create database cm_422;
          create database cm_hb_422;
          ```

    3. 将第 2 步中备份的数据库 SQL 文件，还原为原数据库。

          ```shell
          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/rm_422.sql" -Drm_422

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_422.sql" -Dcm_422

          mysql -hxxx.xxx.xxx.1 -P<port> -u<username> -p<password> -e "source /home/admin/cm_hb_422.sql" -Dcm_hb_422
          ```

    4. 重启 OMS 社区版 V4.2.2-CE 旧容器。

          ```shell
          sudo docker restart ${CONTAINER_NAME}
          ```

8. 升级完成后，请先删除浏览器缓存，再进行登录。

## 从 V4.1.0-CE 升级至 V4.2.3-CE

### 升级限制

* 目前仅支持 OMS 社区版 V4.1.0-CE 直接升级至 V4.2.3-CE，如果是 V4.1.0-CE 之前的版本，请先升级至 V4.1.0-CE，再通过本文的操作升级至 V4.2.3-CE。升级至 V4.1.0-CE 的详情请参见 [V4.1.0-CE 升级指南](https://www.oceanbase.com/docs/enterprise-oms-doc-cn-1000000000000113)。

* 升级之前以及升级过程中，请确保没有用户正在使用 OMS 社区版新建数据迁移或数据同步项目。

* 升级之前请确认当前 OMS 社区版 V4.1.0-CE 中，没有处于 **运行中** 状态的全量迁移和全量校验任务。

* 升级之后，OMS 社区版 V4.2.3-CE 的控制台页面不会展示 V4.1.0-CE 中已经完成的全量迁移任务的详情。如果您需要查看，请进入 OMS 社区版容器的 `/home/ds/run/{组件 ID}/migrate/{subid}` 目录下进行查看。

  * `overview-done`：用于存储已经完成全量迁移的表。

  * `overview-failed`：用于存储全量迁移异常表。

### 升级步骤

1. 复制原 OMS 社区版 V4.1.0-CE 的配置文件。

   ```shell
   sudo docker cp ${CONTAINER_NAME}:/home/admin/conf/config.yaml ${宿主机目录}
   ```

    <main id="notice" type='explain'>
    <h4>说明</h4>
    <p><code>CONTAINER_NAME</code> 为创建容器的名称。</p>
    </main>

2. 暂停 OMS 社区版 V4.1.0-CE 旧容器。

    ```shell
    sudo docker stop ${CONTAINER_NAME}
    ```

3. 从 OMS 社区版 V4.2.3-CE 镜像中拉取升级部署脚本。

    ```shell
    sudo docker run -d --net host --name oms-config-tool ${OMS_IMAGE} bash && sudo docker cp oms-config-tool:/root/docker_remote_deploy_410_up_423_version.sh . && sudo docker rm -f oms-config-tool
    ```

    <main id="notice" type='notice'>
    <h4>注意</h4>
    <p>请替换 <code>${IMAGE_TAG}</code> 为执行 <code>docker load -i</code> 命令实际导入的镜像名称。</p>
    </main>

4. 执行升级部署脚本，开始部署 V4.2.3-CE。

    ```shell
    sh docker_remote_deploy_410_up_423_version.sh -o ${挂载目录} -c ${宿主机目录}/config.yaml -i ${当前机器 IP} -d ${IMAGE_TAG}
    ```

    | 参数   |  描述  |
    |-------------------|--------------------|
    | 挂载目录 | 必须和 OMS 社区版 V4.1.0-CE 容器的挂载目录一致。|
    | config.yaml| 必须是步骤 1 复制出的 OMS 社区版 V4.1.0-CE 容器中使用的配置文件。|
    | IMAGE_TAG | 请替换为执行 `docker load -i` 命令实际导入的镜像名称。|

    升级脚本会自动备份配置文件 `config.yaml` 至 `config_copy.yaml`。同时，OMS 社区版部署工具会自动校验 CPU、Memory 和 Disk 三项配置的资源。其中任意一项资源不达标，则提示对应资源不足，影响数据迁移速度。

5. 根据部署工具提示完成部署，每次输入后，通过回车进行下一步。

   1. 请选择部署模式。

      此处请选择 **单地域单节点** 选项。

   2. 请选择您所需要进行的任务。

      此处请选择 **已通过脚本 [-c] 选项传入参考配置文件，基于参考配置文件开始配置**。

   3. 出现 **元数据库中对应数据库名已存在！这样可以吗？** 提示后，请输入 y。

   4. 出现 **元数据库中对应数据库名已存在，是否需要重新初始化元信息库** 提示后，请输入 y。

   5. 如果配置文件检查通过，会为您展示所有的配置信息。如果确认无误，请输入 n。如果需要修改，请输入 y。

      如果配置文件未检查通过，请根据提示修改配置信息。

   6. 请输入和 OMS 社区版 V4.1.0-CE 容器一致的挂载目录。

   7. 请确认部署 OMS 社区版的镜像名为 <OMS_IMAGE> 是否可以。

      如果确认无误，请输入 y。如果需要修改，请输入 n。

   8. 请确认是否需要在 OMS 社区版容器中挂载 HTTPS 证书。

      如果需要，请输入 y，并根据提示输入 https_key、https_crt 目录。如果不需要，请输入 n。

   9. 请确认配置文件的存储路径是否可以。

      如果确认无误，请输入 y。如果需要修改，请输入 n。

   10. 开始执行部署，请耐心等待部署完成。

      如果部署失败，您可以登录至运行的 OMS 社区版容器中，查看 `/home/admin/logs` 目录下以 `docker_init` 为前缀的 `.log` 文件，获取日志信息。如果 OMS 社区版容器未成功启动，则无法获取日志。

6. 开始升级。

   1. 进入 OMS 社区版 V4.2.3-CE 容器。

      ```shell
      sudo docker exec -it ${CONTAINER_NAME} bash
      ```

   2. 进入 root 目录，查看名为 `docker_oms_ce_version_upgrade.sh` 的升级脚本。

      ```shell
      cd /root
      ls
      ```

   3. 执行升级脚本。

      ```shell
      sh docker_oms_ce_version_upgrade.sh
      ```

7. 等待升级完成后，出现 **【结束】全部初始化步骤执行成功**，即可访问 OMS 社区版 V4.2.3-CE。

8. 请自行确认数据迁移和数据同步项目是否成功，组件是否正常运行。

   升级完成后的常见问题及其解决方法请参见 [从 V4.1.0-CE 升级至 V4.2.3-CE 的常见问题](../1300.upgrade-guide/400.faq.md)。

### 回滚步骤

您可以根据下文操作，将 OMS 社区版 V4.2.3-CE 回滚至 V4.1.0-CE。

<main id="notice" type='notice'>
<h4>注意</h4>
<p>进行回滚前，请确认以下问题。</p>
<ul>
<li>
<p>没有在 OMS 社区版 V4.2.3-CE 中创建数据迁移或数据同步项目。</p>
</li>
<li>
<p>没有在 OMS 社区版 V4.2.3-CE 中创建 HBase 等 V4.1.0-CE 不支持的数据源。</p>
</li>
</ul>
</main>

1. 执行回滚脚本。

   1. 进入 OMS 社区版 V4.2.3-CE 容器。

      ```shell
      sudo docker exec -it ${CONTAINER_NAME} bash
      ```

   2. 进入 root 目录，查看名为 `docker_oms_ce_version_roll_back.sh` 的回滚脚本。

      ```shell
      cd /root
      ls
      ```

   3. 执行回滚脚本。

      ```shell
      docker_oms_ce_version_roll_back.sh
      ```

   4. 等待运行完成，出现 **【结束】全部初始化步骤执行成功** 即可。

2. 暂停及删除 OMS 社区版 V4.2.3-CE 容器。

   1. 退出新容器。

   2. 暂停新容器。

      ```shell
      sudo docker stop ${CONTAINER_NAME}
      ```

   3. 删除新容器。

      ```shell
      sudo docker rm ${CONTAINER_NAME}
      ```

3. 检查 OMS 社区版 V4.1.0-CE 的配置文件 `config.yaml` 是否和 `config_copy.yaml` 一致。

   `config_copy.yaml` 为 V4.1.0-CE 使用部署备份的配置文件，由于新部署了 V4.2.3-CE，导致 `config.yaml` 中的内容被覆盖。重启 V4.1.0-CE 容器时，读取的是 `config.yaml`，所以需要还原 V4.1.0-CE 容器的配置。如果不一致，请根据下述两种方式，将 `config.yaml` 中的值替换为 `config_copy.yaml` 中的值。

   * 方式一

      使用 `sudo su` 命令切换到 root 用户。然后执行 `cat config_copy.yaml > config.yaml` 命令，覆盖 `config.yaml` 的内容。

   * 方式二

      执行命令 `cat config_copy.yaml | sudo tee config.yaml > /dev/null`。

4. 启动 OMS 社区版 V4.1.0-CE 容器。

   ```shell
   sudo docker start ${CONTAINER_NAME}
   ```
