# 迁移 Milvus 数据库的数据至 OceanBase 社区版

本文为您介绍如何使用 OceanBase 迁移服务（OceanBase Migration Service，OMS）社区版迁移 Milvus 数据库的数据至 OceanBase 社区版。

## 背景信息

Milvus 是一种高性能、高扩展性的向量数据库，能够提供强大的数据建模功能，详情请参见 [Milvus 官网文档](https://milvus.io/docs/zh/from-m2x.md)。

下表为您介绍 Milvus 数据库中的重要概念。

| 概念 | 描述 |
|------------------|----------------|
| Database | 相当于 Schema。Milvus 数据库中可以存在多个 Database，一个 Database 中可以存在多个 Collection。|
| Collection| 相当于表，用于存储具体的数据。Collection 中存在多个字段。您也可以在创建 Collection 时指定为动态字段方式 withEnableDynamicField，表示每一条记录可以有不一样的字段。|
| primary key | 主键字段。一个 Collection 只能有一个主键字段。|
| Partition | Collection 可以分区，相当于分区表。|

OMS V4.2.9-CE 及之后版本支持 Milvus 指定动态字段迁移至 OceanBase 社区版。

* 如果目标端表存在 `OMS_DYNAMIC_FIELD` 字段或设置 `sink.omsDynamicField=xxx`，则将动态字段数据作为整体的 JSON STRING 写入 `OMS_DYNAMIC_FIELD` 或 `sink.omsDynamicField` 配置的字段名中。

* 如果目标端表不存在 `OMS_DYNAMIC_FIELD` 字段，也没有设置 `sink.omsDynamicField=xxx`，则动态字段将被丢弃。

## 使用限制

* **源端数据库的操作限制**

   **请勿在结构迁移和全量迁移阶段执行库或表结构变更的 DDL 操作，否则可能造成数据迁移任务中断。**

* 目前 Milvus 数据库至 OceanBase 社区版的数据迁移任务不支持全量校验和反向增量。

* 目前支持 Milvus 数据库 V2.4.5 及之后版本。

* OMS 社区版仅支持迁移库名、表名和列名为 ASCII 码且不包含特殊字符（包括换行、空格，以及 |"'`()=;/&）的对象。

* 建议您一次性迁移的表数量不超过 1000 张，避免影响数据迁移任务的运行。

## 数据类型映射

|    Milvus 数据库     | OceanBase 社区版 |
|------------------|------------------------|
|  BOOL         |    BOOL/TINYINT(1)  <br>布尔类型，用于存储 true 或 false，适用于描述二进制状态。 |
|  INT8         |   TINYINT  <br>8 位整数，适用于存储小范围整数数据。|
|  INT16        |   SMALLINT <br>16 位整数，适用于存储中范围整数数据。|
|  INT32        |   INT/INTEGER <br>32 位整数，适用于存储产品数量或用户 ID 等一般整数数据。|
|  INT64        |   BIGINT  <br>64 位整数，适用于存储时间戳或标识符等大范围数据。|
|  FLOAT        |   FLOAT  <br>32 位浮点数，适用于等级或温度等需要一般精度的数据。|
|  DOUBLE       |   DOUBLE <br>64 位双精度浮点数，适用于财务信息或科学计算等高精度数据。|
|  VARCHAR      |   VARCHAR <br>指定 `max_length`（有效范围为 1~65,535），它定义了 VARCHAR 字段可以存储的最大字节数。|
|  FLOAT_VECTOR |   VECTOR <br>向量数据类型，存储 32 位浮点数，通常用于表示科学计算和机器学习中的实数。适用于区分相似向量等需要高精度的场景。|
|  FLOAT16_VECTOR | VECTOR <br>存储 16 位半精度浮点数，用于深度学习和 GPU 计算。在推荐系统的低精度召回阶段等精度要求不高的情况下，它可以节省存储空间。|
|  BFLOAT16_VECTOR | VECTOR <br>存储 16 位脑浮点数（bfloat16），使用于大规模图像检索等需要快速处理大量向量的场景。|
|  BINARY_VECTOR  | VARBINARY <br>存储二进制向量类型。|
|  SPARSE_FLOAT_VECTOR | JSON <br>存储稀疏向量类型，值类似 KV 的 Map 结构：`{1: 0.6180500771665887, 0: 0.8255673677331509, 4: 0.4227293590979655, 2: 0.09220348558380687}`。|

## 操作步骤

1. 新建数据迁移任务。

   1. 登录 OMS 社区版控制台。

   2. 在左侧导航栏，单击 **<UI-TERM key="oms-community.New.components.EndpointForm.DataMigration">数据迁移</UI-TERM>**。

   3. 在 **<UI-TERM key="oms-community.Migration.Detail.DataMigration">数据迁移</UI-TERM>** 页面，单击右上角的 **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">新建迁移任务</UI-TERM>**。

2. 在 **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">选择源和目标</UI-TERM>** 页面，配置各项参数。

   |   参数   |                  描述                          |
   |--------|------------------------------------------------|
   | 迁移任务名称 | 建议使用中文、数字和字母的组合。名称中不能包含空格，长度不能超过 64 个字符。                                                                                                                                                 |
   | 标签（可选）     | 单击文本框，在下拉列表中选择目标标签。您也可以单击 **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">管理标签</UI-TERM>**，进行新建、修改和删除。详情请参见 [通过标签管理数据迁移任务](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md)。                                                                            |
   | 源端     |  如果您已创建 Milvus 数据源，请从下拉列表中进行选择。如果未创建，请单击下拉列表中的 **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">新建数据源</UI-TERM>**，在右侧对话框进行新建。参数详情请参见 [新建 Milvus 数据源](../800.create-and-manage-data-sources/100.create-a-data-source/1200.create-a-milvus-data-source.md)。                          |
   | 目标端    |  如果您已创建 OceanBase 社区版数据源，请从下拉列表中进行选择。如果未创建，请单击下拉列表中的 **<UI-TERM key="oms-community.EndpointPublic.Empty.AddADataSource">新建数据源</UI-TERM>**，在右侧对话框进行新建。参数详情请参见 [新建 OceanBase-CE 数据源](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md)。   |

3. 单击 **<UI-TERM key="oms-community.StepsForm.demo.Next">下一步</UI-TERM>**。在 **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">选择迁移类型</UI-TERM>** 页面，配置各项参数。

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">迁移类型</UI-TERM>** 包括 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SchemaMigration">结构迁移</UI-TERM>**、**<UI-TERM key="oms-community.Migration.constants.FullMigration">全量迁移</UI-TERM>** 和 **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">增量同步</UI-TERM>**。

   | 迁移类型 |      描述            |
   |------|-------------------------------------------------------------------------|
   | 结构迁移 |结构迁移任务开始后，OMS 社区版会迁移源库中的数据对象定义（表、索引、约束、注释和视图等）至目标端数据库中，并自动过滤临时表。<br>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">需要手动调整表结构</UI-TERM>**：OMS 社区版支持用户自定义表结构。勾选后，结构迁移阶段仅获取表结构 SQL，待您修改完成后，才开始执行。|
   | 全量迁移 | 全量迁移任务开始后，OMS 社区版会迁移源库表的存量数据至目标端数据库对应的表中。 |
   | 增量同步 | 增量同步任务开始后，OMS 社区版会同步源库发生变化的数据（新增、修改或删除）至目标端数据库对应的表中。<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">增量同步</UI-TERM>** 目前仅支持 **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">同步 DML</UI-TERM>** 中的 `Insert` 和 `Delete`。  |

4. 单击 **<UI-TERM key="oms-community.StepsForm.demo.Next">下一步</UI-TERM>**。在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">选择迁移对象</UI-TERM>** 页面，选择迁移对象和迁移范围。

   您可以通过 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">指定对象</UI-TERM>** 和 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">匹配规则</UI-TERM>** 两个入口选择迁移对象。本文为您介绍通过 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">指定对象</UI-TERM>** 方式选择迁移对象的具体操作，配置匹配规则的详情请参见 [配置迁移对象的匹配规则](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md)。

      <main id="notice" type='notice'>
      <h4>注意</h4>
      <ul>
      <li>
      <p>待迁移的表名和其中的列名不能包含中文字符。</p>
      </li>
      <li>
      <p>当数据库的库名或表名存在 &quot;$$&quot; 字符时，会影响数据迁移任务的创建。</p>
      </li>
      </ul>
      </main>

     OMS 社区版支持导入对象、重命名对象名称，以及移除单个或全部迁移对象。

     |   操作    |                                   步骤                                                                          |
     |---------|---------------------------------------------------------------------------------------------------|
     | 导入对象    | <ol><li> 在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">选择迁移范围</UI-TERM>** 区域的右侧列表中，单击右上角的 **<UI-TERM key="oms-community.components.Transfer.ImportObjects">导入对象</UI-TERM>**。   <li>在对话框中，单击 **<UI-TERM key="oms-community.Operator.Store.useStoreAction.Update">确定</UI-TERM>**。<br> **注意：**<br> 导入会覆盖之前的操作选择，请谨慎操作。  <li>在 **导入迁移对象** 对话框中，导入需要迁移的对象。<br>您可以通过导入 CSV 文件的方式进行库表重命名等操作。详情请参见 [下载和导入迁移对象配置](../600.data-migration/1500.manage-data-migration-projects/400.download-and-import-the-settings-of-migration-objects.md)。   <li> 单击 **<UI-TERM key="oms-community.components.ImportTransferObj.TestLegality">检验合法性</UI-TERM>**。   <li> 通过合法性的检验后，单击 **<UI-TERM key="oms-community.components.ProjectLabel.LabelManager.Determine">确定</UI-TERM>**。</ol>    |
     | 重命名     | OMS 社区版支持重命名迁移对象的名称，详情请参见 [数据库库表重命名](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md)。                     |
     | 移除/全部移除 | OMS 社区版支持在数据映射时，对暂时选中到目标端的单个或多个对象进行移除操作。 <ul><li>移除单个迁移对象 <br>在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">选择迁移范围</UI-TERM>** 区域的右侧列表中，鼠标悬停至目标对象，单击显示的 **<UI-TERM key="oms-community.Migration.constants.Remove">移除</UI-TERM>**，即可移除该迁移对象。  <li> 移除全部迁移对象 <br>在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">选择迁移范围</UI-TERM>** 区域的右侧列表中，单击右上角的 **<UI-TERM key="oms-community.Transfer.target.RemoveAll">全部移除</UI-TERM>**。在对话框中，单击 **<UI-TERM key="oms-community.Endpoint.New.Add">确定</UI-TERM>**，即可移除全部迁移对象。  </ul>   |

5. 单击 **<UI-TERM key="oms-community.StepsForm.demo.Next">下一步</UI-TERM>**。在 **<UI-TERM key="oms-community.MigrationObjectForm.MigrationTypeParams.MigrationOptions">迁移选项</UI-TERM>** 页面，配置各项参数。

   如果您需要查看或修改全量迁移、增量同步组件参数，请单击相应区域右上角的 **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">配置详情</UI-TERM>**。参数说明请参见 [组件参数说明](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) 模块的文档。

   * 全量迁移

      在 **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">选择迁移类型</UI-TERM>** 页面，选中 **<UI-TERM key="oms-community.Migration.constants.FullMigration">全量迁移</UI-TERM>**，才会显示下述参数。

      |参数|描述|
      |----|----------------------------------|
      | 并发速度 | 包括 **<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Smooth">平稳</UI-TERM>**、**<UI-TERM key="oms-community.components.MigrationParamsConfig.MigrationParamsForm.Normal">正常</UI-TERM>**、**<UI-TERM key="oms-community.Migration.constants.Quick">快速</UI-TERM>** 和 **<UI-TERM key="oms-community.pages.Audit.Custom">自定义</UI-TERM>**。全量迁移的性能不同，全量迁移任务所需要的资源也不同。当您选择 **<UI-TERM key="oms-community.pages.Audit.Custom">自定义</UI-TERM>** 时，可以根据实际情况设置 **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">读取并发</UI-TERM>**、**<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">写入并发</UI-TERM>** 和 **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM 内存</UI-TERM>**。|
      | 目标端对象存在记录时处理策略 | 处理策略包括 **<UI-TERM key="must.PreCheck.constants.Skip">忽略</UI-TERM>** 和 **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">停止迁移</UI-TERM>**：<ul><li>选择 **<UI-TERM key="must.PreCheck.constants.Skip">忽略</UI-TERM>**，当目标端表对象存在数据时，如果原数据与写入数据冲突，OMS 社区版采用将冲突数据记录日志，保留原数据不变的策略进行数据写入。<main id="notice" type='notice'><h4>注意</h4><p>选择 <b>忽略</b>，全量校验将使用 IN 模式拉取数据，无法校验目标端存在源端没有的数据的场景，并且校验性能会有一定程度降级。</p></main></li><li>选择 **<UI-TERM key="oms-community.New.components.ParameterForm.StopProject">停止迁移</UI-TERM>**，当目标端表对象存在数据时，全量迁移会报错不允许迁移，请处理好目标端数据后再继续迁移。<main id="notice" type='notice'><h4>注意</h4><p>如果出错后单击恢复，OMS 社区版将忽略该配置选项，继续迁移表数据，请谨慎操作。</p></main></li> </ul>|
      | 写入方式 | 包括 **SQL**（通过 `INSERT` 或 `REPLACE` 写入表）和 **Direct Load**（通过旁路导入方式写入）。目前暂不支持通过旁路导入的方式写入向量类型的数据。|

   * 增量同步

      在 **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">选择迁移类型</UI-TERM>** 页面，选中 **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">增量同步</UI-TERM>**，才会显示下述参数。

      |参数|描述|
      |----|----------------------------------|
      | 并发速度 | 包括 **<UI-TERM key="oms-community.New.components.ParameterForm.Smooth">平稳</UI-TERM>**、**<UI-TERM key="oms-community.Notification.Setting.AlarmChannel.Normal">正常</UI-TERM>**、**<UI-TERM key="oms-community.New.components.ParameterForm.Quick">快速</UI-TERM>** 和 **<UI-TERM key="oms-community.pages.Audit.Custom">自定义</UI-TERM>**。增量同步的性能不同，增量同步任务所需要的资源也不同。当您选择 **<UI-TERM key="oms-community.pages.Audit.Custom">自定义</UI-TERM>** 时，可以根据实际情况设置 **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">读取并发</UI-TERM>**、**<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">写入并发</UI-TERM>** 和 **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM 内存</UI-TERM>**。|
      |增量同步起始位点| <ul><li> 如果选择迁移类型时已选择 **<UI-TERM key="oms-community.Operation.constants.FullMigration">全量迁移</UI-TERM>**，该参数不显示。   <li> 如果选择迁移类型时未选择 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">全量迁移</UI-TERM>**，但选择了 **<UI-TERM key="oms-community.Sync.constants.IncrementalSynchronization">增量同步</UI-TERM>**，请在此处指定迁移某个时间节点之后的数据，默认为当前系统时间。详情请参见 [设置增量同步位点](../600.data-migration/1600.migration-function-introduction/1000.incremental-synchronization-timestamp.md)。  |

6. 单击 **<UI-TERM key="oms-community.SystemParam.contants.Precheck">预检查</UI-TERM>**，系统对数据迁移任务进行预检查。

   在 **<UI-TERM key="oms-community.Sync.New.Precheck">预检查</UI-TERM>** 环节，OMS 社区版会检查数据库用户的读写权限、数据库的网络连接等是否符合要求。全部检查任务均通过后才能启动数据迁移任务。如果预检查报错：

   * 您可以排查并处理问题后，重新执行预检查，直至预检查成功。

   * 您也可以单击错误预检查项操作列中的 **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">跳过</UI-TERM>**，会弹出对话框提示您跳过本操作的具体影响，确认可以跳过后，请单击对话框中的 **<UI-TERM key="oms-community.Migration.hooks.useMigrationObject.Determine">确定</UI-TERM>**。

7. 单击 **<UI-TERM key="oms-community.components.MigrationPreTable.StartAProject">启动任务</UI-TERM>**。如果您暂时无需启动任务，请单击 **<UI-TERM key="oms-community.biz.EndpointSupplement.Save">保存</UI-TERM>**，跳转至数据迁移任务的详情页面，您可以根据需要进行手动启动。

      OMS 社区版支持在数据迁移任务运行过程中修改迁移对象，详情请参见 [查看和修改迁移对象](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md)。数据迁移任务启动后，会根据选择的迁移类型依次执行，详情请参见 [查看数据迁移任务的详情](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) 中《查看迁移详情》模块的内容。
