# 迁移 PostgreSQL 数据库的数据至 OceanBase 社区版

本文为您介绍如何使用 OceanBase 迁移服务（OceanBase Migration Service，OMS）社区版迁移 PostgreSQL 数据库的数据至 OceanBase 社区版。

## 背景信息

在 OMS 社区版控制台创建从 PostgreSQL 数据库迁移数据至 OceanBase 社区版的数据迁移任务，您可以通过结构迁移、全量迁移和增量同步，无缝迁移源端数据库中的存量业务数据和增量数据至 OceanBase 社区版。

PostgreSQL 数据库支持单主库、单备库和主备库等模式。迁移 PostgreSQL 数据库的数据至 OceanBase 社区版时，不同类型的数据源支持的操作也不同。

| 类型  |                          支持的操作                           |
|-----|----------------------------------------------------------|
| 单主库 | 结构迁移 + 全量迁移 + 增量同步+ 全量校验 + 反向增量                          |
| 单备库 | 结构迁移 + 全量迁移  + 全量校验                                      |
| 主备库 | 主库：支持增量同步 + 反向增量 <br>备库：支持结构迁移 + 全量迁移 + 全量校验 |

## 前提条件

* 已在目标端 OceanBase 社区版中创建对应的 Schema。OMS 社区版支持迁移表和列，您需要提前在目标端创建对应的 Schema。

* 已为源端 PostgreSQL 数据库和目标端 OceanBase 社区版创建专用于数据迁移任务的数据库用户，并为其赋予了相关权限。详情请参见 [创建数据库用户](../800.create-and-manage-data-sources/300.create-a-database-user.md)。

## 使用限制

* **源端数据库的操作限制**

   **请勿在结构迁移和全量迁移阶段执行库或表结构变更的 DDL 操作，否则可能造成数据迁移任务中断。**

* 目前支持的 PostgreSQL 数据库版本为 V10.x、V11.x、V12.x、V13.x、V14.x、V15x 和 V16.x。

* OMS 社区版支持迁移 PostgreSQL 数据库的有主键表、无主键表或 NOT NULL UK 表至 OceanBase 社区版。

* OMS 社区版迁移 PostgreSQL 数据库的数据至 OceanBase 社区版时，不支持同步 DDL。

* 目标端是数据库的情况下，OMS 社区版不支持目标端存在 Trigger。如果存在，可能导致数据迁移失败。
  
* 迁移 PostgreSQL 数据库的分区表时，有以下限制：

  * 父表和子表的表结构需要相同。

  * 父表和子表的主键列/NOT NULL UK 列和分区列相同，或者主键列/NOT NULL UK 列包含分区列。

  * 从父表的视角需要确保主键/NOT NULL UK 唯一。

* PostgreSQL 数据库中待迁移父表和子表的 `REPLICA IDENTITY` 均需要为 FULL。

  * 如果 `REPLICA IDENTITY` 不为 FULL，可能导致业务数据更新、删除操作失败。

  * 指定迁移对象时，如果存在通配符，PostgreSQL 数据库需要订阅已选数据库的所有表（包括已选表、未选表和新增表）。所有表的 `REPLICA IDENTITY` 均需要为 FULL，否则可能导致业务数据更新、删除操作失败。

* OMS 社区版不支持迁移 PostgreSQL 数据库中的 Unlogged 表和临时表。

* 数据源标识和用户账号等，在 OMS 系统内全局唯一。

* OMS 社区版仅支持迁移库名、表名和列名为 ASCII 码且不包含特殊字符（包括 |"'`()=;/& 和换行）的对象。

* OceanBase 社区版不支持指定数组下标，PostgreSQL 则支持指定数组下标，格式为 `[开始下标:数组元素个数]={x,x,x,x}`。

   例如，PostgreSQL 指定的数组下标为 `[-1:10]={0,0,0,100,101,102,NULL,NULL,NULL,NULL,NULL,200}`，写入到 OceanBase 社区版为 `{0,0,0,100,101,102,NULL,NULL,NULL,NULL,NULL,200}`。反向写入 PostgreSQL 时，下标信息也会重置到 1，如果您的应用程序依赖下标则会存在如下问题。

  * 字符串数组中，数据项包含换行会异常报错。

  * PostgreSQL 中数组实际支持多维数组。例如，VARCHAR(255)[] 在进行数据写入时，实际可以写入的是多维数组数据：

    * {{a,b},{c,d}}

    * {{{1,a},{2,b}},{{1,c},{2,d}}}

    * ...

    目标端 OceanBase 社区版不支持多维数组，对于上述情况，OMS 社区版提供以下两种解决方法，您可以根据实际情况进行选择。

    * 方法一：目标字段根据实际数据维度创建对应维度的数组类型。例如，PostgreSQL 数据是二维数组，在 OceanBase 社区版也新建二维数组。

    * 方法二：目标字段使用 JSON 类型存储。

## 注意事项

* 建议您一次性迁移的表数量不超过 1000 张，避免影响数据迁移任务的运行。

* 如果表没有主键或所有列具备 NOT NULL 的唯一键，则迁移数据至目标端时，可能出现重复数据。

* 在反向增量场景中，对于 UPDATE、DELETE 采用全列匹配的方式迁移数据，可能出现以下问题。

  * 可能出现性能问题。
  
    由于不存在主键索引，会导致每次的 UPDATE 和 DELETE 操作都是在全表扫描之后进行。

  * 可能出现数据一致性问题。
  
    由于 UPDATE 和 DELETE 操作在 PostgreSQL 数据库中不支持 LIMIT 语法，当全列匹配时匹配到多条数据，可能会出现 UPDATE 或 DELETE 数据比目标端多的情况。例如，无主键表 t1 中存在 c1 和 c2 两列，在源端有两条 c1=1 和 c2=2 的数据。当源端删除其中一条数据时，由于匹配条件是 `where c1 = 1 and c2 = 2`，会导致目标端的两条 c1=1 和 c2=2 的数据均被删除，导致源端和目标端的数据不一致。

* PostgreSQL 数据库至 OceanBase 社区版的反向增量中，当 OceanBase 社区版为 V3.2.x 之前的版本且具有全局唯一索引的多分区表时，如果您更新了表的分区键的值，可能导致数据迁移过程中丢失数据。

* 如果您变更目标端的唯一索引，需要重启增量同步组件，否则可能存在数据不一致的问题。

* 节点之间的时钟不同步，或者电脑终端和服务器之间的时钟不同步，均可能导致延迟时间（增量同步/反向增量）不准确。

   例如，如果时钟早于标准时间，可能导致延迟时间为负数。如果时钟晚于标准时间，可能导致延迟。

* 库表汇聚场景下：

  * 建议您使用导入对象或匹配规则的方式映射源端和目标端的关系。

  * 建议您自行在目标端创建表结构。如果使用 OMS 社区版创建，请在结构迁移步骤跳过部分失败对象。

* 如果源端和目标端的表结构不完全一致，可能会出现数据不一致的情况。目前已知场景如下：

  * 用户手动创建表结构时，因超出 OMS 社区版的支持范围，可能产生隐式的转换问题导致源端和目标端列的类型不一致。

  * 目标端的数据长度小于源端的数据长度时，可能出现数据截断的情况，导致源端和目标端的数据不一致。

* 如果创建数据迁移任务时，您仅配置了 **<UI-TERM key="oms-community.Migration.constants.IncrementalMigration">增量同步</UI-TERM>**，数据迁移要求源端数据库的本地增量日志保存 48 小时以上。

   ​​​如果创建数据迁移任务时，您配置了 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullMigration">全量迁移</UI-TERM>** + **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">增量同步</UI-TERM>**，数据迁移要求源端数据库的本地增量日志至少保留 7 天以上。否则数据迁移可能因为无法获取增量日志导致数据迁移任务失败，甚至导致源端和目标端数据不一致。

## 操作步骤

1. 新建数据迁移任务。

   1. 登录 OMS 社区版控制台。

   2. 在左侧导航栏，单击 **<UI-TERM key="oms-community.components.CustomizedTable.DataMigration">数据迁移</UI-TERM>**。

   3. 在 **<UI-TERM key="oms-community.components.UserGuidance.DataMigration">数据迁移</UI-TERM>** 页面，单击右上角的 **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">新建迁移任务</UI-TERM>**。

2. 在 **<UI-TERM key="oms-community.Sync.New.SelectSourceAndDestination.1">选择源和目标</UI-TERM>** 页面，配置各项参数。

   |   参数   |                             描述                                                      |
   |--------|-----------------------------------------------------------|
   | 迁移任务名称 | 建议使用中文、数字和字母的组合。名称中不能包含空格，长度不能超过 64 个字符。                                                                                                                                 |
   | 标签     | 单击文本框，在下拉列表中选择目标标签。您也可以单击 **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">管理标签</UI-TERM>**，进行新建、修改和删除。详情请参见 [通过标签管理数据迁移任务](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md)。                                            |
   | 源端     | 如果您已创建 PostgreSQL 数据源，请从下拉列表中进行选择。如果未创建，请单击下拉列表中的 **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">新建数据源</UI-TERM>**，在右侧对话框进行新建。参数详情请参见 [新建 PostgreSQL 数据源](../800.create-and-manage-data-sources/100.create-a-data-source/900.create-a-pg-data-source.md)。<br> 您可以选择单主库或主库+备库类型的 PostgreSQL 数据源，本文以主库+备库类型为例。 |
   | 目标端    | 如果您已创建 OceanBase 社区版数据源，请从下拉列表中进行选择。如果未创建，请单击下拉列表中的 **<UI-TERM key="oms-community.pages.Endpoint.AddADataSource">新建数据源</UI-TERM>**，在右侧对话框进行新建。参数详情请参见 [新建 OceanBase-CE 数据源](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md)。                                    |
   |场景类型|包括 **<UI-TERM key="oms-community.Migration.constants.OnlyUniqueKeyTableMigration">仅支持唯一键表迁移</UI-TERM>** 和 **<UI-TERM key="oms-community.Migration.constants.SupportsAllTableMigration">支持全部表迁移</UI-TERM>**：<ul><li>唯一键表：指具有主键或者非空唯一键的表。<li>​全部表：指具备主键的表、唯一键表和无唯一键表，但不包含临时表。</ul>|

3. 单击 **<UI-TERM key="oms-community.Sync.New.Next">下一步</UI-TERM>**。

   如果您选择场景类型为 **<UI-TERM key="oms-community.Migration.constants.OnlyUniqueKeyTableMigration">仅支持唯一键表迁移</UI-TERM>**，还需要单击弹出提示框中的 **<UI-TERM key="oms-community.New.components.EndpointForm.ISee">我知道了</UI-TERM>**。

4. 在 **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">选择迁移类型</UI-TERM>** 页面，配置各项参数。

   **<UI-TERM key="oms-community.Detail.components.MigrationInfos.MigrationType">迁移类型</UI-TERM>** 包括 **<UI-TERM key="oms-community.Migration.constants.SchemaMigration">结构迁移</UI-TERM>**、**<UI-TERM key="oms-community.Migration.constants.FullMigration">全量迁移</UI-TERM>**、**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">增量同步</UI-TERM>**、**<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullVerification">全量校验</UI-TERM>** 和 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.ReverseIncrement">反向增量</UI-TERM>**。

   | 迁移类型 |       描述             |
   |------|-------------------------------------------------------------------------|
   | 结构迁移 | 结构迁移任务开始后，OMS 社区版会迁移源库中的数据对象定义（表、索引、约束、注释和视图等）至目标端数据库中，并自动过滤临时表。<ul><li>**<UI-TERM key="oms-community.MigrationTypeParams.components.StructConfigForm.NeedToManuallyAdjustTable">需要手动调整表结构</UI-TERM>**：OMS 社区版支持用户自定义表结构。勾选后，结构迁移阶段仅获取表结构 SQL，待您修改完成后，才开始执行。<li>**<UI-TERM key="oms-community.biz.ParamsCfg.ParamsDetail.TargetTableObjectStorageType">目标端表对象存储类型</UI-TERM>**：目标端 OceanBase 社区版为 V4.3.0 及之后版本，并且选中 **<UI-TERM key="oms-community.Migration.constants.SchemaMigration">结构迁移</UI-TERM>** 时，才会显示该区域的参数。<br>目标端表对象存储类型包括 **<UI-TERM key="oms-community.Migration.constants.Default">默认</UI-TERM>**、**<UI-TERM key="oms-community.Migration.constants.LineDeposit">行存</UI-TERM>**、**<UI-TERM key="oms-community.Migration.constants.ColumnStorage">列存</UI-TERM>** 和 **<UI-TERM key="oms-community.Migration.constants.RowAndRowMixed">行列混存</UI-TERM>**，该配置用于确定结构迁移或增量同步时目标端表对象的存储类型，详情请参见 [default_table_store_format](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002015561)。<main id="notice" type='explain'><h4>说明</h4><p><b>默认</b> 选项是根据目标端参数配置自适应其他选项，是结构迁移的表对象根据设置的存储类型写对应的结构。</p></main></ul>|
   | 全量迁移 | 全量迁移任务开始后，OMS 社区版会迁移源库表的存量数据至目标端数据库对应的表中。如果选择 **<UI-TERM key="oms-community.Migration.constants.FullMigration">全量迁移</UI-TERM>**，建议您在迁移数据前，使用 `ANALYZE` 语句收集 PostgreSQL 数据库的统计信息。                                                                                                                                                                                                                                               |
   | 增量同步 | 增量同步任务开始后，OMS 社区版会同步源库发生变化的数据（新增、修改或删除）至目标端数据库对应的表中。<br>**<UI-TERM key="oms-community.New.components.MigrationObjectForm.IncrementalMigration">增量同步</UI-TERM>** 的 **<UI-TERM key="oms-community.components.DBVerbTypeCheckGroup.DataChangeDml">同步 DML</UI-TERM>** 包括 `Insert`、`Delete` 和 `Update`，您可以根据需求进行选择。详情请参见 [DML 过滤](../600.data-migration/1600.migration-function-introduction/100.migration-dml.md)。<br>PostgreSQL 数据库作为源端的增量同步会自动创建 publication 和 slot。但是需要用户来监测归档文件的磁盘使用情况。OMS 社区版默认每 10 分钟通知更新一次 slot 的 confirmed_flush_lsn，间隔周期支持配置。并且默认归档文件需要保存 48 小时，因此只会通知可清理超过 48 小时以上的归档日志（可配置）。<br>在迁移过程中，如果因为 slot 而无法清理归档日志，则需要销毁数据迁移任务后，再清理归档日志。  |
   | 全量校验 | <ul><li> 如果选择 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.FullVerification">全量校验</UI-TERM>**，建议您在全量校验开始前，分别收集 PostgreSQL 数据库和 OceanBase 社区版的统计信息。OceanBase 社区版的收集详情请参见 [手动收集统计信息](https://www.oceanbase.com/docs/common-oceanbase-database-cn-1000000002017252)。  <li>如果您选择了 **<UI-TERM key="oms-community.SyncParameter.components.IncrSyncForm.IncrementalSynchronization">增量同步</UI-TERM>**，且 **<UI-TERM key="oms-community.components.SyncOption.CheckSyncKind.DataChangeDml">同步 DML</UI-TERM>** 选项中未选择所有的 DML，则 OMS 社区版不支持本场景下的全量数据校验。<li>OMS 社区版仅支持对唯一键表（指具有主键或者非空唯一键的表）进行全量数据校验。</ul>                                                                                                                                     |
   | 反向增量 | 反向增量任务开始后，可以实时回流业务切换后在目标端数据库产生的变更数据至源端数据库。以下情况均不支持选择 **<UI-TERM key="oms-community.Migration.constants.ReverseIncrement">反向增量</UI-TERM>**： <ul><li>存在多表汇聚的情况。  <li>存在 Schema 多到一映射的情况。              |

5. （可选）单击 **<UI-TERM key="oms-community.Sync.New.Next">下一步</UI-TERM>**。如果您选择了 **<UI-TERM key="oms-community.Migration.constants.ReverseIncrement">反向增量</UI-TERM>**，且目标端 OceanBase 社区版数据源未配置 Configurl、DRC 用户用户名和密码，则会弹出 **<UI-TERM key="oms-community.biz.EndpointSupplement.DataSourceSupplementaryInformation">数据源补充信息</UI-TERM>** 对话框，提醒您配置相应参数。参数详情请参见 [新建 OceanBase-CE 数据源](../800.create-and-manage-data-sources/100.create-a-data-source/100.add-an-oceanbase-ce-data-source.md)。

   补充完成后，单击 **<UI-TERM key="oms-community.biz.EndpointSupplement.TestConnectivity">测试连通性</UI-TERM>**。测试连接成功后，单击 **<UI-TERM key="oms-community.Endpoint.New.Save">保存</UI-TERM>**。

6. 单击 **<UI-TERM key="oms-community.components.MigrationObjectForm.NextStep">下一步</UI-TERM>**，在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">选择迁移对象</UI-TERM>** 页面，选择迁移对象和迁移范围。

   您可以通过 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">指定对象</UI-TERM>** 和 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">匹配规则</UI-TERM>** 两个入口选择迁移对象。本文为您介绍通过 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">指定对象</UI-TERM>** 方式选择迁移对象的具体操作，配置匹配规则的详情请参见 [配置迁移对象的匹配规则](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md)。

        * 调整 sys 租户参数

            ```sql
            // parallel_servers_target 用于设置每个 Server 上的并行查询排队条件。
            // 如果完全为了性能，建议您将该参数调整为大于物理 CPU 的值，例如 1.5 倍。同时设置的值不超过 64，避免产生 OceanBase 社区版内核抢锁问题。
            set global parallel_servers_target = 64; 
            ```

        * 调整业务租户参数

            ```sql
            // 文件内存缓冲区限制
            alter system set _temporary_file_io_area_size = '10' tenant = 'xxx'; 
            // 4.x 关闭限流
            alter system set sys_bkgd_net_percentage = 100;  
            ```

      * 如果您使用的是 OceanBase 社区版 V3.x，请通过黑屏客户端工具调整以下 sys 租户参数。

         ```sql
         // parallel_servers_target 用于设置每个 Server 上的并行查询排队条件。
         // 如果完全为了性能，建议您将该参数调整为大于物理 CPU 的值，例如 1.5 倍。同时设置的值不超过 64，避免产生 OceanBase 社区版内核抢锁问题。
         set global parallel_servers_target = 64; 
         // data_copy_concurrency 用于设置系统中并发执行的数据迁移复制任务的最大并发数。
         alter system set data_copy_concurrency = 200;
         ```
