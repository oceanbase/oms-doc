# 迁移 Redis 数据库的数据至 OBKV Redis 数据库

本文为您介绍如何使用 OceanBase 迁移服务（OceanBase Migration Service，OMS）社区版迁移 Redis 数据库的数据至 OBKV Redis 数据库。

## 使用限制

* 目前 Redis 数据库至 OBKV Redis 数据库的数据迁移任务仅支持全量迁移。

* 目前支持 Redis 数据库 V2.8.0 及之后的版本。

## 注意事项

* 对于目标端 OBKV Redis 数据库中不支持的字段，OMS 社区版会统一转换为 STRING 类型写入。

* 全量迁移过程中，如果数据迁移任务中断，再次启动之后，LIST 类型的数据会出现数据重复的问题。

## 操作步骤

1. 新建数据迁移任务。

   1. 登录 OMS 社区版控制台。

   2. 在左侧导航栏，单击 **<UI-TERM key="oms-community.components.UserGuidance.DataMigration">数据迁移</UI-TERM>**。

   3. 在 **<UI-TERM key="oms-community.New.components.EndpointForm.DataMigration">数据迁移</UI-TERM>** 页面，单击右上角的 **<UI-TERM key="oms-community.Migration.Empty.CreateAMigrationProject">新建迁移任务</UI-TERM>**。

2. 在 **<UI-TERM key="oms-community.Migration.New.SelectSourceAndDestination">选择源和目标</UI-TERM>** 页面，配置各项参数。

   |   参数   |                  描述                          |
   |--------|------------------------------------------------|
   | 迁移任务名称 | 建议使用中文、数字和字母的组合。名称中不能包含空格，长度不能超过 64 个字符。                                                                                                                                                 |
   | 标签（可选）     | 单击文本框，在下拉列表中选择目标标签。您也可以单击 **<UI-TERM key="oms-community.components.ProjectLabel.LabelSelect.ManageTags">管理标签</UI-TERM>**，进行新建、修改和删除。详情请参见 [通过标签管理数据迁移任务](1500.manage-data-migration-projects/300.use-tags-to-manage-data-migration-projects.md)。                                                                            |
   | 源端     |  如果您已创建 Redis 数据源，请从下拉列表中进行选择。如果未创建，请单击下拉列表中的 **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">新建数据源</UI-TERM>**，在右侧对话框进行新建。参数详情请参见 [新建 Redis 数据源](../800.create-and-manage-data-sources/100.create-a-data-source/1300.create-a-redis-data-source.md)。                          |
   | 目标端    |  如果您已创建 OBKV Redis 数据源，请从下拉列表中进行选择。如果未创建，请单击下拉列表中的 **<UI-TERM key="oms-community.Endpoint.New.AddADataSource">新建数据源</UI-TERM>**，在右侧对话框进行新建。   |

3. 单击 **<UI-TERM key="oms-community.components.ViewObj.AddObject.NextStep">下一步</UI-TERM>**。在 **<UI-TERM key="oms-community.Migration.New.SelectMigrationType">选择迁移类型</UI-TERM>** 页面，勾选 **<UI-TERM key="oms-community.Migration.constants.FullMigration">全量迁移</UI-TERM>**。

   全量迁移任务开始后，OMS 社区版会迁移源库表的存量数据至目标端数据库对应的表中。

4. 单击 **<UI-TERM key="oms-community.Migration.New.Next">下一步</UI-TERM>**。在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectObjectsToBeMigrated">选择迁移对象</UI-TERM>** 页面，选择迁移对象和迁移范围。

   您可以通过 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">指定对象</UI-TERM>** 和 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.MatchRules">匹配规则</UI-TERM>** 两个入口选择迁移对象。本文为您介绍通过 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SpecifiedObject">指定对象</UI-TERM>** 方式选择迁移对象的具体操作，配置匹配规则的详情请参见 [配置迁移对象的匹配规则](../600.data-migration/1600.migration-function-introduction/300.configure-matching-rules-for-migration-objects.md)。

   <main id="notice" type='notice'>
   <h4>注意</h4>
   <ul>
   <li>
   <p>待迁移的表名和其中的列名不能包含中文字符。</p>
   </li>
   <li>
   <p>当数据库的库名或表名存在 &quot;$$&quot; 字符时，会影响数据迁移任务的创建。</p>
   </li>
   </ul>
   </main>

     OMS 社区版支持重命名对象名称、设置行过滤、查看列信息，以及移除单个或全部迁移对象。

     |   操作    |                                   步骤                                                                          |
     |---------|---------------------------------------------------------------------------------------------------|
     | 重命名     | OMS 社区版支持重命名迁移对象的名称，详情请参见 [数据库库表重命名](../600.data-migration/1600.migration-function-introduction/500.db-table-rename.md)。  <br>请注意重命名的表名也需要符合 OBKV 表名的格式 `表名$列族名`。                     |
     | 设置      | OMS 社区版支持 `WHERE` 条件实现行过滤，详情请参见 [SQL 条件过滤数据](../600.data-migration/1600.migration-function-introduction/600.migration-row-filters.md)。<br>您还可以在 **<UI-TERM key="oms-community.biz.ETL.ETLFormDrawer.ViewColumns">查看列</UI-TERM>** 区域，查看迁移对象的列信息。                      |
     | 移除/全部移除 | OMS 社区版支持在数据映射时，对暂时选中到目标端的单个或多个对象进行移除操作。 <ul><li>移除单个迁移对象 <br>在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">选择迁移范围</UI-TERM>** 区域的右侧列表中，鼠标悬停至目标对象，单击显示的 **<UI-TERM key="oms-community.components.ViewObj.DelObject.Remove">移除</UI-TERM>**，即可移除该迁移对象。  <li> 移除全部迁移对象 <br>在 **<UI-TERM key="oms-community.New.components.MigrationObjectForm.SelectAMigrationRange">选择迁移范围</UI-TERM>** 区域的右侧列表中，单击右上角的 **<UI-TERM key="oms-community.Transfer.target.RemoveAll">全部移除</UI-TERM>**。在对话框中，单击 **<UI-TERM key="oms-community.src.layout.BasicLayout.Confirmation">确定</UI-TERM>**，即可移除全部迁移对象。  </ul>   |

5. 单击 **<UI-TERM key="oms-community.Migration.New.Next">下一步</UI-TERM>**。在 **<UI-TERM key="oms-community.Migration.New.MigrationOptions">迁移选项</UI-TERM>** 页面，配置全量迁移的各项参数。

    |参数|描述|
    |----|----------------------------------|
    | 并发速度 | 包括 **<UI-TERM key="oms-community.Migration.constants.Smooth">平稳</UI-TERM>**、**<UI-TERM key="oms-community.New.components.ParameterForm.Normal">正常</UI-TERM>**、**<UI-TERM key="oms-community.Migration.constants.Quick">快速</UI-TERM>** 和 **<UI-TERM key="oms-community.New.components.ParameterForm.Custom">自定义</UI-TERM>**。全量迁移的性能不同，全量迁移任务所需要的资源也不同。当您选择 **<UI-TERM key="oms-community.pages.Audit.Custom">自定义</UI-TERM>** 时，可以根据实际情况设置 **<UI-TERM key="oms-community.migration.new.components.communityForm.readConcurrency">读取并发</UI-TERM>**、**<UI-TERM key="oms-community.migration.new.components.communityForm.writeConcurrency">写入并发</UI-TERM>** 和 **<UI-TERM key="oms-community.migration.new.components.communityForm.jvmMemory">JVM 内存</UI-TERM>**。|

    如果您需要查看或修改全量迁移组件参数，请单击 **<UI-TERM key="oms-community.Migration.constants.FullMigration">全量迁移</UI-TERM>** 区域右上角的 **<UI-TERM key="oms-community.migration.new.components.communityForm.configDetail">配置详情</UI-TERM>**。参数说明请参见 [组件参数说明](../900.o-m-manual/400.components/500.component-parameters/100.coordinator.md) 模块的文档。

6. 单击 **<UI-TERM key="oms-community.SystemParam.contants.Precheck">预检查</UI-TERM>**，系统对数据迁移任务进行预检查。

   在 **<UI-TERM key="oms-community.Migration.New.Precheck">预检查</UI-TERM>** 环节，OMS 社区版会检查数据库用户的读写权限、数据库的网络连接等是否符合要求。全部检查任务均通过后才能启动数据迁移任务。如果预检查报错：

   * 您可以排查并处理问题后，重新执行预检查，直至预检查成功。

   * 您也可以单击错误预检查项操作列中的 **<UI-TERM key="oms-community.components.SyncSwitch.CreateDestStore.Skip">跳过</UI-TERM>**，会弹出对话框提示您跳过本操作的具体影响，确认可以跳过后，请单击对话框中的 **<UI-TERM key="oms-community.Operator.JDBCWriter.useJDBCWriterAction.Start">确定</UI-TERM>**。

7. 单击 **<UI-TERM key="oms-community.Sync.New.StartATask">启动任务</UI-TERM>**。如果您暂时无需启动任务，请单击 **<UI-TERM key="oms-community.Endpoint.New.Save">保存</UI-TERM>**，跳转至数据迁移任务的详情页面，您可以根据需要进行手动启动。

      OMS 社区版支持在数据迁移任务运行过程中修改迁移对象，详情请参见 [查看和修改迁移对象](../600.data-migration/1500.manage-data-migration-projects/200.view-and-modify-migration-objects.md)。数据迁移任务启动后，会根据选择的迁移类型依次执行，详情请参见 [查看数据迁移任务的详情](../600.data-migration/1500.manage-data-migration-projects/100.view-details-of-a-data-migration-project.md) 中《查看迁移详情》模块的内容。
