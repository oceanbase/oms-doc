# Full-Verification 组件参数说明

| 参数         |      默认值    |    描述    |    适用版本 |
|-------------|-----------|---------------|-------------|
| limitator.platform.threads.number |  默认值和设置的全量校验资源配置相关|校验数据源读线程数。源端和目标端的读线程的数量取决于参数 `limitator.platform.threads.number` 和 `limitator.source.max.thread.size`，计算逻辑如下：<ol><li>`limitator.source.max.thread.size` 参数的默认值为 6。</li><li>一端的读线程的初始值=`limitator.platform.threads.number`/2。 </li><li>则读线程的数量取 `limitator.source.max.thread.size` 的值和一端的读线程的初始值的较小值。</li></ol>例如，`limitator.platform.threads.number`=10，则源端和目标端读线程各有 5 个。`limitator.platform.threads.number`=14，则源端和目标端读线程各有 6 个。|  全部版本 |
| limitator.platform.split.threads.number | 16 |校验切片线程数。|  全部版本 |
| limitator.select.batch.max  | 600 | 每个切片的最大记录数。以 PK/UK 方式切片时，该数值是准确的每个切片处理的最大记录数。<main id="notice" type='explain'><h4>说明</h4><p>非切片性能瓶颈时，不建议修改该参数。</p></main>| 全部版本 |
| limitator.reviewer.rounds.max | 20  | 复检轮数。<main id="notice" type='explain'><h4>说明</h4><p>存在数据不一致的情况时，如果您需要快速获取不一致的结果，或已经确认是数据不一致的场景，可以设置该参数的值为 0，不进行复检直接输出数据对比的结果。</p></main>| 全部版本 |
| limitator.reviewer.review.batch.max |  100 |每一个复检任务要校验的不一致的唯一键个数。| 全部版本 |
| limitator.review.query.batch.limit |100  | 【复检】每次查询源端/目标端的唯一键数量。该参数和 `limitator.reviewer.review.batch.max` 配合使用。例如，`limitator.reviewer.review.batch.max = 100`，而 `limitator.review.query.batch.limit=50`，说明一个复检任务会复检 100 个唯一键，而每次查询源端/目标端 50 个唯一键。因此该复检任务会查询两次数据库。|  oboms-verifier-2.0.0-xxx 之后版本 |
| filter.verify.rectify.type | no | 数据订正设置参数，包括 `no` 和 `now`。<ul><li>no：表示发现不一致数据不订正。</li><li>now：表示发现不一致数据立即订正。</li></ul><main id="notice" type='notice'><h4>注意</h4><ul><li>非应急场景禁止将该参数配置为 <code>now</code>。如果需要配置，请和 OMS 社区版技术支持人员确认。</li><li>`oboms-verifier-2.0.0-xxx` 之后的版本支持 MySQL->OB_MySQL 和 OB_MySQL->OB_MySQL 自动订正功能，`oboms-verifier-1.xxx` 版本不支持该功能。</li></main>| 全部版本 |
| filter.verify.inmod.tables | 无  |使用 inmode 机制校验表的配置参数。OMS 社区版校验包含普通校验和 inmode 校验，主要区别是目标端读取数据的方式。使用 inmode 模式校验，目标端不会根据切片范围去查询，而是根据源端通过某个切片读出的所有数据，从而计算出主键的值，目标端再根据主键的值进行查询。</li></ul><main id="notice" type='notice'><h4>注意</h4><p>使用 inmode 模式校验，将无法校验目标端存在源端没有的数据的场景，并且校验性能会有一定程度降级。</p></main>常见场景示例如下：<ul><li>配置当前任务的所有表均使用 inmode 校验：`filter.verify.inmod.tables=.*;.*;.*`</li><li>配置 D1 库下的 T1 表使用 inmode 校验：`filter.verify.inmod.tables = D1;T1;.*`</li><li>配置 D1 库下的 T1 和 T2 表使用 inmode 校验：`filter.verify.inmod.tables = D1;T1;.*\|D1;T2;.*`</li><li>配置 D1 库下的 T1、T2 表和 D2 库下的 T3、T4 表使用 inmode 校验：`filter.verify.inmod.tables = D1;T1;.*\|D1;T2;.*\|D2;T3;.*\|D2;T4;.*`|  全部版本 |
| limitator.table.diff.max | 10000 | 每张表允许的最大不一致数量。如果校验发现某张表不一致的数量超过该值，则将该表的状态置为异常，不会继续校验该表的数据。<main id="notice" type='notice'><h4>注意</h4><p>不建议将该值设置为千万级别以上。</p></main>| 全部版本 |
| limitator.ready.verify.record.queue.size | 64 |等待校验数据队列数量。|  oboms-verifier-2.0.0-xxx 之后版本|
| limitator.ready.rectify.record.queue.size | 64  |等待订正数据队列数量。 |  oboms-verifier-2.0.0-xxx 之后版本 |
| limitator.sink.slice.queue.size | 64 |目标端切片队列大小. |  oboms-verifier-2.0.0-xxx 之后版本 |
| task.coordinatorSection.reviewTaskQueueSize | 64 |复检任务队列大小。|  oboms-verifier-2.0.0-xxx 之后版本|
| limitator.verify.thread.size |  8 |校验线程数。| oboms-verifier-2.0.0-xxx 之后版本|
| limitator.review.thread.size | 16 | 复检线程数。| oboms-verifier-2.0.0-xxx 之后版本 |
| limitator.rectify.thread.size | 32 |订正线程数。|  oboms-verifier-2.0.0-xxx 之后版本|
| limitator.slice.split.batch.size | 无 | 如果目标端使用 in 查询，则一次查询拼接的唯一键数量。| oboms-verifier-1.0.23-20230904200300 之后版本 |
| task.sourceMasterSection.matchAllColumn | true | 校验设置是否全字段匹配，包括 true 和 false。<ul><li>true：表示需要全字段匹配才会进行校验。</li><li>false：表示源端字段无需全部映射到目标表字段中，仅校验匹配的字段，未匹配的字段则不进行校验。</li></ul>  |  OMS 社区版 V4.2.4-CE 及之后版本|
| task.sourceMasterSection.excludeColumn | 无 |指定源表排除校验的字段。请注意不可以用于排除 PK 和 UK 中的字段，否则会导致校验异常。格式为 {"正则表达式":"c1,c2,.."}，正则表达式匹配的表名格式为 `schema.tablename`。  | OMS 社区版 V4.2.4-CE 及之后版本|
| task.sourceMasterSection.joinField | 无  | 配置指定用于表 Join 的字段。格式为 `{"库名.表名": "源端字段名:目标字段名,...."}`。多个字段之间使用英文逗号（,）分隔。<br>如果源端字段名和目标端字段名一致，您可以直接配置为 `{"库名.表名": "源端字段名,....."}`。 | OMS 社区版 V4.2.11-CE 及之后版本|
| datasource.master.extConfig | 无 | 源端连接的额外配置项，格式为 `map<string,string>`。配置参数包括 `useSSL`（是否启用 SSL）、`trustStore`（授信证书路径）、`trustStorePassword`（授信证书密码）、`keyStore`（客户端密钥库路径）、`keyStorePassword`（客户端密钥库文件密码）和 `disableSslHostnameVerification`（是否禁用主机名验证）。 | OMS 社区版 V4.2.13-CE 及之后版本 |
| datasource.image.extConfig | 无 | 源端连接的额外配置项，格式为 `map<string,string>`。配置参数包括 `useSSL`（是否启用 SSL）、`trustStore`（授信证书路径）、`trustStorePassword`（授信证书密码）、`keyStore`（客户端密钥库路径）、`keyStorePassword`（客户端密钥库文件密码）和 `disableSslHostnameVerification`（是否禁用主机名验证）。| OMS 社区版 V4.2.13-CE 及之后版本 |

上述表格中的适用版本是指数据校验组件的的版本，您可以通过以下方式查看 OMS 社区版当前校验版本。

1. 登录 OMS 社区版部署服务器。

2. 进入 Docker 容器。

   ```shell
   docker exec -it ${CONTAINER_NAME} bash
   ```

   <main id="notice" type='notice'>
    <h4>注意</h4>
    <p><code>CONTAINER_NAME</code> 为创建容器的名称。</p>
   </main>

3. 执行下述命令，查询校验组件的版本。

    ```shell
    rpm -qa | grep "verifier"
    ```
